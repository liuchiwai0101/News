一、DeepSeek Harness 是什么？

Harness 這個詞翻譯過來就是「駕馭」，如果把 AI 模型比作一匹馬，那 Harness 就是你駕馭 AI 模型這匹馬所需要的一切工程。

所謂 Harness 工程，就是研究怎麼讓 AI 模型這匹馬跑得更快、更穩，順利完成任務。

你給 AI 寫的項目規則文件、配置的各種工具、安排的任務拆分和執行順序、設計的測試檢查流程，這些統統都算 Harness。

有一个很精妙的公式：**Agent = Model + Harness**

模型負責思考和生成，Harness 負責把這些能力接入文件系統、終端、網頁、工具鏈，讓 AI 真正能在現實環境裏幹活。

之前 DeepSeek 只開源了模型這一半，Harness 一直沒動靜，這次終於補齊了。

你可以把 DeepSeek Harness 理解成一個 **可以高度定製的 AI 編程工具**，對標 Claude Code 和 Codex。

但它的野心比這些工具更大，不只是一個編程 Agent，而是一套可配置、可重組的 Agent 運行環境，官方口號是「一切皆插件」。

接下來我們瞭解一下 DeepSeek Harness 的幾種運行模式，看看它還有什麼用法。

四、4 種運行模式

DeepSeek Harness 提供了四種運行模式，適配不同的使用場景。

**標準模式** 就是我們前面實戰一直在用的那個。它加載了完整的工具組合，包括文件編輯、Shell 命令、網頁搜索、子 Agent、Skills 技能等等，覆蓋了日常開發的所有需求。絕大多數情況下用它就好了。

**極簡模式** 只保留了 Bash 和文件編輯這兩件最基礎的工具，其他能力全部關掉。這個模式主要是官方拿來跑模型基準測試用的，在最小環境下考驗模型的純編程能力，普通用戶基本用不到。

**PTC 模式** 全稱是「程序化工具調用」。普通模式下 AI 是一步一步調用工具的，每步執行完才能決定下一步做什麼。但在 PTC 模式下，模型可以直接生成一段 TypeScript 代碼，把多步工具調用串聯起來一次性執行完。適合那種步驟很多但邏輯清晰的任務，比如批量重命名文件、跑一整套自動化流程，效率比一步步確認要高得多。

**創造模式** 適合想要開發插件、創造新工具或者定製模式預設的同學。它繼承了標準模式的全部能力，在此基礎上還讓 AI 可以檢查當前運行時有哪些插件在跑、在內存裏試驗新的插件組合、甚至自己創作出一個全新的模式預設。後面我們會用這個模式來開發自己的插件。

總結一下，這四種模式的本質區別就是「當前會話加載了哪些工具插件」。極簡模式只留兩件工具，標準模式疊滿全套能力，創造模式還能讓 AI 自己查看和改裝當前的插件配置。

看到這裏，你已經超過了 80% 的同學，但 DeepSeek Harness 真正讓我興奮的地方纔剛剛開始。

五、插件

接下來要聊 DeepSeek Harness 跟 Codex、Claude Code 這些工具最大的區別了，就是它的插件系統。

一切皆插件

DeepSeek Harness 中的一切皆插件。

模型、工具、技能、會話、沙箱、UI，甚至 Agent 的運行循環本身，都是插件，都可以拔掉換成別的。

也就是說，如果你對這個工具哪個地方不滿意，隨時可以自己替換或者安裝插件來擴展，不需要改框架源碼。

Codex 和 Claude Code 雖然也有一定的擴展能力，但遠沒有做到這種級別的開放，DeepSeek Harness 的定製化能力要強得多。

接下來我先帶大家使用社區插件，再帶大家開發屬於自己的插件。
