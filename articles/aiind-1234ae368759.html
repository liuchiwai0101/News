輕量化異構雙臂 × VLA/世界模型：家庭服務具身機器人的落地實踐

內容機器翻譯自第三方媒體（InfoQ），僅供參考，以原文為準。

正文

具身智能在家庭場景的落地正從概念驗證走向產品化探索，但如何在非結構化環境中實現長時序任務、多模態交互與持續成長，仍是行業共同面對的難題。

本文整理自樂享科技聯席 CTO、穹明智能總經理 李元慶 在 AICon 全球人工智能開發與應用大會 2026 深圳站 的分享《輕量化異構雙臂 × VLA/世界模型：家庭服務具身機器人的落地實踐》。他系統梳理了家庭機器人的形態定義、輕量化本體設計、分層軟件架構以及仿真到真機的數據閉環實踐，重點討論了 rule-based 與 modular-based 策略的協同關係、端到端方法在現實約束下的差距、軟硬一體開發中的自動化代碼生成，以及機器人自我進化系統 RSI 的構建思路。

坦率地説，目前大家對 to C 具身智能是否到了落地的節點仍有疑慮，但家庭場景中的真實需求是存在的。每個人在家裏都希望有機器人能夠幫你做越來越多的事情，我們對於廚師、保姆、阿姨這些角色的期待，本質上就是希望從大量重複性家務中解放出來。這幾年工作日裏大家越來越忙碌，很多人選擇點外賣而不是自己做飯，那麼週末能不能把時間還給自己，這些事情在 to C 場景裏大有可為。

在具身智能這個賽道，數據、本體、場景和硬件就像一隻手的五個手指頭，只有握在一起才能成為一個拳頭。這個比喻非常形象。對於現在做機器人的團隊來説，這幾個維度目前還沒有真正做到清晰的解耦。做硬件的團隊、做模型的團隊、做軟件的團隊，彼此之間仍然需要非常多的打磨。原因很簡單，做 AI 的人都會圍繞數據和落地的應用成功率展開工作，場景決定了數據的結構，數據結構又決定了模型的參數量和形態。而一旦在真機中引入 physical 本體，本體產生的數據中，on policy 強化學習和 post training 那一部分依然是至關重要的。這説明硬件本體、數據採集和策略訓練之間並沒有完全分開，它們天然地綁定在一起。

家庭機器人的理想與現實之間還存在明顯的鴻溝。to C 有一個好處是數據的 diversity，它可能讓 AI 的整個基線跑得更快。而且在應用端，我們可以通過 IP、情緒價值和營銷策略讓用户更早地接受產品，這是 to C 與 to B 不一樣的地方。但與此同時，to C 場景中的本體往往還比較笨重，能不能做得更輕、更小，是一個非常現實的問題。舉個例子，幫我們拿一杯水這個看似簡單的任務，在複雜家庭環境中其實是一個長時序任務。機器人需要先去找水，找到水的過程中可能需要先打開一扇門，走到冰箱旁邊，打開冰箱門，再在冰箱內部找到那瓶水並把它拿出來。整個過程是一個 long context，也是一個 long horizon 的任務。交互的多模態與情感化同樣重要。當用户説“幫我拿一杯水”時，如果機器人只是一個多模態模型，它怎麼知道哪一杯水屬於用户？這需要前面的 memory，也需要非常準確的 reasoning 來完成移動。

非結構化的家庭環境是另一個挑戰。這幾年一些團隊在做酒店、康養等半結構化場景，但家庭場景始終是最後一個複雜、高動態、高靈活度的地方。此外還有隱形的意圖與長短記憶問題。用户説出的一句話攜帶的信息量其實非常少，機器人想把任務做對的難度極大。“出廠即精英”的假設也不符合實際需求。我們在調研中感受到，機器人走進家裏的時候更像一個笨笨的小朋友，它需要像阿姨一樣熟悉用户的生活習慣。比如用户説“幫我拿杯水”，早上九點拿的可能是一杯白水，下午三點拿的可能是一杯冰可樂。這些上下文習慣必須被長期記憶和學習，這件事才有可能真正做成。

基於 to C 的思考，我們採用了一個比較務實的產品策略。當機器人出現在家庭中，它首先面臨的問題是自己到底是什麼：是一個工具、一個家電，還是一個家庭成員？我們把產品身份定義為三種形態：pet、partner、assistant。

三者的區別非常清晰。Pet 提供純粹的情緒價值和功能價值，更像日本之前 LOVOT 那種笨笨的機器人，用户感受到的是多巴胺和催產素的分泌，購買決策由營銷和情感驅動。Partner 的核心能力是養成系能力：它走進家裏時一半是情緒價值，能在交互和簡單移動操作中給出情感上的理解，同時能完成基礎任務，並在這個家庭中持續成長。Assistant 則純粹是功能價值，像鋼鐵俠裏的賈維斯，或者那個笨笨機器人幫你拿滅火器去噴着火的工作台。我們認為這三類形態是未來具身智能走進家庭時最真實的產品形態。

在這些形態背後，我們在整個公司體系下做了一些前沿探索。技術側我們自研了高扭矩密度電機。之所以要自研，是因為前兩年我們在國內供應鏈中尋找能把機器人做輕做小的方案時遇到了限制。如果希望機器人保持同樣的末端負載和同樣的工作空間，就必須把電機儘可能做小，這樣才有機會把上半身做輕，底下也做輕。這是輕量化最本質的路徑。另外在情緒識別上，我們發現語言裏包含的信息太少，能不能把語音的語調、語速都作為參考輸入，把人的表情、説話時間和前面的上下文聯繫在一起，這是我們智能大腦的一部分工作。機械臂、靈巧手和 VLA 模型共同組成智能大腦，這一點後面會在軟件架構上展開。

我們最近發佈了一款輕量化的家庭協作機器人。當前整機重量是 30 千克，我們還在繼續壓重量。它的底盤很小，直徑只有 45 釐米，比家裏的掃地機器人大一圈，接近一個大號花盆。升降高度從 82 釐米到 147 釐米，82 釐米，機器人蹲在那裏像家裏一個大一點的桶，147 釐米則接近身材矮小女生在操作時胳膊的高度。

我們做了三個版本，大家在看到產品時可能會注意到兩個機械臂有的一樣、有的不一樣。兩個七自由度臂的方案，是這幾年大家都在講 data driven，通過 common sense 策略，用像人胳膊一樣的自由度去完成同樣的事情。但這對機器本體的要求非常高。另一個方案是一個四自由度和一個七自由度配合。這裏的設計邏輯是：人是分左手和右手的。在做穿針引線這類動作時，左手往往負責固定的握持和約束，右手執行精細化操作。比如擰瓶蓋時，人其實是用兩隻手協作，但如果放到標準的笛卡爾空間裏考慮，左手可以固定住，只要把握持動作做好，右手來做精細操作。因此我們設計了四加七的結構。四自由度這邊整條臂可以做得非常輕，配合拖鏈和型材結構，完成高處的動作時前後摩擦力需要對抗，但抬起的動作非常輕，這樣整個策略都依賴於一個穩定的約束。如果只看這一半，它是一個標準的笛卡爾座標系，對 AI 算法來説，做 manipulation、動態視覺追蹤和策略都輕鬆很多。底盤方面我們提供了全向輪和差速輪兩個版本，都是基於成本和實際業務中的發現來選擇的。比如機器人會纏到頭髮、需要越過小的門檻縫、用户對柔性化靈活度有要求，這些我們都做了大量測試。最終推出目前這三個產品版本，是希望用户在用的時候能感受到工程師在設計時的認真。

我們發佈了一支產品視頻，畫面是温馨的藝術化渲染。視頻裏展示了一個理想場景：家裏不只是一間房子，有人提前為你把生活的雜亂捋清，每句叮囑都有回應，小恩協作機器人會把你顧不上的小事一件一件放在心上，出門時提醒你帶上口袋裏的愛心，疲憊時輕輕接住你。雖然視頻是藝術渲染的結果，但大家可以從中感受一下，如果這個機器人純靠遙操作，它能完成的工作空間和想象空間到底在哪裏。接下來我把它的技術底座和實際做到的東西跟大家分享。

軟件架構上，我們的設計思路是分層的。這幾年大家聽到 agent 比較多，前兩年聽到端到端比較多。現在大家聽到 rule-based 這個詞可能覺得陌生，但它其實在這個賽道已經存在很久了。狀態機、behavior tree 都是 rule base 的典型代表，本質上就是明確地遇到一個情況然後產生一個行為，類似 switch case 或者 if else。掃地機裏很早就積累了大量這樣的經驗：捲到窗簾就退出來，捲到地毯就退出來，被門擠了一下就退出來。這些都是之前工程師積累的 corner case 和長尾問題經驗。家裏並不是從來沒有過智能機器人，掃地機器人曾經走進過家裏，在移動導航和避障上積累的經驗非常有價值。我們能不能把這些高解釋性、高可靠性、低成本的策略作為機器人的兜底？這是我們的第一層，它也像無人駕駛裏的 questions 和 checker 一樣，承擔安全兜底和基礎行為保障的角色。

第二層是 modular-based。這個階段大家做的策略其實很像 agentic 架構：把 perception、decision making、reasoning、memory 以及後面的 action 和各種 skills 都拆開去做。這件事很有意思，因為通過 modular-based 策略，能把一個機器人的軟件體系先完整地連在一起。它看起來可能很慢，泛化能力也不夠強，但它能夠把前面各個可解釋性的環節連通起來。它主要解決了一個困惑行業很久的問題：可控性的 AI 到底怎麼做？後來我們發現，可控性的 AI 可以總結為一句話：讓每一個模塊都完全可控。這句話聽起來抽象，但核心意思是不能讓所有模塊細節都變成黑盒，中間必須有一個階段是拆分的。拆分之後，我們能看到顯式的結構特徵。在早期可能是專家網絡或稠密結構，通過這些顯式結構特徵，機器人可以快速學會一個東西，實現 few shot，從而替代掉端到端在現階段難以落地的部分。

端到端仍然是未來要努力去攻克的方向。目前在 modular-based 架構下，perception 環節需要反覆看一個東西，調用攝像頭的次數很多。端到端則是像看一個事情就推一個 chunk，攝像頭調用次數大幅減少，能耗會壓縮，模型大小會變小，API 調用次數也會減少。只要考慮到一天的落地運行，穩定性和能耗就是必須面對的問題，端到端一定要做。而且端到端的信息利用效率是最高的。modular-based 階段我們做分塊，是因為自然語義文本和環境信息裏包含的內容太少，我們必須在合適的節點把最合適的數據交給它，否則有些地方數據是浪費的，有些地方數據又實在太少。這一頁內容做得比較早，後面論文更新會進一步展開。

把軟硬一體這件事展開來看，我其實很早以前就開始做機器人，那時候 state machine 和 behavior tree 比較多。一個最真實的感覺是，這幾年大家講 AI 講得有點亂了，總説 AI 和 data driven 體系需要重新做一遍。但如果真的去看，很多東西其實沒有那麼大的變化。研發策略和研發效率需要在 artifact 這一層做明確的拆解。硬件這一層，我們通過自動化的策略來把問題解決的速度提高。這幾年確實出現了很多新名詞，但本質上這些是我最開始做傳統機器人賽道時就在用的東西。藍色標註的部分都是現在新加的。AI 對機器人開發者的意義在於，它把能力邊界擴大了，讓性能有機會更高，這些藍色空間為機型帶來了更多能力。AI 在 robotics 能力上的賦能確實非常大。

軟硬一體的另一個進展是，我們前面已經能在一些成熟的硬件本體上完成 general 的物體放置、剛性物體和均勻尺寸物體的操作，當時成功率已經可以做到百分之百。這類似於大家前面用 grasp net 識別抓取位姿，後面用 IK 去執行，已經很成熟了。今年我們在做的事情是，在自由度高、約束複雜的情況下，把 WBC 的整個 control 做得更強，讓它完成更強的跟隨能力、更強的避障能力，以及模式層中更好的能力。更讓我自豪的是，這一塊代碼已經不再是人寫的了。我們在某個仿真的小 simulation 閉環裏，機器人可以自己去做 evaluation，然後 AI 自己去改代碼。人在裏面大部分參與的環節，只是在決策鏈條中有些 checklist 選擇走哪條路徑可能收斂更快。最終我們看到的結果是，硬件本體在那裏做的事情成功率越來越高。

在整個 infra 上，這幾年大家做 VLA 或者 VAM，確實看到了一些不錯的東西。但回到本質，主要還是 sim to real，也就是強化學習那一套和後面的 behavior cloning 幾條路線。這裏想跟大家分享的是機器人賽道所謂的 RSI 可能是什麼。簡單來説，就是把 target model 構建、system model 構建中間的 development、deployment、verification、evaluation 串起來。設定一個目標之後，能不能把 system 友好地整合在一起；這個 system 包含 robot 本體、hardware、software 和整個架構。development 是開發過程中你開發了什麼，我們做的是前面的 modular-based，然後往端到端再往上一層走。

deployment 的難度被普遍低估了。做一台 deployment 很簡單，但做到三十台到一百台的時候，你會發現非常依賴雲端廠商的邊端推理能力，需要非常穩定的數據傳輸和非常穩定的信息鏈路。再往下是 verification，你必須清晰地完成任務驗證，搞清楚什麼成功了、什麼失敗了、哪裏失敗、怎麼失敗的，把它清晰定義出來再做評估。這裏有一個比喻：做一台特別好的機器人，就像一把刀和一把尺的關係。你必須有一把非常強的尺，才有機會做出一把更好的刀；再把精細度高的刀配上這把尺，才能形成閉環，把事情越做越好。所以 RSI 的底層就是一個自動化系統，只有這樣才能看到 evolving 或者 evolution。

在演示中，我們連續詢問機器人狀態：“小恩小恩，錄製得怎麼樣了？”“小恩小恩，結束錄製。”“小恩小恩，構建的怎麼樣了？”它回覆：“構建進度 60%、空間定位完成。”接下來是物體更換為掛飾、物體是個邏輯等一系列指令。用户繼續問：“小恩小恩，你的記憶裏有什麼？”它回答有視頻、遙控器、儀表盤、鞋子、小包裹盒、顯示器和音響。然後用户説：“小恩小恩，幫我拿瓶可樂。”機器人回答要去看一下，確定目標物品並執行抓取。這是一個非常真實的 agentic 架構演示，或者説是我們稱之為 modular-based 架構的真實演示。這裏的細節是，整個過程一點 hard code 都沒有，所有東西都靠系統一點一點疊出來。前面我分享過，在 simulation 裏面我們已經把 AI 自己的驗證功能跑通了。現在在 real world 下，我們也完成了一部分驗證，能看到的效果就是視頻中展示的那樣。

機器人的智慧不像人類那麼強，所以我們的 reasoning 做得比較複雜。人類的 recognition 能力比想象中強很多，而機器人在看東西時很像我這種近視眼：最開始視野模糊，先構建整個語義，用長鏈條去大概知道每個房間有什麼、在哪個位置。在家庭場景中，它需要知道自己在廚房、卧室還是客廳，需要知道不會變的東西是傢俱，比如桌子、椅子、櫃枱，甚至門從房子建立第一天起就不會變。在門之上，我們用類似八叉樹的策略構建上面所有物品的關係。找東西的過程就像近視眼找東西：先看到一個模糊的位置，看看哪個東西疑似目標，然後做 template 匹配、多模態識別、槽位和微辨識，大致知道東西在哪裏之後，再“戴上眼鏡”仔細靠近，找到它並帶回來。大家看到的任務鏈條時間很長，但成功率提高了特別多。這比之前純粹的端到端在現階段效果好很多，同時它也是一個真正具備泛化性、用有限能力完成任務的方法。

在這些 modular-based 的基礎上，我們也在看怎麼在小的 skills 上、在 action experts 這一層做得更好一點。大家之前可能比較熟悉 digger 或者 husserl，以及強化學習之後的很多東西。我們做的事情是把策略裏的各種數據策略都走了一遍。比如我們做了自己的 UMI 夾爪，雖然沒有產品化，但在實驗室裏一直在用；一臂的策略也做了，centridig 的策略、後面 in the loop 的策略全部過了一遍，並且自己搭建了整套 simulation evaluation 的 loop。我們嘗試在採集數據的過程中，把數據清洗和上傳鏈條在雲端完整搭建出來。實際的效果是，我們用各種各樣的數據做了各種各樣的訓練，把真實實驗室中的流程搭建了出來，去構建小的 VLA、小的 VAM、小的 skills。我達到的結論是，之前做的有些東西很值得參考，七比二比一是我們目前拿到的一個比較真實的數據結果。

今年上半年我們開始看 human centric 的工作。我們的做法是拿人的第一視角，用手去做一些簡單的操作，然後把 assumption 拿出來，下一件事開始給它做，把不需要的部分去掉，現在加上仿真的隱形機械臂，把機械臂的工程、IK、動力學和運動學都模擬出來。最早做這個是為了提高整個 human centric 對有遮擋物體的想象能力。這一塊用的就是李飛飛老師現在比較強調的 real to sim to real 的事情。我們這個鏈條做了很多，希望大家能一起看到未來。
