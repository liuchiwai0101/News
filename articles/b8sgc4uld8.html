一個大型 TypeScript 項目，從打開 VS Code 到看見第一條類型錯誤，要等多久？

以前可能是 17.5 秒，現在不到 1.3 秒。

這不是換了臺更貴的電腦，也不是關掉類型檢查換來的速度。微軟把 TypeScript 編譯器和語言服務移植到了 Go，做成了今周正式發佈的 **TypeScript 7.0** 。

過去一年，很多開發者已經通過 tsgo 體驗過這個原生版本。正式版發佈後，tsgo 這個預覽階段的名字也完成了使命。現在直接安裝標準 typescript 包，拿到的就是新的 tsc。

npm install -D typescript
npx tsc

對於每天被類型檢查、編輯器卡頓和 CI 排隊折磨的前端團隊，這次升級可能比新增十幾個語法特性更有感。

TypeScript 6 及更早版本的編譯器以 TypeScript 編寫，運行在 JavaScript 環境中。TypeScript 7 則是一個新的 Go 原生代碼庫。

微軟沒有重新設計一門語言，而是儘量保留舊代碼庫的結構與邏輯，讓兩個編譯器得到一致的檢查結果。變化集中在底層執行方式：原生代碼、共享內存多線程，以及圍繞新架構加入的一系列優化。

這也是爲什麼提升不是常見的 10% 或 20%，而是直接跨了一個數量級。

在官方測試的 5 個大型開源項目中，完整構建速度提升了 **7.7 倍到 11.9 倍** ：

速度更快，內存也沒有跟着失控。上述項目的總內存用量下降了 6% 到 26%。其中 Bluesky 從 1.8 GB 降到 1.3 GB，減少 26%。

我的第一反應不是“編譯終於快了”，而是 **TypeScript 開始更充分地使用現代多核硬件了** 。過去你給 CI 增加 CPU，類型檢查未必能線性受益。TypeScript 7 會並行執行解析、類型檢查、代碼輸出和項目引用構建，大型 monorepo 更容易喫到硬件升級的紅利。

只看構建耗時，會低估這次重構的影響。

TypeScript 同時掌管編輯器裏的自動補全、跳轉、查找引用和錯誤診斷。項目越大，語言服務的延遲越容易把開發節奏切碎。你剛進入狀態，點了一次“查找全部引用”，然後開始盯着進度條發呆。

TypeScript 7 的語言服務改用 LSP，並能通過多線程同時處理請求。在 VS Code 代碼庫上，從啓動編輯器到顯示首個錯誤，由約 17.5 秒縮短到 1.3 秒以內。Canva 的反饋也很直觀，同一個過程從約 58 秒降到了 4.8 秒。

更關鍵的是穩定性。微軟公佈的內部數據中，新語言服務失敗的命令減少超過 80%，崩潰減少超過 60%。快是一眼就能看見的變化，少崩纔是團隊長期使用時真正省心的地方。

把這次性能提升簡單歸因於“Go 比 TypeScript 快”，會漏掉一半故事。

--watch 模式都獲得了新的實現基礎。默認情況下，TypeScript 7 會啓用 4 個類型檢查 worker。大型項目可以通過實驗性的 --checkers 參數繼續加並行度。官方把 worker 調到 8 個後，VS Code 的完整構建耗時進一步從 10.6 秒降到 7.51 秒，相比 TypeScript 6 快 16.7 倍。

但 worker 不是越多越好。更多檢查器會消耗更多內存，--checkers 與並行項目構建參數 --builders 疊加後，還可能瞬間拉高併發量。資源有限的 CI 機器，反而適合減少 worker，或者用 --singleThreaded 排查問題。

普通 Node.js 和前端項目可以先在分支裏試。安裝方式沒有額外門檻，原來的 npx tsc 命令也不用改。

不過，TypeScript 7.0 還沒有提供穩定的編程 API。這會影響直接嵌入 TypeScript 編譯器或語言服務的工具。官方預計 TypeScript 7.1 纔會帶來一套新的 API。

@typescript/typescript6 兼容包正是为过渡准备的。TypeScript 7 还继承了 6.0 的新默认值和废弃项处理。strict 默认开启，module 默认改为 esnext，target: es5、moduleResolution: node、baseUrl 等旧配置也不再受支持。老项目如果跨版本升级，先处理 TypeScript 6 的迁移问题，会比直接硬切顺利得多。

我認爲 TypeScript 7 最有分量的變化，不是某個項目跑出了 11.9 倍，而是編譯器和語言服務共用了一套能繼續擴展的原生基礎。

對個人小項目來說，幾十毫秒和幾百毫秒未必有明顯區別。對擁有幾百萬行代碼、數百名開發者的大型團隊來說，每次類型檢查少等幾秒，乘上每天的提交、CI 和編輯器操作，就是一筆可觀的時間。

當然，7.0 還不是生態遷移的終點。穩定 API 要等 7.1，部分框架工具鏈也需要時間適配。但 tsgo 所代表的原生代碼庫已經走進標準 typescript 包，這說明最難的底層遷移已經完成。

從今天開始，TypeScript 的性能上限不再只由 JavaScript 運行時決定。對於前端工程化來說，這可能是未來幾年裏最實在的一次基礎設施升級。
