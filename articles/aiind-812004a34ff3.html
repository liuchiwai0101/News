納德拉回應微軟首次給工程師發“離場費”：Claude Code 讓微軟措手不及，二十年 IDE 優勢半年動搖

內容機器翻譯自第三方媒體（InfoQ），僅供參考，以原文為準。

正文

微軟曾經教全世界的開發者如何寫代碼，如今，它開始為自己的一部分工程師支付離開的費用。

10 月 26 日，微軟宣佈推出新的自願離職方案。11 月 16 日，在《The Pragmatic Engineer》播客中，主持人 Gergely Orosz 向微軟 CEO Satya Nadella 提出了一個尖鋭的問題： 為什麼是現在？這會不會 AI 提效之後，進一步裁員的前奏？ 這個問題背後，還有一場讓微軟始料未及的技術變化。

Claude Code 這個問世才幾個月的產品，竟然開始挑戰積累了二十多年經驗的開發工具。

“我 99% 肯定 Anthropic 公司對微軟的任何戰略都一無所知，他們也毫不在乎。他們完全無視所有現有技術，開發出了一款非常優秀的工具。”Gergely 感慨。他認為，這件事對微軟的衝擊將遠遠超過其他任何事情。“不僅僅是微軟，JetBrains 也同樣措手不及，同樣猝不及防。”

過去二十多年，IDE 幾乎一直是軟件開發的中心。微軟擁有 Visual Studio、VS Code 和 GitHub，還憑藉 GitHub Copilot 率先進入 AI 編程市場。即使 Cursor 出現，競爭也仍然發生在微軟熟悉的編輯器生態中。這曾是一項看似難以撼動的優勢。

Gergely 最近在 X 上回顧微軟的 VS Code 戰略時，用了三個詞概括它： “擁抱、延伸、熄滅”（Embrace, Extend, Extinguish） 。微軟花了十多年時間構建起了一條近乎萬無一失的路線：把 VS Code 做得足夠出色，開放源代碼，讓開發者能夠自由地在此基礎上構建產品，但又很難在開發工具本身的競爭中超越微軟。

而 Claude Code 的出現改變了競爭的方式。Nadella 也承認，Anthropic 在模型能力上的重大進展給微軟帶來了衝擊。短短六個月左右，IDE 就在某種程度上“淡出了人們的視野”。

產品上的失速，正在與組織上的重構同時發生。面對自願離職的問題，Nadella 沒有承諾一切照舊。他明確表示， 未來的團隊規模、工作流程和人員配置都會不同，微軟的 20 萬名員工需要以新的方式重新組織。 “我當然希望能夠告訴所有人，一切都會和過去一樣，但我做不到。”

變化同時也影響着微軟對人才的需求。Nadella 透露，對於初級工程師招聘放緩的現象，現在就斷言這種趨勢會長期持續還為時過早。企業需要先建立新的“軟件工廠”，重新安排人員和 Token 資源，才能決定未來需要怎樣的工程師。

這場訪談因此有了比“AI 能寫多少代碼”更尖鋭的問題：當代碼越來越便宜，微軟過去幾十年積累的工具優勢、組織經驗，以及工程師賴以獲得回報的能力，還能按原來的方式定價多久？ Nadella 給出的方向是“軟件工廠”：人負責規格、意圖和驗證，Agent 承擔越來越多的執行。對於一家靠軟件工程建立起龐大帝國的公司，這意味着它必須親手改造自己的生產方式，也必須重新決定，什麼樣的工程師值得繼續投入，什麼樣的工作需要被重新安排。

Gergely 在訪談結束後，對微軟接下來的變化作出了更直接的判斷：“ 微軟內部還會出現大量組織調整，團隊會變小，崗位會變化。自願離職方案，為那些不願經歷這一輪變化的人提供了退出機會。接下來的變化，很可能會比以往更加密集、更加劇烈。 我想，這種組織重組、崗位變化，以及比過去更強烈的轉型壓力，也會出現在很多其他科技公司裏。”

對於企業在 AI 浪潮中應該守住什麼，他的總結同樣尖鋭：“對一家企業來説， 如果不掌握自己的 AI 基礎設施和 AI 知識產權，那實際上是一種自毀式的戰略。 Satya 認為，每一家成功的公司都會建立自己的 AI 基礎設施，而那些依賴單一供應商或某一家 AI 實驗室的公司，正在犯下重大的戰略錯誤。”

Gergely Orosz：微軟很早就推出了 GitHub Copilot，隨後 Cursor 出現，雙方不斷競爭。但 2025 年 Claude Code 的崛起，讓開發者在短短六個月內開始淡化 IDE 的使用。為什麼擁有深厚開發者基因的微軟，沒有第一時間應對這場變化？

Satya Nadella： 當模型能力出現非線性躍升時，產品形態就必須迅速改變。這是 AI 優先產品開發非常殘酷的地方。你不能迷戀自己已經構建的產品。Cursor 在 Agent 模式上做得很好，隨後 Anthropic 的模型進展又讓 CLI 成為可行的產品形態，開發者開始把完整任務交給模型處理。不過，我不認為 IDE 會永久消失。隨着決策引擎等新能力出現，IDE 甚至可能迎來複興。

Gergely Orosz：你多次提到“軟件工廠”。如果代碼主要由 AI 生成，這種新的軟件開發方式究竟意味着什麼？

Satya Nadella： 在一個代碼生成成本已經變得很低的世界裏，真正困難的事情變成了驗證。代碼從輸入變成了輸出，規格説明、開發意圖和驗證機制因此變得更加重要。工程師需要把任務交給 Agent，檢查任務是否真正完成，並根據失敗構建測試用例。還可以利用生產環境日誌發現問題、驗證修復結果，再將修復部署到生產環境。這仍然是軟件工程，只是工程師與代碼交互的層次發生了變化。

Gergely Orosz：微軟推出自願離職方案後，有開發者擔心，這是否意味着 AI 提高團隊效率之後，公司將進一步裁員。微軟為什麼做出這個決定？

Satya Nadella： 未來仍然會有大量機會，但機會的形態會發生變化，包括團隊規模、工作流程和崗位配置。推出自願離職方案，很大程度上是希望讓員工擁有更多自主選擇權，根據長期職業發展尋找適合自己的位置。我不能説微軟的每個部門都在以同樣的速度轉型。如果員工覺得自己被困在一個沒有跟上變化的團隊裏，應該能夠選擇其他機會，包括微軟內部的崗位。我希望公司能創造這些機會，但我無法保證一切都會和過去一樣。

Gergely Orosz：很多公司已經放緩甚至停止招聘應屆畢業生，因為經驗豐富的工程師似乎更能利用 AI 提高生產力。微軟怎麼看待年輕工程師的招聘？

Satya Nadella： 我認為，現在就把招聘放緩視為長期趨勢還為時過早。企業首先需要調整內部人員配置和工作方式，建立新的軟件工廠，然後才能決定引進什麼樣的人才。AI 原生公司可能從一名員工和一定的 Token 預算開始，當員工用盡預算後，再增加下一名員工及其 Token 預算。未來更多團隊可能採用類似方式，但完成組織重構需要時間，因此應該在更長的時間跨度內觀察招聘變化。

Gergely Orosz：很多公司正在構建自己的 Harness、上下文層和推理基礎設施。你認為大多數企業都應該擁有這些系統，並讓各個組件可以獨立替換嗎？

Satya Nadella： 完全正確。企業必須掌控自己的學習循環，不能在使用 AI 的過程中泄露最有價值的知識。上下文、記憶、Harness 和模型應該相互分離，否則就可能被某個供應商徹底鎖定。我的檢驗標準很簡單：你應該能夠替換任何一個模型，同時仍然在自己的私有評估指標上持續改進。如果做不到，就必須問問自己，究竟還能否自主掌控企業的產出。

Gergely Orosz：企業正在構建大量新的 AI 系統，但很多系統還沒有成熟的架構藍圖。你認為企業應該如何應對其中的可靠性和安全問題？

Satya Nadella： 我認為企業必須建立信任架構。縮放定律帶來了更強的模型能力，但不意味着模型的對齊程度同步提高。我們必須在架構上將智能與權限分離。如果一個不夠可靠的 Agent 同時擁有執行權限，就可能帶來嚴重的內部風險。因此，需要把 Agent 當作潛在的內部風險來管理，在運行時建立監控、可觀測性、審計日誌和安全防護機制，並確保企業始終能夠控制自己的學習循環。
