OpenRouter 解讀 NVIDIA Nemotron 3.5 Lightning 如何承擔 Agent 高頻執行調用

內容機器翻譯自第三方媒體（OpenRouter），僅供參考，以原文為準。

AI 導讀

OpenRouter 發文解讀 NVIDIA 的 Nemotron 3.5 Lightning，這是一款 30B 總參數、約 3B 激活參數的混合專家開源權重模型，定位於工具調用、編碼等高頻、邊界清晰的 Agent 執行步驟，與負責複雜推理的 Nemotron 3 Ultra（550B 總參數、55B 激活）形成分工。

推薦理由

OpenRouter 結合自家端點數據拆解 Nemotron 3.5 Lightning 的定位、上下文和調用差異，讀者可據此評估它在 Agent 執行層的適用性。

正文

一個智能體可能會為規劃一項任務做一次困難的調用，而為執行該任務再做幾十次調用。後面這些調用會讀取文件、選擇工具、驗證結果，並決定下一步該做什麼。NVIDIA 構建 Nemotron 3.5 Lightning 正是為了應對工作流中這一高頻部分。

Nemotron 3.5 Lightning 是一個 30-billion-parameter 的混合專家模型，每個 token 激活約 3 billion parameters。它支持工具調用、編碼任務、指令遵循以及其他範圍明確的智能體步驟。

這個名字很容易與 Nemotron 3 Ultra 混淆，但這兩個模型是為智能體工作流的不同部分而構建的。在它們之間做選擇會影響整個運行過程的成本、延遲和可靠性。

30B MoE 且激活參數為 3B 是什麼意思？

Nemotron 3.5 Lightning 是一個稀疏混合專家模型。它總共包含 300 億參數，但並非每個 token 都會用到所有專家。模型處理每個 token 時，路由器會選擇一小部分專家，使激活參數數量約為 30 億。你也會看到它被寫作 30B-A3B，意思是總參數 300 億、激活參數約 30 億。

這種設計讓模型擁有比 3B 稠密模型更大的總容量，同時無需為每個 token 運行全部 300 億參數。Lightning 正是以此將相對較大的檢查點與頻繁智能體調用所需的吞吐量結合起來。

激活參數數量並不是完整的計算或內存規格。完整模型仍然需要存儲，共享層在推理期間也會運行。硬件需求取決於精度、上下文長度、推理引擎、批處理策略和緩存配置。

Lightning 同樣採用了混合架構，而非純 Transformer 堆棧。NVIDIA 模型卡描述了交錯排列的 Mamba-2 與 MoE 層，並配有選定的注意力層。它還支持可配置推理，並附帶多 token 預測以及兩個投機解碼草稿模型 DSpark 和 DFlash，以實現更快的生成，同時還提供了一個針對推理調優的 NVFP4 檢查點。

Nemotron 3.5 Lightning 是為哪些用途設計的？

長時間運行的智能體會發起大量模型調用。有些調用需要複雜的規劃。而大部分工作則更為狹窄，例如選擇工具、生成參數、檢查結果、編輯文件，或決定下一步該做什麼。

NVIDIA 將 Lightning 定位在這一執行層。當你的工作負載具備以下特徵時，該模型就是一個候選選擇：

  • 智能體會發起大量調用，且延遲或成本會在整個運行過程中不斷累積。
  • 每次調用都有明確的目標以及足以完成它的上下文。
  • 模型需要使用工具、遵循指令，或返回結構化數據。
  • 你希望獲得開放權重，以便針對某個領域或部署目標進行定製。

例如，一個編碼智能體可以使用更大的推理模型來檢查代碼倉庫並確定實現方案。隨後，Lightning 可以處理各個具體步驟，例如定位符號、編輯單個文件、運行工具以及解讀結果。

Nemotron 3.5 Lightning 與 Nemotron 3 Ultra 對比

NVIDIA 從 Nemotron 3 Ultra 蒸餾出了 Lightning，但這兩個模型並不能互換使用。Lightning 是較小的模型，用於高併發的智能體執行。Ultra 是較大的模型，用於複雜推理和編排。

NVIDIA 報告稱，Lightning 的吞吐量最高可達同等規模開源模型的四倍。在 NVIDIA 的 PinchBench 測試中，它以相當的準確率將 10,000 個智能體任務完成速度提升了最高 30%。這些是廠商報告的結果，因此請在你自己的工作負載上測試吞吐量和任務完成情況。

區別在於調用的難度和後果。當一個步驟需要對模糊問題進行深度推理、為長工作流制定計劃，或做出難以逆轉的決策時，Ultra 更為合適。當任務範圍明確且重複頻率足夠高、延遲和成本變得重要時，Lightning 更為合適。

你不需要為整個智能體分配一個模型。將複雜調用路由到 Ultra，將頻繁的執行調用路由到 Lightning。然後衡量這種組合是否在不降低可靠性的前提下改善了每個已完成任務的成本。

在 OpenRouter 上在兩個模型之間進行路由

如果你更願意將模型選擇交給我們，請使用 Auto Router。將 openrouter/auto 作為模型 ID 發送，Auto Router 會根據任務類型、模型能力、工具支持和成本對提示詞進行分類，然後選擇模型。cost_tier 設置用於選擇成本區間，從 low 到 max。它不會將對話從較便宜的模型升級到較貴的模型。如果你希望 Auto Router 僅在 Lightning 和 Ultra 之間選擇，請用 allowed_models 限制其選擇範圍。

在 OpenRouter 之外在兩個模型之間進行路由

NVIDIA 的 NeMo Switchyard 將這種路由模式實現為一個開源編排層。其升級路由器在每次對話開始時使用成本較低的模型，當 LLM 裁判檢測到持續困難時，會將會話轉移到能力更強的模型。在 LangChain 的評估中，針對 145 個多步驟智能體任務，在 Lightning 和 Claude Opus 4.8 之間進行路由，與僅使用前沿模型的基線相比，成本降低了 74%，同時約 7% 的調用被髮送到前沿模型。準確率大約低了六個百分點。這一結果展示了該基準測試上的路由權衡。它並不是 Lightning 與 Ultra 組合的基準測試。在你依賴節省效果之前，請先在自己的任務上測試任何路由設置。

上下文窗口有多大？

Nemotron 3.5 Lightning 在模型層面支持最多 100 萬 token。你的應用程序可用的上下文取決於為其提供服務的端點。

2026 年 9 月 11 日，標準模型 ID 背後的每個提供商都提供 262,144 token 的上下文窗口。補全限制因提供商而異，從 32,768 到 235,929 token 不等。:free 模型提供完整的 100 萬 token 上下文窗口，並將補全上限設為 65,536 token。

如果某個請求需要超過 262,144 token，目前在 OpenRouter 上只有免費端點提供該模型完整的 100 萬 token 上下文。NVIDIA 在該端點上的通知指出，使用情況會被記錄，用於安全目的以及改進 NVIDIA 產品和服務，並要求你不要上傳機密信息或個人數據。對於敏感或生產環境的長上下文工作負載，請選擇其他端點或模型。

當你在這兩個模型 ID 之間切換時，這一差異很重要。一個在免費端點上成功的請求，可能會超出標準端點的上下文限制。免費端點還列出了工具調用，但沒有列出 response_format 或結構化輸出。

請查看模型頁面，而不要把架構的最大上下文當作每個提供商都會兑現的承諾。我們在模型頁面上展示每個端點的當前限制和支持的參數。

開放權重與本地部署

NVIDIA 在 OpenMDW-1.1 許可下發布了 BF16 參考檢查點。模型卡將 BF16 版本描述為後訓練、領域適配、研究以及產出優化變體的起點。NVIDIA 還發布了用於定製和評估的訓練數據與配方，模型卡稱該版本已可用於商業用途。

對於直接推理，NVIDIA 推薦其 NVFP4 版本。它還為受支持的本地系統提供了 GGUF 檢查點。BF16 指南列出單 GPU 部署需要 H100 80GB 或 A100 80GB。優化版本面向 RTX 5090、RTX PRO 6000 和 DGX Spark 等硬件。

在本地運行該模型並不意味着每台機器都能提供完整的 100 萬 token 上下文窗口。在 NVIDIA 當前的 Ollama 指南中，默認上下文隨可用 VRAM 而變化。低於 24GB 時為 4K，24GB 至低於 48GB 時為 32K，48GB 及以上時為 256K。llama.cpp 示例使用約 40K。你可以提高這些限制，但這樣做可能需要更多內存或 CPU 卸載。

權重已公開可用，而“開放權重”是最清晰的描述。在你重新分發修改後的模型或根據其條款做出部署決策之前，請先閲讀 OpenMDW-1.1 許可證。

如何在 OpenRouter 上調用 Nemotron 3.5 Lightning

如果你不想自行配置 GPU 或管理推理引擎，可以通過 OpenRouter 調用 Lightning。標準模型 ID 保持相同的 API，同時我們會針對該模型在可用提供商之間路由請求。

安裝 OpenRouter TypeScript SDK。

npm install @openrouter/sdk

在你的環境中設置 OPENROUTER_API_KEY，然後使用 Lightning 模型 ID 發送請求。該標準模型列出了結構化輸出，因此你可以要求一個 JSON schema，並讓響應符合該 schema。

import { OpenRouter } from "@openrouter/sdk";

const openRouter = new OpenRouter({
  apiKey: process.env.OPENROUTER_API_KEY,
});

const result = await openRouter.chat.send({
  chatRequest: {
    model: "nvidia/nemotron-3.5-lightning",
    messages: [
      {
        role: "user",
        content:
          'Ticket: "Checkout returns a 500 after I click Pay. Started this morning, three customers affected." Return its category and priority.',
      },
    ],
    responseFormat: {
      type: "json_schema",
      jsonSchema: {
        name: "triage",
        strict: true,
        schema: {
          type: "object",
          properties: {
            category: { type: "string" },
            priority: { type: "string", enum: ["low", "medium", "high"] },
          },
          required: ["category", "priority"],
          additionalProperties: false,
        },
      },
    },
    provider: {
      requireParameters: true,
    },
  },
});

if (!("choices" in result)) {
  throw new Error("Expected a non-streaming response");
}

console.log(result.choices[0]?.message.content);

當我們在 2026 年 9 月 11 日運行此請求時，模型返回了 {"category": "Bug (Payment Checkout)", "priority": "medium"}。採樣輸出在不同運行之間會有所變化，請求所保證的是 schema，而非具體的值。

在同一模型內，各提供商對 response_format 和結構化輸出的支持各不相同。默認情況下，我們優先選擇支持你所發送的 tools 和 response_format 參數的提供商，而不支持某個參數的提供商會忽略該參數。如示例所示，將 require_parameters 設置為 true，會把請求限制在支持其中每一個參數的提供商範圍內。完整行為請參閲 提供商路由文檔。

要試用免費端點，請將模型 ID 改為 nvidia/nemotron-3.5-lightning:free。免費端點不列出 response_format，因此在那裏去掉該字段，並自行驗證 JSON。它適用於評估和小規模實驗，並且其限制和可用性與標準端點不同。

不要通過免費端點提交機密信息或個人數據。其模型頁面載有 NVIDIA 的聲明，稱使用情況會被記錄，用於安全目的以及改進 NVIDIA 產品和服務。在決定發送哪些提示詞之前，請先閲讀該聲明。

默認情況下，我們會按價格排序，在標準模型的各個提供商之間進行負載均衡。有兩個變體會改變這一排序。nvidia/nemotron-3.5-lightning:nitro 按吞吐量對提供商排序，nvidia/nemotron-3.5-lightning:exacto 則優先選擇工具調用質量信號更強的提供商。對於為延遲和工具使用而選擇的模型，Nitro 和 Exacto 是兩個值得了解的變體。

Lightning 接受 tools 和 tool_choice，因此你也可以在智能體循環中使用它。請參閲我們的 工具調用智能體循環指南，瞭解完整的請求、工具執行和迭代流程。

你應該使用 Nemotron 3.5 Lightning 嗎？

當你需要一個快速、開放權重的模型來處理頻繁、定義明確的智能體步驟時，Nemotron 3.5 Lightning 值得評估。其 30B-A3B 架構、工具支持以及較低的標價 token 價格，使其成為智能體的候選執行模型——否則這些智能體會把每次調用都發送給大得多的推理模型。

把模型名稱當作起點，而不是決策依據。基於你的智能體所執行的工具調用和任務構建一套評估集。衡量整個運行過程中的任務成功率、重試次數、延遲和總成本。如果智能體反覆重試或頻繁升級處理結果，以至於抵消了節省的成本，那麼更便宜的調用也無濟於事。

從 nvidia/nemotron-3.5-lightning 開始，或者使用 nvidia/nemotron-3.5-lightning:free 在引入付費流量之前測試模型。

常見問題

什麼是 Nemotron 3.5 Lightning？

Nemotron 3.5 Lightning 是 NVIDIA 的開源權重 30B 混合專家語言模型，每個 token 約激活 3B 參數。NVIDIA 將其定位用於高併發智能體執行、工具調用、編程、指令遵循和專業化任務。

Nemotron 3.5 Lightning 和 Nemotron 3 Ultra 是同一個模型嗎？

不是。Nemotron 3.5 Lightning 的總參數量為 30B，激活參數為 3B。Nemotron 3 Ultra 的總參數量為 550B，激活參數為 55B。Lightning 面向高頻執行步驟。Ultra 面向複雜推理和編排。

30B-A3B 是什麼意思？

30B-A3B 意味着該模型總共有 30 billion 參數，每個 token 約激活 3 billion 參數。混合專家路由器為每個 token 選擇模型專家中的一個子集，而不是運行所有專家。

Nemotron 3.5 Lightning 支持工具調用和結構化輸出嗎？

標準 OpenRouter 模型 nvidia/nemotron-3.5-lightning 在其支持的參數中列出了 tools、tool_choice、response_format 和結構化輸出。支持情況因提供商而異，因此如果你的請求依賴其中某一項，請將 require_parameters 設置為 true。免費模型列出了 tools 和 tool_choice，但沒有列出 response_format 或結構化輸出。

有免費的 Nemotron 3.5 Lightning API 嗎？

有。我們列出了 nvidia/nemotron-3.5-lightning:free，由 NVIDIA 提供，不收取 token 費用。免費模型的速率限制和可用性與付費模型不同，並且該端點附有 NVIDIA 數據聲明。請勿通過它發送機密信息或個人數據。

我可以在本地運行 Nemotron 3.5 Lightning 嗎？

可以。NVIDIA 在 OpenMDW-1.1 許可下發布了 BF16、NVFP4 和 GGUF 權重。BF16 參考檢查點面向單塊 80GB H100 或 A100。NVFP4 和 GGUF 版本面向受支持的本地硬件，例如 RTX 5090、RTX PRO 6000 和 DGX Spark。在選擇部署方案之前，請查看 NVIDIA 當前的模型卡和許可。
