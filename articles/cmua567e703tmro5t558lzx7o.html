獨立調查：ChatGPT 的 __obi 跨站 Cookie 可將站外瀏覽行為關聯到 ChatGPT 賬號

內容機器翻譯自第三方媒體（Hacker News 熱門），僅供參考，以原文為準。

AI 導讀

作者通過自己手機上的流量捕獲復現了 OpenAI 廣告收集器機制：bzr.openai.com 在 .openai.com 域設置 __obi Cookie，綁定 ChatGPT 賬號（或穩定的匿名主體），投放廣告的商家站點加載 OpenAI 像素代碼時會把 __obi 連同瀏覽和購買數據回傳給 OpenAI。

推薦理由

作者以第一手流量捕獲復現了 OpenAI 廣告收集器的跨站追蹤機制，讀者可以據此理解 ChatGPT 賬號與站外瀏覽行為的關聯路徑。

正文

OpenAI 的廣告收集器位於 bzr.openai.com，會設置一個名為 __obi 的 cookie，作用域限定為 .openai.com。該值在你使用 ChatGPT 期間存在，並與你的 ChatGPT 賬户綁定。隨後，__obi 會從你訪問的普通網站發送給 OpenAI。

任何在 ChatGPT 上購買廣告的公司都會在自己的網站上安裝一小段 OpenAI 代碼，就像零售商已經安裝 Meta 和 Google 的追蹤代碼一樣。加載這段代碼會將 __obi 連同你正在瀏覽的頁面數據一起發送給 OpenAI。這包括你正在搜索的產品、正在閲讀的文章以及購買行為。

歸根結底，OpenAI 可以將你在這些網站上的行為與你的 ChatGPT 賬户關聯起來。

我在自己的手機上覆現了完整機制，用兩種獨立的捕獲方法進行了驗證，並與覆蓋 1,029 個主機名上 936 個不同廣告主像素的、長達數月的觀測流量進行了交叉核對。

工作原理

第 1 步。ChatGPT 創建一個標識符並對其進行簽名。

在 chatgpt.com 上，客户端生成 16 個隨機字節，並調用 POST /backend-api/bazaar/obi/sync-token（未登錄時則調用 /backend-anon/）。後端返回一個 RS256 JWT：

{
  "iss": "chatgpt-wadi",
  "aud": "bzr.openai.com",
  "purpose": "obi_sync",
  "operation": "set",
  "consent_decision": "analytics_allowed",
  "consent_policy_version": "user_granular_consent_v1",
  "sub": "«redacted: 64-hex account subject»",
  "subject_type": "account_user",
  "obi": "«redacted: 22-char identifier»",
  "exp": "«iat + 60s»"
}

sub 是賬户。obi 是標識符。token 將二者綁定，作用域限定於收集器，並在 60 秒後過期。bzr 代表 bazaar，即 OpenAI 內部對廣告平台的稱呼；wadi 是簽發服務。

第 2 步。該標識符成為 OpenAI 域名下的一個 cookie。

客户端將 {"token": "«JWT»"} 跨站 POST 到 bzr.openai.com/v1/obi/sync。響應如下：

Set-Cookie: __obi=«redacted»; Domain=.openai.com; HttpOnly;
            Max-Age=31536000; Path=/; SameSite=none; Secure

SameSite=none 與 Secure 是 cookie 在跨站請求中被髮送所需的配置。Max-Age 為一年。JWT 中的 obi 值與 cookie 中的值完全相同。

第 3 步。廣告主網站將其回傳。

有三類請求會從廣告主的頁面發往 OpenAI 的主機。在一台 jar 中含有 __obi 的手機上，這三類請求都攜帶了它：

請求攜帶了 __obi備註
GET bzrcdn.openai.com/sdk/oaiq.min.js是腳本本身的加載
POST bzr.openai.com/v1/sdk/events 與 obref是轉化事件
POST bzr.openai.com/v1/sdk/events，裸請求體是該 SDK 的“無憑據”路徑
GET bzrcdn.openai.com/pixel-config/…完全沒有 cookie 頭對照組

第一行尤其值得關注。像素 SDK 有一條省略憑據的代碼路徑，但這無濟於事：在 OpenAI 的任何代碼運行之前，瀏覽器就已經把 cookie 附加到了加載該 SDK 的 <script src> 請求上。僅僅因為加載了這個標籤，標識符就被泄露了。

隨之傳輸的內容

同一個 SDK 還會從廣告主的頁面上收集身份信息。其載荷將四個來源分開，並由 OpenAI 自己標註：in 對應廣告主有意傳入的值，而 fm、ht、js 則對應 SDK 從表單字段、渲染後的頁面文本以及標籤管理器總線中抓取的值。在觀測到的流量中，抓取到的身份信息數量超過了廣告主提供的身份信息，分別為 685 個事件對 255 個。

標籤管理器總線是電子郵件最大的來源。該 SDK 替換了window.dataLayer.push用自己的函數，還讀取adobeDataLayer，並通過解析l=參數（來自gtm.jsscript 標籤）來定位被重命名的 GTM 層。當前版本從中獲取電子郵件和電話。0.1.31 版本在 8 月 27 日縮小範圍之前，還獲取了姓名和地理位置。

電子郵件、電話、名字和姓氏在傳輸前均經過 SHA-256 哈希處理。國家、地區、城市和郵政編碼則以明文發送。郵政編碼是被收集最多的表單字段，在 28 個網站上共發生 100 次事件。

URL 在發送前會被縮減為源站加路徑；在觀測到的 23,929 個 URL 中，沒有一個攜帶查詢字符串。路徑得以保留，而到達收集器的路徑中包括一種醫療狀況、一個債務解決方案漏斗以及一份訴訟受理表單。

在 881 個已知設置的像素中，有 638 個啓用了自動匹配，包括所有觀察到的信貸和借貸廣告主。它由 OpenAI 的 Ads Manager 控制。一份拒絕名單排除了密碼、一次性驗證碼、卡號、SSN、出生日期、病史、診斷和法院相關字段。

該 cookie 被設計為可跨站點使用

在相同的廣告主頁面請求中，瀏覽器屏蔽了所有其他 OpenAI cookie：

Cookie結果
oai-did、oaicom-stable-id已攔截，SameSite=Lax
oai-client-auth-info，會話 cookie已攔截，域名不匹配
__obi已發送

__obi 是唯一配置了 SameSite=None 的 OpenAI 標識符。

觀測到的觸達範圍

在我的設備上，一個 __obi 值從 12 個商業網站通過 13 個不同的像素 ID 被髮送至 OpenAI，其中包括 Chewy、Wayfair、ThriftBooks、Eventbrite、HelloFresh、Coursera 和 SeatGeek。每個請求都以 202 被接受。

在更廣泛的流量中，30 個不同的 __obi 值中有 12 個出現在不止一個廣告主名下，其中一個出現在十個廣告主名下。

在你登出狀態下它依然有效

在 932 個已解碼的同步 token 中，736 個攜帶 subject_type: account_user，196 個攜帶 anonymous。匿名主體與賬户主體一樣穩定：每台設備一個，至少持續 27 天。

OpenAI 的 cookie 政策怎麼説

OpenAI 將 __obi 列在分析類 Cookie 下，有效期一年，出現在 chatgpt.com 和 openai.com 上。它是該欄目中唯一的條目。該政策將分析類 Cookie 描述為幫助 OpenAI 瞭解其服務的表現及使用情況。

OpenAI 將分析類和營銷類作為兩個獨立的同意選項來運行，即 oai_consent_analytics 和 oai_consent_marketing，而我解碼的每一個同步 token 都帶有 consent_decision: analytics_allowed。允許分析類但拒絕營銷類的人就會得到這個。

OpenAI 的回應

我於 9 月 14 日將相關機制和兩個問題發送至 press@openai.com 和 privacy@openai.com：為什麼 __obi 被歸類為分析類 cookie，以及一個授予分析同意但拒絕營銷同意的用户是否仍會收到它。回覆來自 OpenAI Support。它確認收到了詢問，表示相關觀察結果將在內部共享以供審查，但沒有回答這兩個問題中的任何一個。上述腳本加載觀察是在詢問發出之後做出的。如果 OpenAI 作出回應，我將更新本文。

侷限

瀏覽器。 在 Android 版 Chrome 上觀察到。Safari 的智能防跟蹤會阻止所有第三方 cookie，而 iOS 上的 Chrome 運行於 WebKit，因此該機制在任何 iOS 瀏覽器上都不起作用。桌面版 Chrome 尚未測試。

門控。大約每五個 ChatGPT 會話中就有一個會生成同步 token。ChatGPT 的移動網頁客户端在投放廣告時完全不進行同步。按照以下步驟操作的人可能會看到像素觸發，但沒有附帶任何 cookie。

這種關聯並未被觀測到。202 意味着收集器接受了附帶 cookie 的事件。OpenAI 在服務端將其解析到賬户，這一點從設計上可以推斷；我並未親眼觀察到這一過程。

Meta 多年前就構建了結構上等價的東西。一個已登錄的賬户、像素觸發時的第三方 cookie、站外轉化被解析到某個用户畫像。這套機制是廣告技術的標準做法。沒有先例的是將其運行在 AI 聊天產品上。人們會向這些產品傾訴他們不會發在社交網絡上的事情，而這些產品正越來越多地代表他們行事。

該像素的另一個 cookie 不會這樣做。__obref 設置在廣告主自己的域名上。每個站點獲得不同的值，任何站點都無法看到其他站點的值。在觀測到的 2,860 個值中，有 2,828 個僅出現在一個廣告主之下。

廣告主看不到這一點。__obi 屬於一個他們的腳本無法讀取的域名。他們安裝了一個轉化像素，卻無從得知自己的訪客正被解析到某個 ChatGPT 身份。
