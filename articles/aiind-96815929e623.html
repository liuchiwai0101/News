Octop 託管 CodeBuddy 實戰：打造 7×24 小時在線的 AI 程序員

內容機器翻譯自第三方媒體（InfoQ），僅供參考，以原文為準。

正文

本文介紹如何在 Octop 中創建“ 託管專家 ”（一種將 編程智能體 常駐託管於平台內、可被統一調度的 AI 專家），並將它與 CodeBuddy 、 OpenCode 、 Claude Code 、 Codex 等主流編程智能體對接。藉助託管專家，你可以在對話中調度它們，在指定工作目錄完成代碼閲讀、修改、測試與提交，所有操作都在 Octop 內完成，無需切換工具，打造自己的 7×24 小時在線 AI 程序員 。

Octop 是騰訊雲開源、自託管的 AI 助手（https://github.com/TencentCloud/Octop），通過 多 Agent 架構 為團隊、家庭和個人構建既獨立又協作的智能環境。單進程啓動即可運行 Web 控制枱、CLI 和 IM 集成，支持飛書、釘釘、QQ、微信、企業微信及 HTTP/SSE/WebSocket API 等多種通道接入。內置專家庫可一鍵創建專業角色，Connector（OAuth + MCP）無縫對接外部服務，ACP 實現與 IDE/終端 AI 工具的雙向協作——隱私可控，部署簡單，功能完整。

專家是 Octop 的對話入口 。用户可以為不同領域創建專屬專家，配置技能、子智能體、定時任務、通道與模型，並通過 連接器 和 知識庫 為 AI 提供更多上下文，從而更精準地完成任務。

其中， 原生專家 的每輪對話由 Octop Harness 驅動；而 託管專家 則將 Harness 託管給後端綁定的 編程智能體 ，由它在工作目錄中完成代碼閲讀、文件修改、測試運行與代碼提交等實際編程工作。

普通專家 的請求在 Octop 原生的 Harness 內閉環執行：模型調用、工具調度與工作區修改全部由 Octop Harness 統籌，適合查詢資料、編寫文檔，以及調用已配置工具執行固定步驟類任務。

託管專家 則不同：請求進入 Octop 後，隨即被移交給綁定的 編程智能體 。以 CodeBuddy 為例，它會調用自身的文件操作、終端與 Git 能力直接操作倉庫。Octop 本身保留會話管理，並在此基礎上額外為該智能體注入知識庫、插件、連接器與定時任務等能力；對於需要用户授權的操作，也會一併推送到對話中供用户決策。

Octop 提供了 知識庫 、插件、通道與 專家團 等產品形態，並可在原生專家與 託管專家 中以統一方式使用、彼此協同。

知識庫 ：存放可檢索的文檔，如分支策略、接口約定、錯誤碼與發佈檢查。在對話中選中後，專家依據檢索結果回答問題或修改代碼。

連接器 ：對接騰訊文檔、語雀、Notion、飛書、企業微信等外部系統。授權並在對話中選中後，可讀取需求，或將進度寫回外部系統。

技能包 ：一組可複用的技能集合。 普通專家 將其加載到自身技能目錄； 託管專家 則鏈接到 編程智能體 的技能目錄——以 CodeBuddy 為例，對應 .codebuddy/skills 路徑。

專家團 ：由一名 主持人 和至少兩名 成員 組成，主持人負責分派任務。 普通專家 與 託管專家 均可作為成員參與。典型分工例如：託管專家負責代碼修改，另一位普通專家對照知識庫負責審查。

首先需要安裝 Octop 和對應的 Coding Agent 。在不同環境安裝 Octop，可以參考官方網站 https://octop.cloud/ 。以下以 Ubuntu 服務器 操作系統與 CodeBuddy 為例進行講解。

安裝完成後，由用户執行具體的登錄操作，完成 CodeBuddy 的初始化，保證其可正常使用。git、ssh 和 gh 等必要工具可以先安裝，也可以後續使用 Octop 自動安裝。

在「專家」頁新建 託管專家 ， 工作目錄 選中 倉庫目錄 ；在更多配置中可以關聯技能包，選中的技能會鏈接到倉庫內的 .codebuddy/skills，由 CodeBuddy 按其自身目錄加載。知識庫和連接器可在創建時選擇，也可後續編輯添加。

項目創建完成後，用户可直接在對話中完成需求梳理、代碼實現與 代碼提交 等操作，其使用方式與其他 Agent 調用完全一致。

在 「通道」 中把飛書、企業微信、釘釘、微信、QQ 或 Discord 綁定到這位 託管專家 ，當前支持多種 IM 通道。綁定後，你可以隨時隨地從熟悉的聊天工具裏向它發起指令。

在 「知識庫」 中創建知識庫並添加項目文檔。索引創建成功後，在該 託管專家 的對話中即可選中使用；也可將其設為默認知識庫，實現每次對話自動加載。

在 「連接器」 中添加你需要使用的連接器（如 Notion、語雀等）。 託管專家 對話中可同時啓用多個連接器，也可設置多個默認連接器，實現每次對話自動加載。

04 進階使用 除按消息觸發修改外， 託管專家 還可通過 定時任務 和 專家團 實現持續監控與複雜協同。

定時任務 適合按時間週期檢查 Issue 與 Pull Request。例如每個工作日 09:00 自動掃描倉庫，將新開 Issue、待評審 PR 及待決定事項彙總推送至飛書或企業微信，無需人工干預。穩定運行後可疊加更細粒度的巡檢任務，例如只關注標記為 bug 且無人認領的 Issue。定時任務受 併發和超時配置 保護，避免重複執行。
