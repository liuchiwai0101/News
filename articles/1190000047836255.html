一、LCP 的定義與優化目標

**LCP（Largest Contentful Paint）** 衡量頁面最大內容元素（通常是圖片、視頻、大文本塊）的渲染時間。優化目標：**≤ 2.5 秒**。

影響 LCP 的主要因素：

- 資源加載慢（圖片、字體）

- 渲染阻塞（CSS、JS）

- 客戶端渲染延遲

下面按優先級列出 5 個最有效的優化手段。

二、優化手段 1：圖片優化（WebP + 響應式 + 懶加載）

原理

- 使用現代圖片格式（WebP/AVIF）體積更小

- 不同設備加載不同尺寸，減少無效傳輸

- 非首屏圖片懶加載

具體配置

**WebP 替换（Nginx 自动协商）**：

location ~* \.(jpg|jpeg|png)$ {
  add_header Vary Accept;
  if ($http_accept ~* "image/webp") {
    rewrite (.*) $1.webp break;
  }
}

**響應式圖片（HTML）**：

<img
  srcset="hero-480w.webp 480w, hero-960w.webp 960w, hero-1440w.webp 1440w"
  sizes="(max-width: 600px) 480px, (max-width: 1200px) 960px, 1440px"
  src="hero-fallback.jpg"
  alt="description"
  loading="eager"
>

### 收益

首屏圖片傳輸體積減少 50%~70%，LCP 直接降低 1~2 秒。

三、優化手段 2：字體優化（font-display + 預加載）

原理

- 默認情況下，自定義字體下載期間瀏覽器會隱藏文字（FOIT），阻塞渲染

- `font-display: swap`先顯示系統字體，字體加載後替換

- 預加載關鍵字體可提前下載

CSS 配置

@font-face {
  font-family: 'MainFont';
  src: url('/fonts/main.woff2') format('woff2');
  font-display: swap;
}

HTML 預加載

### 收益

消除字體阻塞，FCP 提前 0.5~1 秒，間接改善 LCP。

四、優化手段 3：JavaScript 分割與異步加載

原理

- 大型 JS bundle 會阻塞解析和渲染

- 代碼分割 + defer 讓非關鍵 JS 不阻塞首屏

Webpack 配置（splitChunks）

// webpack.config.js
module.exports = {
  optimization: {
    splitChunks: {
      chunks: 'all',
      minSize: 20000,
      cacheGroups: {
        vendor: {
          test: /[\\/]node_modules[\\/]/,
          name: 'vendors',
          priority: 10,
        },
      },
    },
  },
};

動態導入

// 需要时才加载
import('./heavy-module').then(module => {
  module.init();
});

第三方腳本延遲

// 在 load 事件后加载
window.addEventListener('load', () => {
  const script = document.createElement('script');
  script.src = 'https://analytics.example.com/tracker.js';
  document.head.appendChild(script);
});

收益

首屏 JS 體積減少 60%~80%，主線程空閒提前，LCP 改善 0.5~1 秒。

五、優化手段 4：CSS 內聯關鍵樣式 + 異步加載非關鍵樣式

原理

- 外部 CSS 文件會阻塞渲染

- 首屏需要的樣式（關鍵 CSS）內聯到 ``

- 完整 CSS 文件異步加載，不阻塞

提取關鍵 CSS（使用 `critical` 工具）

npm install -g critical
critical index.html --inline --base dist/ > index-critical.html

異步加載完整 CSS

<link rel="preload" href="/full.css" as="style" onload="this.onload=null;this.rel='stylesheet'">
<noscript><link rel="stylesheet" href="/full.css"></noscript>

收益

消除 CSS 阻塞，FCP 提前 0.3~0.8 秒。

六、優化手段 5：服務器壓縮與 CDN 預熱

原理

- Brotli 压缩比 Gzip 高 20%~30%

- CDN 預熱讓用戶首次訪問即命中邊緣節點

Nginx Brotli 配置（需编译 brotli 模块）

brotli on;
brotli_comp_level 6;
brotli_types text/plain text/css application/javascript application/json image/svg+xml;

CDN 預熱（阿里雲示例）

aliyun cdn PushObjectCache --ObjectPath "https://example.com/static/main.js"### 收益

傳輸體積減少 20%~30%，RTT 高的地區尤其明顯。
