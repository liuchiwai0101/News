Anthropic 發佈 Claude Opus 5.5，面向更長、上下文更重的編碼會話優化成本

內容機器翻譯自第三方媒體（Anthropic），僅供參考，以原文為準。

AI 導讀

Anthropic 發佈 Claude Opus 5.5，稱典型按 token 計費工作負載運行成本比 Opus 5 低約 40%，其中緩存讀取降價 60%、輸入輸出 token 降價 20%。

推薦理由

官方解釋了 Opus 5.5 降價結構與 Claude Code 緩存機制如何配合，長會話開發者可據此調整用量習慣來省錢。

正文

我們估計，對於按 token 計費的典型工作負載，Claude Opus 5.5 的運行成本比 Opus 5 低約 40%。對開發者而言，這些節省究竟如何累積起來才是關鍵。

如果你按 token 付費，那麼在運行時間更長、上下文更高的會話中，成本差異最為明顯——而這正是過去六個月裏愈發普遍的 Claude Code 會話類型。

本文將深入探討 Opus 5.5 為何能在開發者當下（以及未來很可能）的編碼方式下實現成本效益的機制。

Claude Code 趨勢

我們彙總了 2026 年 3 月至 9 月期間開發者使用 Claude Code 的聚合數據。隨着模型能力提升，開發者部署智能體的方式日益精妙。每個會話的提示詞數量保持穩定，但我們發現了一些有趣的行為：

  • Claude 在每個提示詞上的工作時長增加了 3.3 倍，每個提示詞的模型調用次數增加了 40% 以上。中斷次數減少了 68%。
  • 開發者連接工具服務器的可能性約為原來的兩倍，使用技能的可能性也約為兩倍，而將文本粘貼到提示詞中的可能性則減少了三分之一。
  • 每次請求的上下文增長了 2.6 倍。輸入與輸出 token 的比例從 189:1 變為 324:1。

所有這些都表明，開發者正把更勤奮、信息更充分的 Claude 用於更大、更開放式的任務。對於這類會話，上下文工程的經濟影響會被進一步放大。

簡而言之，Claude 讀取的 token 更多了。你需要確保你提供的所有上下文都是必要的，並且儘可能多的上下文是從緩存中讀取的。

是什麼讓 Opus 5.5 在長時間、上下文密集的會話中具備成本效益

有三項變化讓長時間運行、上下文密集的會話更具成本效益：定價的變化、模型行為的變化，以及 Claude Code harness 的變化。讓我們逐一來看。

緩存很便宜

對於按 token 計費的使用，我們將輸入和輸出 token 的成本降低了 20%，並且將讀取緩存 token 的價格降低了 60%。後一項降價意義重大，因為緩存讀取構成了智能體和編程工作成本的大部分。

正如我們剛剛討論的，每次請求的上下文在六個月內增加了約 2.6 倍，這意味着節省正朝着正確的方向發展。對於按 token 計費的用户來説，同樣的價格調整在如今的 Claude Code 流量上比六個月前節省更多，因為現在賬單中更大一部分來自重新讀取的上下文。

截至本文發佈之日，Opus 5.5 上緩存 token 的成本僅為競爭模型的五分之一，同時性能還優於它們。

Claude Code 更擅長利用緩存

這一點與 Opus 5.5 的關係沒那麼大，更多是我們在過去六個月裏為 Claude Code 添加的許多功能所帶來的結果。考慮到我們剛才討論的編碼會話趨勢，你可能會預期緩存未命中的比例更高，但事實恰恰相反。未命中緩存的輸入減少了 50% 以上。

例如，我們讓一些較小的操作更難意外破壞你的緩存，比如刷新登錄。我們也讓一些較大的操作更難破壞緩存，比如在對話中途添加指令或按需加載工具。對於 Opus 5.5 和 Fable 5.1 這類較新的模型，你現在可以在會話過程中更改 effort 級別，而不會重置緩存。

我們還讓緩存對長時間運行和委派的會話更有用。使用 API key 和雲服務商的開發者現在可以設置一小時的緩存生命週期（訂閲用户此前已享有此功能），而分叉出的子智能體會從父級的緩存開始，而不必為相同的上下文再次付費。

同樣的任務，但輪次更少

完成同樣的任務，Opus 5.5 所需的輪次可能比其他模型更少。Zeta Labs 發現，每個任務所需的輪次和工具調用都比 Opus 5 更少，但成本卻只有將近一半，而且他們最難的任務完成數量翻了一倍。

這並不適用於所有任務。在 Opus 5.5 上任務的成本 一文中，Addy 寫道：“在一個範圍明確的任務上，兩個模型完成的輪數大致相同，降價就是你得到的全部好處。差距應該在開放式任務上最大，因為模型可能把許多輪花在錯誤的想法上。沒有任何一個數字適用於所有代碼庫，所以要實際測量。”

換句話説，簡單、簡短、機械的任務會花費相同的輪數，而更長、更難的任務則更有潛力讓 Opus 5.5 避免把 token 浪費在錯誤的思路上。減少的輪數甚至比緩存 token 更具成本效益。

同樣值得注意的是，尤其是當 Claude 長時間無人值守或不間斷地工作時，Opus 5.5 生成輸出的速度比 Opus 5 快 30% 以上。雖然這不會提高緩存命中率或減少 token 用量，但這意味着在長時間運行時等待更少。

保護你的緩存讀取

隨着智能體編程的成熟，各組織已從要求開發者不惜一切代價擴展，轉向要求開發者高效擴展。在 Claude Code 中運行 /usage，查看你的用量中有多少是緩存讀取。然後保護這個數字：

  • 在會話開始時選好你的模型，而不是中途切換，
  • 在離開之前進行壓縮，而不是之後，以及
  • 如果你使用的是 API key 或雲服務商，請為長時間會話設置一小時緩存生命週期。

把 Opus 5.5 用於開放式、上下文繁重的工作，在這些工作中這些習慣會不斷累積產生複利效應，並查看在 Opus 5.5 上運行一項任務的成本瞭解具體的計算數字。
