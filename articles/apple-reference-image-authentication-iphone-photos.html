Apple 開發 Reference Image 認證功能 驗證 iPhone 相片來源

Apple 正在開發新功能，以驗證相片是否真正出自 iPhone 相機。iOS 27 beta 5 的程式碼顯示，這項名為 Apple Reference Image 的功能，會利用與拍攝相機硬件相關的獨特資料，核實相片來源。

防範虛假影像

以合成影像冒充真實相片的問題並非新鮮，但生成式 AI 令情況更為迫切。以往需要專業編輯花數小時甚至數日處理的工序，現時只需輸入簡短提示便可完成。Google 開發 SynthID，在 AI 生成圖片中嵌入肉眼難以察覺的浮水印，OpenAI 等公司亦已採用。Meta 則在 Facebook、Instagram 及 Threads 加入 AI 生成內容標籤，但這類系統在可靠識別被操縱媒體方面仍有侷限。

認證與私隱

除了為 Image Playground 生成的影像加入中繼資料標記，Apple 開發 Apple Reference Image 時亦以私隱為先：Apple 無法讀取原始相片。系統會將相片送到 Private Cloud Compute 認證，只有若干感應器資料及相片中繼資料會傳回 Apple。功能預設關閉，啟用時需在「設定 ＞ 相機 ＞ Reference Image」開啟 Reference 模式，並會顯示私隱提示畫面；使用該模式拍攝的相片才會包含日後可用於認證的來源資料，一般拍攝的相片則不會。

Reference 模式不會自動認證，用戶其後可選擇認證，屆時原始相片及相關來源資料會送到 Private Cloud Compute 驗證，Apple 會為相片分配獨特 ID。若 Apple 判斷某感應器可能遭到入侵，或會撤銷該感應器以往的認證。

分享及傳輸

已認證相片可與他人分享，對方的 Apple 裝置可在本機檢查相片是否仍屬已認證狀態，無需向 Apple 披露正在查看哪些相片。分享時包含的資料視乎方式（AirDrop、Messages 等）及相片屬原始、編輯還是認證版本而定；Apple 表示，若選擇分享所有相片資料，傳輸內容可能包括獨特硬件識別碼及與相片相關的未裁剪片段。Apple 亦為 USB 傳輸加入 Transfer with Provenance 選項，啟用後，傳到 Mac 或 PC 的已認證相片會包含 Reference Image 資料，未認證相片亦可能帶有硬件識別碼等來源資料。
