你上線了一個頁面，自認爲飛快。但用戶那邊轉圈轉了三秒，走了。你渾然不知。今天我們來裝一套“網頁心電圖儀”——前端性能監控。它能告訴你：用戶打開你的網站，到底有多卡？哪裏卡？卡的人多不多？不用等用戶罵你，你就知道該優化哪了。

前言

性能優化不是“我覺得快”，而是“數據證明快”。沒有監控的優化，就像閉着眼睛射箭——中了是運氣，脫靶是常態。 Google 定義了三個核心指標（Core Web Vitals）：LCP（加載速度）、FID（交互響應）、CLS（視覺穩定）。加上我們自己業務關心的指標（比如首屏時間、API耗時），組合起來就是你的“網頁健康報告”。 今天我們就來搭一套輕量級前端性能監控，從採集到上報，再到報警，一條龍。 一、三大核心指標：你的網頁“體檢三項”

LCP（最大內容繪製）：加載速度的“裁判”

LCP 測量頁面主要內容（比如大圖、標題、視頻）加載完成的時間。理想值：2.5秒以內。 什麼算“主要內容”？就是用戶第一眼看到的那個最大的元素。可能是背景圖，可能是大標題，也可能是視頻封面。

FID（首次輸入延遲）：交互響應的“秒錶”

用戶第一次點擊、觸摸或按鍵，到瀏覽器真正開始處理的時間。理想值：100毫秒以內。 如果你的JS主線程被長任務阻塞，用戶點了按鈕沒反應，FID就會高。用戶會覺得“這網站卡死了”。

CLS（累計佈局偏移）：視覺穩定的“防抖測試”

頁面加載過程中，元素突然位移（比如圖片加載出來把按鈕擠下去了）。理想值：0.1以內。 CLS 高，用戶容易點錯按鈕，比如本來要點“購買”，結果圖片加載完，按鈕被擠開，點到了“不感興趣”。 二、怎麼採集這些指標？用 web-vitals 庫 Google 官方提供了 web-vitals 庫，幾行代碼就能拿到 LCP、FID、CLS。 npm install web-vitalsimport { getLCP, getFID, getCLS } from 'web-vitals'; function sendToAnalytics({ name, value, id }) {
