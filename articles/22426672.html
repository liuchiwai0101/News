OPPO AI Agent Team 與 LV-NUS lab 的工作，發表於 **ICML 2026**。當前的自進化記憶系統都停留在用固定的記憶架構去積累經驗這一層，本文提出 **MemEvolve**，一個**同時進化「經驗知識」與「記憶架構本身」**的元進化框架，讓 Agent 不僅能積累經驗，還能不斷改進它是怎麼從經驗裏學習的這件事

背景

語言 Agent 的自我進化高度依賴**記憶系統（Memory System）**：它持續記錄 Agent 與環境的交互，將其蒸餾爲各種形式的知識與技能，從而讓 LLM Agent 在任務求解和世界探索中持續變強。記憶的表徵形態一路演進：從最初的**原始軌跡存儲 + few-shot 提示**，到更抽象的文本產物（tips、shortcuts、reasoning template），再到近期的**結構化工具接口**（API、MCP）和**代碼級倉庫**

於是一個很自然的問題浮現：**到底什麼樣的記憶架構最能驅動 Agent 自我提升？**

本文的核心論斷是：**不存在一個普適最優的記憶架構**。比如一個從歷史軌跡裏蒸餾可複用 API 的記憶系統，在網頁瀏覽任務上表現優異，但對數學、科學推理幾乎無用；反過來，基於自我批判（self-critique）的記憶在推理密集型任務上很強，卻在編碼和工具使用場景下失效。作者認爲這些 trade-off 源於當前記憶系統的**靜態本質（static nature）**：研究者設計一條固定的記憶流水線（ingestion / abstraction / retrieval）嵌進 Agent，就假設它能靠「不斷接觸新經驗」維持長期進化。

但這忽略了一個關鍵現實——**不同任務耦合着不同的記憶需求（memory affordances）**，一個無法針對當前任務自我調整的記憶系統，從根本上就與開放式 Agent 進化的前提相悖

圖2 | Agent 自我進化與人類學習的類比。**平庸學習者（Mediocre Learner）**無法從經驗受益（即無記憶的 Agent）；**熟練學習者（Skillful Learner）**能從過去經驗提取可複用技能，但用的是**固定預定義的抽象方式**；而**自適應學習者（Adaptive Learner）**在積累經驗的同時，還能動態調整「經驗被鞏固和利用的策略」。

**MemEvolve** 研究的核心問題就是：一個記憶系統如何在**促進 Agent 系統進化**的同時，還能**元進化（meta-evolve）自身的架構**，以在目標任務域上取得更優性能，同時保持泛化性？

方法

**MemEvolve** 概念上是一个**双层优化（bilevel optimization）**过程：

-

**內層循環（Inner Loop）**：一階進化。Agent 在固定的記憶系統引導下，通過持續的新任務流填充自己的經驗庫

-

**外層循環（Outer Loop）**：二階進化。元學習出一個更有效的記憶架構，來加速未來的學習

這形成一個良性循環：外層進化出更好的架構 → 提升 Agent 學習效率 → 更強的 Agent 產出更高質量的軌跡 → 爲外層提供更精確的適應度信號去驅動下一輪架構進化

EvolveLab：統一的模塊化設計空間

由於記憶系統的設計空間龐大且異構（知識圖譜、技能庫、向量數據庫……），直接做可控優化幾乎不可能。爲此本文把任意記憶架構 \(\Omega\) 解耦爲四個功能獨立又相互依賴的組件 \(\Omega = (E, U, R, G)\)：

-

**♣ Encode（編碼 \(E\)）**：把原始經驗（軌跡片段 \(\tau_t = (s_t, a_t, s_{t+1})\)、工具輸出、自我批判）轉化爲結構化表徵 \(e_t = E(\epsilon_t)\)。可以簡單如壓縮原始 trace，也可複雜如提煉可泛化的 lessons

-

**♦ Store（存儲 \(U\)）**：把編碼後的經驗整合進持久記憶，\(M_{t+1} = U(M_t, e_t)\)。載體可以是向量數據庫、知識圖譜等

-

**♥ Retrieve（檢索 \(R\)）**：提供任務相關的記憶內容 \(c_t = R(M_t, s_t, Q)\)，指導 Agent 的策略決策。檢索內容可以是可複用工具、規劃經驗或蒸餾的程序性知識

-

**♠ Manage（管理 \(G\)）**：執行離線、異步的操作，如整合（consolidation）、抽象、選擇性遺忘，以維護長期記憶質量與效率，\(M_t' = G(M_t)\)

這一模塊化抽象把每個記憶系統表示爲 \((E, U, R, G)\) 四個可編程實現的具體組合，構成一個**基因型（genotype）**，正是 MemEvolve 元進化的操作對象

基於此設計空間，作者構建了 **EvolveLab**：一個統一、可擴展的自進化記憶代碼庫，把 **12 個代表性記憶系統**（Voyager、ExpeL、Generative、DILU、AWM、Mobile-E、Cheatsheet、SkillWeaver、G-Memory、Agent-KB、Memp、EvolveR）在同一模塊化接口下重新實現，全部繼承自單一抽象基類 BaseMemoryProvider，強制實現統一的四組件接口。

EvolveLab 同時提供標準化測試平臺（GAIA、xBench、DeepResearchBench 等），支持**在線模式（■online，邊處理任務流邊更新記憶）**和**離線模式（■offline，先從靜態軌跡積累經驗再在未見任務上評估）**兩種範式

双层进化过程（Dual-Evolution Process）

傳統自進化記憶在固定 \(\Omega\) 下演化：\(M_{t+1} = \Omega(M_t, \epsilon_\tau),\ \epsilon_\tau \in E(\tau)\)，這能積累知識但**從根本上排除了架構適應**，因爲接口 \(\Omega\) 本身不可變

MemEvolve 不再維護單個靜態 \(\Omega\)，而是在每個進化迭代 \(k\) 維護一個**候選記憶系統的有限集合** \(\{\Omega_j^{(k)}\}_{j \in J^{(k)}}\)，每個 \(\Omega_j^{(k)} \triangleq (E_j^{(k)}, U_j^{(k)}, R_j^{(k)}, G_j^{(k)})\)。初始迭代從單例集（\(|J^{(0)}| = 1\)，即一個手工設計的 baseline 記憶）出發，後續迭代允許多個競爭候選：

-

**内层（经验进化）**：对每个候选 \(\Omega_j^{(k)}\)，其记忆状态从空初始化，沿轨迹 \(\tau \in T_j^{(k)}\) 更新 \(M_{t+1,j}^{(k)} = \Omega_j^{(k)}(M_{t,j}^{(k)}, \epsilon_\tau)\)。执行后对每条轨迹产出反馈向量 \(f_j(\tau) \in \mathbb{R}^d\)（\(d=3\) 对应**任务成功、Token 消耗、延迟**三个指标），聚合算子 \(S\) 汇总为 \(F_j^{(k)} = S(\{f_j(\tau)\})\)

-

**外層（架構進化）**：元進化算子 \(F\) 根據彙總 \(\{F_j^{(k)}\}\) 選出高性能候選、提出新變體，產生下一代候選集：\(\{\Omega_{j'}^{(k+1)}\} = F(\{\Omega_j^{(k)}\}, \{F_j^{(k)}\})\)。具體地，\(F\) 按 \(F_j^{(k)}\) 排序，保留 top-\(K\) 記憶系統，再通過修改或重組它們的四個組件 \((E, U, R, G)\) 生成新架構，\(K\) 爲固定的存活預算（survivor budget）

一句話概括：**每輪迭代交替執行「在固定架構下從空初始化演化經驗庫」和「基於誘導出的性能演化架構本身」**，讓記憶庫與治理它的架構協同進化（co-evolve），產出越來越自適應、越來越資源感知的記憶驅動行爲

Diagnose-and-Design 進化（元進化算子 F 的核心）

元進化算子 \(F\) 分解爲兩個協同部分：**架構選擇**和**診斷-設計進化**

**1. 架构选择（Architectural Selection）**

把每個候選的彙總向量定義爲 \(F_j^{(k)} \triangleq (\mathrm{Perf}_j^{(k)}, -\mathrm{Cost}_j^{(k)}, -\mathrm{Delay}_j^{(k)})\)（三個維度都是越大越好）。候選先按 \(F_j^{(k)}\) 做**非支配排序（non-dominated sorting）**得到 Pareto rank \(\rho_j^{(k)}\)；同一 Pareto rank 內再按主性能指標 \(\mathrm{Perf}\) 排序；取 top-\(K\) 作爲**父代集合** \(P^{(k)}\)。

這保證架構進化由「兼顧任務效果與資源效率的系統」引導，同時在 Pareto 等價的候選中優先任務性能

**2. 诊断-设计进化（Diagnose-and-Design Evolution）**

对每个父代架构 \(\Omega_p^{(k)}\)，\(F\) 通过两阶段生成 \(S\) 个后代 \(\{\Omega_{p,s}^{(k+1)}\}\)：

-

**診斷（Diagnosis）**：用父代自己執行批次 \(T_p^{(k)}\) 的**軌跡級證據**檢查它。對每條軌跡提供結果統計（成功指標、Token 成本）+ 任務查詢的結構化描述；一個**replay 接口**允許回放對應軌跡，做針對性檢查（包括**檢索失敗、無效抽象、存儲低效**等）。診斷階段產出一份**結構化缺陷畫像（defect profile）**\(D(\Omega_p^{(k)})\)，刻畫四個組件上的架構瓶頸

-

**設計（Design）**：以缺陷畫像爲條件，**只修改模塊化接口內允許的實現位點**來構造重設計架構，從而保證兼容性、把架構變更隔離在指定設計空間內。產出 \(S\) 個變體 \(\Omega_{p,s}^{(k+1)} = \mathrm{Design}(\Omega_p^{(k)}, D(\Omega_p^{(k)}), s)\)，它們在編碼策略、存儲規則、檢索約束或管理策略上各不相同，但都符合統一接口、都能被 Agent 執行

聚合所有父代的後代，即得到下一代候選架構集。這一機制保證架構更新既有經驗依據，又被結構化約束在統一設計空間內

實驗

**Benchmark**：GAIA、WebWalkerQA、xBench-DeepSearch（xBench-DS）、TaskCraft 四个高难度 Agentic 基准

**Agent 框架**：集成到两个代表性框架——**SmolAgent**（轻量双 Agent 架构）和 **Flash-Searcher**（高性能单 Agent 深研系统）；另在两个 held-out 多 Agent 系统上验证泛化：腾讯 **CK-Pro**（main/file/web 三 Agent）和 **OWL**（planner/coordinator/web/document/coding 分层系统）

**模型**：主干用 **GPT-5-mini**（同时也支撑元进化算子 \(F\)），另加 **DeepSeek V3.2** 和 **Kimi K2** 测跨 LLM 泛化

**配置**：雙層進化跑 \(K_{max}=3\) 輪；外層存活預算 \(K=1\)（每輪只保留 top-1 架構，擴展出 \(S=3\) 個後代）；內層每個候選在 60 條軌跡的批次上評估（40 條新採樣 + 20 條複用上一輪以穩定跨輪比較）

主要結果

-

**记忆系统对 Agent 至关重要**：xBench 上 SmolAgent + GPT-5-Mini 初始 pass@1 为 51%，接入 MemEvolve 后 +6%，pass@3 涨到 68%；Flash-Searcher + GPT-5-Mini 从 69% 提到 74%。在 GAIA 上 MemEvolve + Flash-Searcher pass@3 达**80.61%**，超过 OWL-Workforce、CK-Pro 等强多 Agent 系统，且避免了构建庞大昂贵的离线知识库

-

**跨任務 / 跨模型 / 跨框架泛化**：WebWalkerQA 和 xBench 上用的記憶系統**直接繼承自 TaskCraft 上進化的結果、未做任何任務特定元進化**，仍帶來一致增益（WebWalkerQA 58.82→61.18%，xBench 69.0→74.0%），說明 MemEvolve 捕獲的是**任務無關的記憶設計原則**而非對單個數據集的過擬合。在跨 LLM 上雖用 GPT-5-Mini 進化，遷移到 Kimi K2 和 DeepSeek V3.2 無需人工適配

-

**成本可控**：MemEvolve 的增益不是靠堆 Token 换来的。API 成本与 No-Memory baseline 相当（GAIA：$0.085 vs $0.086；xBench：$0.136 vs $0.141），执行延迟也与其他自进化 baseline 同一量级

與人工設計記憶系統的對比

作者把 EvolveLab 裏 7 個代表性人工記憶系統接到 Flash-Searcher 上對比：

-

**現有記憶系統難以帶來一致增益**：DILU 在 xBench 和 WebWalkerQA 上提升卻在 GAIA 上掉 2.42%；Dynamic Cheatsheet 靠技能凝練在 WebWalkerQA 上 +1.76% 卻在 GAIA、xBench 上表現很差；**ExpeL 在三個基準上全部退化**，因爲它原本是爲 ALFWorld、HotpotQA 這類簡單具身/QA 場景設計的，機制不適配長程、長上下文的深度研究。這印證了**任務感知記憶設計（task-aware memory design）的必要性**

-

**MemEvolve 提供穩健一致的改進**：雖在 TaskCraft 上進化，卻在三個基準上穩定取得 3.54%~5.0% 的提升，且累積成功率曲線隨任務推進逐漸穩定收斂到明顯更優的水平，說明它發現的是**有原則的記憶設計**而非脆弱的任務特定啓發式

關於「泛化」與「記憶系統無法跨域泛化」這一動機看似衝突的問題，作者澄清：TaskCraft 上進化的記憶

確實不太可能遷移到根本不同的任務族（如具身動作，環境/動作空間/工具集差異巨大）；但 MemEvolve 能在共享任務域內發現廣泛適用的架構，同時保留必要時進一步做任務特定適配的能力

-

第三輪進化裏，從 \(\Omega_3^{(2)}\) **Riva**到 \(\Omega_1^{(3)}\)**Cerebra**，記憶系統學會不僅蒸餾文本洞察，還蒸餾可複用工具，並引入對記憶數據庫的週期性維護，爲底層框架提供更快的進化動量

-

**進化出的記憶在實際中確實有效**（圖7）：從最簡 few-shot baseline 進化出的**Lightweight**系統能在不同任務階段自適應地提供不同粒度的記憶——早期規劃階段給高層任務分解策略，執行推進時給細粒度工具使用建議 + 高亮關鍵信息的工作記憶；它甚至表現出**預測性行爲**，預判目標信息可能出現在在線旅遊網站的圖片內容裏，成功引導 Agent 在 trip.com 上定位證據

總結

MemEvolve 揭示了幾條自動進化出的**記憶設計原則**：**更多的 agentic 參與、分層組織、多層抽象**。它把「自進化記憶」這件事從「人工精心設計單一架構並期望其跨域泛化」推進到「由經驗交互反饋驅動的、架構級的自適應進化」

個人覺得這篇工作的立意很好，抓住了當前記憶系統研究的一個真痛點——**大家都在卷「記憶表徵形態」（tips vs 工具 vs 圖譜），但很少有人去問「這個記憶架構本身該不該隨任務自適應」**。把記憶系統解耦成 Encode/Store/Retrieve/Manage 四組件、再用 Pareto 排序 + Diagnose-and-Design 去做架構級進化，思路是乾淨且可復現的（配套開源了 EvolveLab，把 12 個記憶系統統一實現，這個工程貢獻本身就很有價值）。雙層優化 = 內層進化經驗 + 外層進化架構的框架也很自然
