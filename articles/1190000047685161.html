Pretext 是由前 React 核心開發者 Cheng Lou 創建的瀏覽器文本測量庫，核心能力是**不觸碰 DOM 就能精確計算段落高度和換行位置**。它通過離屏 Canvas 預測量字符寬度、純算術模擬瀏覽器換行邏輯，實現了零布局抖動（layout thrashing）、接近實時的文本排版計算。項目於 2026 年 3 月開源，已在社區引發廣泛關注。

一、瀏覽器文本測量爲什麼難？

在傳統 Web 開發中，計算一段文字在特定寬度下的高度，通常需要：

- 將文字插入 DOM 中的一個隱藏元素

- 觸發瀏覽器佈局（layout）

- 读取 `offsetHeight`或`getBoundingClientRect()`

- 每次容器寬度變化就重複上述過程

這個過程有兩個根本性缺陷：

- **同步強制佈局**（Forced Synchronous Layout）：讀取尺寸會打斷渲染流水線，導致掉幀

- **無法預測**：在元素被渲染前無法知道高度，虛擬滾動、富文本編輯器只能靠估算

Pretext 繞開了這條路，改用**純算術**復現瀏覽器的換行邏輯。

二、核心架构：prepare() + layout()

Pretext 的 API 只有兩個核心函數，分工明確：

prepare()：預測量與緩存

import { prepare } from 'pretext' // [包名待覈實，以 npm 發佈名爲準]
// 傳入文本和字體配置，離線測量每個字符片段的寬度
const segments = prepare(text, {
  fontFamily: 'monospace',
  fontSize: 16,
})
// 結果被緩存，相同字符不會重複測量

prepare() 負責將文本按**軟連字符、非拉丁字符、Emoji** 等規則分段，使用離屏 Canvas 測量各段寬度並緩存。這一步只需執行一次，後續寬度變化無需重新測量字符。

layout()：純算術換行計算

import { layout } from 'pretext' // [包名待核实，以 npm 发布名为准]
// 传入预处理结果和容器宽度，立即返回换行结果
const result = layout(segments, containerWidth)
console.log(result.lines)       // 每行的文本内容
console.log(result.totalHeight) // 段落总高度（px）

layout() 模擬瀏覽器的 word-wrap 邏輯，給定寬度參數立即返回行數和總高度，**不觸碰 DOM，不觸發重排**。容器寬度變化時只需重新調用 layout()，無需重新測量字符。

Pretext 作者 Cheng Lou 對此的回應是：Pretext 的目標是**通用性**而非單場景極限性能，其緩存機制在首次測量後、多次寬度變化的場景下優勢明顯——prepare() 只跑一次，後續每次 layout() 是純算術，速度很快。

**結論**：對於 ASCII 文本的一次性大批量測量，專用工具可能更快；對於需要**反覆響應容器寬度變化**的場景（虛擬滾動、響應式編輯器），Pretext 的緩存架構更有優勢。

六、適用場景

**不推薦場景**：樣式複雜的混排（內聯圖片、多種字號混用、複雜 CSS 僞元素），這類場景的佈局邏輯難以用算術完整復現。

七、CSS 新特性能替代 Pretext 嗎？

CSS 的 text-wrap: balance 和 interpolate-size 等新特性在部分場景下可以減少對文本測量庫的需求，但兩者解決的問題不同：

- `text-wrap: balance`：讓瀏覽器自動平衡多行文本的行寬，- **不提供高度數值**給 JavaScript 使用

- `interpolate-size`：允許對- `height: auto`做過渡動畫，- **不解決預計算問題**

Pretext 的核心價值在於**把高度作爲數值暴露給 JS**，供虛擬滾動、編輯器等需要提前知道尺寸的場景使用。CSS 新特性無法替代這一需求。

八、AI 輔助開發背景

Pretext 的開發過程本身是一個值得關注的案例。Cheng Lou 使用 **Claude 和 Codex** 輔助完成了大量測試迭代工作——讓 AI 系統生成測試用例、與瀏覽器真實渲染結果對比、反覆修正換行算法，歷時數週。

社區對此的普遍看法是：**"AI 特別適合處理需要大量重複測試迭代的工程工作"**。文本換行算法的核心挑戰不在於邏輯複雜度，而在於邊界情況（edge cases）數量龐大——不同語言、字體、Unicode 特殊字符的組合幾乎無窮無盡，正是 AI 輔助開發能大幅提速的類型。

**Q：Pretext 是純前端庫嗎？可以在 Node.js 中用嗎？**`layout()` 是純算術函數，無需瀏覽器環境，可以在 Node.js 或 Worker 中直接使用。`prepare()` 依賴 Canvas API 測量字符寬度，在 Node.js 中需要搭配 `node-canvas` 等庫提供 Canvas 實現。

**Q：Pretext 和 React 怎么配合使用？**

Cheng Lou 本人是前 React 核心開發者，設計上考慮了 React 場景。prepare() 可在數據加載階段執行，layout() 結果可作爲 state 驅動列表渲染，避免 useLayoutEffect 中的強制同步佈局。
