Next.js 部署：从本地跑得欢，到线上飞得稳

你在本地npm run dev，頁面秒開，爽得不行。一部署到服務器，慢得像老太太過馬路，圖片加載半天，首屏白屏幾秒，用戶投訴。今天我們就來把Next.js應用“送上天”——從部署到優化，讓你的線上應用和本地一樣快。而且，還能免費蹭HTTPS和CDN。## 前言

Next.js最大的優勢之一就是**部署極其方便**。官方團隊就是做部署平臺Vercel的，所以你用Next.js，就等於半隻腳踩進了“一鍵部署”的門檻。但這不代表你可以隨便扔到服務器就跑。部署姿勢不對，照樣卡成狗。

今天我們講兩種部署方式：**無腦簡單版（Vercel）** 和 **手搓硬核版（自託管）**，以及上線前必做的優化。

一、Vercel部署：連命令都不用記

Vercel是Next.js的親爹（母公司）。你把代碼推到GitHub/GitLab，Vercel自動構建、部署、給CDN、給HTTPS，甚至自動給你一個.vercel.app域名。

**步驟**：

- 把代碼推到Git倉庫。

- 登錄vercel.com，用GitHub賬號登錄。

- 點擊“Import Project”，選擇你的倉庫。

- 默認配置（Next.js自動識別），點擊Deploy。

- 幾十秒後，你會得到一個鏈接 `https://你的項目.vercel.app`，已經上線了。

之後每次git push，Vercel自動重新部署。你連服務器都不用買。

**優點**：零運維、自動HTTPS、全球CDN、自動優化（圖片、字體）、免費額度夠用（個人項目）。 **缺點**：自帶域名在國內訪問可能慢（但可綁定自己的域名，解析到國內CDN節點）。流量超了要付費。

**生活比喻**：你把菜做好，遞給外賣騎手，他幫你送到客戶手裏，你什麼都不用管。

二、自託管（自己買服務器）：更自由但更折騰

如果你必須用國內服務器、或者公司要求私有化部署，那就得自己搭。

方案一：Node.js服務器運行

npm run build   # 构建生产版本
npm start       # 启动Node服务器（默认3000端口）

然後用Nginx反向代理，配置HTTPS。注意：你需要自己管理進程（用PM2），自己配置CDN，自己處理日誌。

pm2 start npm --name "nextjs" -- start### 方案二：静态导出（如果全站都是SSG）

如果你的所有頁面都用了getStaticProps（沒有getServerSideProps），可以導出純靜態文件，放到Nginx或OSS上。

next build && next export會生成out文件夾，直接扔到任意靜態託管（如阿里雲OSS + CDN），超便宜，超快。

**缺点**：不能用`getServerSideProps`、API Routes等服务器特性。

方案三：Docker容器化

写Dockerfile，构建镜像，跑在K8s或Docker Compose上。

FROM node:18-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build
EXPOSE 3000
CMD ["npm", "start"]

適合雲原生環境。

三、上線前必做的優化：讓Next.js飛起來

1. 图片用`next/image`，别用`<img>`

next/image自動壓縮、懶加載、轉webp、響應式。你啥都不用做，圖片體積直接小一半。

import Image from 'next/image';
<Image src="/hero.png" width={1200} height={600} alt="Hero" />

**坑**：寬高必須指定，或者用`layout="fill"` + 父容器相對定位。

2. 字体用`next/font`

Next.js 13+內置字體優化，自動內聯CSS、避免佈局偏移。

import { Inter } from 'next/font/google';
const inter = Inter({ subsets: ['latin'] });
<html className={inter.className}>

3. 脚本用`next/script`

控制第三方腳本加載時機，不阻塞頁面。

import Script from 'next/script';
<Script src="https://example.com/tracker.js" strategy="afterInteractive" />

4. 開啓壓縮（Vercel默認開啓，自託管需配置）

在next.config.js中：

module.exports = {
  compress: true, // 开启gzip，Nginx也要配
};

5. 移除未使用的CSS（結合Tailwind或PurgeCSS）

如果你用Tailwind，默认已清理。如果用普通CSS，可以考虑@fullhuman/postcss-purgecss。

6. 設置緩存頭

自託管時，在Nginx裏對靜態資源（_next/static）設置永久緩存：

location /_next/static {
  expires 1y;
  add_header Cache-Control "public, immutable";
}

7. 啓用增量靜態再生（ISR）

不需要每个页面都getServerSideProps，能用getStaticProps + revalidate尽量用。

export async function getStaticProps() {
  return { props: { data }, revalidate: 60 };
}

四、性能監控：別靠猜

部署後，用**Vercel Analytics**（付費）或自建**Google Lighthouse CI**，定期跑分。也可以集成**Sentry**監控運行時錯誤。

npm install @sentry/nextjs配置後，線上報錯自動發到Sentry，不用等用戶罵你。

五、總結：從開發到上線，一條龍

- **個人項目/創業公司**：無腦用Vercel，省下的時間寫代碼。

- **企业自托管**：用Node.js + PM2 + Nginx，或Docker + K8s。

- **纯静态站点**：- `next export`扔OSS。

- **優化必做**：圖片、字體、壓縮、緩存、ISR。

做了這些，你的Next.js應用就能從“本地火箭”變成“太空飛船”。用戶打開，秒開；谷歌爬蟲，狂喜；老闆看數據，點頭。
