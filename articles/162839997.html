React 19 最大的變化不是任何 API，而是 React Compiler（原 React Forget）終於從實驗走向生產。它的核心邏輯是自動追蹤組件依賴關係，在編譯階段完成 useMemo/useCallback 級別的優化，不需要開發者手動寫 memo 化代碼。

React Compiler 在編譯時對組件代碼進行靜態分析，自動識別哪些值需要緩存、哪些回調需要穩定引用。它遵循 React 的渲染規則，確保優化後的代碼在行爲上與原始代碼完全一致。

  const filtered = products.filter(p =>
    p.name.toLowerCase().includes(filterText.toLowerCase())
  );
  const handleClick = (id) => {
    console.log('点击了商品:', id);
  };
  return (
    <ul>
      {filtered.map(product => (

          key={product.id}

          onClick={handleClick}
        />
      ))}
    </ul>

在 React 19 之前，爲了優化這段代碼，開發者需要手動添加 useMemo 和 useCallback：

// React 18 及之前需要的优化代码
function ProductList({ products, filterText }) {
  const filtered = useMemo(() =>
    products.filter(p =>
      p.name.toLowerCase().includes(filterText.toLowerCase())
    ),
    [products, filterText]
  );
  const handleClick = useCallback((id) => {
    console.log('点击了商品:', id);
  }, []);
  return (
    <ul>
      {filtered.map(product => (
        <ProductItem
          key={product.id}
          product={product}
          onClick={handleClick}
        />
      ))}
    </ul>
  );
}

React Server Components（RSC）在2026年已經從"爭議特性"變成了"默認選項"。Next.js 15、React Router v7、TanStack Start 都已經深度集成 RSC。流式渲染配合 RSC，讓首屏體驗有了質的變化。

RSC 的核心思想是將組件分爲服務端組件和客戶端組件兩類：

- **服務端組件**：在服務端渲染，可以直接訪問數據庫和文件系統，不會增加客戶端 JS 體積

- **客戶端組件**：在瀏覽器中運行，處理交互和狀態管理

Vue 3.6 帶來了一個重磅更新：Vapor Mode。它的思路跟 Svelte 類似——在編譯階段直接生成原生 DOM 操作指令，跳過虛擬 DOM diff 的開銷。

傳統的 Vue 3 渲染流程是：模板 → 虛擬 DOM → 真實 DOM。虛擬 DOM 在中間起到"緩衝層"的作用，通過 diff 算法計算出最小的 DOM 更新操作。這個設計在大多數場景下表現良好，但對於大型列表、高頻更新等場景，虛擬 DOM 的運行時開銷就變得不可忽視。

Vapor Mode 改變了這個流程：模板 → 編譯時分析 → 直接生成 DOM 操作代碼。編譯器在構建階段就分析出哪些部分是靜態的、哪些是動態的，然後生成針對性的更新代碼。

<!-- 原始模板 -->
<template>
  <div class="card">
    <h2>{{ title }}</h2>
    <p>{{ description }}</p>
    <span class="badge">{{ count }} 条评论</span>
  </div>
</template>

在 Vapor Mode 下，編譯器會分析出：

- `div.card`和- `h2`、- `p`、- `span.badge`的结构是静态的

- `title`、- `description`、- `count`是动态绑定的

- 只有動態部分需要更新，靜態結構不需要 diff

生成的代碼大致等價於：

// Vapor Mode 编译产物（伪代码）
function render(instance) {
  // 静态结构只在首次创建
  if (!instance._vapor_dom) {
    const root = document.createElement('div');
    root.className = 'card';
    const h2 = document.createElement('h2');
    const p = document.createElement('p');
    const span = document.createElement('span');
    span.className = 'badge';
    root.append(h2, p, span);
    instance._vapor_dom = { root, h2, p, span };
  }
  // 只更新动态内容
  const dom = instance._vapor_dom;
  dom.h2.textContent = instance.title;
  dom.p.textContent = instance.description;
  dom.span.textContent = `${instance.count} 条评论`;
}

官方給出的數據是：初始渲染速度提升 50%，打包體積縮小 40%。這對 Vue 來說是一個戰略性的轉變——Vue 長期以來最大的爭議點就是虛擬 DOM 的運行時開銷，Vapor Mode 直接從架構層面回應了這個問題。

Vapor Mode 的一個重要設計決策是支持漸進式遷移。開發者可以在組件級別選擇啓用 Vapor Mode，不需要整個項目一刀切：

<!-- 在单个组件中启用 Vapor Mode -->
<script setup vapor>
import { ref } from 'vue';
const count = ref(0);
</script>
<template>
  <button @click="count++">
    点击次数: {{ count }}
  </button>
</template>

Svelte 4 的響應式依賴 $: 標籤語法：

<script>
  let count = 0;
  // Svelte 4: 编译器需要分析这段代码的依赖
  $: doubled = count * 2;
  $: {
    console.log(`count 变为 ${count}`);
  }
</script>

這種隱式依賴分析在簡單場景下很方便，但在複雜場景下會帶來問題：

- TypeScript 支持不完善（`$:`不是合法的 JS/TS 語法）

- 依賴分析在複雜表達式面前可能出錯

- 重構時容易遺漏依賴關係

Svelte 5 的 Runes 解決了這些問題：

<script>
  // Svelte 5: 显式声明响应式状态
  let count = $state(0);
  let doubled = $derived(count * 2);
  $effect(() => {
    console.log(`count 变为 ${count}`);
  });
</script>

- **完整的 TypeScript 支持**：所有 Runes 都是合法的 JavaScript/TypeScript 语法

- **明確的依賴關係**：不需要編譯器猜測，開發者顯式聲明

- **更好的可維護性**：重構工具可以正確追蹤依賴

- **.svelte.js 文件**：Runes 可以在- `.svelte.js`文件中使用，實現跨組件的響應式邏輯複用

Solid.js 在2026年的數據很硬核——渲染速度比 React 19 快 300%，核心庫 7KB（不到 React 的 1/6），內存佔用僅比原生 JS 高 26%，GitHub 星標突破 32k。

Solid.js 的祕訣是"細粒度響應式"：它不是重新運行整個組件函數，而是隻更新依賴變化的具體 DOM 節點。

import { createSignal } from 'solid-js';
function Counter() {
  const [count, setCount] = createSignal(0);
  // Solid 的组件函数只运行一次
  // 后续更新只影响依赖 count 的具体 DOM 节点
  return (
    <div>
      <p>当前计数: {count()}</p>
      <button onClick={() => setCount(c => c + 1)}>+1</button>
    </div>
  );
}

在 React 中，每次 count 變化，整個 Counter 函數都會重新執行。在 Solid 中，只有

標籤的文本內容會更新，其餘 DOM 結構保持不變。
