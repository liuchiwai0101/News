Claude Tag 上線：Karpathy 口中的 LLM 第三次革命 — Aciemind 銳利之思

2026 年 6 月 23 日，Anthropic 丟出了一枚震撼彈：**Claude Tag**。這不是一個新模型，也不是一個新版本的聊天介面——它是一種全新的 AI 存在形式：Claude 以團隊成員的身份，直接加入你的 Slack 頻道。

消息一出，剛加入 Anthropic 的 AI 大神 Andrej Karpathy 給出了極高評價。他將其定義為 **LLM 使用者介面的第三次重大革命**。第一次是網站（ChatGPT 式對話），第二次是桌面應用（Claude Code、Cursor 等 IDE 整合），第三次——AI 變成獨立、持久、異步的實體，擁有組織範圍內的工具與上下文，與人類團隊並肩工作。

這不是升級，是範式轉移。

如果你用過 Claude Code 或 GitHub Copilot，Claude Tag 的互動方式不會陌生。但它的本質完全不同。

具體怎麼用？在 Slack 頻道裡 @Claude，用自然語言委派任務，它會自動拆解成多個步驟、逐一執行，最後在討論串中回報結果。

張三給 Claude 佈置了任務，李四進入頻道可以直接看到進度並接手推進，王五再加入時也能理解來龍去脈。所有人圍繞**同一個 Claude** 協作，而不是各自維護自己的上下文。

Anthropic 官方給出的數據令人側目：公司產品團隊 **65% 的程式碼**已由內部版本的 Claude Tag 參與生成。除了工程場景，員工還用它追蹤產品指標、處理支援工單、定位複雜 Bug 的根源。

Claude Tag 的設計圍繞四個關鍵能力，每一項都在挑戰傳統 AI 工具的邊界。

**共享上下文（Multiplayer）**：在同一個 Slack 頻道內，只有一個 Claude 與所有人互動。每個人都能看到它在做什麼，也能在前一個人結束的地方繼續對話。操作完全透明，這在企業環境中至關重要。

**持續記憶（Learns over time）**：隨著長期參與頻道討論，Claude 會逐漸累積組織知識——理解專案背景、團隊慣例、技術棧偏好以及協作流程。使用者不必每次都從零開始解釋上下文。這是從「無狀態 API 呼叫」到「有記憶的團隊成員」的質變。

**主動介入（Ambient Mode）**：這是整個產品最激進的設計。開啟主動模式後，Claude 不再只是等待別人提問——它會自己冒出來。提醒被忽視的重要討論，跟進長時間沒有解決的問題，標記需要決策的事項，甚至在發現相關資訊後主動通知團隊。某種意義上，Claude 開始具備了「主動工作」的能力。

**非同步執行（Works asynchronously）**：任務佈置完後，使用者完全可以離開 Slack。Claude 會自己安排執行計畫，持續推進專案，在數小時甚至數天後完成並主動回報結果。這是 Agent 的本質——不是幫你打字，是幫你完成工作。

技術上，Claude Tag 固定使用 Opus 4.8 模型，配備組織級與頻道級雙重 Token 配額控制。目前僅在 Slack 平臺上以 Beta 形式提供給 Claude Enterprise 和 Team 客戶，未來將擴展到更多工作場景。

Andrej Karpathy 將 LLM 人機互動的演進歸結為三個階段：

**第一階段：網站**。LLM 是一個你需要主動打開瀏覽器去訪問的網站。ChatGPT 的對話框是這個時代的圖騰。互動模式是「使用者發起、模型回應、對話結束」。

**第二階段：應用**。LLM 變成一個你下載到電腦上的軟體，深度整合進開發環境和工作流程。Claude Code、Cursor、GitHub Copilot 是代表。互動模式是「開發中即時輔助、IDE 內嵌」。

**第三階段：隊友**。LLM 變成一個獨立、持久、非同步運行的實體，擁有組織內的工具和上下文，真正實現和人類「並肩工作」。Claude Tag 是開端。

Karpathy 的判斷邏輯值得細品：前兩次變革改變的是「在哪裡用 AI」，第三次變革改變的是 **「AI 以什麼身份存在於組織中」**——從工具變成了有持續記憶、主動行為、共享狀態的團隊角色。

更深一層看，Claude Tag 的「羣聊即 Prompt」機制也極具啟發性。使用者無需切換窗口、無需額外解釋背景，模型直接進入羣聊上下文，自然理解任務意圖。這大幅降低了 AI 協作的摩擦成本。

任何範式轉移都伴隨著不安。

最尖銳的質疑來自「數位監工」：當 Claude 常駐羣聊、主動追問進度，它究竟是「助手」還是「管理者的監控工具」？你把 Claude Tag 拉進五人團隊的那一刻，每個人的每一條消息都成了一條 AI 在讀的消息。輸出好，可能被解讀成「她在外包思考」；輸出平庸，可能被解讀成「你看，這就是我們擔心的」。幾乎沒有第三種結果能讓懷疑者閉嘴。

隱私與信任層的建設，將是 Claude Tag 能否活下來的關鍵變數。即便 Anthropic 從技術上設置了權限隔離、操作可查等保障機制，但信任從來不是技術問題——它是人的問題。

另一個角度看，Claude Tag 選在 Slack 首發極具策略性。Slack 覆蓋近 80% 的《財富》100 強企業、擁有 20 萬以上付費客戶，是企業非結構化資訊最活躍的來源。這不是 AI 去找場景，而是直接在場景裡原生嵌入 AI。Anthropic 賭的是：**最好的 AI 產品不是另一個 App，而是直接住進你已經在用的工具。**

Claude Tag 目前仍處於 Beta 階段，30 天後將強製取代舊版 Claude in Slack。這只是一個開始。

如果 Karpathy 的判斷是對的，我們正在見證的不只是一個新功能的上線，而是 **AI 從「被召喚的工具」變成「在場的隊友」的歷史轉折**。

而一個會主動提醒你、會記住上下文、會在深夜繼續推進任務的 AI 隊友——這件事對工作方式的衝擊，可能比所有人想像的都要深遠。
