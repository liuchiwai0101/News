OpenAI 在 API 中推出全雙工語音模型 GPT-Live-1

正文

GPT‑Live‑1 將 ChatGPT 自然、全雙工的對話能力帶入 API，讓開發者能更好地控制語音智能體的説話與行動方式。

我們正式在 API 中推出 GPT‑Live‑1，為開發者提供一個強大、自然的語音模型，用於構建支持語音的應用和業務工作流。GPT‑Live‑1 最初在 ChatGPT 中亮相，它能夠同時聽和説，並且正如在 Codex 和 ChatGPT Work 中所見，它可以將更深層的推理和操作委派給它所搭配的模型和工具。

針對 GPT‑Live‑1 的 API 版本，我們重點打造了多項新能力，讓開發者能夠圍繞自己的用户、工作流和目標來引導和定製語音體驗。GPT‑Live‑1 的一項核心優勢——流暢的中斷處理——已經帶來了實際業務影響：在早期評估中，Speak 發現 GPT‑Live‑1 讓學習者在語言輔導老師回應之前有更多時間思考，與以往基於輪次的系統相比，中斷減少了近 80%。

GPT‑Live‑1 在 API 中的關鍵優勢：

  • **中斷處理：**通過單一模型同時對傳入和傳出音頻進行推理，改進了中斷處理，避免了鏈式 STT–LLM–TTS 架構的延遲和脆弱的交接。
  • **推理與工具調用委派：**GPT‑Live‑1 可以將推理和工具調用委派給後端文本模型，例如 GPT‑6 Astra 或第三方模型。
  • 語氣、節奏和風格： 讓開發者通過系統提示詞來塑造智能體的語氣、節奏和對話風格。
  • 靜默上下文管理與背景噪聲： 更好地處理背景噪聲和靜默，不會打斷對話，也不會把每一步都大聲敍述出來。
  • 長會話可靠性： 提升長時間交互中的上下文保持能力和對話質量。
  • 電話支持： 支持部署用於電話通話的全雙工語音智能體，從餐廳預訂到客户支持均可覆蓋。

Yelp Host 藉助 GPT‑Live‑1 處理背景噪聲、旁支對話和打斷，順暢地完成預訂。

簡化你的語音智能體架構，降低語音延遲

傳統語音智能體將語音轉文字、推理模型和文字轉語音拼接在一起。每一次交接都會增加延遲，也帶來更多丟失時機、上下文或對話自然節奏的可能。開發者往往要負責協調這些環節，包括當有人打斷、停頓或改變話題時該如何處理。

GPT‑Live‑1 在單一模型中同時處理聽與説，簡化了語音層。它能在打斷和確認應答發生時即時響應，同時將更深層的推理交給後端處理。這讓對話在工作於後台進行的同時得以持續。

“與我們此前的級聯式構建相比，GPT‑Live‑1 將我們的代碼庫簡化了 80%，並移除了 23K 行代碼。這實現了自然、實時的患者對話，並讓我們的團隊得以騰出手來改進從預約掛號到就醫導航的體驗。”

——Tony Stoyanov，聯合創始人兼 CTO

開發者可選擇對話背後的模型、工具和智能體框架。例如，他們可以將 GPT‑Live‑1 與 Luna 這樣的模型搭配，用於排程或訂單更新等高併發任務，並使用 Astra 這樣的模型處理需要推理的複雜客户問題。這種靈活性讓開發者能夠為每項任務匹配相應的推理深度、速度和成本。

GPT‑Live‑1 原生提供 ASR 轉寫文本和響應文本。它還具備出色的字母數字理解能力，並支持關鍵詞偏置。儘管 GPT‑Live‑1 並非基於輪次的模型，但它原生支持輪次檢測，因此開發者仍可圍繞明確的輪次邊界進行構建。
