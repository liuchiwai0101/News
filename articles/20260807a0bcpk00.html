大家好，我是程序員晚楓。

睡前我順手打開OpenAI的主頁看看有沒有更新，結果還真有重磅消息。

沒有新模型，沒有跑分，沒有“再見了某某行業”。頁面只說了一件事：給 AI 智能體的插件（**Agent Plugins**），規定一種大家都能看懂的包裝方式。

但我把參與名單看完，還是愣了一下。

**Amazon、Cursor、Microsoft、OpenAI 和 Vercel 的维护者，正在一起推动 Agent Plugins 这套开放标准。**

**如果它真的被廣泛採用，未來一個插件可能不必爲 Codex、Cursor、GitHub Copilot 各做一遍。AI 插件正在等自己的“USB-C 接口”。**

*圖片來源：Agent Plugins 官方網站*

一個插件就可以在所有 AI 智能體上用

你是不是也有這種煩惱？

現在每家 AI 智能體都有自己的插件體系。Codex、Cursor、GitHub Copilot、Kiro，看起來都能安裝技能、連接外部服務，但目錄放哪裏、配置怎麼寫、哪些部分能被識別，並不完全相同。

對普通人來說，這種區別很像買了五臺電器，結果收到五種插頭。

東西都能用，但換一臺設備，就要重新找轉接頭。最忙的不是 AI，而是那個四處複製文件的人。

Agent Plugins 想做的事情很剋制：**先規定一個插件最小應該長什麼樣。**

每個插件都要有一張“身份證”，告訴客戶端它叫什麼、採用哪個版本；裏面可以放教 AI 怎麼做事的技能，也可以放連接外部工具和數據的 MCP 服務。某一家產品想增加自己的獨有能力，也可以放進單獨的擴展區，其他產品看不懂就忽略，不影響公共部分。

官網把這叫作“可移植的最低標準”。我覺得這個詞特別準確。

它沒有要求所有產品長得一樣，也不管每家商店怎麼安裝、怎麼收費、怎麼彈權限提醒。它只負責讓大家收到同一個包裹時，至少知道標籤在哪、說明書在哪、工具放在哪。

目前公開的是 **Agent Plugins 1.0.0**。官網把規範狀態標爲 **Working Draft，也就是工作草案**。

所以它已經是一份可以實現的正式版本，但還不是刻在石頭上的行業終局。坦率地講，現在就喊“所有 AI 插件徹底統一”，跟裝修剛打完地基就開始收婚禮份子錢差不多，氣氛到了，房子還沒封頂。

真正值錢的，是讓AI能力跟着人走

很多朋友可能不知道，一個 AI 智能體能不能幹好活，不只取決於它背後的模型。

我一直覺得，模型更像一個聰明的大腦。但只有大腦，沒有工作方法，也沒有可以動手的工具，它最多是坐在會議室裏給建議。

這裏順手把三個容易混在一起的概念講明白。

Skill教它怎麼做，MCP讓它真的能做

**Skill，也就是技能，像一份經過驗證的工作手冊。**

它會告訴 AI，什麼時候應該使用這項能力，要按什麼步驟做，有哪些坑不能踩。像公衆號寫作規範、合同檢查流程、公司內部發布清單，都可以被整理成技能。

**MCP 更像一套通用工具接口。**

它讓 AI 可以在得到授權後讀取資料、查詢系統或者執行操作。一個負責教方法，一個負責把手伸到真實世界裏幹活。

而 Plugin，就是把這些東西裝進同一個行李箱，再貼上一張統一託運標籤。

這個設計的“啊哈時刻”就在這裏：**標準沒有試圖統一所有 AI 的大腦，它先統一大腦隨身攜帶的經驗和工具。**

模型今天用 Codex，明天換 Cursor，後天團隊決定使用 GitHub Copilot。如果技能和工具可以跟着走，用戶積累下來的就不再只是某個平臺裏的幾段聊天記錄，而是一套能搬家的工作能力。

你喜歡哪個 AI，可以繼續用哪個。你的能力包，不必被一起扣在裏面。

先別急着喊大一統，它還缺最難的一半

看到這裏，可能有小夥伴納悶：以後是不是隨便下載一個插件，Codex、Cursor、Copilot 都能安全使用？

還真不能這麼理解。

Agent Plugins 1.0.0 目前只統一兩類公共組件：Skills 和 MCP 服務。插件的分發、安裝、更新、權限提示、用戶界面，仍然由各家客戶端自己決定。

這幾件事可不是邊角料。

插件既能教 AI 做事，又可能讓它連接文件、賬號和外部服務。一個來路不明的插件，危險的地方不在於“回答錯一道題”，而在於它可能拿着你給的鑰匙，認真執行了一份有問題的說明書。

所以我自己的判斷是：**Agent Plugins 解決了可移植性問題，但還沒有替用戶解決信任問題。**

這也是爲什麼它現在更像 USB-C 的接口標準，而不是一個已經審覈好所有應用的手機商店。接口統一之後，劣質充電器仍然是劣質充電器。能插進去，不代表應該插進去。

回到 Agent Plugins 這塊，我是真的覺得它會火。

不是因爲今天多了一個新名詞，而是 AI 智能體終於開始面對一個成熟生態遲早要回答的問題：**我們積累的能力，到底屬於某個平臺，還是應該屬於我們自己？**

過去大家爭的是誰的模型更聰明。下一階段，大家還會爭誰能讓用戶帶着自己的技能、工具和工作方法自由遷移。

接口只是第一步。

但很多真正改變行業的事情，最開始看起來，也只是一張很無聊的接口說明書。
