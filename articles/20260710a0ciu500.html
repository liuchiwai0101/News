微軟主導的 TypeScript 7.0 正式發佈首個穩定版本。得益於使用 Go 語言對編譯器進行徹底重寫，新版帶來了數量級的性能提升。

這是自啓動實驗性原生 Go 實現以來，首個包含基於 Go 的編譯器重寫的穩定版本。微軟首席產品經理 Daniel Rosenwasser 表示，TypeScript 7 引入了原生代碼速度、共享內存多線程及多項新優化，通常在完整構建中可實現 8 到 12 倍的速度提升。

此次重寫顯著縮短了文件打開、代碼搜索及自動補全的響應時間。值得注意的是，這種加速主要作用於開發階段，而非部署階段。過去常被歸咎於文本編輯器的延遲，實則多由 TypeScript Language Server（語言服務器）的性能瓶頸導致。

JavaScript 已難勝任

TypeScript 團隊去年便着手解決性能瓶頸。TypeScript 創始人 Anders Hejlsberg 宣佈，語言服務器的所有組件均需從頭重寫。Hejlsberg 指出，從最初由 V8 引擎執行的 JavaScript 編譯器移植到原生代碼，旨在獲取 10 倍的提速，其中一半源於原生代碼，另一半得益於共享內存併發能力。

此前，大型項目開發者深受緩慢的語言服務器困擾。以 Slack 爲例，其開發人員曾因本地類型檢查過慢，被迫將任務移交持續集成服務器。隨着 TypeScript 7 的發佈，Slack 開發人員已可再次在本地完成完整的類型檢查。

基準測試數據顯示了顯著的性能飛躍：在編譯擁有 230 萬行代碼的 VS Code 時，TypeScript 6 耗時 125 秒，而 TypeScript 7 僅耗時 10.6 秒，提升達 11.9 倍。此外，TypeScript 7 在處理其他大型代碼庫時也表現優異：Sentry（190 萬行代碼）耗時 15.7 秒，Bluesky（62.8 萬行代碼）耗時 2.8 秒，Playwright（52.8 萬行代碼）耗時 1.47 秒。

爲何選擇 Go

儘管微軟擁有 C# 且行業青睞 Rust，團隊最終仍選擇 Go 進行重寫。Go 由 Google 工程師創建，以簡化分佈式應用開發著稱，並在雲原生社區（如 Kubernetes）中佔據主導地位。

Hejlsberg 解釋稱，Go 是能提供跨平臺完整原生代碼支持的最低級別語言，且在併發處理上表現出色。TypeScript 開發團隊負責人 Ryan Cavanaugh 補充指出，Go 語法與 JavaScript 高度相似，便於人員理解和機器遷移，這對於仍需維護數年的舊 JS 服務器代碼至關重要。

此外，Go 在內存分配和圖遍歷方面優勢明顯。對於大多數編譯過程，TypeScript 可關閉 Go 的垃圾回收器，從而大幅降低代碼庫複雜性和運行時成本。Go 在處理複雜語法樹時的效率，也使其能更好地理解錯綜複雜的代碼結構。

面向未來的智能體優勢

前 Google Go 產品負責人 Steve Francia 指出，Go 還爲 TypeScript 帶來了構建時間、依賴管理、錯誤反饋和貢獻者流失率方面的優勢。這些因素不僅影響開發者體驗，更關乎未來自動化智能體的效率。

Francia 認爲，緩慢的構建、損壞的依賴解析及薄弱的錯誤反饋會阻礙迭代，而生態系統的變化可能導致智能體知識失效。他強調，在開發循環中，關鍵問題並非“哪種語言最容易編寫”，而是“哪種語言最容易編寫、審查和發佈”。正是 Go 的這些人性化特質，使其成爲推動 TypeScript 飛速發展的理想選擇。
