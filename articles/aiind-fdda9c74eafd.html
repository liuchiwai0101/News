Agent 越用越多，企業為何仍不夠 AI Native？

正文

當 Agent 真正進入企業流程，哪些工作可以交給 AI ？50 + 實戰案例揭曉答案！

AI 正在從回答問題的輔助工具，走向理解目標、調用系統、完成任務的工作承擔者。當 Agent 真正進入企業流程，問題不再是 “如何把 AI 做出來”，而是哪些工作可以交給 AI、結果如何驗收、權限、成本與風險如何收住。隨着大模型向推理、工具調用、多模態和長任務延伸，開發重心正從單次調用轉向上下文、工具、執行環境與反饋迴路的設計，Coding Agent 也從代碼補全演進為能理解代碼庫、運行測試、完成複雜任務的工程協作者。OpenAI、Google Cloud、Anthropic 的最新實踐共同指向一個結論：模型決定 Agent 能做什麼，工程決定它能否真正進入生產、創造價值。

在這一背景下， 2026 年 AICon 人工智能開發與應用大會 · 北京站 正式啓動。本次大會將於 12 月 18–19 日 ，在北京新雲南皇冠假日酒店舉辦。本屆大會以 探索 A 應用邊界 為主題，設置 13 大技術專題，覆蓋 大模型後訓練、推理優化、Agent 工程、知識工程、智能體評測與安全、自進化系統、AI 軟件交付、原生架構及組織變革 等核心方向，匯聚一線技術專家，深入分享 AI 技術突破與企業規模化落地的真實實踐。

騰訊資深研發工程師陳偲穎已確認出席 “ Agentic Software Engineering｜從代碼生成到軟件交付 ” 專題，並發表題為 《 AI Native 企業研發工具鏈：架構重構與持續演進 》 的主題分享。當 Agent 開始參與企業業務研發，承擔需求拆解、業務配置與實現、質量校驗等任務，工具鏈要解決的問題也隨之變化：單次業務系統操作成功，如何保證整條研發任務鏈路正確？長任務中的業務狀態偏差和上下文失真，如何發現並恢復？業務操作權限如何隨風險受控開放？一次任務中的修正，又如何成為下一次可複用的經驗？這些問題涉及業務系統接口、Agent 運行時和治理機制，需要在平台層統一處理。

陳偲穎團隊的實踐從配置驅動轉向意圖驅動：用户表達業務目標，系統結合專家知識生成方案，通過低代碼 Harness 編排執行。工具主要封裝企業業務系統的操作能力，研發工具鏈將這些能力組織成可執行、可校驗的任務流程。底座圍繞四條主線建設：業務操作工具協議化與能力原子化、Agent 運行時工程化、上下文工程平台化，以及摩擦信號驅動的改進閉環。

這套架構以“AI 的操作系統”為定位，重點是減少任務執行中的不確定性。輸入側通過知識、規則和上下文收斂方案；輸出側讓用户看懂執行過程、判斷結果是否可信，並能直接修改。權限、審計、評測和人工審批貫穿其中，支持 Agent 在受控範圍內逐步承擔更多工作。

目前已覆蓋需求拆解、業務配置與實現、質量校驗等核心鏈路。本次分享將結合實際案例，討論業務操作工具的粒度、低代碼 Harness、上下文治理與人機分工的設計取捨，以及如何把執行中的失敗和用户修正沉澱為平台規則與可複用的經驗，讓同類任務少踩一次坑。

陳偲穎，騰訊資深研發工程師，曾任職於多家全球知名科技公司，專注營銷活動技術領域，持有多項技術專利。2023 年起聚焦 LLM 與工程效能的深度融合，作為核心負責人主導某互聯網大廠低代碼平台 AI 能力建設。成功完成多年數據資產的價值轉化，將人工經驗沉澱提煉為知識複利方法論，構建"LLM + 低代碼"雙驅動的智能研發體系。打通"一句話需求到上線"的端到端智能化鏈路，推動承載數百款業務的平台完成從傳統開發模式向 AI 原生開發範式的演進升級。

2. 架構：以“AI 的操作系統”為定位，圍繞任務降熵建設底座

通過統一工具協議封裝企業業務系統的操作能力，按業務語義劃分邊界，保持能力正交，並明確重試與冪等約束。一個工具對應一項能説清楚、能校驗結果的業務操作

工具描述採用“動作 / 輸入 / 輸出 / 用例”四段式，寫清業務對象、操作前置條件、影響範圍與結果狀態，顯式聲明副作用

業務操作粒度不宜一味拆細：過粗會隱藏業務判斷和變更範圍，過細又會增加跨系統調用、上下文負擔和中間失敗點

Harness 統一承接業務操作工具召回、Prompt 組裝、任務狀態機、Hooks、執行觀測與回放，避免每個業務場景重複搭建執行邏輯

用低代碼方式組織任務執行與擴展點配置，降低業務團隊組合能力、接入 Agent 的成本

打通低代碼流程與代碼實現，兼顧業務側的易用性與研發側的靈活性

討論取捨：哪些能力由平台統一約束，哪些允許業務擴展；低代碼覆蓋到哪裏，什麼時候需要進入代碼層

專家知識庫為意圖理解和方案生成提供業務依據；規則支持按業務、渠道和場景配置，在任務各環節引導執行

上下文管理優先保證信噪比，圍繞當前任務組織業務規則、配置與系統狀態，通過分層緩存、結構化切分與上下文預算管理控制信息規模

區分當前任務狀態、業務規則與個人記憶，避免過時的業務配置或個人偏好被當成當前系統事實
