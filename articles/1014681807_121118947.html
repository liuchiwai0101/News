用 Claude Code 还是 Codex?

爲什麼 Claude Code 不像 GPT-5.4那樣廢話連篇，爲什麼它寫的代碼比較剋制？

除了其本身的工程設計之外，很重要的原因就是其精妙的系統提示詞的設計。

有人專門維護了 Claude Code 所有歷史版本的系統提示詞，通過這套系統提示詞，可以清晰地看到Claude Code 的設計理念。

提示词地址： https://cchistory.mariozechner.at/

① 角色定義（最頂層）

原文（精簡之後的）

You are a Claude agent... helps users with software engineering tasks.

你是一個 Claude 代理，主要幫助用戶完成軟件工程相關任務。

作用

這是**身份鎖定**，它決定了模型：

- 優先“做代碼相關事情”

- 而不是泛聊天 / 寫作文

影響非常大，後面所有行爲都圍繞“工程助手”展開。

② 安全邊界（紅線）

原文

Assist with authorized security testing... Refuse destructive techniques...

允許：授權的安全測試、防禦、CTF

拒絕：破壞性攻擊、DoS、大規模攻擊、供應鏈攻擊等

作用

這是**法律/安全護欄**

控制模型：

- 不會變成黑客工具

- 但保留“安全研究”能力

屬於強約束（hard rule）

③ 輸出規則（你看到的內容）

原文

All text you output... use markdown...

你輸出的所有內容都會直接展示給用戶，可以用 markdown。

作用

明確“沒有隱藏層”

模型不能：

- 假裝有內部狀態

- 輸出不可見內容

④ 工程任務默認理解

原文

If unclear, interpret as software engineering tasks...

如果用戶說得不清楚，要按“工程任務”來理解。

作用

這是**自動補全意圖**

比如：

用户说：改 methodName

模型理解：去代碼裏改，而不是解釋命名

⑤ 不要改沒讀過的代碼（關鍵規則）

原文

Do not propose changes to code you haven't read.

沒讀過的代碼，不要改。

作用

防止“幻覺式修改”

強制流程：

Code

Read → Understand → Edit

這是代碼代理質量的核心之一。

⑥ 不要亂建文件

原文

Do not create files unless absolutely necessary.

除非必要，不要新建文件。

作用

防止代碼庫污染

AI 常見問題：

- 到處新建 helper 文件

- 生成重複結構

這條在壓制這種行爲。

⑦ 避免過度工程（非常重要）

原文

Avoid over-engineering...

不要過度設計：

- 不要加沒要求的功能

- 不要提前抽象

- 不要做“未來優化”

作用

這是**壓制 AI 發散能力**

AI天然傾向：

- 重構

- 優化

- 抽象

這段在強行限制它：

**只做“剛好夠用”的修改**

⑧ 安全編碼要求

原文

Be careful not to introduce vulnerabilities...

不要引入安全漏洞（XSS、SQL注入等）。

作用

防止生成“能跑但危險”的代碼

⑨ 不要做多餘驗證

原文

Don't add error handling... unless needed.

不要亂加：

- 錯誤處理

- fallback

- validation

作用

這是反直覺但很重要

AI常見問題：

- 到处 try/catch

- 加一堆 if 判斷

這裏直接限制：

**只在邊界加驗證（用戶輸入 / API）**

⑩ 高風險操作必須確認

原文

Destructive operations... ask for confirmation.

危險操作必須先問用戶，比如：

- 刪除文件

- force push

- 改 CI

作用

控制“執行權限”

把模型變成：

- 默認謹慎

- 不自作主張

⑪ 工具使用規則（最核心工程能力）

原文

Do NOT use Bash when a dedicated tool exists...

有專用工具就不要用 Bash：

作用

這是**架構級設計**

讓代理：

- 操作可審計

- 權限可控

- 行爲結構化

而不是 bash亂跑

⑫ 並行工具調用

原文

Make tool calls in parallel when possible.

能並行就並行調用工具。

作用

提升性能

讓代理更像：

- 多線程工程師

而不是一步一步慢慢查

⑬ TodoWrite（任务拆解）

原文

Break down work with TodoWrite...

把任務拆成步驟，並逐個完成。

作用

防止 AI“中途迷路”

強制：

Code

計劃 → 執行 → 標記完成

⑭ Agent 子代理機制

原文

Launch specialized agents...

可以啓動子代理（Explore / Plan 等）做複雜任務。

作用

這是**多代理架構**

主代理：

- 做決策

子代理：

- 做探索 / 規劃

⑮ 輸出風格限制

原文

Be short and concise.

要簡短直接。

作用

抑制“廢話 AI”

⑯ Git 操作規範（非常細）

原文

NEVER update git config... NEVER force push...

Git 規則：

- 不要強推

- 不要 reset --hard

- 不要 amend（除非要求）

作用

防止“毀倉庫”

這是實際工程中最危險的地方。

⑰ Commit 流程（標準化）

原文

Run git status, diff, log...

提交前必須：

- 1看狀態

- 2看 diff

- 3看歷史

作用

让 commit：

- 有上下文

- 有風格一致性

⑱ PR 流程（完整工作流）

原文

gh pr create...

創建 PR 要：

- 分析所有 commit

- 写 summary

- 写 test plan

作用

讓 AI 不只是寫代碼，而是參與完整開發流程

⑲ Memory 系統（長期記憶）

原文

persistent memory system...

有一個本地記憶系統，存：

- 用戶信息

- 偏好

- 項目背景

- 外部資源

作用

讓代理“越用越懂你”

而不是每次重來。

⑳ Memory 分类

原文

user / feedback / project / reference

四類記憶：

- user：用戶是誰

- feedback：你喜歡怎麼合作

- project：項目背景

- reference：外部链接

作用

結構化長期記憶
