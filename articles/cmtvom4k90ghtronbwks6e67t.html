Shopify 宣佈從 React Native 全面遷回 Swift 和 Kotlin 原生開發

正文

原生開發如今已成為 Shopify 移動端的未來

我們在 2020 年決定全力投入 React Native，而這一押注極其成功。我們只需構建一次功能就節省了大量時間，讓沒有移動端背景的開發者也能為我們的應用做出貢獻，並讓我們擺脱了不斷追趕功能對齊的困境。

2025 年 1 月，我曾寫道，React Native 的未來一片光明，Shopify 計劃持續投入其中。基於我們當時的認知，這是事實。React Native 當時對我們運行良好，如今它依然是一個出色的框架。但自那以後，編碼模型變得顯著更強，對於我們的應用和團隊而言，用 Swift 和 Kotlin 構建同樣的功能不再像過去那樣代價高昂。

我們不會僅僅因為某個決定當時取得了成功就固守它。當某個核心假設發生變化時，我們願意回過頭去追問它是否仍是正確的選擇。LLM 改變了我們 2020 年決策背後的一個核心假設，因此我們從第一性原理出發重新評估了我們的移動端技術棧。

我們的發現讓我們重新回到了原生開發。

為何要切回原生開發

我們在 2020 年決定從原生開發轉向 React Native，原因有三：

  • 不再把同樣的功能構建兩次
  • 讓開發者能夠跨技術棧工作
  • 少花時間追趕功能對齊，多花時間交付價值

React Native 持續帶來了這些收益。我們發現自己投入了大量時間和資源來優化性能、改進 React Native 的關鍵基礎領域，並跟進框架更新和外部依賴，但這些是可以接受的取捨。使用 React Native 帶來的收益，遠遠超過了我們在這些方面不得不做出的投入。

Shopify 自 2021 年起就開始使用 LLM 來構建軟件（比 ChatGPT 還早一年！）。最初，我們用它們來實現功能、調查和修復 bug，以及審查代碼。隨着模型不斷進步，我們放心交給它們承擔的工作複雜度也隨之提升。到 2025 年底，它們不再只是幫我們更快地寫代碼。它們已經能夠讓我們質疑：把軟件構建兩遍，是否還意味着要做兩倍的工作。

我們決定重新評估我們的移動技術棧，並開始做原型驗證，看看我們的技術選型是否依然站得住腳。我們用 LLM 以 Swift 和 Kotlin 重建了我們最大幾款應用中的若干核心部分，結果之好令我們驚訝。智能體：

  • 能夠以 iOS 版本為參照，在 Android 上實現某個功能，反之亦然
  • 幫助開發者快速上手，並在自己主技術棧之外的領域有效貢獻
  • 通過共享的規格説明、測試和審查檢查點，大幅降低了維持平台間功能對齊的成本

原生開發仍然意味着要在兩個平台上構建和維護軟件，這項成本並未消失。改變之處在於，智能體現在能夠完成足夠多的實現、轉換、測試和審查工作，使其不再是 2020 年那樣的決定性因素。

React Native 應用可以很快。我們的應用就是如此。我們做出這一改變，是因為智能體降低了共享實現帶來的優勢，而為每個平台單獨構建的優勢依然存在。原生開發讓我們更貼近平台能力和第一方工具，代碼與平台之間的框架和依賴層更少。

我們 React Native 開源庫的未來

在我們介紹遷移方式之前，我們希望確保這次過渡乾淨利落。從一開始，我們就想回饋 React Native，讓它變得更好。我們發佈的開源庫已成為各自類別中的首選。我們感謝社區的熱烈反響，並承諾確保這是一次平穩、無意外的過渡。

React Native Skia

Shopify 將繼續贊助該項目直至 2026 年底，此後 William Candillon 將繼續推進。他將在未來幾個月內 fork 該倉庫，並以新名稱開始發佈這個庫。過渡完成後，原倉庫將被歸檔。我們會沿途發佈更新，讓每個人都有充足的時間遷移。如果你的應用依賴這個庫，請考慮贊助它。

FlashList

這個庫每週約有 200 萬次下載，已成為 React Native 中渲染高性能列表的默認方式。鑑於它對整個生態的重要性，Shopify 將繼續修復破壞兼容性的關鍵問題。我們目前正在與多家公司商討接手 FlashList 的長期維護工作。如果你有興趣，可以在這裏聯繫我。

Restyle

Restyle 的用户群比我們其他庫要小，因此我們將歸檔這個倉庫。我們會讓它繼續運行到 2026 年底，之後停止維護。歡迎任何人 fork 並接手推進，如果有團隊願意接手，我們會協助完成交接。

我們如何遷移

Shopify 有幾款大型應用（Shopify、Shop、Point of Sale、Inbox）。全球數百萬商家和買家每天都依賴它們來謀生，並從他們喜愛的品牌購買心儀的產品。

我們曾在逐步遷移到原生（棕地）與從零重建（綠地）之間反覆權衡。過去我們遷移到 React Native 時，對一些最大的應用選擇了棕地方式，因為重寫它們需要數年時間，而且在重寫進行期間我們不得不停止發佈新功能。

然而，這一次全新開發（greenfield）成為了明顯的贏家，原因如下：

  • 大語言模型擅長以 React Native 版本為參照，用 Swift 和 Kotlin 構建功能
  • 它給了我們一張白紙，讓我們能夠以最佳方式重建，不受此前任何約束
  • 我們的原型表明，我們重建這些應用的速度可以比在編碼智能體出現之前快得多

Shop 應用經常在應用商店購物類榜單中名列前茅，是第一個被遷移的。在 AI 的輔助下，團隊僅用 12 周就從概念驗證走到了完全重建的原生應用併發布到應用商店。我們在這裏深入撰寫了這次遷移。

Shopify 應用的遷移（我們最大的應用，擁有 300+ 屏幕、主屏幕與鎖屏小組件、Apple Watch 應用、複雜功能、Siri Shortcuts 等）也在進行中，將於今年晚些時候發佈。我們其餘的應用也將很快遷移。

防止粗製濫造

把大語言模型直接指向 React Native 代碼庫，試圖一次性在原生端實現相同功能，這很誘人，但行不通。即使你讓它事先儘可能多地收集信息，將其固化為規格説明、任務文件，然後再實現，最終你得到的仍是大量無法維護、無法發佈的代碼。

為了解決這個問題，我們構建了一個名為 Helix 的系統，它採用了一種更為漸進的方式。它不指望第一次輸出就是正確的，而是構建了一個循環：不完美的嘗試根本無法向前推進，直到它變成一個好結果。

開發者將 Helix 指向一個屏幕。Helix 讀取 React Native 代碼，並提出一系列檢查點（將工作切分成小的、有序的片段），這些檢查點可以在幾分鐘內完成審查。然後，它逐個檢查點地構建：每一個檢查點都必須通過測試證明其行為，在視覺審查中與運行中的應用保持一致，經受住兩名對抗性代碼審查員的檢驗，並在提交、開啓下一個檢查點之前獲得人工的點頭認可。每次審查的反饋都會被記住，因此隨着遷移的推進，這個循環會變得更加自主。

Helix 使用 Swift 和 Kotlin 重建 Shopify 移動應用中的一個屏幕

這種方法效果極佳，讓我們能夠以極短的時間重建我們的應用。

實現快速反饋循環

對模擬器的智能體控制一直是個瓶頸。我們發現自己不斷地照看它們，因為它們無法可靠地構建、測試和迭代。我們構建了工具，讓智能體能夠自主復現 bug、修復它們並驗證修復，但它既慢又脆弱。React Native 的熱模塊重載有助於緩解這一情況，但並未解決它，因為模擬器控制本身就很慢。這主要是因為依賴無障礙樹或截圖來獲取應用狀態、執行操作並驗證結果。智能體可以在幾秒內完成代碼修改，但測試輸出卻要花上幾分鐘。這使得迭代極其緩慢且依賴人工。無論模型多好，如果它無法快速測試自己的工作，那都無濟於事，而這在移動端尤其困難。

我們正在通過設計同時服務於人類和智能體的應用架構來解決這個問題。這裏的核心原則是，業務邏輯應完全與 UI 解耦，並能夠在桌面端無頭運行。然後我們通過 CLI 將其提供給智能體，讓它們能夠在毫秒級而非分鐘級進行迭代，而無需涉及模擬器。

使用 CLI 瀏覽應用並執行操作

CLI 讓智能體能夠檢查應用狀態、在不同板塊之間導航並執行操作，全程無需觸碰 UI。這實現了極快的反饋循環，並讓智能體能夠一次自主工作數小時。

當需要與模擬器交互時，CLI 可以通過遠程模式連接到它們，並通過命令驅動 UI，而無需檢查佈局或無障礙樹。這帶來了極快的性能和端到端測試。

接下來是什麼

我們將在整個過程中藉助 AI，把所有移動應用遷移到 Swift 和 Kotlin。Shop 已經作為完全原生應用發佈，Shopify 應用正在進行中，其餘的也將很快跟進。我們推進得很快，但並不是靠降低標準。每一次重建都必須達到或超越人們如今所期望的性能、穩定性、無障礙性和產品質量。這不僅僅是把同樣的應用用不同語言重寫一遍。我們重建它們，是為了讓人類和智能體都能快速理解、測試和修改它們。

遷移並不是終點線。成功意味着我們的團隊能夠比以往更快地為商家和買家交付更好的體驗。我們將通過產品迭代速度、應用質量，以及智能體能夠自主完成多少工作來衡量這一點。

我們會分享一路上的所學，包括對 Helix、我們面向智能體的架構，以及我們如何用智能體構建移動應用的深入探討。我們曾坦誠分享從 React Native 中學到的東西，我們也打算對這次轉型同樣坦誠。

這是我們承接過的最具雄心的移動工程項目之一。如果你想幫助打造 Shopify 下一代移動應用，我們正在招聘移動工程師、基礎設施工程師，以及在 AI 與軟件工程交叉領域工作的開發者。

致謝

原生開發對現在的 Shopify 來説是正確選擇，但 React Native 在 2020 年對 Shopify 來説也是正確選擇。那次成功之所以成為可能，全靠那些讓它運轉起來的人。
