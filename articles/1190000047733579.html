我們用CRA（create-react-app）寫的React應用，是純**客戶端渲染（CSR）**。服務器只返回一個空

和一堆JS，瀏覽器先白屏，下載JS、執行完才顯示內容。問題：

- 首屏慢：JS越大越慢。

- SEO差：爬蟲抓不到內容，因爲要等JS執行。

- 社交分享卡片難看：分享鏈接時，預覽圖標題描述都是空的。

**Next.js**是React的服務端渲染框架。它能在服務器端提前生成HTML，用戶直接看到內容，然後再“激活”交互。而且它還能靜態生成、服務端渲染、甚至當後端用。今天我們就來上手Next.js，解決“白屏+SEO”兩大痛點。

一、Next.js解決了什麼？一張圖看懂

- **CSR（CRA）**：瀏覽器請求 → 返回空HTML → 下載JS → 執行 → 顯示內容。用戶等得花兒都謝了。

- **SSR（Next.js）**：瀏覽器請求 → 服務器執行React，生成完整HTML → 返回給瀏覽器 → 顯示內容 → 下載JS綁定事件。用戶立刻看到內容，體驗好。

- **SSG（靜態生成）**：構建時就生成HTML，訪問時直接返回，最快。

Next.js同時支持SSR、SSG、CSR，你能根據頁面特性選擇不同渲染方式。

二、5分鐘上手Next.js

npx create-next-app@latest my-app
cd my-app
npm run dev

打开http://localhost:3000。目录结构：

- `pages/`：路由系统，- `pages/index.js`就是首页，- `pages/about.js`就是- `/about`。

- `public/`：静态资源。

- `styles/`：CSS。

三、路由：不用react-router，文件即路由

在pages下創建文件就是路由。

- `pages/index.js`→- `/`

- `pages/about.js`→- `/about`

- `pages/blog/[slug].js`→- `/blog/hello-world`（动态路由）

頁面鏈接用Link組件：

import Link from 'next/link';
export default function Home() {
  return (
    <Link href="/about">关于我们</Link>
  );
}

四、預渲染的三種模式

1. 靜態生成（SSG）：在構建時生成HTML

適用於博客文章、產品頁、幫助文檔等不常變的內容。速度最快，可放CDN。

// pages/blog/[id].js
export async function getStaticPaths() {
  // 告诉Next.js有哪些动态路径需要生成
  const paths = await fetchPosts().then(posts => posts.map(p => ({ params: { id: p.id } })));
  return { paths, fallback: false };
}
export async function getStaticProps({ params }) {
  const post = await fetchPost(params.id);
  return { props: { post } };
}
export default function Post({ post }) {
  return <div>{post.title}</div>;
}

構建時next build會生成每個文章的HTML。

2. 服務端渲染（SSR）：每次請求時在服務器生成HTML

適用於用戶個性化頁面、實時數據頁面。

// pages/profile.js
export async function getServerSideProps(context) {
  const user = await fetchUser(context.req.cookies.token);
  return { props: { user } };
}
export default function Profile({ user }) {
  return <div>欢迎 {user.name}</div>;
}

每次訪問都會調用getServerSideProps，所以可以獲取請求上下文（cookies、headers等）。

3. 客戶端渲染（CSR）：就跟普通React一樣

適用於儀表盤、後臺管理等不需要SEO的部分。

import { useEffect, useState } from 'react';
export default function Dashboard() {
  const [data, setData] = useState(null);
  useEffect(() => {
    fetch('/api/dashboard').then(r => r.json()).then(setData);
  }, []);
  if (!data) return <div>加载中...</div>;
  return <div>{data.chart}</div>;
}

五、API Routes：把你的Next.js當後端用

在pages/api下創建文件，就能寫服務端代碼，相當於一個小型Node後端。

// pages/api/hello.js
export default function handler(req, res) {
  res.status(200).json({ message: 'Hello Next.js!' });
}

訪問/api/hello得到JSON。你可以在這裏連接數據庫、驗證請求、調用第三方API。這樣就不需要單獨起一個後端服務了。

六、內置優化：你啥都沒幹，它幫你做了

- **图片优化**：用- `next/image`自动压缩、懒加载、生成webp。- `import Image from 'next/image'; `

- **字體優化**：自動內聯CSS，減少佈局偏移。

- **Script优化**：- `next/script`控制加载时机（beforeInteractive、afterInteractive、lazyOnload）。

- **靜態資源緩存**：會爲文件生成hash，永久緩存。

七、實戰：從CRA遷移到Next.js的收益

假設一個博客站：

- CRA：首屏加載時間3.5秒（白屏1.5秒+JS執行2秒），谷歌搜不到內容。

- Next.js SSG：首屏時間0.5秒（直接返回HTML），谷歌爬蟲抓取完整文章，分享卡片完美顯示。

用戶打開頁面立刻看到文章，體驗提升了7倍，SEO也來了。

八、總結：別猶豫，新項目就用Next.js

- 首屏快：SSR/SSG預渲染。

- SEO好：內容直接寫在HTML裏。

- 開發爽：文件路由、API Routes、內置優化。

- 零配置：比CRA還簡單。

如果你還在用CRA寫非純後臺的系統，強烈建議試試Next.js。你的用戶會感謝你，老闆也會誇你。
