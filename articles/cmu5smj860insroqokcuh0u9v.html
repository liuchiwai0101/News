引言#

今天，我們正式推出Qwen3.8-Omni-Flash，這是我們下一代原生全模態模型。其核心目標是強化智能體在真實生產力場景中的能力，推動全模態模型從“理解全模態內容”邁向“規劃任務、調用工具並完成創作工作”。在編碼、文本類知識工作和 GUI 操作等通用智能體能力的基礎上，Qwen3.8-Omni-Flash 進一步拓展了以音頻和視頻為核心的智能體應用，在視頻剪輯、音樂視頻創作、影片製作與解説、音視頻摘要以及實時對話等工作流中均取得了出色表現。

Qwen3.8-Omni-Flash 支持 1M token 的上下文窗口，同時保持與同等規模純文本模型相當的文本性能，並在全模態能力上實現顯著提升。在 29 項評測1中，其平均得分較 Qwen3.5-Omni-Plus 提升超過 25%；每小時音頻輸入的 API 價格下降超過 98%，每小時音視頻輸入的價格下降超過 93%2。在音視頻智能體、編程和長時程任務方面，該模型在 WildClawBench-MM 上提升 36.5 分，在 AgenticVBench 上提升 22.3 分，同時在 UniClawBench 上取得 69.6 的強勁成績。其核心能力在長音頻與音視頻理解、音視頻推理、音視頻描述以及多説話人識別方面也有顯著提升。例如，它在 LongAudioSpan 上提升 8.3 分，在 OmniVideoBench 上提升 9.6 分；其 OmniCap-IF 的 CSR 和 ISR 分別提升 8.5 分和 14.1 分；其 AliMeeting 的 DER 和 cpWER 從 88.11 / 89.61 降至 3.35 / 17.18。通過擴展數據、上下文和智能體環境，Qwen3.8-Omni-Flash 實現了接近 Gemini 3.8 Flash 的音視頻性能，以及超越 Gemini 3.8 Flash 的整體音頻性能。這些進展也意味着，音頻和視頻正從感知輸入演變為智能體理解環境、進行推理和執行任務的核心媒介。

音頻和視頻是將智能體帶入真實世界生產力場景的重要媒介，但它們也帶來了一系列新的系統級挑戰。長音頻和長視頻在多輪推理中的存儲、傳輸和處理成本高昂；現有的智能體 harness 框架缺乏對這些模態的原生支持；而將全模態理解與端到端任務執行相連接的工作流仍處於早期階段。要應對這些挑戰，需要模型、harness 工具和運行時環境協同演進。

為應對這些挑戰，我們使用 Qwen3.8-Omni-Flash 來探索如何將源內容理解、任務規劃、工具執行與結果交付串聯成一條完整的流水線。它支持端到端、長時程的工作流，例如視頻剪輯、翻譯、影視解説和內容創作，推動 Omni 從音視頻理解邁向自主行動與任務完成。

為此，我們進一步擴展了 Qwen-MM-Plugins，為其加入面向長音頻和長視頻的按需感知、工具調用與工作流執行能力。我們還開源了 Qwen-Live Harness，作為面向持續、實時全模態交互的原生運行時。二者共同應對長時程工作流與實時交互，同時與模型一道持續拓展全模態智能體的能力。

長音頻與長視頻理解#

Qwen3.8-Omni-Flash 為長音頻與長視頻理解帶來了重大升級——從可控描述與智能體式證據收集，到理解會議並推進後續任務，最終到生成以視頻為核心的深度研究報告。它不僅僅是處理更長的內容，而是更精準地找到相關證據、更深入地進行推理、更高效地採取行動。

可控音視頻描述#

對於一段視頻應該如何描述，並不存在唯一的答案。內容創作優先考慮敍事，素材檢索聚焦於特定片段，而資產管理則依賴於結構。不同的應用需要不同的視頻描述。在 Qwen3.8-Omni-Flash 中，我們將視頻描述從回答"模型看到了什麼"升級為理解"用户想知道什麼"。用户可以自由指定主體、時間範圍、詳細程度和輸出格式。對於同一段視頻，模型可以提供概覽、定位關鍵片段，或者深入分析人物動作、鏡頭、燈光和聲音，並按需生成結構化結果。你定義看什麼、看多細，以及如何呈現。

智能體式長時音視頻理解#

對於長達數小時的視頻，傳統方法要求模型從頭到尾處理整個錄像，即便答案只出現在其中幾分鐘的畫面裏。原生 Qwen3.8-Omni-Flash 智能體從問題出發，自主決定觀看和收聽的內容，並通過多輪由粗到細的證據收集來定位關鍵信息。無需處理每一幀，它就能將有限的計算和 token 預算集中在相關片段上，從而實現更高效的長視頻理解。在 OmniVideoBench 上，智能體理解將準確率從 63.4 提升至 67.8，同時將 token 消耗從 145,736 降低至 79,117，降幅約為 45.7%。下表對比了靜態理解與智能體理解在 OmniVideoBench 上的準確率和 token 消耗：

長會議：從會議紀要到行動#

多參與者會議是最複雜的音視頻理解場景之一：發言者輪流發言並相互重疊，而身份、指代和討論主題不斷變化。Qwen3.8-Omni-Flash 跨音頻和視頻聯合識別發言者，並原生支持長達一小時的音視頻輸入。它能夠端到端地執行發言者分割、內容轉寫和身份對齊。給定一段完整的會議視頻和一項請求，該模型可以梳理參與者關係、生成會議紀要、識別行動事項並分析項目風險，利用視覺信息來消解音頻中的指代和實體歧義。結合智能體與工具使用，它還能根據會議需求發送郵件、整理任務，甚至開始編寫代碼——從理解會議邁向對會議採取行動。

利用音頻和視頻開展深度研究#

當用户帶着某個具體問題觀看視頻時，答案往往超出視頻本身。Qwen3.8-Omni-Flash 將用户的需求與視頻內容相結合，識別出值得深入探究的問題，整理關鍵素材，並在全網搜索多模態來源——包括圖像、視頻和文檔。隨後，它會生成一份以視頻為中心、圖文並茂的研究報告，幫助用户理解內容並解決實際問題。

例如，當用户遇到 Photoshop 頭髮摳圖邊緣出現色邊的問題時，該模型可以拆解教程步驟，研究 Multiply 和 Screen 混合模式背後的原理，比較其他邊緣修復技術，並説明哪種方法最適合用户的具體情況。

音視頻製作與編輯#

Qwen3.8-Omni-Flash 正將音視頻智能體帶入一個新階段：從理解聲音和圖像，到自主規劃、調用工具並交付成片，將全模態智能帶入專業音視頻內容製作工作流。

Music2MV#

在音樂視頻（MV）創作方面，Qwen3.8-Omni-Flash 能夠細緻理解用户所提供歌曲的結構、節奏、情緒、人聲以及器樂變化，為角色、場景和鏡頭的設計提供依據。它還能輸出帶時間戳的逐行歌詞，以對齊演唱、字幕和畫面。結合 Qwen-MM-Plugins 等創意工具，該模型支持從音樂理解、創意策劃到最終質量審核的完整工作流，展現出強大的音視頻理解、推理與創作能力。

長片影評解説#

為兩三個小時的全長電影製作解説視頻，往往需要反覆觀看影片並梳理劇情，隨後還要進行鏡頭挑選、腳本撰寫、配音、配樂和剪輯。這是一個複雜且耗時的過程。藉助基於 Qwen3.8-Omni-Flash 構建的智能體，用户只需提供一部電影並用一句話描述創作需求，即可完成長視頻理解、關鍵劇情提取、解説策劃、配音與配樂製作、剪輯、渲染以及最終質量審核。

該智能體還能智能地將原片對白與解説交錯穿插，自動調整語速和音量，使旁白、原聲、背景音樂與畫面自然融合，打造出更真實、更具沉浸感、更有電影質感的解説視頻。

從使用模型到優化模型#

真實世界的多模態應用往往復雜且對成本敏感，要求模型在質量、延遲、算力與部署成本之間取得平衡。

因此，針對特定場景定製更小的模型，是規模化部署應用的一條重要路徑。然而傳統工作流涉及數據構建、問題診斷、多輪訓練與評估，耗時且高度依賴人工專業知識。這一次，我們將 Qwen3.8-Omni-Flash 延伸到模型開發本身，探索一種新方法：由大模型驅動研發，而小模型服務於業務需求。

我們給 Qwen3.8-Omni-Flash 佈置了一項任務：在 12 小時內提升 Qwen2.5-Omni-3B 的四川方言語音識別能力，並交付一個可用的模型。它獨立選定了 WenetSpeech-Chuan 評測集，確定了評測標準，並建立了基線。隨後它直接聆聽音頻樣本，利用識別結果診斷問題，並構建有針對性的訓練數據。在連續四輪實驗中，該智能體創建了 3,413 條訓練樣本，根據評估反饋調整策略，保留有效的改進，並回滾不成功的嘗試。Qwen2.5-Omni-3B 在同一評測集上的字符錯誤率最終從 25.79% 降至 15.30%，相對降低約 40.7%。

這一實驗展示了模型演進的另一種可能：通用多模態模型理解數據、規劃實驗並推動迭代，而更小的模型則獲得面向特定應用的專業能力。智能體可以超越"用模型幫助解決實際業務問題"這一層面。

音視頻信息壓縮#

音頻和視頻承載着豐富的信息，但其線性、非結構化的形式使得檢索和複用變得困難。Qwen3.8-Omni-Flash 能夠理解聲音、視覺和時間線中的內容，通過智能體工作流提取信息、重組其結構並驗證結果。它將長視頻中的核心知識和實踐經驗轉化為更密集、更易於消費和複用的信息資產。

Video2Note#

為了將視頻知識轉化為結構化資源，我們在 Qwen-MM-Plugins 中開源了 Video2Note。藉助 Qwen3.8-Omni-Flash 對語音、視覺和流程的聯合理解能力，它能夠自動組織知識、拆解關鍵步驟、選取代表性幀，並生成圖文對應的 PDF 筆記。自動化審核與迭代修正進一步將數小時的視頻濃縮為清晰易讀、便於回顧的文檔。

Omni Skill Creator#

視頻不僅記錄了"如何做某件事"，還記錄了專家積累的實踐經驗。基於這一考慮，我們在 Qwen-MM-Plugins 中引入了 Omni Skill Creator 這一全新的開源能力。它可以從演示中提取標準操作流程（SOP），以執行可複用的自動化工作，或從專家指導中學習工具使用方法、決策標準和關鍵洞見。一次演示即可轉化為經過驗證和評估的智能體技能，從而基於全模態內容構建可複用、可分享的技能。

實時音視頻交互#

Qwen3.8-Omni-Flash 專為對完整音視頻內容的深度理解與創作而設計。針對連續、低延遲的交互場景，我們進一步推出 Qwen3.8-Omni-Flash-Realtime。它在接收實時音視頻流的同時進行感知與響應，並利用實時上下文調用工具、執行任務，將全模態能力從“理解一段內容”推進到“參與一場交互”。

實時口語練習#

口語沒有標準輸入。口音、元音與輔音的替換以及聲調偏差，都可能導致逐字轉寫的結果偏離原本要表達的含義。Qwen3.8-Omni-Flash-Realtime 對發音與語義進行聯合建模，能夠理解受口音影響的非標準表達，將其與正確的詞對齊，並實時生成標準發音示範。在多次練習輪次中，模型會結合新的音頻更新其判斷，在糾正影響理解的錯誤的同時，保留自然的節奏、語調與情感。

全模態空間音頻感知#

在真實空間中，聲音提供了視覺之外的另一條座標軸。Qwen3.8-Omni-Flash-Realtime 將空間聲音與視覺信息相結合，在感知障礙物、可通行區域以及場景變化的同時，持續判斷聲源的方向與距離，使其成為首個能夠通過聲音定位目標的全模態模型。

對於“過來這裏”或“去看看是什麼發出了那個聲音”這類指令，模型能夠從環境噪聲中分離出人聲和目標聲音，將其含義錨定在周圍空間中，並調用工具完成定位、搜索、路徑規劃和導航——從聽到目標到抵達目標。

用於音視頻交互的外部知識#

實時交互不僅需要低延遲，還需要能夠為每個應用動態加載知識和行為。Qwen3.8-Omni-Flash-Realtime 支持通過技能注入身份設定、表達風格、業務知識和交互規則，而工具調用則將這些能力延伸到任務執行中。

在客户服務等場景中，模型可以實時加載品牌話術和服務流程，理解用户的語音、視覺信息和上下文，生成符合業務要求的回覆，並執行操作。因此，同一個實時模型可以承擔不同的知識、角色和行為方式。

智能體全模態理解#

長音頻和視頻錄製中的關鍵信息往往分散在不同片段中，而複雜問題需要跨聲音和圖像進行多步推理。智能體全模態理解使模型能夠從問題出發，規劃方法、調用工具，並逐步定位和驗證證據。通過將計算集中在相關內容上，它提升了長時音視頻理解的準確性和效率。為評估這一能力，我們在 OmniVideoBench、Video-MME-v2 和 LVOmniBench 上，在兩種設置下對比了 Qwen3.8-Omni-Flash 和 Gemini 3.8 Flash：靜態模式，即模型直接解讀輸入；以及使用 Qwen Code 的智能體模式。這一對比展示了引入智能體工作流如何影響各模型的表現。

Qwen3.8-Omni-Flash 快速上手#

API 用法#

Qwen3.8-Omni-Flash 正式支持 reasoning_effort，用於調整推理深度並控制成本：

  • xhigh（默認）：適用於需要深入分析的複雜任務。
  • medium：兼顧準確性與速度。
  • low：針對速度和成本優化的高效推理。

此外，preserve_thinking 在所有場景下默認啓用，以提供最佳的開箱即用體驗。

Qwen3.8-Omni-Flash 支持行業標準協議，包括兼容 OpenAI 的 Chat Completions 和 Responses API。示例如下：

"""
Environment variables:
  DASHSCOPE_API_KEY: Your API Key from https://platform.qianwenai.com/home
  DASHSCOPE_BASE_URL: (optional) Base URL for compatible-mode API.
    - Beijing: https://dashscope.aliyuncs.com/compatible-mode/v1
    - Singapore: https://dashscope-intl.aliyuncs.com/compatible-mode/v1
"""
from openai import OpenAI
import os
api_key = os.environ.get("DASHSCOPE_API_KEY")
if not api_key:
    raise ValueError(
        "DASHSCOPE_API_KEY is required. "
        "Set it via: export DASHSCOPE_API_KEY='your-api-key'"
    )
client = OpenAI(
    api_key=api_key,
    base_url=os.environ.get(
        "DASHSCOPE_BASE_URL",
        "https://dashscope-intl.aliyuncs.com/compatible-mode/v1",
    ),
)
messages=[
    {
        "role": "user",
        "content": [
            {
                "type": "image_url",
                "image_url": {
                    "url": "https://help-static-aliyun-doc.aliyuncs.com/file-manage-files/zh-CN/20241022/emyrja/dog_and_girl.jpeg"
                },
            },
            {
                "type": "input_audio",
                "input_audio": {
                    "data": "https://help-static-aliyun-doc.aliyuncs.com/file-manage-files/zh-CN/20250211/tixcef/cherry.wav",
                    "format": "wav"
                },
            },
            {"type": "text", "text": "Please describe the image and tell me what is being said in the audio."},
        ],
    },
]
completion = client.chat.completions.create(
    model="qwen3.8-omni-flash",
    messages=messages,
    extra_body={
        "enable_thinking": True,
        # "preserve_thinking": True,
    },
    reasoning_effort="xhigh",  # supported levels are xhigh, medium, and low
    stream=True,
)
reasoning_content = ""
answer_content = ""
is_answering = False
print("\n" + "=" * 20 + "Reasoning" + "=" * 20 + "\n")
for chunk in completion:
    if not chunk.choices:
        print("\nUsage:")
        print(chunk.usage)
        continue
    delta = chunk.choices[0].delta
    if hasattr(delta, "reasoning_content") and delta.reasoning_content is not None:
        if not is_answering:
            print(delta.reasoning_content, end="", flush=True)
        reasoning_content += delta.reasoning_content
    if hasattr(delta, "content") and delta.content:
        if not is_answering:
            print("\n" + "=" * 20 + "Answer" + "=" * 20 + "\n")
            is_answering = True
        print(delta.content, end="", flush=True)
        answer_content += delta.content

Make sure your description covers every one of the following dimensions:
Visual
- Subjects and characters: appearance, clothing, gender/age cues, identity, distinctive features

- Spatial layout and relations between subjects/objects; counts and quantities
- On-screen text: captions, titles, subtitles, logos, UI — exact content and appearance
- Visual style: colors, lighting, camera shots, angles, and camera movement
Audio
- Speech: the exact spoken content, transcribed verbatim
- Speakers: who is speaking (mapped to the on-screen person or voice-over), with accent, tone, gender/age cues

- Non-speech vocalizations: laughter, crying, applause, etc.
Audio-visual correspondence
- Which speech or sound aligns with which on-screen person or visual event
- The timing of each event, expressed with timestamps
It should explicitly include three sections:
1. A structured chronological storyline of **every noticeable audio and visual details**
2. A structured list of all visible text. For each text element, include start timestamp, end timestamp, the exact text content, the appearance characteristics. If no text appears, explicitly state so.
3. Qwen3.8-Omni-Flash-Realtime 快速上手#

API 用法#

Qwen3.8-Omni-Flash-Realtime 支持通過 WebSocket 和 WebRTC 連接。運行下面的基礎示例會打開攝像頭和麥克風，進行實時音視頻對話。我們建議使用耳機。

# Run pip install websocket-client pyaudio dashscope opencv-python -U to install dependencies
"""
Environment variables:
  DASHSCOPE_API_KEY: Your API Key from https://platform.qianwenai.com/home
  DASHSCOPE_BASE_URL: (optional) Base URL for realtime API.
    - Beijing: wss://dashscope.aliyuncs.com/api-ws/v1/realtime
    - Singapore: wss://dashscope-intl.aliyuncs.com/api-ws/v1/realtime
"""
import os
import base64
import time
import pyaudio
import cv2
from dashscope.audio.qwen_omni import MultiModality, AudioFormat,OmniRealtimeCallback,OmniRealtimeConversation
import dashscope
url = f'wss://dashscope-intl.aliyuncs.com/api-ws/v1/realtime'
dashscope.api_key = os.getenv('DASHSCOPE_API_KEY')
# Determine the voice
voice = 'Tina'
# Determine the model
model = 'qwen3.8-omni-flash-realtime'
# Determine the model role
instructions = "You are Qwen-Omni, a helpful assistant."
video_fps = 1
video_size = (1280, 720)
class SimpleCallback(OmniRealtimeCallback):
    def __init__(self, pya):
        self.pya = pya
        self.out = None
    def on_open(self):
        # Initialize audio output stream
        self.out = self.pya.open(
            format=pyaudio.paInt16,
            channels=1,
            rate=24000,
            output=True
        )
    def on_event(self, response):
        if response['type'] == 'response.audio.delta':
            # Play audio
            self.out.write(base64.b64decode(response['delta']))
        elif response['type'] == 'conversation.item.input_audio_transcription.delta':
            # Streaming preview: text is the confirmed prefix, stash is the confirmed suffix
            preview = response.get('text', '') + response.get('stash', '')
            print(f"\r[User] {preview}", end='', flush=True)
        elif response['type'] == 'conversation.item.input_audio_transcription.completed':
            # Transcription completed, print the final text and a new line
            print(f"\r[User] {response['transcript']}")
        elif response['type'] == 'response.audio_transcript.done':
            # Print the assistant's response text
            print(f"[LLM] {response['transcript']}")
# 1. Initialize audio device
pya = pyaudio.PyAudio()
# 2. Create callback function and session
callback = SimpleCallback(pya)
conv = OmniRealtimeConversation(model=model, callback=callback, url=url)
# 3. Establish connection and configure session
conv.connect()
conv.update_session(output_modalities=[MultiModality.AUDIO, MultiModality.TEXT], voice=voice, instructions=instructions)
# 4. Initialize audio input stream
mic = pya.open(format=pyaudio.paInt16, channels=1, rate=16000, input=True)
camera = cv2.VideoCapture(0)
next_frame_at = 0.0
# 5. Main loop to process audio and video input
try:
    if not camera.isOpened():
        raise RuntimeError("Cannot open camera 0.")
    camera.set(cv2.CAP_PROP_FRAME_WIDTH, video_size[0])
    camera.set(cv2.CAP_PROP_FRAME_HEIGHT, video_size[1])
    camera.set(cv2., 1)
    print(f"Conversation started with camera ({video_fps} fps, {video_size[0]}x{video_size[1]}), speak into the microphone (Ctrl+C to exit)...")
    while True:
        audio_data = mic.read(3200, exception_on_overflow=False)
        conv.append_audio(base64.b64encode(audio_data).decode())
        success, frame = camera.read()
        if not success:
            raise RuntimeError("Cannot read a camera frame.")
        if time.monotonic() >= next_frame_at:
            frame = cv2.resize(frame, video_size)
            success, image = cv2.imencode('.jpg', frame, [cv2.IMWRITE_JPEG_QUALITY, 80])
            if not success:
                raise RuntimeError("Cannot encode a camera frame.")
            conv.append_video(base64.b64encode(image).decode())
            next_frame_at = time.monotonic() + 1 / video_fps
        time.sleep(0.01)
except KeyboardInterrupt:
    pass
finally:
    # Clean up resources
    camera.release()
    conv.close()
    mic.close()
    if callback.out:
        callback.out.close()
    pya.terminate()
    print("\nConversation ended")
