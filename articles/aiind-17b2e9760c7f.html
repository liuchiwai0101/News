Agent演示驚豔，一進生產就不好用：SAP直指企業AI落地的最大幻覺

內容機器翻譯自第三方媒體（InfoQ），僅供參考，以原文為準。

正文

“POC 非常成功，領導都非常高興，説我們就去幹吧。可真正做起來，效果完全不一樣，數據不準確，其他問題也都出來了。”蔡彥斌在談及企業部署 AI Agent 的實際情況時直言。

企業的業務系統往往經過多年建設，數據分散在不同平台，系統之間存在複雜的依賴關係，業務規則也並不總是一致。AI Agent 接入這些系統後，如何理解業務上下文、協調不同系統，以及應對生產環境中的異常情況？這些問題決定了 Agent 能否真正承擔業務任務。

在日前落幕的 SAP TechEd 2026 上，AI Agent 進入企業核心業務流程成為重要議題。但從技術演示到真正投入生產，仍有不少工程問題需要解決。

圍繞這些問題，InfoQ 專訪了 SAP 全球高級副總裁、SAP 全球研發網絡總裁柯曼博士（Prof. Dr. Clas Neumann），以及 SAP 中國研究院院長、SAP 全球副總裁、HCM 產品全球化研發負責人蔡彥斌博士。

模型能夠理解行業知識，卻未必知道一家企業究竟如何經營。蔡彥斌舉了一個例子：他的一位朋友經營着一家自行車貼牌加工廠，曾讓兩個 Agent 制定未來幾個月的產品定價策略。模型給出的分析看起來相當完整，卻無法直接使用，因為它不瞭解具體產品，也不清楚企業的客户情況。

在小範圍測試中，企業可以為模型準備數據、設定明確任務。但進入生產環境後，Agent 需要面對分散在不同系統中的業務數據、長期積累的管理規則，以及大量無法提前窮舉的實際情況。

柯曼認為，企業 AI 的目標應該是能夠根據業務意圖自主採取行動。例如，一家供應商的關鍵零部件延遲交付，系統不僅要及時識別風險，還要判斷對生產和供應鏈的影響，並採取相應的補救措施。

在這一思路下，SAP 提出了“自主運營企業”（Autonomous Enterprise）願景，希望讓 AI 從輔助工具逐漸進入企業核心業務，承擔更多流程編排和執行工作。

不過，對於已經運行着大量 ERP、財務和供應鏈系統的企業，Agent 要真正接手這些工作，仍需要解決數據、流程、權限和系統集成等問題。

“企業裏面有兩個系統，到底應該遵循哪一個系統的規則？這個事情，智能體自己解決不了。”蔡彥斌説道。

相比按照固定規則執行任務的機器人流程自動化（RPA），Agent 能夠根據環境變化進行判斷，選擇不同工具和執行路徑。但企業內部的數據往往分佈在多個系統中，不同部門甚至可能對同一個業務概念採用不同定義。

例如，某個系統中的“客户”可能指簽訂合同的主體，另一個系統則按照實際收貨或結算對象管理。如果沒有統一的業務語義，Agent 即使能夠讀取兩套系統，也可能在執行任務時產生錯誤判斷。

蔡彥斌認為，企業部署 Agent 首先需要做好“乾淨的數字化核心” （Clean Core），包括數據標準化、流程標準化和主數據治理。在此基礎上，還要實現“語義就緒”，讓 AI 理解不同數據所對應的業務含義，以及它們之間的關聯。

為此，SAP 正在將長期積累的業務數據和管理流程整合進知識圖譜。據悉，其 ERP 系統積累了 700 多萬個字段、50 多萬張數據表和超過 15000 個業務流程。知識圖譜的作用，是將這些數據及其業務關係提供給 AI，使其能夠結合企業自身情況進行分析和執行。

以財務預算為例，模型需要了解的不只是某個部門的預算金額，還包括成本中心歸屬、支出規則、審批流程和相關係統接口。具體地，財務人員向 Joule Work 提出一個任務：第四季度電價預計上漲 20%，需要分析哪些部門的剩餘預算可能不足。系統隨後調用企業後台數據，找出六個成本中心，識別其中三個可能出現預算缺口，並提出進一步核實電價生效時間、部門用電量和追加預算的處理建議。

這個體現了企業上下文的重要性。模型可以理解電價上漲的含義，但要判斷哪些部門受到影響、預算如何調整，還需要調用企業已有的數據和流程。

那麼，隨着 Agent 開始理解業務意圖、調用系統和執行流程，傳統 ERP 未來會變成什麼樣？

蔡彥斌認為，企業軟件的使用方式肯定會改變。過去，員工需要熟悉不同的事務代碼和功能界面，在 ERP 或 SaaS 系統中找到相應模塊才能完成工作。未來，用户可能只需要向 Joule Work 提出需求，由 AI 協調後台系統完成操作。

但傳統界面不會因此完全消失。“特別是在人需要干預的時候，或者某一個點有突發情況時，人還是需要跑到後台找到對應的事務代碼、對應的屏幕。”蔡彥斌表示。

他預計，通過 AI 入口完成工作的比例會逐漸提高，傳統界面的使用頻率相應下降。但在可預見的階段，兩種方式仍將並存。

SAP 也據此調整了企業軟件架構。在其提出的體系中，Agent 負責理解用户意圖、編排任務；原有應用繼續承載財務、人力資源、供應鏈等業務流程；數據層則提供企業知識和業務語義。

蔡彥斌透露，SAP 目前已經發布了 300 多個智能體，希望通過 Agent 重新組織現有 ERP 流程，逐步覆蓋更多端到端的企業業務。但這些智能體不會直接取代底層應用。

具體到產品，Joule Work 承擔用户交互和任務協調，Joule Studio 則用於構建智能體。後者允許業務人員通過自然語言描述需求，由系統結合企業已有流程、數據和接口，生成相應的 Agent。

這種開發方式也在改變企業 IT 團隊與業務部門的關係。蔡彥斌認為，業務人員可以更多參與技術開發，技術人員則需要更加理解具體業務。對於 SAP 而言，原來負責傳統 SaaS 應用的部分研發人員，也開始將積累的業務知識用於智能體開發。
