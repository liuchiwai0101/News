1. ReToken：讓視覺模型先找對畫面，再回答問題

**論文**：

*ReToken: One Token to Improve Vision-Language Models for Visual Retrieval*

**作者与机构**：Yao Xiao、Reuben Tan、Zhen Zhu、Yuqun Wu、Jianfeng Gao、Derek Hoiem；University of Illinois at Urbana-Champaign、Microsoft Research、Google DeepMind。2

**提交时间**：2026 年 7 月 31 日 01:59（北京时间），arXiv:2607.28627v1。7

**原文與代碼**：arXiv 摘要頁；完整 HTML；代碼倉庫。

問題背景

長圖像集合和長視頻裏的大多數幀都是干擾項。視覺語言模型如果一次處理全部 token，顯存和計算會隨上下文變大；如果直接照搬語言模型裏的 query-key attention 檢索，相關視覺信息又不一定會被選出來。作者在 Qwen3VL-8B 上測到，基於 attention 的檢索器在 QAEgo4DTest-MC 的平均 Recall@1 只有 5.1%。2

方法要點

ReToken 只向問題中追加一個可學習 embedding，把它訓練成「檢索目標」。模型先把圖像或視頻幀寫入視覺 KV cache，再用這個 token 與最後一層的 frame mean value vector 做相似度匹配，選出少量相關視覺 token；默認設置下視覺語言模型本體凍結，只訓練這個 token 和一個投影矩陣。作者的診斷也很直接：在受控的雙圖設置中，把目標短語匹配到 value 空間後，Qwen3VL-8B 的 Recall@1 從 65.7 提到 78.0，InternVL3.5 從 78.8 提到 83.8。2

結果亮點

在 Visual Haystacks 上，ReToken 让 Qwen3VL-8B 提升

**13.4 個百分點**，讓 InternVL3.5 提升**12.4 個百分點**，論文稱相對提升超過 20%；在訓練只使用多圖問答的前提下，它遷移到長視頻 LVBench，並讓 Qwen3VL-8B 零樣本提升**8.0 個百分點**。訓練和長視頻推理都能放進一張 H100。7### 適用邊界

這不是一個獨立的通用圖像檢索器，而是嵌在 VLM 自己的 KV cache 裏的輕量檢索頭。它的訓練信號來自規模較小的圖像問答數據，實驗重點也在 Visual Haystacks 與 LVBench；論文同時發現，視覺 token 在寫入 cache 時會吸收此前圖像的干擾信息，長視頻中需要跨幀關聯時，過度追求乾淨的單幀 cache 可能反而帶來代價。2

一句話閱讀價值

如果你在做長視頻 VLM，先看它如何把「檢索」放進模型已有的視覺 cache，而不是另起一個外部檢索器；真正值得復現的是 value 空間爲何比 attention 分數更適合選證據。

2. Beacon：代理首先要學會判斷工具是否必要

**論文**：

*Beacon: Knowing When and How to Perform Agentic Visual Reasoning*

**作者与机构**：Qixun Wang、Yang Shi、Letian Cheng 等 14 位作者；Peking University、Kling Team、HKUST(GZ)、CUHK、浙江大学、清华大学。3

**提交时间**：2026 年 7 月 31 日 01:46（北京时间），arXiv:2607.28595v1。8

**原文、代碼與模型**：arXiv 摘要頁；完整 HTML；代碼；模型。

問題背景

視覺代理的工具調用有一個容易被平均準確率遮住的損失：工具確實能幫助模型解決「只靠文字推理做不出來」的難題，但也可能讓原本能答對的簡單題多走一步、引入新錯誤。Beacon 把這個問題拆成兩個指標：

**Mode Adaptiveness**衡量模型是否會按題目難度選擇工具，**Tool Effect**衡量工具帶來的增益是否超過它造成的損害。作者對已有模型的分析顯示，許多模型要麼幾乎總用工具，要麼幾乎不用；工具在難題上的收益常被簡單題上的錯誤抵消。3### 方法要點

Beacon 以 Qwen3-VL-8B-Instruct 爲底座，先用合成軌跡做監督微調，讓模型具備裁剪、標註、增強、旋轉、拼接圖像和數值計算等 Python 工具能力，再用 GRPO 做強化學習。

**Necessity-Aware Adaptive Reward**鼓勵模型只在必要時調用工具；**Hint-Guided Capability Expansion**則給最難、確實需要工具的樣本提供有效軌跡，避免強化學習只學到「多調用」這個表面策略。3### 結果亮點

Beacon 在 13 個視覺搜索、空間感知、定量推理和代理任務基準上，拿到開源模型最高平均成績，並在 13 項中的 11 項排名第一；相對 Qwen3-VL-8B-Instruct，平均提升

**6.07 個百分點**。在專門分析工具行爲的 5 個數據集上，Beacon 的工具可用準確率相對無工具準確率的增益爲**+1.96%**，Tool Effect 的「增益減損害」爲**+3.14%**；無工具平均準確率也達到 51.57%，高於基座模型的 49.75%。3### 適用邊界

「13 項中 11 項第一」是作者在其報告結果上的開源模型比較，不等於超過所有閉源模型；表中 Gemini 3.1 Pro 仍是單獨的閉源參照。實驗基於 Qwen3-VL-8B、固定的工具接口和作者設計的 13 個基準，工具選擇是否能遷移到不同模型、不同代碼沙箱和更開放的任務，還需要獨立復現。3

一句話閱讀價值

這篇論文把「會不會用工具」改寫成了「什麼時候用工具、用了之後是否淨增益」；評估視覺代理時，至少要把這兩個問題和總準確率分開看。

3. PhiZero：用 physical language 先预测世界如何变化

**論文**：

*PhiZero: A World Model Built Around Physical Language*

**作者与机构**：Shuyao Shang、Yuqi Wang、Ruopeng Gao、Xu Chen、Tieniu Tan、Lue Fan、Zhaoxiang Zhang；中国科学院自动化研究所 NLPR。4

**提交时间**：2026 年 7 月 31 日 01:59（北京时间），arXiv:2607.28624v1。9

**原文與項目頁**：arXiv 摘要頁；完整 HTML；項目頁。

問題背景

多數視頻世界模型直接在像素或高維視覺 latent 上預測下一段視頻，畫面可以逼真，但「物體爲什麼這樣運動」仍藏在生成器內部，難以顯式推理、控制和遷移。PhiZero 的問題意識更窄：能不能把世界狀態的變化單獨表示出來，再讓視頻生成器負責補回外觀細節？4

方法要點

PhiZero 學習一種作者稱爲

**physical language**的離散狀態轉移表示。Physical Language Tokenizer 從無標註、自然採集的視頻中自監督學習，把相鄰時空狀態壓縮成離散符號；Physical Language Reasoner 以 Qwen3-VL-4B 初始化，先根據當前畫面和動作意圖預測這串符號，再由擴散解碼器把狀態變化渲染成視頻。一個 33 幀視頻被編碼成**256 個**transition symbols，詞表規模爲 25K；整體流程是「reason-then-render」，把動力學推理和像素生成分開。4### 結果亮點

在 Physics-IQ Verified 的 66 个受控物理实验上，PhiZero 的 S-IoU、ST-IoU、WS-IoU 和 IQ-Score 分别为

**58.2、36.8、27.6、41.2**；IQ-Score 高于表中 Wan2.2-14B 的 32.2。在 PhyGround 上，PhiZero 的 Physics Score / Overall 为**3.01 / 2.97**；WorldModelBench 上的 Physics Adherence / Total 为**4.88 / 8.19**，均为表中最高。4在 500 个四秒真实视频的重建实验中，physical language 只用 256 个离散 token，PSNR / SSIM / LPIPS 为

**28.9 / 0.903 / 0.087**；Wan2.2 VAE 需要 44,800 個連續視覺 token，PSNR / SSIM / LPIPS 爲 37.7 / 0.957 / 0.042。這個對比說明它用更強壓縮換取了仍可用的重建質量，不能解讀成在所有視覺保真指標上都超過 VAE。4### 適用邊界

Physical language 目前是從視頻數據中學出的經驗表示，不是可解釋的物理定律，也沒有直接落到質量、速度、接觸力等物理變量上。只靠視覺觀察的訓練數據，對觸覺交互、微觀粒子等不可見或視覺歧義較大的狀態變化覆蓋有限；作者也明確指出，當前模型和數據規模仍相對有限，結論更像是可擴展路線的驗證，而不是完整物理模擬器。4

一句話閱讀價值

如果你關注 Physical AI 或視頻世界模型，這篇論文值得讀的不是「生成畫面更像不像」，而是把可遷移的狀態轉移從外觀中剝離出來，給控制和跨 embodiment 遷移留出接口。

4. CoMem：把長上下文緩存從 token 軸移到 depth 軸

**論文**：

*Understanding Is Done Early: A Depth Division of Labor in Large Language Models and Its Use for Unbounded-Context Memory*

**作者与机构**：Hanzuo Liu、Xuan Qi、Chunyu Liu、Haotian Zhong、Yulong Wang、Rayying Key、Alex Lamb、Mingyu Gao；清华大学、腾讯。5

**提交时间**：2026 年 7 月 30 日 22:19（北京时间），arXiv:2607.28263v1；论文备注称已提交 ACL Rolling Review。10

**原文與代碼**：arXiv 摘要頁；完整 HTML；代碼倉庫。

問題背景

長上下文通常沿 token 軸壓縮或淘汰 KV cache，但寫入和讀取仍要處理完整深度的表示。論文先用 probing、因果截斷和 split-depth sweep 觀察到：語義信息在較低或中間層已經可用，上層更多服務於當前 query 和最終預測。CoMem 把這個深度分工變成緩存策略。5

方法要點

寫入時，每個 context chunk 只計算到中間層

j，緩存該層 residual tensor；讀取時先檢索固定數量的相關 chunk，再把 query 和這些 residual states 打包，只重算 j:L 的上層。旗艦設置在凍結的 Qwen3-8B 上訓練 rank-32 self-distillation LoRA，另有 adapter-free 對照，目標是在固定檢索預算下讓模型側的讀取計算和顯存不隨存儲上下文長度增長。5### 結果亮點

在統一的無 chat template 協議下，CoMem 的 RULER 得分爲

**97.05**，LoCoMo 为**38.27**，对比 KV-Direct 的**34.59**；在 128k、H20-class 平台的 adapter-free 效率控制中，显存为**18.26 GB**，对照为**89.36 GB**，prefill 加速**7.83 倍**。作者还报告，LoCoMo 的优势在 conversation-cluster bootstrap 和独立 judge 审计下仍为正。5### 适用边界

CoMem 不是所有 in-window 任務的準確率 SOTA：BABILong qa2 仍只有 27.0，且結果沒有和 YaRN 擴展後的 full-context 模型直接比較。它依賴 BM25 top-12 檢索、固定 512 token chunk 和英文 retrieval-style QA；多語言、代碼、多模態記憶、動態索引更新和連續變化的 memory stream 都不在本次實驗範圍內。H20、bf16/SDPA、單請求 harness 下的絕對延遲，也不能直接當作併發服務吞吐。5

一句話閱讀價值

做長上下文 serving 時，可以把「緩存哪些 token」之外的另一條軸也納入設計：哪些層值得保存，哪些層應該留到查詢發生時再算。

5. ORCA-bench：讓軟件代理面對真正像 on-call 的證據

**論文**：

*ORCA-bench: How Ready Are Language Model Agents for Oncall?*

**作者与机构**：Albert Gong、Kyuseong Choi、Abhineet Agarwal、Jason Schechner、Ryan Huang、Raj Agrawal、Anish Agarwal、Raaz Dwivedi；Cornell Tech、Traversal、Columbia University。6

**提交时间**：2026 年 7 月 31 日 01:14（北京时间），arXiv:2607.28545v1。11

**原文與數據**：arXiv 摘要頁；完整 HTML；公開數據集。

問題背景

代碼代理的常見 benchmark 給它一個靜態倉庫、測試失敗和明確目標；on-call 的根因分析卻從模糊的用戶投訴開始，要在指標、日誌、trace 和源碼之間來回檢索，還要處理故障同時發生、調查開始得太晚等情況。ORCA-bench 把這段證據鏈完整放進評測，而不是隻讓模型猜一個 fault label。6

方法要點

基準運行一個帶 OpenTelemetry 的微服務系統，暴露 Prometheus 指標、Jaeger trace、OpenSearch 日誌（通過 Grafana 查詢）和完整源碼；測試集包含

**1,079 個**RCA 任務，改變用戶報告的具體程度、time-to-detection、併發故障類型和調查難度。專家 SRE 審覈 ground truth；40 個 Verified 任務上的 LLM judge 與人工重評分的加權 Cohen’s κ 爲**0.90**。6### 結果亮點

五個 frontier coding agents 在這個 50 GB、六天的公開 testbed 上測試。最現實的 Medium 難度中，最高 RCA Accuracy 爲

**25.3%**；Hard 難度只有**10.0%**。去掉源碼訪問後，所有模型的指標都下降，論文報告 RCA Accuracy 的降幅爲**9—16 個百分點**；不同模型有**7%—40%**的報告會寫出與任何合理根因都不匹配的 hallucinated root cause。6### 適用邊界

這些數字是在固定代碼庫、公開 instrumentation、任務彼此隔離且只讀調查的環境中得到的。真實生產系統更大、更動態，也更私有；模型可能對公開的 Astronomy Shop 系統有預訓練記憶，反而讓這裏的結果偏樂觀。論文沒有評估代理部署修復後觀察症狀是否消失的 action loop，也沒有覆蓋持續記憶和跨 incident 學習。6

一句話閱讀價值

如果你在評估 coding agent，不要只問它能否修一個倉庫裏的 bug；先看它能否在模糊報告、髒 telemetry 和併發故障中找全根因，並把源碼訪問從評測裏拿掉再測一遍。

把昂貴計算留給真正需要的地方

這 5 篇論文的任務不同，但都在處理同一種系統浪費：把所有輸入、所有層、所有工具和所有畫面一視同仁。ReToken 先篩視覺 token，Beacon 先決定是否調用代碼，PhiZero 先預測狀態轉移，CoMem 先保存中間層表示，ORCA-bench 則反過來證明：如果關鍵證據沒有開放給代理，性能會系統性下降。23456

按閱讀目的選擇即可：長視頻和多圖輸入先看 ReToken；視覺工具代理先看 Beacon；物理世界模型和具身遷移先看 PhiZero；模型 serving 和長上下文先看 CoMem；軟件代理上線前的可靠性評估先看 ORCA-bench。每篇論文都給出了可複查的數字，但它們仍是預印本或受限實驗設置，數字應和各自的任務、基座模型、硬件與數據邊界一起讀。
