+ 8 潛伏超過十年的兩個致命缺陷 這兩個漏洞的技術細節，揭示了 PHP 底層多年來的隱患。

CVE-2026-109618（GHSA-w8hw-w9fx-j79w）涉及 PHP 的記憶體管理機制。當一個請求恰好在特定時機觸發了 PHP 的 memory_limit 限制時，部分初始化的內部數據會被遺留，隨後被當作有效數據處理，造成記憶體損毀。

這兩個漏洞的技術細節，揭示了 PHP 底層多年來的隱患。（PHP） 在 Apache + mod_php 的默認配置下，研究人員成功演示了未經認證的遠端執行程式碼；在 PHP-FPM 環境中也通過應用層代碼路徑得到確認 。

CVE-2026-109619（GHSA-6wmf-4rv5-p3rp）則關乎 PHP 的錯誤處理流程。當 fatal error 在錯誤的時間點發生時，內部狀態仍然指向上一個請求的內存區域。

後續請求在同一個 worker 中重複使用了已釋放的記憶體空間（Use-After-Free, UAF）。研究人員在 Apache + mod_php 環境上，針對真實應用程序成功演示了遠端執行程式碼。

兩個漏洞都深入 PHP 引擎中幾乎每個請求都會觸及的部分，也就是內存管理和錯誤處理。更棘手的是，受影響的 PHP 版本範圍從 5.4 一直延伸到 8.5，覆蓋了過去十多年間發布的所有主流版本。

事實上，這類問題早就有人注意到了。2024 年，PHP 迎來了多年來的首次外部安全審計，由 Sovereign Tech Agency 資助、OSTIF 組織、Quarkslab 執行。

在修復 Quarkslab 報告的一個問題時，PHP 基金會的一名核心開發者發現了 OOM（內存溢出）問題的初步跡象 。當時團隊推演了一種可能的攻擊方式，但沒有找到具體的利用路徑。

隨後的修復方案在內部陷入了僵局。安全團隊提出了多種修復思路，但每種都有各自的代價：有的會破壞向後兼容性，有的可能引入新的 DoS 攻擊面，有的需要第三方擴展同步修改。

PHP 基金會在事後檢討復盤中坦承，決策流程多次停滯和重啟，這是一次「結構性失敗」（structural failure），根源在於決策機制和資源不足。直到 AI 真正找到了可利用的攻擊路徑。

但計劃趕不上變化。10 月 20 日，也就是正式披露前一天，漏洞消息在 Hacker News 論壇上洩漏。安全公司 watchTowr 在 X 上發布了相關訊息，更糟糕的是，Calif 團隊誤發了一段概念驗證（PoC）攻擊視頻。

與此同時，開發平台 Chainguard 提前發布了包含補丁的二進製版本，這讓攻擊者得以通過對比代碼差異反推出漏洞細節。

PHP 基金會在博文中對此表達了不滿，稱此舉「無視了多方數周以來為協調披露所做的努力」。

PHP 維護者被迫提前在 php.net 上發布更新預告，敦促用户做好準備。安全公司 Sansec 預測「大規模攻擊將在補丁發布 15 分鐘內開始」。
