AMD Radeon 驅動疑似讓 SSD 健康度每月掉 1% 玩家追查出閒置時仍持續寫入

內容機器翻譯自第三方媒體（Ludens Media · BigGo 財經 · UNIKO's Hardware · XFastest News 等5家），僅供參考，以原文為準。

正文

Radeon 驅動 SSD 寫入異常，AMD 已承認 atieclxx.exe 閒置時仍持續寫碟，回報速度 0.3 至 5 MB/s，26.10.2 版本中未列入修正。

AMD 官方已承認 Radeon Bug 如果你的 Radeon 電腦明明放著不動，硬碟燈卻老是在閃，這次可能真的不是錯覺。近期 有 Radeon 用户回報 ，AMD 顯示卡驅動程式裡有一個元件，會在系統閒置時持續把資料寫進系統碟，而且問題橫跨多個 Adrenalin 版本。AMD 官方人員已在論壇承認這是個需要處理的問題，修正也在進行中，但截至截稿期間，最新的 Adrenalin 26.10.2 更新説明並沒有提到這件事。

這個話題在 11 月初再度升温，起因是 Reddit 網友 darklinkpower 在 r/pcmasterrace 版面發出的提醒文，指出最新的 Adrenalin 更新之後，系統可能出現悄悄且持續的 SSD 寫入。不過問題並不是這幾天才冒出來，AMD 論壇上最早的相關回報出現在 7 月，有用户使用 Windows 10 LTSC、Radeon RX 7800 XT 與驅動 26.6.4，看到相關程序持續讀寫約 2 MB/s，Process Monitor 的紀錄顯示 10 分鐘內寫入了約 600 MB。

AMD 方面，官方代表 AMD_Matt 在 10 月於 Adrenalin 26.10.1 更新説明的討論串中回覆，表示這看起來確實是個問題，公司正在調查，目標是在未來的驅動版本中解決，但沒有給出時程。另一位代表 AMD_Vik 隨後在 Reddit 透露，修正內容可能已經提交，只是或許趕不上下一版驅動的截止時間。10/30 釋出的 Adrenalin 26.10.2，無論在已修正項目或已知問題裡都沒有出現這個議題，所以修正版何時到位，AMD 目前並未正式公佈。

此次肇事的元件是 AMD External Events Utility，它會隨 Radeon 驅動一起安裝，透過 atiesrxx.exe 與 atieclxx.exe 兩個程序運作，後者在工作管理員裡的名稱是 AMD External Events Client Module。據社群説明，這項服務與螢幕的連接及套用螢幕設定有關。

各方回報的寫入速度落差不小，Reddit 上有用户看到約 5 MB/s 的持續寫入，AMD 論壇上的數字則多落在 0.3 至 1.5 MB/s 之間。AMD 代表貼出的截圖是 Radeon RX 9070 XT 搭配 26.10.1，約為 0.7 MB/s。另有 Windows 10 22H2 搭配 RX 9060 XT 的用户，從 26.7.1、26.8.1 就有此現象，到 26.10.1 速度提高到 1.5 MB/s。至於 Windows 11 26H2 搭配 RX 9070 XT 的用户，在 26.9.2 與 26.10.1 量到的是 0.3 MB/s。

實際來計算一下，假如把 5 MB/s 當成全天候不間斷來算，理論上一天的主機端寫入量約為 432GB，一個月會接近 13TB。換成 0.3 MB/s，大約是每天 26GB，1.5 MB/s 則約為每天 130GB。以回報 5 MB/s 的那顆 Kingston NV3 2TB 為例，官方標示的耐寫量是 640 TBW，若以 1.5 MB/s 連續寫入，約 13.5 年耗盡，5 MB/s 則約 4 年。

不過這些數字有幾個前提要先講清楚，它們是假設寫入從不間斷，計算的是系統送出的主機端寫入量，並不等於實際寫進 NAND 快閃記憶體的量。目前並沒有足夠證據説明這個 Bug 究竟讓 SSD 壽命縮短多少，甚至不確定有沒有縮短。另外，5 MB/s 這個數字也沒有出現在 AMD 論壇的公開回覆裡。

值得一提的是，這已不是同一項服務第一次因寫入行為被盯上。去年底就有用户發現，使用者移動或調整視窗大小時，External Events Utility 會不斷寫入 System32 底下 EEUDumps 資料夾裡的紀錄檔。當時 Tom’s Hardware 的看法是 ，現代 SSD 搭配快取機制，這類紀錄檔寫入雖然頻繁，但單筆很小，未必構成實質的壽命問題。這次的情況不同，寫入是持續發生的，而且寫入位置也與當時不同。

從目前的回報來看，這個問題在 Windows 10 與 Windows 11 都出現過，完整安裝與只安裝驅動程式的情況也都有人遇到，但並非所有 Radeon 電腦都會中招。例如有一位 Radeon RX 7900 XTX 用户就沒有出現異常，RX 9070 XT 搭配 Windows 11 26H2 的回報也兩極，有人能重現，也有人在 26.10.2 上看不到。用户回報中，25.12.1 與 26.2.2 版本沒有這個問題。

另外有網友把畫面頓挫、影片掉格等狀況歸咎於這個程序。Reddit 上有貼文提到，《控制：共振》出現卡頓與音訊斷續，《戰爭機器：事變日》有貼圖載入問題，關閉服務後都消失了。不過 AMD 並未證實這些症狀與該 Bug 的關聯，也未確認它與 Resizable BAR 之間的關係，這部分仍屬於用户經驗，讀者看看就好。

目前有幾種檢查方式，有些不需要額外安裝軟體，用 Windows 內建的資源監視器就能完成。先按下 Win + R，輸入 resmon 後執行，切換到「磁碟」分頁，再把程序依寫入量排序，接著找有沒有 atieclxx.exe 持續出現在前段、而且在電腦閒置時也有穩定的寫入量。筆者也要提醒，這筆寫入有時會掛在 System 程序底下，檔案路徑指向 atieclxx.exe，工作管理員裡也不一定看得到，所以建議以資源監視器為準。

在正式修正推出前，網友提出了三種做法。第一種是開啟服務 (services.msc)，把 AMD External Events Utility 服務停掉，寫入確實會停止，但可能影響 FreeSync 的運作與 Adrenalin 快捷鍵，也有人提醒會牽涉到螢幕熱插拔與色彩設定檔，停用後建議確認 FreeSync 與 Adrenalin 程式運作是否正常。第二種是在 BIOS 裡關閉 Resizable BAR 與 Above 4G Decoding，同樣能讓寫入消失，代價是部分遊戲與應用程式的效能可能下滑。第三種則是退回舊版驅動，AMD 建議回退時搭配 AMD Cleanup Utility 清理乾淨。

另外，在確認自己真的中招之前，最好也不要亂動這些設定，畢竟 AMD 已經在處理，也許下一次驅動更新就能在不犧牲功能的前提下一併解決。對多數人來説，現階段比較務實的做法，是先用資源監視器確認狀況，沒有異常就維持現狀，等官方修正版釋出再更新。
