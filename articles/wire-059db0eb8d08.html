Windows 11 備份災情未解？微軟號稱已修正 File History 問題，仍有用户反映備份時間異常

內容機器翻譯自第三方媒體（電腦王阿達 · Yahoo 新聞），僅供參考，以原文為準。

正文

微軟在 2026 年 9 月推出的 Windows 安全更新，原本是要修補系統漏洞，沒想到卻讓部分使用者的「檔案歷史記錄」（File History）備份功能發生異常。儘管微軟隨後推出修正更新，並在官方文件中將問題標示為已解決，但仍有使用者反映備份時間沒有更新、檔案無法正常還原等狀況。日本科技媒體也在實際測試中發現，部分備份相關異常並未隨著更新完全消失。對於長期仰賴 Windows 內建功能備份重要資料的使用者來説，恐怕還是得親自確認備份檔案是否真的成功儲存。

九月 Windows 更新闖禍，微軟已承認備份功能出問題 這起事件最早可以追溯到 2026 年 9 月 8 日。當時微軟針對 Windows 11 24H2、25H2 推出例行安全更新 KB5124008，但更新後陸續有使用者反映，原本正常運作的 File History 突然無法辨識備份硬碟。

微軟剛叫大家別拖延更新，Windows 11 九月更新就出事了(KB5124008 災情)

File History 是 Windows 內建的檔案備份功能，可以定期將使用者的文件、圖片及其他支援的資料夾內容備份到外接硬碟或網路儲存位置，並保留不同時間點的檔案版本，方便日後還原。

問題在於，部分使用者明明已經正確連接外接硬碟，系統仍持續顯示「重新連接磁碟機」的警告。更麻煩的是，有些電腦甚至沒有明顯的錯誤訊息，卻出現備份時間不再更新、檔案找不到先前版本的情況。

微軟在官方支援文件中證實，九月安全更新可能導致 File History 無法建立或更新備份，部分電腦的事件檢視器還會留下 FileHistory.exe 與 KERNELBASE.dll 相關的程式當機紀錄。

由於備份功能不像一般應用程式，使用者不一定每天都會檢查，一旦長期沒有發現問題，等到真正需要還原資料時，才可能發現最近的檔案根本沒有成功備份。

KB5124010 宣稱修復，但日本媒體實測仍發現異常 針對這次問題，微軟在 9 月 22 日推出 Windows 11 預覽更新 KB5124010，官方更新説明明確將 File History 列為已修復項目，指出這次更新解決了系統錯誤要求重新連接備份磁碟機，以及無法正常備份或還原檔案的問題。

日本科技媒體「 ニッチなPCゲーマーの環境構築Z 」在 9 月 28 日發表的報導中指出，即使安裝 KB5124010，仍收到部分使用者表示 File History 無法正常運作的回報。

Source 該媒體也自行進行測試，發現一個相當微妙的問題：在控制枱中手動執行備份後，「最後複製的日期和時間」並沒有更新，但實際檢查備份資料夾後，發現新建立的檔案確實已經成功備份。換句話説，至少在這個測試案例中，問題並不是備份完全失效，而是系統顯示的時間資訊與實際備份狀態不一致。

該媒體另外使用停留在 2026 年 2 月更新狀態的測試電腦比較，發現舊環境執行手動備份後，日期可以正常更新，因此認為新版 Windows 的相關行為仍有異常。

Microsoft Q&A 也有使用者在安裝 KB5124010 後回報，雖然系統已能顯示正確的備份磁碟機，卻仍然出現無法辨識磁碟機的錯誤。不過，目前尚無足夠證據顯示這些殘留異常是大規模災情，也無法確認所有案例都出自同一原因。

十月更新已推出，還有讀者反映備份問題未解決 到了 10 月 13 日，微軟正式推出 Windows 11 累積安全更新 KB5127648，適用於 24H2、25H2 與 26H2，Windows 10 的延伸安全更新版本則推出 KB5126657。其中 Windows 10 的 KB5126657 官方更新説明，也將 File History 無法備份及還原的已知問題列為已修正項目。

然而，電腦王阿達近日收到讀者來信，表示自己在 Windows 11 25H2 與 Windows 10 22H2 上，經歷多次更新後仍然遇到與 File History 有關的異常。

手動按下「立即執行」備份後，最後複製日期沒有正確更新。

備份磁碟機可以正常讀寫，但部分新增或修改檔案沒有顯示最新的備份版本。

在檔案內容的「先前的版本」頁面中，無法找到最新備份。

備份資料夾內部分檔案與預期不一致，擔心備份資料不完整。

這名讀者表示，已經多次與微軟技術支援聯繫，也在 Microsoft Community Hub 及意見反應中樞提出相關問題。值得注意的是，讀者也曾手動調整 FileHistory 備份資料夾名稱，因此目前仍無法排除既有備份索引或本機設定影響後續行為的可能性。

另一方面，部分類似的清理版本錯誤在過去的 Windows 版本便曾出現，不能將所有異常都直接歸因於今年九月或十月的更新。

因此，現階段比較準確的説法是： 微軟已修復先前確認的 File History 備份問題，但部分使用者仍回報相似症狀，尚待進一步釐清。

不能只看備份時間！如何確認 Windows 真的有備份成功？ 對一般使用者來説，這次事件最大的提醒，就是不能只依靠 Windows 顯示的備份狀態判斷資料是否安全。如果你平常就有使用 File History，建議可以透過以下方式進行檢查。

開啟「控制枱」→「系統及安全性」→「檔案歷程記錄」（File History），確認備份目的地仍然正常連接，並查看目前顯示的備份時間。
