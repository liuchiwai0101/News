Google公佈全新AI代理人安全控管介面

內容機器翻譯自第三方媒體（iThome），僅供參考，以原文為準。

正文

Agent Gateway是Google旗下Gemini Enterprise Agent Platform的網路安全控管元件，整合代理人註冊、身分驗證、安全政策及可觀測性等機制，讓企業能統一管理AI代理人與使用者、工具及其他代理人之間的網路通訊及存取權限。（圖片來源／Google Cloud）

因應AI代理人導入為企業帶來潛在的資料及隱私風險， Google週二（11月24日）公佈 一組專門的代理人控管介面，以現代化建構工具及介面，提供代理人活動的可視度及控管。

Google指出，傳統REST API是為以人類速度執行的App設計，這種情境，有效的OAuth權杖即代表使用者的真實意圖。但在AI代理人由讀取資訊到以機器速度在電子郵件、文件、資料集和雲端基礎架構間自主行動，有效的權杖已經不足以提供證明。在代理人請求的路徑上，政策檢查、資料邊界和人類確認必須全部都啟用。

為此，Google Cloud已全新上線一組預建的安全控管介面，作為代理人活動的安全控管，包含Workspace MCP伺服器、Workspace CLI和Google Cloud Agent Gateway。現在Workspace MCP伺服器和Workspace CLI已在Google Cloud正式上線，而Google Cloud Agent Gateway則和整合式防護工具已經在Workspace和Google Cloud運作。

Workspace MCP Server是Gmail、Google Drive、Docs、Sheets、Slides、Calendar、Chat、Tasks的專屬遠端伺服器。其建構工具具備單一介面內建權限和DLP檢查，且原生支援人工介入(human-in-the-loop)的確認機制。這些伺服器也會拒絕非代理人的OAuth用户端(client)，並且能和Google Cloud的安全工具包括Model Armor或提示注入過濾服務共用。

Workspace CLI現在已正式在本地代理人、終端工作流和自動化環境下上線，提供Workspace服務結構化JSON輸出和OAuth登入。

Google Cloud Agent Gateway為Google Cloud上LLM、MCP和Agent2Agent (A2A)流量專用的協定原生閘道。它會根據Agent Registry驗證代理人身分、執行身分和存取管理(IAM)政策與預設拒絕的輸出規則，並以Model Armor過濾代理人請求。

三者組合運用可提供AI代理人以MCP和A2A標準為基礎的協同原生開放路徑。它會自動執行權限放行、確認、提示過濾和稽核日誌。這些都是專門用於代理人安全控管。傳統App則維持在現有REST API執行。

Google説，這三項介面執行於Workspace和Google Cloud上形成統一的安全模型。不論是在企業Workspace或Google Cloud上，都會提供安全控管，包括每次請求皆執行政策檢查、獨立代理人的身分與實施用量上限、重要操作由人把關，以及提供清楚的透明度與即時撤銷代理人動作。

Google Cloud也提供相關使用資源，如Workspace開發人員的 Workspace MCP配置指引 、管理員可從管理員控制枱一覽連結的應用程式和代理、設定管理政策和監控活動日誌、Google Cloud客户則可在Agent Registry註冊代理人身分，並以Agent Gateway、Model Armor及政策來管理代理人和MCP伺服器等。
