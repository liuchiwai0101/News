React 效能優化：從「卡成狗」到「絲般順滑」的 5 個秘訣

React已經很快了，但如果你不注意細節，它會做很多“無用功”：組件沒必要的重渲染、大列表全量渲染、狀態更新導致整個頁面刷新……這些問題累積起來，再好的電腦也扛不住。

今天我們不聊虛擬DOM原理，直接上代碼、上工具，告訴你哪些寫法是“性能殺手”，哪些是“救星”。優化完，你的React應用會快得讓用戶懷疑是不是裝了外掛。

一、第1招：用`React.memo`避免“父動子也動”

React默認：父組件更新，所有子組件都會重新渲染（即使props沒變）。這會導致大量浪費。

**差代碼**：

const Child = ({ name }) => {
  console.log('Child渲染了');
  return <div>{name}</div>;
};
const Parent = () => {
  const [count, setCount] = useState(0);
  return (
    <div>
      <button onClick={() => setCount(c => c+1)}>点击 {count}</button>
      <Child name="张三" />
    </div>
  );
};

每次點擊按鈕，Child都會重新渲染，但它的name根本沒變。

**好代碼**：用`React.memo`包裝子組件。

const Child = React.memo(({ name }) => {
  console.log('Child渲染了');
  return <div>{name}</div>;
});

現在只有name變化時，Child纔會重新渲染。

**注意**：如果`Child`接收的props包含函數或對象，需要配合`useCallback`、`useMemo`（見第2招）。

二、第2招：用`useCallback`和`useMemo`緩存函數和值

在React組件裏，每次渲染都會重新創建所有內聯函數和對象。即使內容相同，引用也不同，導致React.memo失效。

**差代碼**：

const Parent = () => {
  const handleClick = () => console.log('clicked'); // 每次渲染都是新函数
  return <Child onClick={handleClick} />;
};

**好代碼**：用`useCallback`緩存函數。

const Parent = () => {
  const handleClick = useCallback(() => console.log('clicked'), []); // 依赖为空，永远不变
  return <Child onClick={handleClick} />;
};

對於複雜計算的值（比如過濾大列表），用useMemo緩存結果：

const visibleTodos = useMemo(() => filterTodos(todos, tab), [todos, tab]);## 三、第3招：虚拟列表，渲染一万条也不怕

直接渲染長列表（比如聊天記錄、商品列表）會導致瀏覽器創建上萬個DOM節點，內存爆炸，滾動卡頓。**虛擬列表**只渲染可視區域內的幾條，滾動時動態替換。

**不用自己造輪子，用現成庫**：

- `react-window`（轻量）

- `react-virtualized`（功能全）

import { FixedSizeList as List } from 'react-window';
const Row = ({ index, style }) => (
  <div style={style}>行 {index}</div>
);
<List
  height={400}
  itemCount={10000}
  itemSize={35}
  width={300}
>
  {Row}
</List>

一秒渲染一萬條，滾動絲滑。

四、第4招：代碼分割 + 懶加載，別一次加載所有組件

你的用戶訪問首頁，結果你把後臺管理、用戶設置、訂單詳情所有頁面的代碼都下載了。浪費流量，也拖慢首屏。

**用 React.lazy + Suspense**：

const Dashboard = lazy(() => import('./Dashboard'));
const Settings = lazy(() => import('./Settings'));
function App() {
  return (
    <Suspense fallback={<div>加载中...</div>}>
      <Routes>
        <Route path="/dashboard" element={<Dashboard />} />
        <Route path="/settings" element={<Settings />} />
      </Routes>
    </Suspense>
  );
}

每個路由的代碼單獨打包，只有訪問時才加載。

五、第5招：避免內聯對象和函數傳遞

即使不用memo，內聯對象也會導致子組件每次接收新對象，觸發重渲染。

**差代碼**：

// 每次渲染都是新对象**好代码**：把对象提取到组件外部或使用useMemo。

const childStyle = { color: 'red' }; // 外部定义，引用不变
<Child style={childStyle} />

六、額外絕招：使用`useTransition`標記非緊急更新

React 18引入了useTransition，可以把某些更新標記爲“低優先級”，讓高優先級交互（如輸入框打字）更流暢。

const [isPending, startTransition] = useTransition();
const [query, setQuery] = useState('');
const [list, setList] = useState([]);
const handleChange = (e) => {
  const value = e.target.value;
  setQuery(value); // 紧急更新：更新输入框
  startTransition(() => {
    // 非紧急更新：过滤大列表
    const filtered = hugeList.filter(item => item.includes(value));
    setList(filtered);
  });
};

這樣打字不會卡，列表過濾稍後完成。

七、工具检测：React DevTools Profiler

安裝React DevTools，打開Profiler標籤，錄製一段操作，可以看到每個組件渲染耗時。顏色越黃/紅，越需要優化。

八、總結：優化口訣

- 子組件純展示，包上`React.memo`。

- 函数和对象，用`useCallback`、`useMemo`缓存。

- 長列表用虛擬滾動。

- 路由懶加載，按需取。

- 內聯對象移出去，引用不變。

- 緊急更新與非緊急分開，用`useTransition`。
