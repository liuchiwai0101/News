容器隔離還不夠：Edera 從虛擬機監控器層限制 AI 智能體

內容機器翻譯自第三方媒體（InfoQ），僅供參考，以原文為準。

正文

Edera 推出了對象能力受限權限模型 ，承諾保護自主 AI 智能體工作負載的安全，使自主 AI 工作負載和模型上下文協議（MCP）服務器與敏感憑證隔離。該技術由 Edera 聯合創始人、傑出工程師 Ariadne Conill 牽頭。她因對底層開源安全技術的貢獻而知名。該技術通過直接在虛擬機監控器層實施細粒度的對象能力控制，應對現代企業架構面臨的一項緊迫挑戰：在不向 AI 智能體提供常規訪問憑證的情況下，嚴格限制其活動範圍。對象能力受限權限是一種安全模型，在實施細粒度訪問控制的同時，使自主 AI 工作負載和 MCP 服務器與敏感憑證隔離。

隨着越來越多的組織將自主編碼智能體和外部工具集成部署到生產環境，它們經常把敏感的 API 令牌、雲密鑰和管理員訪問憑證直接暴露給執行環境，而這些環境仍可能受到提示注入和供應鏈操縱的影響。

受限權限架構的核心，是將完成任務所需的操作權限與執行任務所依賴的底層憑證分離。傳統容器安全很大程度上依賴邊界隔離，以及注入環境變量或配置文件的靜態密鑰。如果由大語言模型驅動的智能體遭到入侵，攻擊者通常可以提取這些令牌，並在內部系統間橫向移動。Edera 提議通過虛擬機監控器強制執行對象能力控制，將智能體限制在明確界定的操作範圍內，同時不把密鑰放進工作負載本身。例如，AI 編碼助手可以在不持有個人訪問令牌的情況下，獲得修改單個 GitHub 倉庫的權限，從而確保遭入侵後的影響嚴格侷限於這一範圍。

為實現這種細粒度隔離，其 Agent Runtime 框架集成了多個運行時組件。 capcurl 負責無憑證 API 訪問，將獲準的請求經由隔離的代理轉發，同時不向智能體暴露底層認證材料。類似地， capsudo 管理限定作用域的命令執行，使工作負載無需獲得長期有效的管理員權限或 root 權限，就能運行特定的特權命令。通過集成 SPIFFE 和 SPIRE ，工作負載身份可得到密碼學驗證，並在不依賴長期有效的靜態密鑰的情況下建立雙向 TLS 連接和服務身份。

這些架構機制也直接延伸到模型上下文協議服務器。MCP 服務器連接大語言模型與企業工具和數據庫，因此經常成為高價值攻擊目標。通過在基礎設施層定義明確的對象能力，安全團隊可以將 MCP 服務器限制在特定的外部資源和命令範圍內。即使宿主模型行為異常或遭遇提示注入漏洞，也能防止其不受控制地訪問資源。這種方法通過將潛在入侵的影響範圍從整個環境縮小到離散的、針對特定任務的操作，補充了由硬件強制執行的運行時隔離。

評估自主智能體的工程團隊通常需要投入大量開發工作，構建自定義的憑證處理中間件和臨時拼湊的權限代理。受限權限模型承諾將這種控制機制下沉到虛擬機監控器和運行時層，統一企業系統向行為不確定的軟件授予權限的方式。聚焦於限定作用域的命令執行和工作負載身份的初步功能已經發布；基於憑證代理的 API 訪問和與編排器的深度集成，將作為更廣泛的 Project Lunchbox 計劃 的一部分在後續推出。
