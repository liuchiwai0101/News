OpenRouter 實測 Jev 1.13 與 Claude Opus 5 在 Banking77 分類任務上的準確率、延遲與成本

內容機器翻譯自第三方媒體（OpenRouter），僅供參考，以原文為準。

AI 導讀

OpenRouter 用 Banking77 測試集的 3,080 條客服語料對比 Jev 1.13 與 Claude Opus 5 的意圖分類表現。Jev 準確率 81.0% 比 Opus 的 84.4% 低 3.3 個百分點，但中位延遲 175 ms 約為 Opus（2,266 ms）的 1/13，每千次請求成本 $0.11 對 $2.42（啓用提示詞緩存）。

推薦理由

原文用同一測試流程給出兩家模型的準確率、延遲與成本數據，並演示了基於置信度的級聯路由方法，便於讀者按自身流量權衡選型。

正文

Jev 是 TypeSafe 的 System One 決策模型。給它一個應用狀態對象和一個帶類型的問題，它就會返回一個帶類型的答案、一個置信度分數，以及每個可能選項的概率（即 Decisions API 的響應類型，而非聊天端點）。根據 TypeSafe 的宣傳，在此類分類任務上，你可以用像 Jev 這樣的小型判斷模型替換前沿聊天模型，從而在成本和延遲兩方面都獲得顯著降低。那麼你犧牲了多少準確率？

我們將 3,080 條 Banking77 客户支持話語分別輸入 Jev 1.13 和 Claude Opus 5——截至 2026 年 9 月 22 日，後者是 OpenRouter 用户在其 排行榜頁面的 Task spend 板塊中用於分類任務花費最多的模型。每條話語被歸入 77 種銀行意圖之一，兩個模型都獲得了相同的每種意圖的一行描述。

下圖將 Jev 和 Opus 並排展示，呈現它們在準確率、中位延遲和每千次請求成本上的對比。

Jev 在準確率上落後 Opus 3.3 個百分點，但其中位速度快 13 倍，成本僅為 Opus 的 1/22。

我們如何運行

Banking77 是來自 PolyAI 的一個話語級客户支持意圖數據集，採用 CC BY 4.0 許可。這些話語很短，中位數為九個詞，每一條都標註為 77 個意圖之一。當我們在 Banking77 上運行 Jev 和 Opus 時，我們使用了完整的測試劃分，其中包含 3,080 個樣本，每個意圖 40 個。有些意圖彼此足夠接近，以至於模型不能只抓住幾個關鍵詞就停止閲讀。想想 card_arrival 與 card_delivery_estimate。

我們僅根據標籤名稱，為每個意圖寫了一條單行判定標準，完全沒有查看測試數據，並且把完全相同的一份標準清單同時給了 Jev 和 Opus。為了給 Jev 打分，我們把每句話作為一道 Decisions API Choice 問題發送，並將這 77 條標準作為選項。對於 Opus，我們構建了一個提示詞，其中系統消息列出所有標準，然後是一條僅包含該話語的用户消息。我們以 temperature 為零、關閉推理，並使用帶 77 個標籤枚舉的嚴格 JSON schema 響應格式來運行 Opus。我們為系統消息開啓了 提示詞緩存，因為它在每次請求中都完全相同。兩個模型都從同一台機器運行，我們一次發送 8 個併發請求，並將延遲測量為客户端通過 OpenRouter 觀察到的往返時間。

Jev 的準確率如何？

來説數字。在 Banking77 上，Jev 為 81.0%，Opus 為 84.4%。配對 bootstrap 給出的 95% CI 為 2.3 到 4.4 個百分點，因此 Opus 領先約三個百分點不太可能是噪聲。

從好的方面看，這兩者的一致性非常高。它們在 89.3% 的話語上意見一致。在它們出現分歧的地方，Opus 單獨答對 175 個，Jev 答對 72 個。

從不利的方面看，兩者仍明顯低於在所有 10,003 個 Banking77 訓練樣本上微調過的編碼器所報告的略高於 90% 的水平。這就是依賴單行標準而不是進行完整微調的代價。

按類別劃分，Opus 在 77 個意圖中有 35 個領先 Jev，Jev 在 15 個上領先，27 個打平。Opus 領先幅度最大的是 receiving_money，達到 80.0%，而 Jev 為 52.5%。與此同時，Jev 在 compromised_card 上表現出色，達到 95.0%，而 Opus 為 70.0%。Opus 傾向於將盜刷的銀行卡信息誤判為無法識別的支付。

Jev 有多快、有多便宜？

簡而言之，Jev 的往返延遲中位數為 175 ms，p95 為 270 ms。而 Opus 在未開啓推理模式的情況下，往返延遲中位數為 2,266 ms，p95 為 3,004 ms。這意味着 Jev 最慢的一次調用（約 1.6s）比 Opus 最快的一次調用（約 1.9s）還要快。

Jev 的總費用為 $0.34，即每千次請求 $0.11。Opus 則為 $7.44，即每千次請求 $2.42。Opus 的這個數字是在 3,700-token 系統提示詞已緩存的情況下得出的，因此所有請求都按緩存讀取費率計費，而非標價費率。如果不使用緩存，Opus 的標價費率約為每千次請求 $19。所以，如果你在使用前沿模型搭配標籤分類體系，記得緩存那個系統提示詞。

基於 Jev 置信度的路由

Jev 會給出一個置信度分數，但它並非經過校準的概率。在這裏，它在中間區間高估了自身的準確率。儘管如此，它的排序表現仍然不錯。在置信度 ≥0.99 的 58% 話語中，準確率為 96.3%。而在低於 0.5 的 3.5% 話語中，準確率為 29.6%。

這種排序正是你實現級聯所需要的。接受高於給定閾值的 Jev，其餘交給 Opus。以下是每個閾值下的準確率和每千次成本，範圍從僅用 Jev 一直到僅用 Opus。

注意事項

所以讓我們狹義地談談我們實際做的測試：一個數據集、一個領域、一種提示詞設計，以及某個下午的一個十五分鐘窗口。

如果這裏存在 Opus 的記憶化優勢，它的得分可能會因此被略微抬高，因為 Banking77 發佈於 2020 年。但僅憑這一次運行無法判斷。

另一點是，兩個模型都在某一個類別上栽了跟頭，因為判定標準僅根據標籤名稱編寫，沒有參考示例消息。在這個案例中，其中一個標籤是 get_physical_card，它涵蓋的是關於 PIN 是否單獨發送的查詢。僅憑名稱幾乎不可能猜到這一點。兩個模型在該類別上都是 40 題得 0 分，將大多數消息路由到了 change_pin。僅排除這一個類別，Jev 達到了 82.1%，Opus 達到了 85.5%。但一個上線團隊會使用留出的訓練數據來迭代判定標準，而不是測試集，兩個模型都會變得更好。

我們展示的級聯表格使用的正是用於準確率測量的那 3,080 個樣本，所以這是一個上限。請根據你自己的流量來選擇閾值。

最後，這些測試是在 Opus 處於“推理關閉”模式且開啓結構化輸出的情況下運行的。Opus 未在“推理開啓”模式下測試，也未使用其他 schema 或 few-shot 示例進行測試。

這意味着什麼

如果 3 個百分點的準確率優勢值得每千次請求多花 $2.42，那就選 Opus。如果你面對的是高流量、低延遲的場景，或者需要一個備用方案，Jev 單獨運行與 Opus 的差距在 3.3 個百分點以內。更好的做法是，基於 Jev 的置信度分數運行級聯，能將與 Opus 的差距縮小到 0.4 個百分點以內，而成本不到 30%。

Decisions API 參考文檔介紹了基本的請求結構。Jev cookbook通過一個可運行的 TypeScript Choice 問題帶你上手。Jev 驗證級聯 cookbook用代碼展示了升級模式：由廉價模型起草，Jev 檢查草稿，前沿模型只處理未通過檢查的部分。Banking77 測試集是 PolyAI 倉庫中一個 3,080 行的 CSV 文件。

常見問題

在意圖分類上，Jev 與 Claude Opus 5 相比準確率如何？

在 2026 年 9 月 22 日運行的 Banking77 測試集上（包含 77 個意圖的 3,080 條語句），Claude Opus 5 達到了 84.4% 的準確率和 83.6% 的 macro-F1，而 Jev 1.13 達到了 81.0% 的準確率和 80.5% 的 macro-F1。

配對差距在準確率上為 3.3 個百分點，95% bootstrap 區間為 2.3 至 4.4 個百分點。兩個模型在 89.3% 的語句上結果一致。

在分類任務上，Jev 比前沿模型快多少？

在客户端觀測到的往返延遲中位數和 p95 上，Jev 實現了中位數 175 ms 和 p95 270 ms，而禁用推理的 Claude Opus 5 實現了中位數 2,266 ms 和 p95 3,004 ms，中位數約高出 13 倍。這些數字是在 8 個併發請求下從同一客户端測得的。它們包含網絡時間以及提供商系統在實際推理前的任何排隊時間。

在 OpenRouter 上用 Jev 做文本分類要花多少錢？

在 typesafe/jev-1.13 上，全部 3,080 次 Banking77 請求總計計費 $0.34，即每千次請求 $0.11，約合每次請求 $0.0001。對包含 77 個標籤的系統提示詞使用提示詞緩存後，同樣的請求在 anthropic/claude-opus-5 上總計計費 $7.44，即每千次 $2.42。若不使用緩存，Opus 按標價計費約為每千次 $19。

我可以用 Jev 的置信度分數來決定何時回退到更大的模型嗎？

可以，在我們的數據中它確實能作為排序信號發揮作用。我們測得，在置信度至少為 0.99 的那 58% 話語上，Jev 的準確率為 96.3%；而在置信度低於 0.5 的那 3.5% 話語上，準確率為 29.6%。將所有置信度低於 0.9 的請求路由到 Claude Opus 5 後，準確率恢復到 84.0%，與單用 Opus 相差在 0.4 個百分點以內，成本為每千次請求 $0.69。

由於該分數並未按概率進行校準，請根據你自己的數據選擇適用的閾值。
