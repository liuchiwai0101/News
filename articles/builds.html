代理 的能力取決於其執行的環境。快速可靠的開發環境，讓代理 能夠從頭到尾完成複雜、耗時的任務。

過去，每個雲端工作階段都需要大量設定：啟動機器、複製儲存庫，並執行安裝指令碼。在大型、複雜的儲存庫中，這種即時啟動可能要花上好幾分鐘，代理 才能開始執行。

今天，我們推出 打造：由 Cursor 持續在背景準備、可立即使用的開發環境副本，且無需額外費用。當您啟動代理 時，它會在已準備好的環境中立即開始執行，讓您更快獲得回應，速度最高提升 3 倍。

當錯誤的提交或相依套件更新導致環境無法運作時，代理 仍會使用上次成功的 打造。您可以不中斷地繼續工作，同時在背景進行偵錯。

打造是 Cursor 在背景準備好的開發環境副本。預設情況下，Cursor 每小時會建立一個新的打造。Agent 無須在每個工作階段從頭設定環境，而是直接啟動至已就緒的版本：儲存庫已複製、相依套件已安裝，安裝指令碼也已完整執行。

打造成功後，便會成為後續 Agent 啟動時使用的環境。Cursor 會保留隨時可用的暖機副本，讓新的 Agent 從運作中的機器分支，而非從磁碟還原。如此一來，工作階段幾乎可立即啟動，不必讓下一個 Agent 等待。

環境設定既已完成，Agent 就能更快開始處理實際工作。在 Cursor，我們的內部環境現在啟動速度快了 10 倍，首次產生 token 的速度快了 3 倍。

我們的客戶也有同樣的體驗：

雲端代理一律從最新成功的建置開始。如果相依套件升級導致安裝指令碼失效，或 Docker 建置失敗，該建置就不會啟用，您也會收到通知。新的和現有的工作階段都能安全地持續執行，同時您可手動或使用代理在背景偵錯環境。

您現在可以直接在 雲端代理 儀錶板中查看每個打造，內容包括：

- 每個環境的 **打造**分頁，顯示類型、狀態、開始時間和版本資訊

- 包含日誌及打造所擷取確切提交 SHA 的打造資訊

- 將每次代理執行準確對應至所使用打造的記錄

- 可設定打造 Git 狀態的閾值，避免代理相較於您的預設分支落後太多才開始執行

Agent 也可以使用內建的 Cursor Cloud MCP 查看及管理打造。

針對現有環境，請在 雲端代理 儀錶板中開啟該環境，前往 **打造** 分頁，然後按一下 **Enable Builds**。或者，先按一下 **Run setup agent**，以測試遷移並審查建議的組態變更。

由於 打造 使用檔案系統快照運作，因此此階段有幾項值得確認的事項：

- 更新安裝指令，納入可預先準備的所有項目，例如相依套件

- 如果安裝作業需要私有登錄檔的認證，請使用團隊或環境密鑰。使用者密鑰不會納入 打造，而會在代理啟動時加入。

- 首次向代理輸入提示詞時，啟動指令仍會執行。請將其用於工作階段開始時必須保持最新狀態的服務，例如啟動 Docker 容器或其他長時間執行的行程

自 8 月 17 日起，所有新環境和現有環境都將預設使用 打造，您無需支付額外費用。
