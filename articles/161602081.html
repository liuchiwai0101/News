最近我一直在研究 AI Agent 這個方向。之前幾篇文章提到過，Agent 是前端轉型 AI 全棧最該切入的點之一。這次我直接從零搭建了一個 Agent 項目，把過程和代碼都記下來了。

2026 年行業裏出現了一個新角色——Agent 工程師。核心不是訓練大模型，而是編排 AI Agent 的工作流：給它工具、定義規則、讓它自主完成任務。前端工程師有用戶視角和交互思維，做這件事有天然優勢。

這篇教程用 LangChain + LangGraph 搭建一個智能客服 Agent，能理解用戶問題、查詢知識庫、生成回答。技術棧選的都是前端友好的方案。

要做的 Agent 能完成這幾件事：

- 理解用戶的自然語言問題

- 從預設知識庫中檢索相關信息

- 根據檢索結果生成回答

- 知識庫裏沒有答案時，如實告知

**1. 向量檢索結果不穩定**

一開始知識庫只有 3 條數據，檢索效果很差。後來發現 Embedding 質量比數量更重要——知識庫裏每條內容應該是一個完整的知識點，而不是大段文字切開的碎片。

**2. Agent 會編造答案**

提示詞裏寫了“不知道就說不知道”，Agent 偶爾還是會自己編。把 temperature 調到 0.3 以下，同時在提示詞中給明確約束，好一些了。

**3. 工具調用死循環**

Agent 拿到問題後反覆調用同一個工具。原因是沒有設置終止條件。在提示詞里加上“每個工具最多調用一次”就解決了。

**4. 響應速度慢**

Embedding + LLM 兩重調用，首屏響應 2-3 秒。我的優化方案：先返回“正在思考”的佔位消息，再用流式輸出逐步展示回答。

改改提示詞、換換工具，看看 Agent 的行爲會怎麼變化，這是學 Agent 最快的方式。
