Java4Shell 漏洞 CVSS 9.2 分　CISA 促即時修補 Oracle Java

內容機器翻譯自第三方媒體（NewMobileLife 流動日報），僅供參考，以原文為準。

美國網絡安全及基建安全局（CISA）於 2026 年 11 月 17 日發出警報，要求機構即時修補被稱為 Java4Shell 的 CVE-2026-114938 漏洞。這是涉及 x86-64 HotSpot JVM Base64 解碼器的嚴重記憶體損壞問題，特製輸入可令 JVM 崩潰，甚至免認證執行任意程式碼。

一則 65 字元輸入就觸發

發現漏洞的資安公司 Calif 表示，65 個字元輸入，即 64 個 A 加一個等號，已可觸發。解碼器為該輸入配置 50 bytes 陣列，尾部補位令輸出長度算成負數，結果完整寫入 64 bytes，越界 62 bytes。Calif 按 CVSS 4.0 評 9.2 分，Oracle 則按 CVSS 3.1 評 8.1 分。

要 AVX-512 VBMI 才算中招

漏洞只在支援 AVX-512 VBMI 的 x86-64 處理器上觸發，包括 Intel Ice Lake 或更新架構、AMD Zen 4 或更新架構，ARM64 不受影響。Oracle 公告列出的受影響版本為 Java SE 17.0.21.0.3、21.0.13.0.3、25.0.5.0.3 及 27.0.1.0.3；OpenJDK 17.0.6 或更新的建構版本同樣受影響。

補丁已出　未及更新先用啟動參數

Oracle 11 月安全更新已包含修正；OpenJDK 亦於 11 月 17 日發布安全公告。未能即時更新者可用啟動參數 -XX:-UseBASE64Intrinsics 或 -XX:UseAVX=2。

CISA 建議機構先盤點 JDK 及 Java runtime，包括第三方應用及容器映像內建版本，優先修補對外系統；短期間可限制及驗證 Base64 輸入大小、限制未認證存取。

Calif 已示範對 Keycloak、Jira、Confluence、JFrog Artifactory、Jenkins 及 PingFederate 免認證執行任意程式碼，部分產品則要登入後才可；目前沒有通用利用程式。Quang Luong 稱要求 Codex 審視 JIT 及 intrinsics，一小時找到漏洞，兩小時做出首個利用程式。
