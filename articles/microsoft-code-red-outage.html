Microsoft 宣佈「Code Red」　24 小時大故障後全面改革工程流程

內容機器翻譯自第三方媒體（NewMobileLife 流動日報），僅供參考，以原文為準。

Microsoft 發生長達 24 小時的服務故障後，宣佈集團內最嚴重、最緊急的「Code Red」警示，全面改革重大故障的預防與應對方式。路透社報道引述內部備忘錄指出，11 月 12 至 13 日的事故影響澳洲、日本及美國的政府部門，延誤交易公司及幹擾航空通訊。Microsoft 表示，事故與網絡活動或 AI 代理無關。

Exchange Online 史上對客户影響最大事故

事故波及 Exchange Online、Outlook、Teams、Copilot 等產品。總裁 Jason Henderson 在備忘錄指，這是 Exchange Online 史上對客户影響最大的事故，從未有如此多客户長時間無法使用電郵。Microsoft 把成因歸於 7 月引入、一直未被偵測到的 Windows 擴展性缺陷，行政總裁 Satya Nadella 已公開道歉。

11,000 條訊息組成的「戰爭迷霧」

企業副總裁 Amanda Silver 在週一的備忘錄中形容，工程師在「戰爭迷霧」中應變。公司派出頂尖工程人員，但回應人員在 11 個 Teams 對話中交換超過 11,000 條訊息，診斷數據亦散落於碎片化的內部追蹤系統，令團隊難以對假設和決策維持統一的整體圖像。執行副總裁 Charles Lamanna 在檢討會上稱，出事元件經歷了「大約十年的可接受故障量」。

五條工作線　目標一小時內全球解決

Microsoft 為 Code Red 動員五條工作線，涵蓋卸載負載、按地域分割流量及加快復原機制等工作。公司訂下的目標，是未來發生事故時在一小時內於全球解決問題，同時計劃部署 AI 代理，協助工程師更快診斷系統健康數據。Henderson 亦會與 Substrate 領導團隊每日開會、每週檢討，追蹤事故衍生的行動。

Henderson 承認：「我們多年來所做的一切，不足以在週四保護我們。」他亦承認緊急修補程式的全球部署速度太慢。另一份本月初的備忘錄指出，一次緊急生產修復需時五至六日才達到全球飽和；至於最緊急的安全問題，目標是由偵測至安全地完成全球部署只需一小時，但公司「顯然還未做到」。Microsoft 發言人回覆路透社時表示，服務恢復不等於工作結束，團隊正日以繼夜落實教訓。
