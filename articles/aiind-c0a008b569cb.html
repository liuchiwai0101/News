2026年IDEA 大會：AI時代編程語言將深刻影響軟件能力交付上限

內容機器翻譯自第三方媒體（InfoQ），僅供參考，以原文為準。

正文

“計算機界的諾貝爾獎”圖靈獎 1966 年設立至今，因編程語言獲獎的成果約佔五分之一，主要研究領域為編程語言的獲獎人約佔三分之一。在 2026 年 IDEA 大會上，美國工程院外籍院士、IDEA 研究院創院理事長沈向洋由此笑稱，“懂語言者得圖靈”。

這背後是計算機科學的一條主線。代碼是所有工作流、所有邏輯的底層，編程語言則是人向機器表達邏輯的媒介。每一個計算時代都有與之相應的語言，語言的演進始終回應着計算需求的變化。

AI 時代的變化在於，編程的主體正在從人變成 Agent。對人來説，語言似乎不再重要，用 Vibe Coding 提出需求就能得到能跑的程序，不必關心 AI 選了哪門語言。但對 Agent 來説，語言的選擇直接決定軟件的安全性、性能與可維護性，也就決定了最終交付軟件的能力上限。

舊的語言為上一個計算時代定型，為 Agent 而生的新語言，則打開了參與定義 AI 時代基礎軟件體系的機會窗口。

基於這個判斷，IDEA 研究院四年前立項自研語言 MoonBit。四年間，這門語言從零起步，如今在全世界每週被下載近百萬次，近四成代碼由海外開發者貢獻。在近期的 2026 IDEA 大會上，MoonBit 正式發佈 1.0 版本。MoonBit 的作者張宏波在編程語言領域深耕近二十年，此前在彭博和 Meta 做語言開發，沈向洋稱他是自己所知唯一一位寫出的編程語言被全球數萬人使用的中國人。

過去一年，整個軟件工程發生了巨大的變化，很多軟件基礎架構都在重寫，比如版本管理工具、代碼審核工具。但這還是比較上層的東西。更底層一點看，編程語言是我們每個程序員都要使用的工具，隨着智能體編程的範式轉移，它會不會引入新的工具和革新？這是我們今天討論的話題。

AI 時代，編程語言其實存在一個悖論。一部分人認為編程語言不再重要了，因為人只需要表達需求，智能體去編寫代碼，不需要關心它用什麼語言寫。另一部分人則認為編程語言無比重要：它是冰山之下的技術，選用什麼語言，對軟件實現的可靠性和性能非常關鍵。比如選 Python 這樣的動態語言，性能很容易碰到天花板，也很難進行驗證。這也是為什麼過去一年，Rust 這樣一門系統編程語言變得非常流行。2023 年有人問 Elon Musk，什麼樣的編程語言可以用來構建 AGI，他的回答是 Rust；今年 9 月，微軟也把 Rust 列為公司的 tier1 語言。

這裏還有兩個很有意思的例子。ArtCraft 這家公司在用 Rust 把 Adobe 全家桶，比如 Photoshop，以及微軟的 Office 套件移植過來，基本已經達到了可用的原型版本，大家可以去體驗一下。為什麼選 Rust？因為 Rust 提供了非常可靠的性能和健壯性，只要編譯通過，系統就能比較好地運行。另一個例子發生在今年年初。Anthropic 旗下的 Bun，大家可能不太熟悉，但應該知道 Claude Code，這可能是現在 AI 領域最賺錢的軟件，底層支撐技術就是 Bun。Anthropic 的工程師把 Bun 的開發語言從 Zig 換成了 Rust，整個代碼庫大約 54 萬行，只用 11 天就完成了移植，並行最多開了 64 個 Claude。這在以前是需要幾年時間的高風險工作，現在 11 天就能完成，按 API 定價算，成本大約 17 萬美元。

這是個非常了不起的工作，也説明 AI 時代編程語言的選擇標準正在發生劇烈變化。以前 Python 為什麼是最受歡迎的編程語言？因為它對人非常友好，不管科班還是非科班出身，都容易看懂、容易上手。但當代碼越來越多由 AI 編寫，這些對人友好的優化指標就不再那麼重要了，語言的價值更多體現在能否幫助智能體高效、可靠地交付軟件。這就是 Rust 突然大受歡迎的原因。

那麼 Rust 就是終極答案嗎？我覺得不一定。Rust 畢竟是 2006 年提出的語言，快 20 年了，智能體時代的語言還有一些新需求。Golem Cloud 的 CEO John 寫過一篇推文，説 Rust 最近在智能體編程中走紅，但很多使用者其實並不懂 Rust；如果性能、磁盤佔用和內存消耗問題得不到顯著改善，這股熱潮就難以持久。他還寫過另一篇很有意思的推文：“MoonBit 類似 Rust，但有 GC 和內置異步，用起來非常愉快。”Golem 即將發佈的 1.5 版本就支持 MoonBit，可以用它構建高可靠、可持久運行的智能體。

John 的觀察説明，智能體時代對編程語言提出了新的要求：從安全到機器可驗證，從運行快到迭代快。傳統編程語言不太重視編譯速度，C++、Rust 都編譯得很慢，因為它們更在意運行性能。但現在代碼由智能體修改，編譯速度就變得非常重要：人一小時可能只編譯幾次，智能體一小時可能編譯幾百次甚至上千次，如果編譯很慢，智能體的主要瓶頸就卡在編譯速度上。AI 也改變了開發成本結構，代碼生成本身變得很便宜，瓶頸更多在於等待編譯、驗證反饋、安全執行和工具集成。舉個誇張的例子，瀏覽器本身編譯一次就要幾個小時，智能體就很難做快速迭代。

軟件需求同樣在變化。傳統上我們更多依賴基石軟件，腳本沒那麼重要；但 AI 時代，智能體完成數字自動化的方式，是寫幾行代碼調用基石軟件來完成任務，智能體成了主要的軟件生產者。整個軟件需求由此分成兩部分：即時腳本，和高可靠的基石軟件。過去這兩部分對應兩類不同的語言，腳本用 TypeScript、JavaScript，基石軟件用性能好、可靠的 Rust。那麼，能不能用同一套語言和工具鏈同時覆蓋這兩類需求？這就是新的 AI 原生編程語言的機會。

歸納一下，智能體時代的編程語言需要做到三件事：讓智能體安全地執行、可靠地交付、高效地迭代。落到語言特性上就是四點：安全、可驗證、編譯快、運行快。我們認為，這也是 AI 原生編程語言最顯著的四個特性。

MoonBit 就是按照這四個特性從頭設計的。它由粵港澳大灣區數字經濟研究院（簡稱“IDEA 研究院”） 基礎軟件中心主導開發，2022 年 10 月立項後一個月，ChatGPT 就發佈了。它可以説是一門和大模型時代共同成長的編程語言與工具鏈。它的目標，就是用同一套語言與工具鏈，同時支撐剛才説的即時腳本和高可靠的基石軟件。

MoonBit 是一門面向 AI 時代、為智能體設計的通用編程語言。雖然為 AI 而設計，但它首先是一門通用編程語言，對標 Java 和 Go，靜態類型、自動內存管理，面向應用程序開發。它的一個顯著特點是多後端，可以編譯到 JavaScript、WASM 和 Native，用同一套語言就能構建前後端，既可以做 GUI 開發，也可以做雲服務開發，WASM 後端還可以用於智能體開發。MoonBit 支持多種編程範式，包括函數式、面向對象和麪向數據編程。大家感興趣的話，可以到官網查閲更多資料，這裏就不展開了。

MoonBit 為 AI 所做的設計，其實很早就體現出來了。早在 2024 年，我們就寫過一篇探索 AI 友好的語言與工具鏈設計的文章，發表在 LLM4Code 上，當時還是在一個比較老的小模型 Code Llama 34B 上，研究怎麼讓 AI 更好地生成 MoonBit 代碼。

不過，要論證什麼樣的語言對 AI 更友好、什麼樣的語言不友好，其實是一個很複雜的問題。我們很難做 A/B 對照實驗，你無法構建兩個同樣的大模型，讓 A 語言和 B 語言的語料完全相當，再來對比它們的 AI 代碼合成通過率。比較幸運的是，學術界有同行做了這樣的研究。瑞士和西班牙的兩位教授寫了一篇文章，比較 MoonBit 和 Gleam 這兩門語言在 GPT-4o 上的 AI 代碼合成通過率。在 GPT-4o 這個比較老的模型上，這兩門語言的語料都比較匱乏，而 MoonBit 當時的倉庫量只有 Gleam 的七分之一。他們發現，在 HumanEval、MBPP 和 McEval-Hard 這幾個測試集上，語料更少的 MoonBit 合成通過率反而遠高於 Gleam，比如在 McEval-Hard 上有將近 6.6 倍的提升。

到了今年，我們用一個更大、更新的前沿大模型 Opus 5.5，讓它分別用 MoonBit 和 Rust 編寫同一個與 SQLite 兼容的數據庫引擎，各做了三次測試，測試集約 500 項，其中 242 項是隱藏測試。我們驚喜地發現，MoonBit 消耗的 token 甚至比 Rust 還少 12%，成本也比 Rust 略微便宜一點，而兩種語言的測試通過率幾乎相同。

這是一個非常了不起的結果。即使在最新的前沿大模型上，MoonBit 的語料比 Rust 低兩個數量級，大約只有 Rust 的 1%，我們仍然能得到與 Rust 持平甚至更好的效果。我們有理由相信，在下一代大模型上，MoonBit 的 AI 代碼合成效果會超過 Rust。

所以展望 2027 年，隨着更多高質量語料的積累，疊加 AI 友好的語言設計，MoonBit 有機會超越主流語言，提供更經濟、更高效的代碼合成流水線。我們也預計 2027 年生態會進一步發展，會有大規模的代碼移植到 MoonBit 生態。

具體來説，MoonBit 通過三個特性支撐智能體的安全執行、可靠交付和高效迭代：輕量級沙箱、原生的機器證明系統，以及極致的迭代速度與運行效率。下面逐一展開。

第一個是沙箱。沙箱其實是一個古老的概念，很早以前做服務器開發時就有了，但智能體的流行讓它變得無比重要。今天數字世界的自動化，基本都是通過智能體寫一段代碼來完成的，而智能體寫的代碼不像人寫的代碼那樣可靠，它很可能犯錯誤，比如不小心刪掉你的文件，帶來災難性的後果。所以我們需要把智能體生成的代碼放在沙箱裏執行。比如一段讀取銷售報表、生成彙總報告的代碼，我們可以授權它訪問指定的資源文件，但必須拒絕它訪問互聯網，這正是沙箱要做的事情。

MoonBit 的沙箱是基於 WASM 的語言級輕量沙箱，和 Docker 沙箱、MicroVM 沙箱不一樣，它的啓動速度極快，可以做到微秒級，而 Docker 和 MicroVM 即使做了非常好的優化，大概也只能到毫秒級。其次，沙箱本身需要和宿主集成，如果沙箱完全不能訪問外部世界，你沒法給它提供資源文件，它什麼事也做不了。MoonBit 的沙箱和宿主的集成是輕量級的，不需要做任何特殊設置，而 Docker 和 MicroVM 需要做文件掛載之類的配置。
