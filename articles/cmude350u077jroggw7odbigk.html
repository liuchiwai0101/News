OpenRouter 發佈 2026 年最佳嵌入模型選型指南，覆蓋 37 個目錄條目

內容機器翻譯自第三方媒體（OpenRouter），僅供參考，以原文為準。

AI 導讀

OpenRouter 於 2026 年 9 月 11 日核實嵌入模型目錄共 37 個條目，並通過自家 embeddings API 向 19 個模型發送批量請求、共 28 項檢查，確認請求與響應行為。

推薦理由

作者用自家 API 實測 19 個模型並按用例給出候選、價格與維度，讀者可按輸入類型和存儲約束直接對照選型。

正文

嵌入向量模型決定了你的檢索系統能檢索到什麼。它把每個輸入轉換為一個向量，並將相關的輸入彼此靠近放置，這樣你的應用就能按語義而非精確措辭來檢索。

最佳選擇取決於你需要檢索的材料。英文知識庫、多語言支持檔案庫、源代碼倉庫，以及文本加圖像的集合，各自有着不同的需求。向量維度、上下文長度、公開權重和價格也會改變這一決策。

我們為英文 RAG、多語言檢索、代碼搜索、文本加圖像檢索以及低成本索引分別篩選了候選模型，然後通過我們的 embeddings 端點向每一個模型發送了實時請求。

最後驗證時間： 2026 年 9 月 11 日。我們的嵌入向量模型目錄在該日期返回了 37 個條目，其中包括部分模型的批量和預覽變體。

提供商可能會增加或移除路由，提示詞價格也可能變化。在開始大規模索引或重新索引任務之前，請查看當前的模型頁面。如果模型頁面與本指南不一致，請以模型頁面為準。

簡而言之

  • 英文 RAG 從 openai/text-embedding-3-small 開始。
  • 當你的輸入超過 8,192 tokens，或者你想在 Voyage 4 各檔之間切換而無需重建索引時，可以測試 voyageai/voyage-4-large。如果你想要一個開放權重替代方案，qwen/qwen3-embedding-8b 擁有更長的上下文窗口，且提示詞價格更低。
  • 使用 qwen/qwen3-embedding-8b 進行多語言檢索，採用公開權重；使用 voyageai/voyage-code-4 進行代碼搜索；使用 google/gemini-embedding-2 或 voyageai/voyage-multimodal-3.5 進行文本與圖像檢索。
  • perplexity/pplx-embed-v1-0.6b 在我們候選名單中的付費文本模型裏擁有最低的提示詞價格。nvidia/nemotron-3-embed-1b:free 是一個免費的文本嵌入向量路由，具有 32,768-token 的上下文窗口。
  • 我們的 API 檢查確認的是請求和響應行為，而非檢索質量。在構建或重建完整索引之前，請至少用你應用中的標註查詢和文檔對比兩個候選方案。

我們如何選擇這些模型

我們使用實時目錄來確認可用性、上下文窗口、輸入類型和提示詞價格。我們查閲了模型提供商的文檔以瞭解其能力和基準測試結果，然後通過我們的嵌入向量端點發送實時請求，以確認請求和響應行為。

我們向 19 個模型發送了雙字符串批量請求，共運行了 28 項檢查，涵蓋批量輸入、可配置維度、圖像輸入、文本加圖像輸入以及錯誤處理。16 個付費模型每個輸入返回一個向量。響應確認了下表中的默認維度，並表明 dimensions 參數適用於 OpenAI Text Embedding 3 Small、Gemini Embedding 2 和 Voyage 4 Large。對不存在的模型發起請求會返回 400 錯誤，並附帶消息 Model openai/does-not-exist does not exist。

這三條免費路由從我們的測試賬户返回了 404 錯誤，因為該賬户的隱私設置不允許路由到可能使用免費模型提示詞進行訓練的提供商。我們將在下文的免費選項部分描述該設置。我們為這些模型列出的默認維度來自它們的模型卡，而非來自我們的響應。

這些請求確認了 API 兼容性。它們並未衡量檢索質量。我們排除了響應時間，因為每個模型都是在不同的服務條件下接收一個較小的請求。我們將每個用例與一項有文檔記錄的能力進行匹配，然後使用語言覆蓋範圍、上下文長度、輸出維度、公開權重和提示詞價格來縮小候選範圍。已發佈的評測，包括 MTEB 和 CoIR，幫助我們確定了要測試的模型。你標註的檢索結果應當決定你部署哪一個。

英文 RAG 的最佳默認選擇

當你需要一個用於英文知識庫的託管模型時，從 openai/text-embedding-3-small 開始。它的默認向量有 1,536 個值，是 openai/text-embedding-3-large 默認值的一半。在相同的數值格式下，Small 使用的原始向量存儲只有一半。首次評估時保留 1,536 個值的默認設置，只有當默認設置滿足檢索目標但存儲或搜索成本仍是制約因素時，才考慮縮減。

你可以用 dimensions 參數縮短它的向量。我們使用 "dimensions": 256 的請求返回了一個包含 256 個值的向量。更小的向量佔用更少的數據庫存儲，並減少相似度搜索所需的工作量，但它們也可能降低檢索質量。在更改現有索引之前，先測試更小的尺寸。

OpenAI 將 text-embedding-3-large 描述為其在英文和非英文任務上能力最強的嵌入模型。當 Small 遺漏相關結果時，尤其是當用户跨語言搜索時，測試它。遷移到 Large 會改變向量大小和提示詞價格，因此在重新嵌入語料庫之前，先在留出問題上比較兩個模型。

如果你的輸入超過 Small 的 8,192-token 限制，測試 Voyage 4 Large。對於較短的輸入，使用相同的分塊、查詢和相關性標籤來比較兩個模型。

Voyage 4 系列，適用於更長的輸入

當你需要一個託管的 32,000-token 模型，且要求維度可調、併兼容 Voyage 4 各檔位時，可以測試 voyageai/voyage-4-large。它最多接受 32,000 tokens，並支持 256、512、1,024 和 2,048 維。在我們的 API 檢查中，將 dimensions 設為 512 返回了一個包含 512 個值的向量。

該系列包括 voyageai/voyage-4 和 voyageai/voyage-4-lite，它們使用相同的上下文窗口。Voyage 表示，使用 4 系列創建的所有嵌入向量彼此兼容。這讓你可以針對現有索引測試另一個 Voyage 4 檔位。在部署前，請在具有代表性的樣本上驗證檔位變更。兼容的向量空間免除了重建索引的要求，但並不能保證檢索結果完全一致。

用 Large 和至少一個更低的 Voyage 4 檔位在同一評估集上運行。如果它們在相同截斷點檢索到相同的相關段落，那麼更低的檔位可能滿足你的需求。

Voyage 模型是託管服務。如果你需要公開權重以便自託管或控制部署，Qwen3 Embedding 8B 是本短名單中的開放權重替代方案。

最適合多語言檢索的開放權重模型

qwen/qwen3-embedding-8b 是我們開放權重的多語言選擇。它支持 100 多種語言，你可以從 Hugging Face 下載權重，或通過我們的 API 調用託管模型。我們的默認 API 請求返回了 4,096 個值。在相同的數值格式下，一個 4,096 值的向量佔用的原始存儲空間是一個 1,024 值向量的四倍。在估算索引大小時要把這一差異考慮進去。我們的 API 檢查並不能確定 Qwen3 Embedding 8B 是否比 nvidia/nemotron-3-embed-1b:free 檢索效果更好。當路由成本和向量大小會影響決策時，在最終確定之前，請在同一份標註數據集上對兩者都進行測試。

Qwen 模型卡顯示，截至 2025 年 6 月 5 日，其在 Massive Text Embedding Benchmark（MTEB）上的多語言得分為 70.58。這是廠商報告的公開基準測試結果。用它來把 Qwen 列入候選名單，然後測試你的應用所支持的每一種語言和領域，因為你的語料庫可能得出不同的排名。

模型頁面列出了 32,768 token 的上下文窗口，但該限制是按端點設置的。2026 年 9 月 11 日，Qwen3 Embedding 8B 的 DeepInfra 和 SiliconFlow 端點列出的是 32,768 token，而 Nebius 端點列出的是 32,000。如果你發送的輸入超過 32,000 token，請查看 端點列表，並固定選擇一個限制更大的提供商，或將輸入保持在 32,000 token 及以下。

4B 版本使用相同的模型級上下文窗口，在我們的檢查中返回了 2,560 個值。它自行運行所需的資源更少。託管價格取決於可用的提供商，因此在選擇之前，請比較 Qwen3 Embedding 8B 和 4B 當前的模型頁面。

baai/bge-m3 為你提供了第二個開放的多語言模型，可在你自己的數據集上與 Qwen3 進行對比。其 模型卡涵蓋 100 多種語言，輸入上限為 8,192 個 token，我們的請求返回了一個 1,024 維的向量。上游模型可以返回多種表示類型，包括稠密向量和稀疏向量。我們的標準嵌入響應返回的是稠密向量。如果你的檢索設計依賴於其他表示類型，請使用上游實現。

最適合代碼搜索的嵌入模型

當查詢需要檢索某個函數、文件或某段代碼文檔時，請使用 voyageai/voyage-code-4。Voyage 專為代碼檢索和編碼智能體工作負載構建了該模型。其 32,000 token 的上下文窗口可以接受較長的文件或查詢，不過索引分塊仍應代表在被檢索時有用的代碼單元。

mistralai/codestral-embed-2505 是我們目錄中主要的代碼專用替代方案。在我們的文本請求檢查中，它返回了 1,536 個值。其上下文窗口為 8,192 個 token，而 Voyage Code 4 為 32,000 個。請先測試 Voyage Code 4，並將 Codestral Embed 作為對比模型。

公開評測可以幫助你比較候選模型。代碼信息檢索基準 CoIR包含十個數據集，覆蓋七個領域中的八項代碼檢索任務。在將最強的候選模型用於你自己代碼倉庫中的工作進行測試之前，可以用它來比較模型。一個有用的內部評測方式，是將 issue 描述或開發者問題映射到解決它們所需的文件和分塊。

最適合文本與圖像檢索的模型

當同一個索引需要同時檢索文本和圖像時，請使用 google/gemini-embedding-2。它把兩種輸入類型放入同一個嵌入向量空間，因此文本查詢可以檢索到含義相關的圖像，圖像查詢也可以檢索到相關文本。

我們通過 embeddings 端點驗證了文本、base64 編碼的 PNG 圖像，以及文本與圖像組合的請求。每個請求都返回一個包含 3,072 個數值的向量。我們還發送了一個使用 "dimensions": 768 的文本請求，收到了一個包含 768 個數值的向量。在我們的檢查中，一張 64 × 64 像素的 PNG 計為 258 個提示詞 token，費用為 $0.000128。截至 2026 年 9 月 18 日，我們的目錄在 模型頁面上為該模型單獨標註了圖像輸入價格，為每百萬圖像 token $0.45，因此在為大規模圖像集合建立索引之前，請先查看模型頁面。本指南將推薦範圍限定為文本和圖像輸入，因為這些是我們驗證過的請求類型。

voyageai/voyage-multimodal-3.5 是我們驗證的第二個文本與圖像模型。它的圖像請求和文本與圖像組合請求各自返回一個包含 1,024 個數值的向量，同樣一張 64 × 64 像素的 PNG 計為 89 個提示詞 token，費用為 $0.00003。它具有 32,000 token 的上下文窗口，提示詞價格為每百萬 token $0.12。Gemini Embedding 2 和 Voyage Multimodal 3.5 使用不同的向量空間，因此在建立索引之前請先選定其中一個。

google/gemini-embedding-001 是一個獨立的純文本模型，具有 20,000 token 的上下文窗口。這兩個 Gemini 模型使用不同的向量空間，因此在它們之間切換需要你重新為索引生成嵌入向量。

nvidia/llama-nemotron-embed-vl-1b-v2:free 是我們目錄中一個免費的文本與圖像路由，上下文窗口為 131,072 個 token。由於下文所述的隱私設置原因，我們的測試賬號無法調用它，因此我們將其排除在推薦之外。

最佳低成本與免費選項

perplexity/pplx-embed-v1-0.6b 在我們候選名單中擁有最低的付費文本價格，為每百萬輸入 token $0.004。它最多接受 32,000 個 token，並返回了一個包含 1,024 個值的向量。更大的 perplexity/pplx-embed-v1-4b 返回了 2,560 個值，其提示詞價格為每百萬輸入 token $0.03。

Perplexity 將 0.6B 模型定位為輕量、低延遲的檢索，將 4B 模型定位為更高質量的檢索。我們的 API 檢查確認了默認向量大小，但並未確認哪個 Perplexity 模型檢索效果更好。將提供商的定位視為候選信號，並在帶標註的查詢上比較這兩個模型。

將免費路由用於評估，而不是作為大型生產索引任務的唯一路徑。當你需要一個免費的候選模型來測試時，可以從 nvidia/nemotron-3-embed-1b:free 開始。它的上下文窗口為 32,768 個 token，並且 NVIDIA 的模型卡 報告了 2,048 個值的輸出向量、覆蓋 34 種語言的評估，以及通過 L2 重新歸一化將向量切分為更小尺寸的支持。NVIDIA 在 OpenMDW-1.1 許可下發布了權重。在將免費路由用於生產索引任務之前，請查看當前模型頁面以瞭解可用性和速率限制。可用性和速率限制可能會在批處理期間發生變化。

我們目錄中的免費路由由數據政策可能允許使用你的提示詞進行訓練的提供商提供服務。你的賬户隱私設置中，付費模型和免費模型有各自獨立的開關。當免費模型開關關閉時，向這些路由之一發出的請求會返回 404 錯誤，該錯誤會指明免費模型訓練設置並列出被排除的端點。我們的測試賬户關閉了該開關，這就是那三條免費路由未能通過我們檢查的原因。一個禁用免費模型訓練的工作區護欄，或在請求中將provider.data_collection設置為deny，會排除相同的端點併產生相同的 404 錯誤。關於我們如何應用這些設置，請參閲提供商日誌記錄與訓練政策。

liquid/lfm-2.5-embedding-350m:free是候選名單中的另一條免費文本路由。其 512-token 上下文窗口將每次輸入限制為一段短文本，因此較長的文檔需要比本指南中其他模型更小的分塊。僅當每個嵌入文本段都適合在 512 tokens 以內時使用它，例如簡短的 FAQ 條目、標題或句子級片段。當你的檢索單元需要更長的上下文時，請將其排除。

在你的數據上評估嵌入向量模型

對每個候選模型使用相同的語料庫、查詢、相關性標籤、分塊和檢索指標。只更換模型，保持評估的其餘部分固定不變，以便結果保持可比性。

評估英文 RAG

為每個候選方案使用相同的分塊策略。先從約 512 到 1,024 個 token 的塊開始，並設置重疊，然後根據你的文檔結構和檢索結果調整塊大小。

從你的用户提出的問題入手，並標註包含答案的塊。使用你的應用發送給生成模型的相同檢索塊數量來衡量召回率。當多個塊都相關、但其中一些比另一些更有用時，加入歸一化折損累計增益，即 nDCG。

評估多語言檢索

納入你計劃支持的所有語言。如果用户可能用一種語言寫查詢、卻檢索另一種語言的文檔，就加入跨語言用例。將每種語言的結果單獨報告，並與總體平均值並列呈現，這樣某一語言的優異結果就不會掩蓋另一語言的糟糕結果。

評估代碼搜索

使用開發者的問題或 issue 描述，並標註能解決它們的文件或代碼塊。CoIR 可以補充這一數據集。你針對自己代碼倉庫的標註應佔更大權重，因為它們反映了你的應用實際會運行的搜索。

計算向量存儲

將向量存儲納入比較。一百萬個 4,096 維的 float32 向量在索引開銷之前需要約 16.4 GB。一百萬個 1,024 維的向量需要約 4.1 GB。你可以用以下公式估算原始存儲：

vector storage in bytes = number of vectors x dimensions x bytes per value

在每一個受支持的向量維度上比較檢索質量，然後選擇滿足你目標的最小維度。將選定的模型和維度同時用於索引和查詢。

為索引和查詢使用兼容的模型

來自不同模型族的向量不共享同一座標空間。如果你用 openai/text-embedding-3-small 為文檔建立索引，就必須用相同的模型和配置為每個查詢生成嵌入向量。混用模型會產生不可靠的檢索結果。同樣的規則也適用於 google/gemini-embedding-2 和 google/gemini-embedding-001。在它們之間切換需要重建索引。

更換模型通常需要重新為整個語料庫生成嵌入向量。Voyage 在設計 Voyage 4 文本模型時就使其產生兼容的向量，這在該模型族內構成了一個有文檔記錄的例外。在更改查詢或索引路徑之前，先對樣本進行測試，因為所選的層級仍可能影響檢索質量。

將模型 slug、輸出維度、提示詞格式和創建日期與索引元數據一起存儲。一些嵌入模型使用 input_type 值來區分查詢（例如 search_query）與索引內容（例如 search_document）。將每一側所使用的值隨索引元數據一起存儲。這些字段讓後續部署在查詢索引之前能夠核對其嵌入配置。

在我們的整個模型目錄中，端點保持不變。模型 slug 和輸出維度必須與構建索引時所用的配置一致。如果你用非默認維度構建了索引，那麼在為查詢生成嵌入向量時也要包含相同的 dimensions 值。

通過我們的 API 調用嵌入模型

向 https://openrouter.ai/api/v1/embeddings 發送請求。以下 Python 示例使用了通過我們驗證的相同批量請求結構：

import os

import requests

response = requests.post(
    "https://openrouter.ai/api/v1/embeddings",
    headers={
        "Authorization": f"Bearer {os.environ['OPENROUTER_API_KEY']}",
        "Content-Type": "application/json",
    },
    json={
        "model": "openai/text-embedding-3-small",
        "input": [
            "Reset a password from the account settings page.",
            "Refunds are available within 14 days of purchase.",
        ],
    },
    timeout=90,
)

response.raise_for_status()
result = response.json()
vectors = [item["embedding"] for item in result["data"]]

print(len(vectors))
print(len(vectors[0]))

響應中會按相同順序為每個輸入返回一個向量。當所選模型支持可調維度時，請在請求中添加 "dimensions": 256 或其他受支持的維度值，並將該值與索引元數據一起存儲。

對於 Gemini Embedding 2 和 Voyage Multimodal 3.5，請將圖像輸入放入 content 數組中，該數組位於 input 列表內。我們已在兩個模型上驗證了這一請求結構：

payload = {
    "model": "google/gemini-embedding-2",
    "input": [
        {
            "content": [
                {"type": "text", "text": "A purple square"},
                {
                    "type": "image_url",
                    "image_url": {"url": "data:image/png;base64,BASE64_IMAGE_DATA"},
                },
            ]
        }
    ],
    "encoding_format": "float",
}

省略文本部分即可僅嵌入圖像。完整的請求與響應 schema 請參閲我們的 Embeddings API 文檔。

常見問題

我應該使用哪個嵌入向量模型？

根據你檢索的材料以及對部署至關重要的約束條件來選擇。先從支持你的輸入類型、語言覆蓋範圍、上下文長度和權重要求的候選模型入手。在同一組標註查詢上至少比較兩個模型，然後選擇那個在可接受的存儲和索引成本下滿足你檢索目標的模型。

我可以在不重建索引的情況下更換嵌入向量模型嗎？

切換到另一個模型系列需要重建索引，因為文檔和查詢必須使用來自同一模型和配置的向量。Voyage 表示，Voyage 4 Large、Voyage 4 和 Voyage 4 Lite 的嵌入向量彼此兼容。在更換檔位之前，先在樣本上測試檢索質量。

最快的嵌入向量模型是什麼？

我們沒有為本指南運行受控的延遲基準測試。延遲會隨輸入長度、批大小、提供商負載和路由而變化。請用你的應用實際會使用的輸入和批大小來測試這些端點。

我應該使用最大的嵌入維度嗎？

根據你的檢索結果和存儲限制來選擇嵌入維度。更高的維度需要更多存儲，每次相似度搜索也需要更多計算。當模型支持降低維度時，使用在你的評估集上滿足檢索目標的最小維度。

text-embedding-ada-002 還是一個好的默認選擇嗎？

我們不會把 text-embedding-ada-002 作為新的基於 OpenAI 的索引的默認選擇。先評估 text-embedding-3-small，然後如果你的檢索結果足以證明更高的提示詞價格和更大的向量是合理的，再將其與 text-embedding-3-large 進行比較。

為什麼一個免費的嵌入向量模型會返回 404 錯誤？

我們目錄中的免費嵌入向量路由由數據政策可能允許使用你的提示詞進行訓練的提供商提供服務。如果你的賬户隱私設置、工作區護欄，或將 provider.data_collection 請求字段設置為 deny 排除了那些會使用免費模型提示詞進行訓練的提供商，那麼就沒有符合條件的端點，請求會返回 404 錯誤，並指明免費模型訓練限制。在你認定該模型 ID 無效之前，請先檢查你賬户的隱私頁面以及應用於該 API key 的任何護欄。
