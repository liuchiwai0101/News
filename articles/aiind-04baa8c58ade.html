AI+垂類Agent：任務跑得久、工具用得熟，撐不起Agent公司長期競爭力｜貝聯珠貫創始人兼CEO 畢玄分享

內容機器翻譯自第三方媒體（InfoQ），僅供參考，以原文為準。

正文

在 1024 模力工場 · AI社區日 主論壇上，模力工場貝聯珠貫創始人兼 CEO、前阿里巴巴集團研究員畢玄，以 《以 SREAgent 為例：看垂類 Agent 的競爭力》 為題作主題分享。

SREAgent，是一款面向企業 IT 系統的 AI 運維助手 ，通過分析監控數據和日誌，幫助運維人員排查故障、定位原因並處理問題。 畢玄以 SREAgent 的實踐為例，討論了一個垂類 Agent 公司繞不開的問題：大模型越來越強，客户為什麼還需要垂類 Agent？

畢玄坦言，他們團隊曾認為，讓 Agent 長時間執行任務、熟練使用通用工具，是拉開競爭差距的關鍵；但隨着大模型進步，這些能力正逐步成為模型本身的能力。 在他看來，給大模型“補短板”，可以帶來短期優勢，卻撐不起垂類 Agent 公司的長期競爭力。

機會藏在具體業務的“髒活累活”裏。以運維為例，每家企業的監控系統、數據來源和採集方式都不一樣，如何接入並用好這些數據，需要逐一解決。

他介紹，SREAgent 3.0 已嘗試讓客户用自然語言描述需求，由系統生成相應的 Skill，降低數據接入門檻，但這種功能也容易被同行追上。 更難複製的是背後的專業經驗：面對大量日誌，哪些信息有用、該如何處理，又該怎樣結合客户業務，建立反映系統運行情況的模型？這套模型還要能隨着業務系統的變化持續更新，否則仍離不開人工維護。

真正支撐長期競爭力的，是對具體業務的理解，以及圍繞專有數據形成的採集、處理、業務建模和模型持續迭代能力。

畢玄強調，尤其是模型能否隨業務變化自我演進，將成為垂類 Agent 公司拉開差距的關鍵。而最終的檢驗標準，是 Agent 能否把問題解決好，運行是否可靠，行為是否受控。

以下為畢玄講演的完整速記，模力工場在不改變原意的前提下進行了訂正和編輯。

Agent 壁壘變了，從長程任務、通用工具，到拼業務模型自我進化

謝謝 Kevin，確實認識很多年了。當年我還在淘寶的時候，我的老闆菲青，應該是他勸説 Kevin 把 InfoQ 引入中國，在中國有了第一次 QCon。那個時候，QCon 對整個中國互聯網公司的幫助，我覺得是非常大的。因為那個時候，我們很多技術都是看國外互聯網公司做了些什麼。所以我覺得，InfoQ 這麼多年來舉辦的各種會議，對整個技術圈的幫助是非常大的。

今天是 1024，其實我現在已經很少在外面做技術類分享，因為我自己已經不大管技術了。創業已經 5 年了，我們現在更多在看生意或者經營層面的事情。今天是 1024，我還是很希望回到一個技術的角色，分享一下我們對技術發展的一些看法。

從去年開始，我們就認為，所謂 AI Agent 公司不大可能是 5 年前誕生的。真正能夠成為 AI Agent 的公司，多數都是這兩年誕生的。因為整個 AI 也就是這幾年的事情，前年開始，AI Agent 在業內就已經比較火了。今年，大眾的整體感受應該越來越強烈，因為個人 Agent、辦公 Agent 開始大面積流行。

大家從廣告層面感受到的變化最明顯。去年的廣告更多是大模型，今年的廣告很多已經變成了 WorkBuddy，或者大洋彼岸的“muse”之類的。Agent 已經開始成為大家很強的一個共識。

很多人會越來越覺得，Agent 這個方向肯定是重點。但是，對於所有的個人、公司來講，大家的空間還有多少？能做什麼？像我們做垂類 Agent 的公司，不斷被各種人問到：做垂類 Agent 公司的競爭力到底是什麼？所以，我今天只是想以我們公司的產品為例，講一下我們看到的垂類 Agent 競爭力的變化。

但這其實是一個動態過程，因為 AI 的發展變化特別快。包括我們去年在一些會上做的分享，後來再看，一兩個月後就被打臉，而且打得很重。這就是因為 AI 發展太快了。所以，今天我講的話，很有可能明天就被打臉，這很正常，沒有關係。

無論對做技術的人，還是做業務的人來講，最重要的是有自己的判斷力，而不是你的判斷正確與否。正確與否沒有那麼重要，但如果沒有自己的判斷力，就會有很大的問題，就會什麼火就做什麼，但其實不一定應該這樣。

我以我們公司的產品為例。不過，我也不希望這裏變成一個廣告大會，所以會非常少地講到我們公司的產品。

先説一下我們的感受。我們是去年上半年開始做 Agent 的，是一家做運維類 Agent 的公司。運維可以認為是一個很垂直的領域，跟研發一樣，研發是一個大的垂直領域，運維是另外一個大的垂直領域。

當時，做 Agent 的公司是怎麼做的？大家看，也就一年多一點，這個變化是非常大的。

一年多以前，我們開始做 Agent 的時候，要做的是自己蓋整棟大樓。如果把做 Agent 看成蓋一棟大樓，最開始，Agent 公司除了不用自己做大模型以外，大模型之上的所有東西，都要自己來蓋。

如果回頭看，大家會看到，當時很多 Agent 公司都在做長程任務執行。包括現在，大模型公司也會講，基於這個大模型可以跑一個 24 小時的任務，甚至一週以上的任務。怎麼樣做到這一點，是大模型公司一直在研究的。

在大模型公司之前沒有空研究這個的時候，誰在研究？不就是 Agent 公司在研究嗎？

所以，那個時候，大家會在網上看到很多做得非常好的 Agent 公司的技術分享。比如，我們一直説，必須感謝像 Manus 這樣的公司，因為他們分享了很多在長程任務執行過程中，Agent 公司應該做好什麼，比如解決好大模型的幻覺、上下文等各種問題。

Anthropic 也分享了很多。他們的博客還是很值得看的，儘管有別的問題，但博客很值得看，他們會分享長程任務等應該怎麼做。所以，當時在長程任務執行上，大家都會看這些公司怎麼做，去學習他們。我們也要在這上面做很多東西。
