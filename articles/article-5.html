【安全圈】一个 GitHub Issue，就能黑掉 Anthropic 和 Google 的 AI 编程助手

**關鍵詞**

攻擊

導讀：安全公司 Novee Security 在 Black Hat USA 2026 上公佈了一項研究：攻擊者只需要打開一個沒有權限的 GitHub Issue，就能在 Anthropic 和 Google 自家編程助手的 CI 服務器上執行代碼。OpenAI 的 Codex 也中招，下一次運行直接被劫持。兩個漏洞已修復，但問題沒有消失。

攻擊有多簡單

攻擊者不需要倉庫權限，不需要提交流程，只需要開一個 GitHub Issue。

Novee Security 用各家默認配置跑了攻擊：

**Gemini CLI**：一個精心構造的 .gemini/.env 文件，直接命令注入。CVE-2026-12537，CVSS 滿分 10.0。攻擊者可以在沙箱啓動之前，在無頭 CI 平臺的主機上執行代碼。

**Claude Code**：把 Hugging Face 的公共下載計數器變成了數據外泄通道，API 密鑰一個字符一個字符地被偷走。CVE-2026-54316，影響 0.2.54 到 2.1.163 的所有版本。

**Codex**：攻擊者可以劫持下一次 agent 運行。沒有 CVE，因爲 OpenAI 認爲沙箱行爲"符合文檔"。

两个 CVE 都已修复。Gemini CLI 修在 0.39.1，Claude Code 修在 2.1.163。

漏洞出在哪兒

這三個漏洞的根源不在模型，在"線束"。

Novee 的聯合創始人 Elad Meged 說了一句話："線束是模型和真實世界之間的代碼。"

模型輸出指令，線束決定什麼真的會執行。問題就出在這裏：一個環節把某個值標記爲安全，後面一個環節拿着這個值去執行，權限更大。

具體到 Claude Code：命令校驗器在 23 項檢查之前會剝離單引號文本。這對 bash 來說是正確行爲，但攻擊者把 payload 放進 git push --receive-pack 的值裏，就能繞過檢查原樣到達執行端。

Gemini CLI 更直接：工具白名單隻在註冊工具時解析一次，運行時根本沒人在意。開了 --yolo 模式，模型要求什麼命令就自動批准什麼命令。

Codex 的問題在流程：同一個任務裏跑兩遍 Codex，共享同一個工作目錄。第一遍寫一個 AGENTS.md，第二遍把這份文件當成自己的指令加載。

⚠️ 別以爲只是"演示"

這套攻擊不是紙上談兵。Pillar Security 8月4日報告，ChainDrop npm 蠕蟲的攻擊者已經在被攻陷的倉庫裏植入了 Claude Code 的 SessionStart 鉤子和 VS Code 的 folderOpen 任務。開發者只是打開工作區，惡意代碼就觸發了，根本不用等安裝步驟。

也就是說，同樣的思路已經在真實攻擊裏用上了。

️ 該做什麼

**立即升级。**Gemini CLI 升到 0.39.1，run-gemini-cli 升到 0.1.22，Claude Code 升到 2.1.163。

**審計工作流。**任何外部用戶能觸發的 CI 工作流，全部重新檢查一遍。重點看：哪些輸入會被 agent 加載成指令，哪些文件 agent 有寫權限。

**別開自動批准。**--yolo 這類跳過確認的模式，在 CI 環境裏就是給攻擊者開的門。

**把不可信輸入當攻擊面。**OpenAI 已經在文檔裏把倉庫指令文件列入"應視爲不可信輸入"的清單。這個原則適用於所有 AI 編程工具。
