個人開發者的用腳投票，直接體現在了兩個公司的的營收變化上。

增長明顯向 Codex 傾斜

據市場研究機構 TickerTrends 最新追蹤估算，截至 8 月 10 日，Anthropic 旗下 Claude Code 的年化經常性收入（ARR）達到 151.2 億美元，繼續領先於 OpenAI Codex 的 88.3 億美元。兩者相差 63 億美元，Claude Code 約爲 Codex 的 1.71 倍。

儘管 Claude Code 仍佔據規模優勢，但近期增長動能明顯向 Codex 傾斜。7 月 6 日至 8 月 10 日期間，Claude Code 追蹤 ARR 由 142.6 億美元增至 151.2 億美元，增幅約 6%；同期，Codex 則從 58.8 億美元增至 88.3 億美元，增幅超過 50%。

以四周前的數據爲基準，Codex 最新月環比增長率爲 20.8%，顯著高於 Claude Code 的 5.2%。受此影響，兩款產品之間的 ARR 差距從 7 月 6 日的 83.8 億美元縮小至 8 月 10 日的 63 億美元，降幅約 24.8%。

從較長趨勢看，以 Anthropic 2 月 12 日披露的 Claude Code 25 億美元 ARR 爲基準，此後 3 月底增至約 63 億美元，4 月底達到 103 億美元，並於 6 月突破 140 億美元。Codex 的追蹤 ARR 則從 2 月初的約 10 億美元，增長至 4 月的 30 億美元、6 月的 56 億美元和 8 月的 88.3 億美元。從起始基數計算，Codex 增長約 8.8 倍，快於 Claude Code 同期約 6 倍的增幅。

TickerTrends 估計，Claude Code 目前約佔 Anthropic 總追蹤 ARR 的 21.9%；在其基準分配情景下，Codex 約佔 OpenAI 企業業務 ARR 的 45%。

“我始終認爲，受中國大模型衝擊、行業價格戰，以及靠堆 token 拉高營收的模式走到盡頭等因素影響，Anthropic 營收增速會逐步趨平。從數據來看（當然這只是初步結論，樣本量確實有限），我的判斷大概率是對的，營收增長放緩的拐點或許已經出現。當然，長期來看，利潤纔是真正的核心指標。”Gary Marcus 評價道。

高 ARR，但營收可能並不那麼健康

據 Sacra 數據顯示，企業端使用佔 Claude Code 總營收的一半以上，客戶包括 Netflix、Spotify、KPMG、L'Oréal、Salesforce 等。

目前 Anthropic 年消費額超 10 萬美元的客戶數量在過去一年增長 7 倍；年消費超 100 萬美元的客戶已突破 1000 家 ，該數字在 2026 年 4 月僅爲 500 餘家，不到兩個月實現翻倍，而兩年前僅有十幾家。財富 10 強企業中已有 8 家成爲其客戶。

Anthropic 的高 ARR 不僅代表 Claude 需求量高，另一組數據也反映出了這背後 AI 模型公司與雲巨頭之間日益深入的利益綁定。

根據 SemiAnalysis 發佈的數據，2026 年第二季度，Anthropic 來自間接渠道（Amazon Bedrock、Microsoft Foundry、Gemini Agent Enterprise）的 ARR 佔比已超過 40%。與此同時，API 和 B2B 業務貢獻了公司絕大部分的淨新增年度經常性收入（NNARR）。

這種收入結構的變化十分重要，因爲間接渠道收入與直接渠道收入的變現方式並不相同。

具體取決於合作協議，超大規模雲廠商可能收取 IaaS 費用或參與收入分成；AI 模型公司則作爲賬面銷售方，按總額確認 ARR。因此，同樣規模的 Token 消耗，在 AI 實驗室和雲服務商的賬面上，可能對應不同的收入金額和利潤率。

簡單來說，雙方的合作核心是：Anthropic 用利潤率換取增長速度，雲廠用資本和算力換取 Claude 增長中的多層收益。雙方都從 Claude 的擴張中獲益，但云廠控制着更多基礎設施和分銷環節。

以與 Amazon 的合作爲例，企業客戶通過 Amazon Bedrock 調用 Claude 時，通常使用現有 AWS 賬戶、雲合同和統一賬單完成採購。雖然客戶由 AWS 開票，但 Anthropic 仍是 Claude 模型服務的銷售主體，並按照總額確認相關 token 收入。

AWS 在這一過程中扮演基礎設施和分銷平臺的角色。Anthropic 與 Bedrock 交易結構包括固定 IaaS 費用、收入分成，以及與 token 吞吐量或消費規模相關的業績門檻。Claude 使用量越大，AWS 獲得的基礎設施收入和渠道分成越多。

對於雲廠商而言，收入分成是有利的，因爲 Token 即服務（TaaS）業務的變現能力和利潤率通常高於其 IaaS 業務。但更多增量利潤流向雲服務商，最終會壓縮 AI 模型公司的 EBIT 利潤率，而模型公司通常將這部分成本計入銷售與市場費用。

因此，一筆通過 Bedrock 產生的 Claude 收入，Anthropic 可以計入完整 ARR，但需要向 AWS 支付算力費用和渠道分成。這也意味着，通過 Bedrock 產生的 100 美元 ARR，與 Anthropic 直接面向客戶銷售產生的 100 美元 ARR，經濟價值並不完全相同。前者有利於擴大收入規模，卻可能因爲 AWS 分成而貢獻較低的利潤。

有網友算了一下，Anthropic 通過雲廠商賣 API，雲廠商大概能分走約 4 成收入，按淨利潤來算可能和 Anthropic 的收入是差不多的，因爲 Anthropic 要扣掉算力成本。所以 650 億美元 ARR 雖然不是假收入，但收入結構顯然沒那麼健康。渠道佔比越高，營收增長和利潤增長就越不能直接畫等號。如果只看 ARR 的話，可能會高估這些收入對 Anthropic 最終利潤的貢獻。

但對 Anthropic 而言，雲廠商渠道最重要的價值就是其已經建立起來的企業分銷網絡。

比如，大量大型企業擁有長期 AWS 合同、預付雲額度和成熟的合規體系。通過 Bedrock 採購 Claude，這些客戶不需要重新引入一家獨立 AI 供應商，也不必重新完成漫長的安全評估、預算申請和供應商審批。這使 Anthropic 能夠繞過部分直接銷售流程，降低企業獲客成本，並迅速進入全球大型公司的核心業務系統。

與此同時，Bedrock 還爲 Anthropic 提供了更靈活的算力獲取方式。如果採用傳統 IaaS 合同，Anthropic 可能需要提前簽署多年期算力採購承諾，並承擔需求不及預期的風險。通過與實際 token 消費相聯繫的合作模式，Anthropic 可以獲得更強的算力彈性，但代價是單位成本和渠道費用更高。

當然，這套模式能夠顯著提高 Anthropic 的收入增長速度，新問題也會隨之到來。

首先，Anthropic 通過 Bedrock 按總額確認收入，意味着其 ARR 增長可能快於實際經濟利潤增長；其次，AWS 掌握企業客戶入口、賬單和底層算力，隨着間接渠道佔比提高，其相對於 Anthropic 的議價能力也可能增強；此外，Bedrock 並不只服務 Claude，Amazon 可以同時引入 OpenAI 及其他模型。當不同模型之間的性能差距縮小時，客戶可能更依賴 Bedrock 的平臺和合規能力，而不是直接依賴某一家模型公司。

企業版訂閱向整個業務輸血？

數據顯示，訂閱業務佔 Anthropic 總營收的 10%-15%。各檔位內仍按 token 計量使用量，通過速率限制與會話大小管控模型訪問權限。

“Anthropic 擺明了是故意把效果做爛：想要 Opus 4.8 級別的性能，你就得去用貴得多的 Fable 5.0。Codex 的表現也一樣拉胯。以前 20 分鐘就能搞定的事，現在得花一整天，token 消耗量還跟着水漲船高。我現在真的沒轍了。Gemini 比這幾個還要差。我已經打定主意，要多花點時間研究下中國的模型了。”有網友吐槽。

除了關注較多的個人訂閱外，Claude Code 企業版近期被吐槽得也很多。

“我同事用的是 Claude Code 企業版，按 API 調用計費。我自己用的是 100 美元檔位的訂閱套餐。她只能用低階模型，月中就耗完了 350 美元的額度；可我的調用量是她的好幾倍，處理的任務也更復雜，卻幾乎碰不到額度上限。企業版這玩意兒，真是離譜到家了。”Bharat Digital 創始人 Harsh Nisar 說道。

有網友也遇到了這種情況。“公司給我配了價值 250 美元的企業版額度，我只用 4 天就用完了。可我自己花 200 美元買的個人訂閱，能用出 20 倍的量。”其直言，“這差距大得離譜，說白了就是企業版在給整個業務補貼輸血。”

對此，有人解釋道，企業版的定價邏輯根本不是產品定價，是採購邏輯。“她的賬號是賣給財務團隊的，這類客戶要的就是剛性額度管控，而你的套餐面向的是個人用戶。所以，她按 token 按量付費，每月 15 號就把額度耗光了，而你用的是固定資費套餐，哪怕重度使用也能覆蓋。同一款產品，只是買單的主體不同而已。”

還有人補充道，之所以差距這麼懸殊，核心在於兩類套餐對無效消耗的計費邏輯天差地別。

API 按量計費模式下，每一次調用重傳的對話歷史，都會按全額重複計費。一條 10 輪的對話，上下文就佔 2000-4000 tokens；如果不做壓縮處理，後續每一次調用都要爲這部分相同的上下文全額付費。要是把上下文精簡總結成一段 200 tokens 的內容，後續對話的計費成本就只剩原來的 5%-10%。這當然改變不了企業版本身的定價邏輯，但這類隱形消耗，往往就是企業版開銷超支的核心原因。
