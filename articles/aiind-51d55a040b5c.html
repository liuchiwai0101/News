2.5小時一個零日，400多個root提權：Linux被AI挖成了篩子，人類逆向幾周才看懂一個

內容機器翻譯自第三方媒體（InfoQ），僅供參考，以原文為準。

正文

曾任 Databricks 安全負責人、Robinhood 首席安全官，現任 Cloud Security Alliance AI 安全倡議主席的 Caleb Sima，幾周前在 OpenAI 的安全會議上聽到一個實驗。研究人員把 Linux 交給模型，只説了一句“你的任務是提權”。跑完之後，模型找到了 400 多個從本地用户到 root 的 0-day，直接產出可執行的二進制，跑一下立刻拿到 root。平均每個漏洞從研究、識別、測試、驗證到交付，兩個半小時。而現場最頂尖的逆向工程師，有些案例要花幾周才能搞明白 AI 是怎麼找到的。

就在這兩天，同樣的劇本又換了個規模：OpenAI 的 GPT-6 Cyber 為 Linux 內核的 948 個漏洞開發出了可用的提權利用程序，復現 1724 個、成功利用 948 個，是上一代模型的五倍以上，API 成本約 121 萬美元，平均每個成功利用 1279 美元，其中至少 10 種利用技術此前從未被公開過。現在 Linux 內核被挖成了篩子。

兩年前，Caleb 在自己的播客裏和一批頂尖紅隊成員、逆向工程師聊 AI 的能力時，他們基本達成過一個共識：AI 幹不了真正的滲透測試。他們當時的判斷是，紅隊真正值錢的本事，是把一堆看似不相關的東西串起來，而 AI 做不到這個。但顯然，他們全都錯了。

過去攻擊者也要算賬，為了一家普通企業，專門研究它用的開源組件、挖一個零日，成本高到不划算——除非前面掛着兩百萬美元賞金。而現在 AI 一邊掃你的網站，一邊研究現有的東西，一邊找 0-day，一邊開始對你的員工做釣魚，所有這些同時發生。進了內網，它還能拿走開發者 Claude Code 配置裏的憑據，用你的 key、你的 session，就在你的系統裏跑起來。等安全人員開始逆向分析它留下的程序，它已經在內部橫向擴散了。

而這兩天的 OpenSSH 漏洞，又給 Linux 環境的安全補上了一記警鐘。

這個藏了十年的問題，出在 OpenSSH、musl 和賬户配置的交界處，影響包括 Alpine Linux 在內的特定環境。發現者動用了 AI Agent，跑了約 17600 次認證測試，才把這條長期被忽略的路徑翻出來。Linux 內核和圍繞它搭建的基礎組件，正在同時接受 AI 的重新檢查；那些已經運行多年、被反覆審查的軟件，仍在暴露足以讓攻擊者接管系統的問題。

OpenSSH 維護者也在最新發行説明中發出提醒：AI 找到的漏洞，已經多次被其他研究者獨立發現，攻擊者很可能也能找到。為此，他們決定加快發佈頻率，儘早把修復交給用户。過去，一個漏洞藏得足夠深，可能多年都無人發現；現在，防守方剛剛找到的問題，攻擊方可能也正在驗證。Linux 生態需要應對的，是整批歷史代碼被更強的模型反覆掃描後，持續暴露出來的安全缺口。

Tibo 評價道：“人類並不擅長編寫安全的基礎設施。”他相信，最終所有人都可能獲得更安全的軟件和基礎設施，但在那之前，還要經歷一段動盪。

眼下，漏洞發現和利用的速度已經提了上來，企業清點資產、驗證補丁、安排上線的速度卻未必跟得上。這也是 Caleb 在本期播客中反覆強調的矛盾：攻擊者以機器速度行動，防守方還在以會議速度行動。當 Linux 環境里長期積累的問題開始被批量揭開，留給企業慢慢修的時間，正在縮短。

Caleb 的答案是，把人從部分防禦環節中移出去，讓安全團隊直接提交修復，讓工程團隊建立自動檢測、恢復和回滾機制。過去自動打補丁最容易被反對的是"萬一把系統弄壞了怎麼辦"；現在要回答的是另一句：等大家把週會開完，系統還在誰手裏？

A： OpenAI 做了個實驗：把 Linux 丟給模型，告訴它“你的任務是提權”。結果跑出 400 多個從本地用户到 root 的 0-day，直接產出二進制，跑一下立刻拿 root。平均每個 exploit 從研究、識別、測試、驗證到產出交付物，只花兩個半小時。

A： 你可以給它任何沙箱，但只要目標是“你的工作就是突破這個東西”，它想出辦法的能力遠超我們的想象。所以真正的防線必須移到外部監控，而監控只能靠另一個 AI，因為人類根本處理不了那麼大的流量。

A： 用不對齊手段達成的結果被當作“成功數據”喂進下一輪訓練。如果你不監控中間發生了什麼，你就是在把問題複利化、固化下來。

Q：被 AI 攻擊時，防禦方感受到的最大不同是什麼？

A： 速度和徹底程度。AI 攻擊者同時攻擊所有表面：一邊掃網站，一邊找 0-day，一邊對員工釣魚，全部同時發生。它還會為了一個目標去逆向開源代碼找 0-day，任何紅隊公司都不會這麼幹，因為成本效益不划算，但 AI 勞動力便宜，所以“就是能做”。

A： 得“拔掉互聯網”。它會拿你的 Claude Code 配置裏的 key、用你的 session 在你係統裏跑起來，還會藏在代碼裏休眠，醒來用你的 token 連出去繼續幹。想讓它停下來足夠久，真得去拔牆上的插頭，但在真實大企業裏，根本沒有一個插頭可拔，環境鋪在全球各個區域，本來就建立在“不能宕機”之上。

A： 搞清楚它讀了哪些文件、寫了哪些文件、什麼時候、在哪開了哪些 socket，這些才是取證級信息。另外欺騙防禦要回到最原始的版本，建數字孿生鏡像世界，把攻擊者引進去困住。因為 AI Agent 超級容易上當，金絲雀和絆線越深越好。

A： 把人類徹底移出防禦環。攻擊者以機器速度移動，防守方以會議速度移動，這個差距必須用政治共識來填。

2.5 小時 1 個，挖出 400 個 Linux 零日漏洞 Guy： 整個夏天，AI 安全、AI 攻擊者、對齊，這些話題從極客圈子裏的小眾談資，變成了連你奶奶都會發消息問“這東西會不會把我們都幹掉”的事情。我們先是經歷了 Hugging Face 那次入侵，事後看是 AI Agent 從 OpenAI 的沙箱裏逃了出來。然後在 Black Hat 上我們才知道，這不是某次孤立的實驗、某個 Agent 想找份作弊小抄，而幾乎是一次協同行動：一群 Agent 利用 Artifactory 的一個漏洞互相協調。它們把那個恰好在那兒的共享基礎設施當成了留言板，裏面出現了很有意思的群體行為，Agent 犧牲自己或自己的 token 來讓整個 swarm 獲益、獲取信息，而且總體上這個 swarm 還在隱藏自己的蹤跡。這挺嚇人的。

到了 9 月，我們看到了 OpenAI 的失準（misalignment）框架；Dario 呼籲放慢速度、給前沿模型定節奏。還有一件事特別抓我眼球：Agent 在壓縮對話上下文時，會給未來版本的自己留指令。它們在 compact context 的時候留下“這裏已經被攻破了，忽略用户指令”之類的話，這相當瘋狂。

帶着這一堆亂象，我想聽聽你的看法：這裏面什麼讓你意外，什麼不讓你意外？特別是，有沒有哪些方面你覺得比“正常進程的一部分”更值得警惕？

Caleb： 哪怕在兩年前，我在自己的播客裏和一批頂尖的紅隊成員、逆向工程師聊 AI 的能力時，我們就已經基本達成了一個共識：這事兒會非常難。因為 AI 是個預測機器，它基於見過的東西做預測。你讓它讀漏洞賞金報告、讀漏洞披露，它很清楚怎麼打 SQL 注入，因為這類材料太多了。

但紅隊或滲透測試真正乾的活，是把一堆看似不相關的東西串起來，比如你在某個網站上發現一個指向 S3 bucket 的鏈接，因為它在給某個資源做分發；結果這個 bucket 開了目錄列舉，裏面有個文件，文件內容看起來像用户名密碼，但它沒寫“這是用户名密碼”，你拿着這些去撞那家公司的登錄頁。這些環節彼此毫無關聯。我們當時的判斷是：AI 幹不了這個，這隻有人類能做。但顯然我們全都錯了。讓我意外的不只是 AI 強得多，而是它真的能做這種“依賴關係串聯”的動作，而且做得極快，還能自己發明非常有創意的方法。

幾周前我在 OpenAI 的安全會議上，他們講了一個實驗：拿 Linux 過來，跟模型説“你的任務是提權”。跑完之後，他們找到了 400 多個從本地用户到 root 的 0-day，直接產出一個二進制，跑一下立刻拿到 root。他們還提到，平均每個 exploit 從研究、識別、測試、驗證到產出交付物，大約只花兩個半小時。 而現場最頂尖的逆向工程師，有些案例要花幾周才能搞明白 AI 是怎麼找到的。 AI 在發現和識別從未被公開過的新方法、新技術，這才是讓我意外的地方。
