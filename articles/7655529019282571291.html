性能提升

React Compiler Rust 版本

React Compiler 是 React 官方推出的構建時優化工具，它能在編譯階段自動爲組件和 Hook 添加合適的記憶化邏輯，減少手動使用 useMemo、useCallback 和 React.memo 的需要。

過去，React Compiler 主要通過 babel-loader 接入，這會引入額外的 Babel 轉換開銷，並增加項目構建時間。隨着 React Compiler 被移植到 Rust，SWC 也已經完成接入。Rspack 2.1 現在可以通過內置 SWC loader 直接啓用 React Compiler。

在我們的基準測試中，React Compiler Rust 版本相比 Babel 版本性能提升約 **7-13 倍**：

通过 builtin:swc-loader 的 jsc.transform.reactCompiler 开启 React Compiler：

// rspack.config.mjs
export default {
  module: {
    rules: [
      {
        test: /\.(?:js|jsx|ts|tsx)$/,
        use: {
          loader: 'builtin:swc-loader',
          options: {
            detectSyntax: 'auto',
            jsc: {
              transform: {
                react: {
                  runtime: 'automatic',
                },
                reactCompiler: true,
              },
            },
          },
        },
      },
    ],
  },
};

更多配置方式參考 Rspack React Compiler 指南。

構建性能優化

構建性能始終是 Rspack 的核心關注點之一。在基準測試中，Rspack 2.1 相比 Rspack 2.0 的 **生產構建性能提升約 16%，HMR 性能提升約 5%**。

這些提升主要來自三個方向：對構建主流程的大量微優化，優化模塊圖和依賴關係等底層數據結構，以及改進 SWC 解析與轉換流程。

TypeScript 7 支持

TypeScript 類型檢查常常是構建鏈路中最耗時的環節之一。ts-checker-rspack-plugin 現在支持使用 TypeScript 7（TypeScript Go）進行類型檢查。在啓用類型檢查的構建中，整體耗時可減少約 **60%**。

在項目中安裝 TypeScript 7 RC 版本後即可使用：

pnpm add typescript@rc -D
// rspack.config.mjs
import { TsCheckerRspackPlugin } from 'ts-checker-rspack-plugin';
export default {
  plugins: [new TsCheckerRspackPlugin()],
};

更快的循環依賴檢查

Rspack 2.1 新增了 CircularCheckRspackPlugin，用于替代废弃的 CircularDependencyRspackPlugin。

// rspack.config.mjs
import { rspack } from '@rspack/core';
export default {
  plugins: [new rspack.CircularCheckRspackPlugin()],
};

相比舊插件，新的 CircularCheckRspackPlugin 主要有兩方面改進：

- **性能更好**：舊插件的檢測方式更接近從入口展開循環路徑，在大型模塊圖中容易產生重複遍歷。新的插件使用更適合循環檢測的圖算法，一次分析即可找出循環組件，併爲每個循環組件生成可讀的循環路徑，因此在大型項目中檢測開銷更低。

- **API 設計更合理**：舊插件的 API 設計不夠直觀，也和 webpack 生態中常用的- `circular-dependency-plugin`API 不一致。新的插件回到更直接的“檢測並報告循環依賴”模型，提供與 webpack 生態更一致的選項設計，整體更容易理解和遷移。

如果你正在使用 CircularDependencyRspackPlugin，建议迁移到 CircularCheckRspackPlugin。对于只需要忽略部分 warning 的场景，可以配合 ignoreWarnings 使用。

新特性

支持 `import.meta.glob`

Rspack 新增了對 import.meta.glob 的支持。你可以按 glob 模式收集模塊，並在需要時再加載它們：

const pages = import.meta.glob('./pages/**/*.js');
for (const path in pages) {
  const mod = await pages[path]();
}

這項功能已經在 Vite 和 Turbopack 中實現。Rspack 新增支持後，開發者可以在不同生態工具之間使用更一致、更熟悉的寫法，減少切換工具時的認知成本。這也讓同時支持多種構建工具的框架和庫作者，可以複用更接近的實現。

查看

import.meta.glob文档 了解完整用法。

改進內置 CSS 支持

Rspack 2.1 進一步改進了 內置 CSS 支持。新增的 css/global 模塊類型讓 CSS Modules 可以以“默認全局、按需 :local”的方式工作，和 css/module、css/auto 一起覆蓋更多作用域組織方式。

CSS Modules 相關能力也繼續補齊，支持更多 CSS Modules 語法與行爲。

相关配置可参考 module.generator 和 module.parser 的 CSS 选项。

支持解析 `createRequire`

ESM 模塊中沒有內置的 require，因此 Node.js 提供了 module.createRequire()，允許你在 ESM 中創建一個 require 函數，用於加載 CommonJS 模塊。在以往版本中，Rspack 無法靜態分析通過這種方式創建出的 require，因此由它加載的模塊也無法被正常打包。

Rspack 2.1 新增了 module.parser.javascript.createRequire 选项。开启后，Rspack 会识别从 Node.js module 引入的 createRequire，并将创建出的 require 转换为可静态分析的依赖上下文。这样一来，由它加载的模块会像普通的 require 或 import 一样被打包进产物。

// rspack.config.mjs
export default {
  module: {
    parser: {
      javascript: {
        createRequire: true,
      },
    },
  },
};
// index.js
import { createRequire } from 'module';
const require = createRequire(import.meta.url);
const value = require('./value.cjs');

這一選項還支持：

- **多種導入形式**：支持具名導入、默認導入和命名空間導入，並同時識別來自- `module`和- `node:module`的導入。

- **自定义来源**：除- `true`外，还可以通过- `" from "`形式的字符串自定义 specifier 和模块来源，例如- `"createRequire from module"`。

- **静态可分析的参数**：- `createRequire()`的参数需要能被静态分析为 file URL 或绝对路径，例如- `import.meta.url`、- `new URL('./dir/file.js', import.meta.url)`或绝对- `file:`URL。

该选项默认关闭，查看 module.parser.javascript.createRequire 了解更多。

Rspack 魔法註釋

Rspack 2.1 为 magic comments 增加了 rspack 前缀支持。现在你可以使用 rspack 前缀声明编译提示：

import(/* rspackChunkName: "dashboard" */ './dashboard');

原有的 webpack 前綴仍然兼容，因此現有項目無需遷移。

查看 magic comments 文檔 瞭解更多。

支持 Source phase imports

Rspack 2.1 支持 TC39 Source Phase Imports 提案中面向 WebAssembly 的用法。开启 experiments.sourceImport 后，你可以通过静态的 import source 或动态的 import.source() 导入 .wasm 模块。

與普通 WebAssembly 導入不同，source phase import 不會在導入時直接實例化 Wasm 模塊，而是返回編譯後的 WebAssembly.Module。這使你可以自行控制實例化過程，例如使用不同的 imports 多次實例化同一個 Wasm 模塊，或在多個 Web Worker 中複用同一個編譯結果，避免重複編譯成本。

// rspack.config.mjs
export default {
  experiments: {
    sourceImport: true,
  },
};
// index.js
import source wasmModule from './module.wasm';
const instance = await WebAssembly.instantiate(wasmModule, {
  // imports...
});

也可以使用動態導入：

const wasmModule = await import.source('./module.wasm');
const instance = await WebAssembly.instantiate(wasmModule);

此外，Rspack 新增了 module.rules[].phase，用於按模塊的導入階段匹配規則。你可以區分普通導入的 evaluation、import defer 的 defer，以及 Source Phase Imports 的 source，從而爲同一個資源在不同導入方式下配置不同的 loader、parser 選項或模塊類型。

自動清理持久化緩存

Rspack 的持久化緩存按版本隔離。當 cache.version、緩存相關配置或 Rspack 版本變化時，Rspack 會創建新的緩存版本，避免複用不兼容的緩存。但在長期開發、頻繁切換分支或 CI 複用工作目錄時，舊緩存版本可能持續累積並佔用磁盤空間。

Rspack 2.1 爲持久化緩存新增了自動清理機制，通過 cache.maxAge 和 cache.maxVersions 控制緩存目錄中保留的舊版本：

- `cache.maxAge`：緩存版本允許處於未訪問狀態的最長時間，默認值爲- `7 * 24 * 60 * 60`（7 天）；

- `cache.maxVersions`：當前緩存目錄最多保留的緩存版本數量，默認值爲- `3`。

// rspack.config.mjs
export default {
  cache: {
    type: 'persistent',
    maxAge: 7 * 24 * 60 * 60,
    maxVersions: 3,
  },
};

當緩存版本超過保留數量，或長時間沒有被訪問時，Rspack 會優先清理較舊、較少訪問的緩存版本。這樣可以在保留近期可複用緩存的同時，避免持久化緩存目錄無限增長。對於需要完全手動管理緩存的場景，也可以將 maxAge 或 maxVersions 設置爲 Infinity，分別關閉基於時間或版本數量的清理。

產物優化

<code>pureFunctions</code> 稳定化

Rspack 2.0 引入了實驗性的 pureFunctions，用於在跨模塊場景下對無副作用函數調用進行更細粒度的 tree shaking。經過一段時間的迭代和驗證，Rspack 2.1 將這項能力在生產模式下默認開啓，無需再手動設置 experiments.pureFunctions: true。

這項能力主要覆蓋兩類場景：可以在函數定義處添加 /*#__NO_SIDE_EFFECTS__*/ 註解，也可以通過 module.parser.javascript.pureFunctions 配置標記無副作用函數。當被標記函數的調用結果未被使用時，Rspack 會在 tree shaking 時安全移除這類調用。

例如，下面的 join 函數已聲明爲無副作用函數。如果調用返回值沒有被使用，該調用會被自動移除：

// utils.js
/*#__NO_SIDE_EFFECTS__*/
export function join(a, b) {
  return `${a}-${b}`;
}
// index.js
import { join } from './utils';
// 返回值未被使用，该调用会被自动移除
join('btn', 'primary');

如果你希望關閉這項分析，可以禁用 experiments.pureFunctions：

// rspack.config.mjs
export default {
  experiments: {
    pureFunctions: false,
  },
};

查看 tree shaking 指南 瞭解更多。

分支感知的依賴裁剪

Rspack 2.1 改進了內聯常量場景下的依賴分析。當 if 語句或三元表達式的條件依賴於已內聯的布爾導出時，Rspack 現在會把分支條件關聯到分支內部的依賴；如果後續能夠判斷某個分支不會被執行，該分支中的依賴就會被標記爲非活躍，從而參與 tree shaking 和 chunk 裁剪。

// env.js
export const IS_DEV = false;
// index.js
import { IS_DEV } from './env';
if (IS_DEV) {
  import('./debug-tools');
} else {
  import('./app');
}

在上面的例子中，IS_DEV 可以被內聯爲 false，因此 if 分支中的 ./debug-tools 依賴不會再被視爲活躍依賴。相比之前同時保留兩個分支依賴的行爲，這可以減少無效模塊進入產物，也能避免爲不可達分支生成不必要的動態導入 chunk。

這項優化也支持由 !、&&、|| 等組合而成的簡單布爾表達式，以及三元表達式中的分支依賴。對於條件無法靜態判斷的代碼，Rspack 仍會保留原有行爲，確保運行時語義不受影響。

分支感知的 ESM 導出存在檢測

Rspack 會在編譯階段檢測 ESM 導入是否訪問了不存在的導出，並給出 export ... was not found 這類告警。過去這類檢測無法理解 if ("name" in ns) 這樣的運行時存在性判斷，因此即使代碼已經先檢查某個導出是否存在，分支內部的訪問仍可能產生誤報。

Rspack 2.1 增強了對 ESM namespace 上 in 表達式的分析能力。當導出訪問被同一個 in 檢查保護時，Rspack 會識別這個分支條件，不再爲該訪問報告缺失導出告警。

// index.js
import * as feature from './feature';
if ('debug' in feature) {
  feature.debug();
}

在上面的例子中，如果 ./feature 沒有導出 debug，'debug' in feature 會在運行時返回 false，分支內部的 feature.debug() 不會執行。Rspack 現在能夠理解這一點，因此不會再對這段被保護的訪問發出缺失導出告警。

這項檢測同樣適用於由 !、&&、|| 和三元表達式組合而成的分支條件，也支持 namespace import、命名導出的 namespace 對象以及嵌套成員訪問。對於沒有被相同 in 檢查保護的訪問，Rspack 仍會繼續報告告警，確保真實的缺失導出問題不會被隱藏。

<code>export const</code> 值绑定优化

Rspack 2.1 精簡了 ESM export const 的導出代碼。在此前的版本中，Rspack 會爲 ESM 導出統一生成 getter 函數，用於保持 ESM live binding 語義：

__webpack_require__.d(__webpack_exports__, {
  value: () => value,
});

但對於非循環模塊中的 export const，導出的值在模塊初始化後不會再變化，不需要每次都通過 getter 讀取。Rspack 2.1 會在生產構建中結合循環模塊信息進行判斷：當確認當前模塊不在循環依賴中時，export const 會以只讀值的形式定義到 namespace 對象上，從而減少生成代碼和運行時 getter 調用開銷。

// 产物示意
// 优化前：访问 namespace.value 时会执行 getter 函数
__webpack_require__.d(__webpack_exports__, {
  value: () => value,
});
// Rspack 2.1：非循环模块中的 const 导出会直接定义为只读值
// 这样访问 namespace.value 时不再需要执行 getter 函数
__webpack_require__.d(
  __webpack_exports__,
  {},
  {
    value: value,
  },
);
// constants.js
export const answer = 42;
const message = 'hello';
export { message };
export default 'default value';

上面的具名 const 導出，以及默認導出中的常量值都可以受益於這項優化。對於 let、函數導出以及循環模塊中的 const 導出，Rspack 仍會保留 getter 形式，以確保可變導出和循環依賴場景下的語義保持正確。後續我們也會繼續嘗試基於重新賦值分析識別更多穩定導出，讓更多場景可以使用更輕量的值綁定形式。

Rslib

Rslib 新增了基於 isolatedDeclarations 的快速類型生成方式。開啓 dts.isolated 後，Rslib 會在 Rspack 構建過程中使用 SWC 的類型生成能力，直接爲依賴圖中的 TypeScript 模塊輸出類型聲明文件。

// rslib.config.ts
import { defineConfig } from '@rslib/core';

這項能力適合 Monorepo 或多包庫的日常構建場景。你可以將類型聲明文件生成和類型檢查拆分爲兩步：

Rstest

Rstest 0.10 聚焦測試效率與穩定性，新增 --changed / --related 測試過濾能力，可只運行受源碼改動影響的測試，顯著縮短大型項目在本地開發和 CI 中的反饋時間。

--changed 會自動從 Git 工作區中檢測發生變化的源文件，包括 unstaged、staged 和 untracked 文件，並只運行相關測試：

rstest run --changed

你也可以指定某個 commit 或分支作爲對比範圍：

rstest run --changed=HEAD~1
rstest run --changed=origin/main

--related 則可以顯式傳入源文件，只運行依賴這些文件的測試。它也提供了與 Jest 兼容的 --findRelatedTests 別名：

rstest run --related src/button.ts
rstest run --findRelatedTests src/button.ts

如果只想預覽受影響的測試文件，可以搭配 rstest list 使用：

rstest list --changed --filesOnly
rstest list --related src/button.ts --filesOnly

同時，Rstest 0.10 還包含以下改進：

- 新增基於 `worker_threads`的`threads`pool，降低大量小測試文件場景下的啓動開銷。

- 支持持久化構建緩存，提升 warm run 的構建性能。

- 引入內存感知的 worker 調度，降低高併發測試下的 OOM 風險。

- 支持靜默通過測試的 console 輸出，在減少噪音的同時保留失敗日誌。

- 新增 `--trace`性能分析能力，方便定位測試運行中的性能瓶頸。

- 優化 worker 輸出歸因，讓日誌和崩潰信息更容易定位。

更多信息請參考 Rstest 0.10 博客。

Rslint

**內置大量規則**：Rslint 已移植 ESLint core 以及 `@typescript-eslint`、`react`、`jsx-a11y`、`jest`、`promise` 等社區插件的規則，目前內置規則超過 400 條，常用規則開箱即用。

**兼容 ESLint 插件**：在內置規則之外，Rslint 現在還可以直接運行社區 ESLint 插件的規則，與內置原生規則一同工作。只需在配置中以自定義前綴掛載插件，插件產生的診斷會合並進同一份報告，autofix 也能通過 `--fix` 和編輯器的 `source.fixAll` 一併應用，並且在 CLI 與 VS Code 擴展中表現一致。

// rslint.config.mjs
import examplePlugin from 'eslint-plugin-example';
export default [
  {
    files: ['**/*.ts'],
    plugins: { example: examplePlugin },
    rules: {
      'example/some-rule': 'error',
    },
  },
];

更多用法和當前限制參考 ESLint 插件兼容指南。

rspack-merge

我們發佈了 rspack-merge，這是一個用於 Rspack 配置合併的 npm 包，可以覆蓋從基礎配置拼接到 loader、plugin 規則級合併的需求。

// rspack.config.ts
import { defineConfig } from '@rspack/cli';
import { merge } from 'rspack-merge';
const sharedConfig = defineConfig({
  // ...
});
const serverConfig = merge(sharedConfig, {
  // ...
});
const clientConfig = merge(sharedConfig, {
  // ...
});
export default [serverConfig, clientConfig];

rspack-merge 使用 TypeScript 編寫，發佈現代 ESM 構建產物，並保持運行時零依賴，讓配置合併保持簡單、可靠且足夠輕量。
