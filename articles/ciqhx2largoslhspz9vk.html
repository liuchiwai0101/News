微软发布搭载原生 Go 编译器的 TypeScript 7.0，构建速度提升 10 倍

微軟發佈 TypeScript 7.0，這是該語言首個搭載其研發已久的原生編譯器的穩定版本。該編譯器將 TypeScript 工具集移植到了 Go 語言。據開發團隊稱，在完整的構建過程中，該版本通常能帶來 8 倍至 12 倍的速度提升。

最初，該項目作爲一項實驗性原生移植計劃於 2025 年 3 月首次公佈，而此前一直是以 @typescript/native-preview 包的形式向社區開放，其每週下載量曾超過 850 萬次。

隨着 7.0 版本的發佈，夜間構建版本已經迴歸到標準 TypeScript 包的 next 標籤下，而新的 tsc 可執行文件可以通過常規方式進行安裝：

npm install -D typescript爲了佐證這些數值，微軟公佈了基於真實代碼庫的構建時間數據。以 VS Code 源代碼爲例，完整構建時間從 TypeScript 6 時代的 125.7 秒縮短至 10.6 秒，提升了 11.9 倍，而總內存佔用量則下降了約 18%。編輯器同樣受益匪淺，因爲新工具基於語言服務器協議（LSP）構建，並採用了多線程處理。此前在 VS Code 代碼庫中打開一個含有錯誤的文件大約需要 17.5 秒，現在則只需不到 1.3 秒。

測試早期版本的團隊也報告了類似的提升。Slack 工程師表示，這一變更將 CI 類型檢查時間從約 7.5 分鐘縮短至 1.25 分鐘，Vanta 也報告了積極的結果：

在 Vanta，我們採用 tsgo 帶來的影響非常顯著。現在一切都快了太多太多了。

並行度可以通過新增的 --checkers 和 --builders 標誌進行調整，或者在資源受限的環境中，可以使用 --singleThreaded 完全關閉並行處理。

TypeScript 7.0 發佈時尚未包含穩定的可編程 API。開發團隊預計，該 API 將在 7.1 版本中推出，因此 typescript-eslint 以及 Vue、Svelte、Astro、MDX 和 Angular 的框架工具目前尚無法使用該功能。

遺憾的是，我只能等 7.1 版本了。

這種並行遷移路徑是遷移過程的關鍵。微軟發佈了一個兼容包 @typescript/typescript6。該包提供了 tsc6 二進制文件，並重新導出了 6.0 版本的 API，可以確保現有的工具能夠繼續正常工作，並通過 npm 別名進行連接。

TypeScript 7.0 還將 6.0 版本中已棄用的功能轉換爲硬性錯誤，並且現在默認使用 strict 和 esnext 模式。因此，爲了實現平穩過渡，建議開發團隊先採用 TypeScript 6.0 。要詳細瞭解相關的行爲差異，可以查閱項目的 CHANGES.md 文件。

esbuild、swc 和 Biome 等工具的速度更快，但它們會在不進行類型檢查的情況下進行類型移除或轉譯，而 TypeScript 7.0 不同，它是在保持完整類型檢查的同時，大幅縮小了速度差距。開發團隊表示，隨着移植版本的發佈，功能開發工作現在已經恢復，預計每三到四個月會發布一次新版本，其中 7.1 版本將重點關注整個生態系統所期待的 API。

TypeScript 是一種由微軟開發和維護的開源編程語言，遵循 Apache 2.0 許可發佈。它在 JavaScript 的基礎上增加了可選的靜態類型，更便於早期發現錯誤，讓開發者更有信心地構建大規模應用程序。
