放棄傳統思想，現在藉助 AI 開發應用，思路得發生轉變

以前，我們如果想要從 0 開發一個 APP，我們大致會經歷過如下階段：

- 產品同學構思業務邏輯並畫好產品原型圖

- 產品同學召集UI、前端、後端一起開會講明需求

- UI 同學對照原型圖設計出 UI

- 前端同學根據 UI 去設計前端頁面

- 後端同學結合原型圖、UI圖設計數據庫、後端架構、制定 API 接口

- 前後端同學進行接口聯調

- 測試同學進行前後端產品成果測試

- 產品同學驗收

然而，當我們藉助 AI 來開發應用時，我們的開發流程就會有所轉變，以下是我的開發流程：

- 構想清楚這個產品的功能、定位客戶人羣、交互方式並寫好功能文檔

- 讓 AI 幫我確定清楚適合的色彩風格並直接寫好前端代碼並寫好 mock 數據

- 自己根據頁面和 mock 數據去調試功能

- 功能調試沒問題之後，讓 AI 根據 mock 數據寫出後端所需要的 API 接口文檔

- 讓 AI 根據接口文檔去創建數據庫建表語句（自己略微調整）

- 讓 AI 根據接口文檔去寫接口

- 將前端的 mock 數據換成真實的 API 接口，自己測試功能

- 有問題的地方直接截圖給到 AI 讓 AI 幫忙解決，直到沒有問題即可

你會發現操作流程上也沒有少幾個步驟，但是當你仔細一琢磨之後，你會發現：

- 以前至少需要產品、UI、前端、後端、測試等崗位的同學相互合作才能做的事情，現在只需要一個人就能幹完

- 如果你想一個人幹整套項目，最好的方式是先從頁面開始，再反向去寫接口可以事半功倍

消息旁邊有“同意”、“拒絕”兩個按鈕

可以對賬本設置“默認”標籤，這樣在首頁、添加賬單時，則添加到默認標籤的賬本中，當然，如果用戶存在於多個賬本中，則可以在首頁、添加賬單時對賬本進行切換。
自己創建的賬本和自己加入別人創建的賬本是有顏色區分的，優先展示自己創建的賬本，如果自己沒有創建賬本，再優先展示加入的賬本
被邀請人可以退出加入的賬本，邀請人不能退出自己創建的賬本，只能刪除賬本。（刪除效果是滑動刪除）「退出」、「刪除」都會有二次確認。

當你將上面的內容都發給 AI 並讓 AI 牢牢記住你的要求之後，你就可以直接將下面的提示詞發給他，讓他幫你寫代碼了

Subject：微信小程序《時光賬記》前端開發任務
Context：我正在開發一款名爲《時光賬記》的微信小程序，目的是創建賬本，然後在賬本下可以記賬，請幫我完成小程序前端代碼。
所有數據請求請使用 Mock 數據模擬，請在項目根目錄下創建一個 mock 文件夾，將所有的 API 返回數據寫在獨立的 JS 文件裏，方便我後期替換成真正的 API。
1、接口協議規範：所有 API 請求的返回格式必須嚴格遵守： {"code": 0, "msg": "提示語", "data": null}
- 當 `code == 0` 時，表示接口請求正常，此時可以從 `data` 中拿到業務數據
- 當 `code != 0` 時，表示接口異常，需要通過 toast 彈出 msg 中的提示內容
- 所有的時間，接口都會返回秒級別的時間戳，前端需要自行進行格式化處理
- 如果用戶已經登錄，需要將用戶登錄的 token 數據放入到請求頭中到 token 字段中
2、前端所有和接口網絡請求有關的方法，都要以 `Api` 爲後綴，比如在前端中有一個方法是封裝去請求接口獲取用戶信息時 `getUserInfoApi` 方便我好分辨這個方法是和網絡請求有聯繫的
3、全局樣式設置：
