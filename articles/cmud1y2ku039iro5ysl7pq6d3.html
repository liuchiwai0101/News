OpenAI 發佈 GPT-6 Sol 和 GPT-6 Luna，API 價格較 GPT-5.6 降 50%

內容機器翻譯自第三方媒體（OpenAI），僅供參考，以原文為準。

AI 導讀

OpenAI 發佈 GPT-6 Sol 和 GPT-6 Luna，將 GPT-6 Astra 的訓練方法用於更快更便宜的模型，API 價格較 GPT-5.6 促銷價下調 50%（Sol 輸入 $4→$2、輸出 $20→$10；Luna 輸入 $0.20→$0.10、輸出 $1.20→$0.50，每百萬 token）。

推薦理由

官方發佈給出各檔模型的具體基準分數、API 價格降幅和緩存改進數據，可以用來對比 GPT-6 家族在成本與能力之間的取捨。

正文

將前沿智能融入你日常工作的更多方式。

本月早些時候，我們推出了 GPT‑6 Astra，這是全球最智能、對齊程度最高的模型。儘管最嚴苛、最重要的項目仍然需要 Astra 的完整深度，但工作會以不同的規模、節奏和預算發生。

正因如此，我們通過 GPT‑6 Sol 和 GPT‑6 Luna 擴展了 GPT‑6 宇宙。GPT‑6 Astra 開啓了新一代智能——這些模型通過在成本效率上推進前沿，幫助將這種智能的益處更廣泛地分配。我們使用與 GPT‑6 Astra 類似的方法訓練了 GPT‑6 Sol 和 Luna，將 Astra 在專業工作、事實性、編程、計算機使用和對齊方面取得最先進性能背後的進步，帶到了更快、更實惠的模型中。

GPT‑6 系列模型在成本—智能曲線上全面領先，在每個層級都具備卓越能力，並配有能夠高效大規模交付這些能力的基礎設施。緩存和推理方面的改進讓我們能夠以更低的成本提供這些模型，我們通過 將 Sol 和 Luna 的 API 價格相較其 GPT‑5.6 促銷定價下調 50%，將這些節省直接傳遞給用户和客户。這些改進共同讓先進 AI 在更多日常任務和大規模應用中變得切實可行。

專業工作

GPT‑6 Sol 能夠承擔困難的工作任務，同時憑藉更高的使用限額和更低的成本，為你留出更多迭代空間，相比價格相近的競品模型提供更強的智能和更好的結果。

在 AutomationBench 這一跨應用業務工作流測試中，GPT‑6 Sol 在 xhigh 努力程度下，以僅為 Claude Opus 5 在 max 努力程度下每任務成本 9% 的開銷，超越了後者。在 high 努力程度下，GPT‑6 Luna 相比其前代提升 5.4 個百分點，每任務成本降低 58%。

事實性

答案的有用性取決於事實是否正確，我們正在事實可靠性方面持續取得進展。在我們的內部事實性評估中——該評估基於經過脱敏的真實世界對話，其中用户標記了我們模型所犯的錯誤——GPT‑6 Sol 所犯的錯誤約為其前代的一半，以低得多的成本接近 Astra 級別的可靠性。GPT‑6 Luna 也有大幅提升；在更高的 effort 水平下，它以約百分之一的成本達到 GPT‑5.6 Sol 的水平。

在此，我們基於經過脱敏處理的 ChatGPT 對話來評估事實性，這些對話中用户曾標記過此前某個模型出現的事實錯誤。這些誘發錯誤的對話並不代表典型使用場景，在典型使用中事實錯誤更為罕見。評分未對長度進行控制；不過，我們的冗長度掃描顯示，答案長度幾乎不產生影響。

編程

今年，編程智能體開始處理比以往任何時候都更復雜、範圍更大、持續時間更長的任務。在 OpenAI，我們的內部使用量呈指數級增長。按 API 價格計算，每日 token 用量中位數研究員已超過 $600，第 90 百分位的研究員則超過 $7,000（研究加速：OpenAI 內部視角）。隨着編程智能體承擔更長、要求更高的任務，持續使用的成本變得更加重要。GPT‑6 Sol 和 Luna 將強大的編程性能與更低的 API 價格相結合，讓開發者有更多空間進行迭代，也讓團隊有信心對 Codex 提出更宏大的要求。

在 FrontierCode 上——該基準評估編程智能體生成的改動是否已準備好合併進真實代碼庫——GPT‑6 Sol 相比 GPT‑5.6 Sol 有大幅提升，並且能夠以低得多的成本匹配 Claude Fable 5.1 xhigh。

計算機使用

為智能體和長對話改進緩存

在降低 token 價格的同時，我們也在幫助基於 GPT‑6 構建的開發者，在應用複用上下文時節省更多成本。我們改進了 GPT‑6 的提示詞緩存，默認帶來更高的緩存命中率，幫助智能體複用更多上下文、更快響應，並享受緩存輸入 token 讀取 90% 的折扣。

開發者還有更多方式來衡量和優化其緩存性能：

  • 監控與診斷。提示詞緩存儀表盤⁠會顯示有多少輸入被緩存，以及這一數值隨時間的變化。診斷工具⁠有助於解釋錯失的緩存機會以及需要修復的地方。

  • 調整推理力度和工具可用性，而不破壞緩存。對於更難的任務，可以提高推理力度⁠，對於更簡單的後續任務則可以降低；隨着智能體需求的變化，還可以啓用或禁用工具⁠。現在這兩項控制都會保留更早的上下文，以供緩存複用。

  • 優化哪些前綴會被緩存。顯式斷點讓開發者可以選擇緩存提示詞前綴的結束位置。這讓開發者對緩存複用擁有更多控制權，並可以提升性能。

GitHub 報告稱，在過去幾個月裏，這些改進使 OpenAI 模型收到的數十億次請求中，需要全新處理的提示詞 token 佔比降低了 50% 以上，從而幫助 Copilot 更快響應。

持續改進對齊

GPT‑6 Sol 和 Luna 建立在 Astra 所引入的對齊工作之上，Astra 是我們迄今為止對齊程度最高的模型。在我們的對齊評估中，Sol 和 Luna 相比各自的 GPT‑5.6 對應版本均有所改進，包括降低了就其編碼工作做出誤導性陳述的比例。

以下評估刻意測試具有挑戰性的情境，並不衡量典型使用場景下的失敗率。完整結果請參見系統卡⁠。

可用性

GPT‑6 Sol 和 GPT‑6 Luna 從今天起在 ChatGPT Work 和 Codex 中面向所有 Plus、Pro、Business、Enterprise 和 Edu 用户開放。Free 和 Go 用户可在桌面應用中訪問 GPT‑6 Luna。這些模型尚未在 Chat 中提供。在 OpenAI API 中，它們以 gpt-6-sol 和 gpt-6-luna 的形式提供。

為了保持對所有人的服務穩定，我們計劃在一天內逐步在 ChatGPT 中推出這些模型。如果你在 ChatGPT Work 或 Codex 中看不到新模型，請稍後再試。

GPT 的評估是在我們的研究環境中或通過我們的 API 進行的，由於系統提示詞、可用工具等方面的差異，其輸出可能與生產環境中的 ChatGPT 略有不同。競品模型的評估取自公開報告。在無法獲得 Claude Fable 5.1 的分數時，報告的是 Claude Fable 5 的分數。
