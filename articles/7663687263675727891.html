一、ArkUI 是個啥？一句話講清楚

**ArkUI 是鴻蒙的聲明式 UI 框架。**

如果這句話你還是覺得抽象，那就換個說法：**它之於鴻蒙，相當於 SwiftUI 之於 iOS、Jetpack Compose 之於 Android、React 之於 Web。**

聲明式 UI 的核心思想就一句：

你告訴框架「我要什麼樣的界面」，而不是「一步步教框架怎麼畫出界面」。

舉個最直接的對比。

**命令式（传统 Android）：**

val textView = TextView(context)
textView.text = "Hello"
textView.setTextColor(Color.RED)
container.addView(textView)

你像個保姆一樣，一步步告訴系統：創建一個 TextView、把文字設成 Hello、顏色設成紅色、塞到容器裏。

**声明式（ArkUI）：**

Text('Hello')
  .fontColor(Color.Red)

你只描述「最終長什麼樣」，框架自己去算怎麼創建、怎麼更新。

聽起來好像沒省多少代碼？那你再想想：當數據變了，命令式你得手動找到那個 TextView 再 setText；聲明式呢？數據一變，界面**自動**重繪。這就叫「數據驅動 UI」，一旦用上就回不去了。

二、三個核心概念，搞懂就能寫頁面

ArkUI 的世界很小，記住這三件套就夠入門了：

#### 1. 组件（Component）—— UI 的乐高积木

ArkUI 内置了一堆组件：Text、Button、Image、Column、Row、List、TextInput……每个组件就是一块积木。

Text('我是一個文本')
Button('我是一個按鈕')
Column({ space: 8 }) { /* 子組件們排成一列 */ }

#### 2. 狀態（State）—— 界面的「源頭活水」

這是聲明式 UI的靈魂。數據變了，界面自動更新。但 ArkUI 對「什麼數據能驅動 UI」有嚴格規定，必須用裝飾器標記：

新手最常踩的坑：**改了變量，界面沒更新？99% 是你忘了加 @State。**

#### 3. 事件（Event）—— 讓界面「活」起來

按鈕被點了、輸入框文字變了、列表滑到底了……這些都是事件。

Button('+1')
  .onClick(() => {
    this.count++   // @State count 变化 → 界面自动重绘
  })

搞懂這三件套，你已經能寫出 80% 的頁面了。下面動手。

#### 3.1 完整代碼

代碼結構很標準，一個 UIAbility 入口 + 一個主頁面：

**入口文件 EntryAbility.ets：**

import { UIAbility, AbilityConstant, Want } from '@kit.AbilityKit';
import { hilog } from '@kit.PerformanceAnalysisKit';
import { window } from '@kit.ArkUI';
const DOMAIN = 'ArkUIDemo';
export default class EntryAbility extends UIAbility {
  onCreate(want: Want, launchParam: AbilityConstant.LaunchParam): void {
    hilog.info(DOMAIN, 'EntryAbility', 'onCreate: 应用进程创建');
  }
  onWindowStageCreate(windowStage: window.WindowStage): void {
    hilog.info(DOMAIN, 'EntryAbility', 'onWindowStageCreate: 加载 Index 页面');
    windowStage.loadContent('pages/Index', (err) => {
      if (err.code) {
        hilog.error(DOMAIN, 'EntryAbility', 'loadContent 失败: %{public}s', err.message);
        return;
      }
      hilog.info(DOMAIN, 'EntryAbility', 'loadContent 成功');
    });
  }
}

**主頁面 Index.ets（核心代碼）：**

// 数据模型
interface TodoItem {
  id: number;
  text: string;
  done: boolean;
}
// 子组件：计数器卡片
// 演示 @State 局部状态 + 按钮事件
@Component
export struct CounterCard {
  @State count: number = 0
  @Prop label: string = '点击次数'
  build(Column({ space: 12 }) {
      Text(this.label).fontSize(14).fontColor('#888')
      Text(`${this.count}`).fontSize(36).fontWeight(FontWeight.Bold).fontColor('#007DFF')
      Row({ space: 8 }) {
        Button('- 1').backgroundColor('#F5F5F5').fontColor('#333')
          .onClick(() => { if (this.count > 0) this.count-- })
        Button('+ 1').backgroundColor('#007DFF').fontColor('#fff')
          .onClick(() => this.count++)
        Button('重置').backgroundColor('#FF4D4F').fontColor('#fff')
          .onClick(() => this.count = 0)
      }
    }
    .padding(20).backgroundColor('#fff').borderRadius(12).width('100%')
  }
}
// 子组件：单条待办
// 演示父子通信：@Link 双向绑定 + 删除回调
@Component
export struct TodoRow {
  @Link item: TodoItem
  onRemove: (id: number) => void = () => {}
  build(Row({ space: 12 }) {
      Checkbox()
        .select(this.item.done)
        .onChange((v: boolean) => this.item.done = v)
      Text(this.item.text)
        .fontSize(16)
        .decoration({ type: this.item.done ? TextDecorationType.LineThrough : TextDecorationType.None })
        .fontColor(this.item.done ? '#bbb' : '#333')
        .layoutWeight(1)
      Button('✕').backgroundColor('#fff').fontColor('#FF4D4F')
        .onClick(() => this.onRemove(this.item.id))
    }
    .padding({ left: 12, right: 12, top: 10, bottom: 10 })
    .backgroundColor('#fff').borderRadius(8).width('100%')
  }
}
// 主页面
// 演示 @State + ForEach 列表渲染 + TextInput 输入
@Entry
@Component
struct Index {
  @State todos: TodoItem[] = [
    { id: 1, text: '学习 ArkUI 声明式语法', done: true },
    { id: 2, text: '理解 @State / @Link / @Prop', done: false },
    { id: 3, text: '跑通第一个 demo', done: false },
  ]
  @State inputText: string = ''
  private nextId: number = 4
  private addTodo(): void {
    const text = this.inputText.trim()
    if (text.length === 0) return
    this.todos.push({ id: this.nextId++, text, done: false })
    this.inputText = ''
  }
  private removeTodo(id: number): void {
    this.todos = this.todos.filter(t => t.id !== id)
  }
  private get remaining(): number {
    return this.todos.filter(t => !t.done).length
  }
  build(Column({ space: 16 }) {
      Text('ArkUI 入门 Demo').fontSize(22).fontWeight(FontWeight.Bold).margin({ top: 16 })
      CounterCard({ label: '今日点击次数' })
      Row({ space: 8 }) {
        TextInput({ placeholder: '添加一条待办…', text: this.inputText })
          .layoutWeight(1)
          .onChange((v: string) => this.inputText = v)
        Button('添加').backgroundColor('#007DFF').fontColor('#fff')
          .onClick(() => this.addTodo())
      }.width('100%')
      Row({ space: 8 }) {
        Text(`共 ${this.todos.length} 条`)
        Text(`剩 ${this.remaining} 条`).fontColor('#FF4D4F')
      }.width('100%').fontSize(13).fontColor('#888')
      List({ space: 8 }) {
        ForEach(this.todos, (todo: TodoItem) => {
          ListItem() {
            TodoRow({
              item: $todo,                          // @Link 双向绑定
              onRemove: (id: number) => this.removeTodo(id)
            })
          }
        }, (todo: TodoItem) => todo.id.toString())   // keyGenerator
      }
      .layoutWeight(1).width('100%')
    }
    .padding(16).backgroundColor('#F5F5F5').height('100%').width('100%')
  }
}

#### 3.2 這段代碼在幹啥？逐塊拆解

**① 數據模型**

interface TodoItem { id: number; text: string; done: boolean }

TypeScript 接口，定義一條待辦長什麼樣。沒什麼神祕的，就是一份「契約」。

**② CounterCard 子组件**

- `@State count`：組件內部狀態，變了 UI 自動重繪

- `@Prop label`：父組件傳進來的字符串，只讀

- `build()`方法：描述這個組件「長什麼樣」

build() 是 ArkUI 组件的**唯一出口**——所有 UI 必须写在 build() 里，就像 React 的 render()。

**③ TodoRow 子组件**

- `@Link item`：和父組件- **共用一份**- `TodoItem`，父子任意一方改，另一方都同步

- `$todo`這種帶- `$`的寫法，是 ArkUI 的「引用傳遞」語法，等價於傳指針

- `onRemove`是個回調函數，子組件點 ✕ 時，調父組件的- `removeTodo`

**④ Index 主页面**

- `@State todos`和- `@State inputText`：驱动整个页面的两份状态

- `ForEach(this.todos, ...)`：列表渲染，第三個參數是- `keyGenerator`，- **強烈建議顯式傳**，否則列表一變動，性能和狀態都可能出問題

- `TextInput`的- `onChange`把输入同步到- `@State inputText`，这就是「受控组件」模式

四、狀態管理：被名字嚇退的新手第一名

很多人卡在 @State / @Prop / @Link 三個裝飾器上。其實你只要記住一個比喻就行：

@State是你自己的錢包，@Prop是別人給你看的錢包照片，@Link是你和別人共用的同一個錢包。

具體區別：

一個常見錯誤：

// ❌ 错：没加 @State，count 改了界面不刷新
let count: number = 0
Button('+1').onClick(() => count++)
// ✅ 对：加 @State
@State count: number = 0
Button('+1').onClick(() => this.count++)

記住這個坑，能省掉你兩個小時的調試時間。

五、列表渲染：ForEach 的三個坑

ArkUI 的列表渲染用 ForEach，看着像 React 的 map，但坑点不一样：

**坑 1：忘了寫 keyGenerator（第三個參數）**

// ❌ 没有第三个参数，框架只能用 index 当 key，列表一变动就可能状态错乱
ForEach(this.todos, (t: TodoItem) => { ... })
// ✅ 显式传 key
ForEach(this.todos, (t: TodoItem) => { ... }, (t: TodoItem) => t.id.toString())

**坑 2：直接改數組但界面沒刷新**

// ❌ 错：push 是有效的，但有时 ArkUI 不会立刻感知
this.todos.push(newItem)
// ✅ 更稳的写法：重新赋值
this.todos = [...this.todos, newItem]
// 或
this.todos.push(newItem)
this.todos = this.todos.slice()   // 触发引用变化

**坑 3： ForEach 外面套了 List，但 List 沒設高度**

List 在 Column 裏默認會撐滿，但如果你給 List 設了固定高度又不夠大，列表項會被裁掉。新手 demo 階段用 layoutWeight(1) 就夠了。### 六、運行步驟（DevEco Studio）
