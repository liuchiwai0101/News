Anthropic 用 Claude 重寫 Messages API　Rust 版 CPU 用量減七成

內容機器翻譯自第三方媒體（NewMobileLife 流動日報），僅供參考，以原文為準。

Anthropic 研究網誌公佈，已把 Messages API 由 Python 遷移至 Rust，Claude 約用一星期寫出核心請求路徑首個版本。新版本每項請求 CPU 用量減少約 70%，首字回應中位時間快約 20%；生產流量已於 2026 年 9 月切換，全程沒有停機。

流量 1,800 倍逼出的重寫

Messages API 是客户與 Claude Code 等自家應用接觸 Claude 的主要途徑，2024 年初至 2026 年秋流量增長約 1,800 倍。團隊 2024 年曾討論轉用 Go 或 Rust，最終擱下。其後先用 Rust 重寫模型輸出解析、由 Python 呼叫，CPU 只減少約 8% 至 10%，但每個 token 要在兩種語言之間來回三次，複雜度抵不上收益。

隨著 Claude 能力提升，團隊重新考慮全量重寫。到 2026 年 5 月，Claude 已寫出 Anthropic 合併的超過 80% 程式碼，寫程式不再是瓶頸，驗證新舊系統是否一致才是難關。最終 Rust 版記憶體用量減少逾 80%，切換期間亦沒有凍結功能開發。

難關是驗證　不是寫程式

團隊原有約 700 個整合測試，但測試與 Python 實作耦合，審核移植結果時發現超過 100 個斷言被削弱。覆蓋亦有限：僅 20 個二元選項已有逾百萬種組合，逐個測要 12 日。團隊改用生產流量對照：4 月 Rust 版通過約 98% 測試，實際輸入只有約四分之一匹配，5 月初一度跌至 6.5%，修復後回升至 99.6%。

為保障私隱，團隊不讀取用户請求或 Claude 的回覆，只記錄差異的形狀。檢查點定位差異發生在哪個步驟和提示詞哪一部分，再以起始位置和長度差組成指紋，區分不同錯誤。由於同一請求的回覆可能不同，團隊只執行模型一次，再把同一輸出重播給 Rust 比較，並確保每項請求只計算一次用量限額和帳單。

三層迴圈　把修正變成規則

腳本每 10 至 30 分鐘把差異分組，出現新類型才通知協調代理，並開 Slack 討論串供工程師跟進。三層驗證分別是少於一秒的沙盒比對、生產流量驗證，以及把人的修正變成規則的記憶迴圈。網頁搜尋工具描述缺失時，代理的捷徑雖通過本地檢查，仍被工程師否決。6 月代理整理約 60 條審核意見寫入 CLAUDE.md，永久檢查包括新測試與合併檢查。
