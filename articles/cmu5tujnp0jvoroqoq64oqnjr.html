Claude Code 重構 Projects：從文件夾變為可託管多線程的對話式項目

內容機器翻譯自第三方媒體（Anthropic），僅供參考，以原文為準。

AI 導讀

Anthropic 重構 Claude Code 的 Projects，用户設定目標後由 Claude 拆解任務、並行調度多個線程、審查輸出並彙總結果，線程本質上是各自獨立分支的 Claude Code 雲端會話。

推薦理由

官方説明瞭重構後的 Projects 如何用協調者加多線程承接長任務，以及灰度範圍和使用限制，便於判斷是否適合現有工作流。

正文

過去，在一次構建中管理多個會話，需要你拆分工作、來回協調交接，再把結果拼接回去。如今在 Claude Code 項目中，你只需描述需要完成什麼，Claude 就會管理這些工作。

Claude 會界定請求範圍、分派工作、協調並行線程、審查輸出，並彙總出最終結果。你可以在整個過程中隨時引導進度，甚至可以用手機操作，而且在你離開電腦後它仍會繼續工作。

例如，配置一個項目並設定目標：降低你應用結賬流程的 p75 延遲。然後讓 Claude 分析各個端點的性能、測試優化方案，並在並行線程中提交 PR。或者，連接你的 API、Web 和移動端倉庫，設定目標：淘汰已棄用的 v1 端點。Claude 會為每個倉庫創建一個線程，遷移調用方、運行測試、提交 PR，然後告訴你哪些需要先合併。

從今天起，更新版項目將以 beta 形式提供給部分 Claude Pro 和 Max 訂閲用户，這些用户需在 Claude Code 中使用雲會話，且目前在網頁端或桌面端沒有任何現有項目。

在接下來的一週內，我們將向這些套餐中的更多 Claude Code 用户擴大訪問權限。之後，更新版項目將覆蓋所有 Claude 以及 Team 和 Enterprise 套餐。如果你是 Pro 或 Max 用户但尚未獲得訪問權限，可以加入等待名單。

Pro 和 Max 套餐中的現有項目將照常運行。隨着推廣範圍擴大到聊天和 Cowork，我們將對它們進行升級。

線程負責幹活，Claude 負責指揮

項目中的各個線程負責幹活，由一個協調者來指揮它們。

當你啓動一個項目時，你需要選擇一個目標以及倉庫或上下文。Claude 會首先建議它可以立即接手的工作。你可以配置項目的雲環境、連接器、插件、指令和模型。

你可以在項目主聊天中監控和引導進度，也可以深入每個單獨的線程去查看和把控細節。像給幕僚長做簡報那樣在項目中向 Claude 交代任務，它會把工作分配到新的或已有的線程中。

Claude 還會主動跟進並落實工作。連接倉庫後，線程會發起 pull request 並運行你的測試；連接文檔後，它會閲讀文檔並起草內容。

在底層，每個線程都是一個 Claude Code 雲會話，在各自的分支和倉庫副本上工作。協調者負責保持工作有序，但如果任何線程修改了相同的代碼，重疊部分會像其他 PR 一樣以合併衝突的方式解決。

每個線程還可以在需要時通過子智能體、循環和工作流進一步拆分所委派的工作，從而讓大型任務更快完成。

上下文隨時間不斷積累

項目是為長時間運行或智能體式工作流而設計的：即那些耗時超過一次回覆、且包含多個部分的工作。

隨着時間推移，Claude 會瞭解更多項目細節，並將其應用到工作中。現在，每個線程都會為共享記憶添磚加瓦，並從中汲取信息，從而減少了對複雜提示詞工程的依賴。

例如，Claude 可以記住發佈推遲到了週五、導出功能為何被移除，或者在改動計費服務之前應該先找誰確認。

一個項目跨越一週。每個請求在右側開啓一個線程；記憶、決策和結果在其下方逐步累積。

Claude 還會記住你的工作和溝通風格。你可以讓它調整彙報的頻率、開啓新線程的頻率，或者每次更新的詳細程度。

除了記憶之外，項目現在還包含一個庫，用於收集你添加的文件以及 Claude 產出的工件。這樣可以更輕鬆地找到相關材料，也讓新工作能夠建立在過往成果之上。

接下來

項目可以同時運行多個線程，每個線程都是一個完整的 Claude Code 會話。因此，項目可能會更快觸及用量上限。你可以查看項目專屬用量，併為協調對話以及工作線程選擇所使用的模型和投入級別。

線程目前在雲端運行；很快就能在你的機器上運行，與你的本地工具和代碼並行，並在你的網絡環境之內。

開始使用項目。
