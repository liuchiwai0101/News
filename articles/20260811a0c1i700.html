Codex 是一個需要主動配置和磨合的工具。默認配置離最佳體驗有距離，很多功能藏在菜單深處或需要手動創建配置文件。

以下技巧按「配置 → 會話 → 上下文 → 收尾」四個階段歸類，幫你把每一次對話都花在刀刃上。

**01 配置優化 · 把底座調好**

**开启 Luna Max 模型**

Codex 默認不會給你 Luna 模型的最強推理能力，需要手動開啓：**設置 → 配置 → 模型功能 → 開啓 Max**。

開啓後，同一個重構任務的處理思路差別很大——默認模式傾向於快速但是有一些問題我自己用的時候，luna Max 模式相對好些。總的來說讓 **Sol** 做規劃和架構判斷（推理成本高），把執行任務丟給 **Luna Max** 跑（快、適合重複性任務）

**02 會話管理 · 線程各司其職**

**三類線程分工**

把 Codex 對話分成三種角色，就會發現openAI真的做了很多來保護你的上下文。因爲**上下文是最稀缺的資源，所以除了主線它有很多別的可以繼續對話的渠道。**

- ㅤ - **主線程**— 落地：日常都用這條線，保持它的上下文乾淨是最重要的

- ㅤ - **Review 線程**— 比如用來打開當前未提交修改的 Review

- ㅤ - **Side Chat**— 邊想邊幹：適合用來討論時候避免污染上下文，用 /side 開啓，討論結果直接轉化爲主線程的執行指令。

**Fork 會話分叉**

這不是「新建聊天」，而是**從當前對話派生一條支線**——帶着已有的背景、約束和歷史判斷，去試另一種方案。很像 Git 分支的工作流。

其實new、fork、side之間的關係可以簡單看成這樣

**如果是在命令行裏，又是三種入口：**

**什麼時候該 Fork？** 驗證另一條路線、用完全不同的方法重做、主線程太長需要減負。如果只是臨時追問一句，沒必要 Fork；如果徹底換題目了，直接新建線程。

另外，Codex 任務執行久了容易卡死（尤其大任務多次壓縮後），Fork 可以完整復刻會話歷史並開啓新進程，避開卡死問題。

**Quick Chat 边等边想**

左上角新建任務旁邊的加號按鈕，點開就是 Quick Chat。設計意圖很明確：等 Codex 跑長任務時，思考不會停止——突然冒出的靈感、對當前方向的疑慮、想快速查個東西，直接在 Quick Chat 裏聊。

聊清楚了點右上角「添加任務」，討論結果一鍵進入當前任務。

而且 Quick Chat 的額度與 Codex 主額度分開——相當於多了一個免費思考空間。

**跨會話發消息協同**

ChatGPT 和 Codex 合併更新後的新功能：在當前會話裏讓 Codex 給其他會話發消息，不同任務間互相傳遞信息，不用手動複製粘貼。

適合多任務協作場景，這時候大白話和 Codex 說就行。

比如同時跑着3個窗總有相互交叉的時候。

**03 上下文傳承 · 跨會話不斷檔**

**HANDOFF.md 交接文档**

跨天推進複雜任務最大痛點：第二天開新會話，AI 完全失憶。HANDOFF.md 是最輕量的方案——每次結束長會話前，讓 AI 寫一份交接文檔。

**@ 引用跨對話上下文**

在對話輸入框打 @ + 關鍵詞，就能檢索和引用其他對話的上下文，支持跨項目。比如在A對話談論B對話的時候，就可以用這種方式實現。
