React useDisclosure Hook：管理模态框和抽屉的打开关闭状态 (2026)

每個 React 應用都會逐漸積累各種可切換的 UI——確認對話框、移動端導航抽屜、設置彈出框、通知面板。它們背後的狀態始終相同：一個布爾值、一個打開方法、一個關閉方法，可能再加一個狀態變化時觸發埋點或焦點管理的回調。於是你寫了 useState(false) 加三個內聯處理函數，複製粘貼到下一個模態框，到第五個可切換組件的時候，你發現同樣的五行模式散落在十幾個文件裏，沒有複用，也沒有生命週期鉤子。

useDisclosure（來自 @reactuses/core）將這一模式提取爲一次性解決方案：默認非受控，需要時可切換爲受控模式，提供 onOpen / onClose / onChange 回調在恰當的時機觸發。返回的處理函數通過 ref 實現引用穩定，不會導致子組件不必要的重渲染。本文介紹 API、內部實現、受控與非受控的契約，以及模態框、抽屜和組合式多重 disclosure UI 的實際模式。TypeScript 優先。

最簡單的用法：模態框切換

import { useDisclosure } from '@reactuses/core';
function App(const { isOpen, onOpen, onClose } = useDisclosure();
  return (
    <>
      <button onClick={onOpen}>打开设置</button>
      {isOpen && (
        <dialog open>
          <h2>设置</h2>
          <p>这里是设置面板内容。</p>
          <button onClick={onClose}>关闭</button>
        </dialog>
      )}
    </>
  );
}

不需要 useState，不需要寫內聯的 () => setOpen(true) / () => setOpen(false)，不需要糾結命名。Hook 返回語義明確的具名函數——觸發器上用 onOpen，關閉按鈕上用 onClose。每次渲染返回相同的函數引用（ref 穩定化），所以把 onClose 傳給 React.memo 包裹的子組件也不會破壞優化。

完整 API

const {
  isOpen,       // boolean — 当前状态
  onOpen,       // () => void — 设为 true
  onClose,      // () => void — 设为 false
  onOpenChange, // () => void — 切换：关闭时调用 onOpen，打开时调用 onClose
  isControlled, // boolean — 如果传了 isOpen prop 则为 true
} = useDisclosure({
  defaultOpen,  // boolean — 初始状态（仅非受控模式）
  isOpen,       // boolean — 传入以进入受控模式
  onOpen,       // () => void — 打开后触发
  onClose,      // () => void — 关闭后触发
  onChange,     // (isOpen: boolean | undefined) => void — 任何变化时触发
});

所有字段都是可選的。不傳任何參數調用 useDisclosure() 就能得到一個初始關閉的非受控切換，覆蓋大多數模態框和抽屜的需求。

生命週期回調：當打開和關閉有副作用時

布爾切換不夠用的時刻，就是你的模態框不只是顯示和隱藏的時刻。真實的 disclosure 組件需要副作用：用戶打開定價彈窗時發送埋點事件，抽屜打開時捕獲焦點，關閉時恢復焦點。內聯處理函數會把這些邏輯分散到 JSX 各處：

// 没有 useDisclosure 时——副作用与 JSX 缠在一起
<button onClick={() => {
  setIsOpen(true);
  analytics.track('pricing_modal_opened');
  focusTrap.activate();
}}>
  查看定价
</button>

使用 useDisclosure，副作用集中在 Hook 调用处：

const { isOpen, onOpen, onClose } = useDisclosure({
  onOpen(track('pricing_modal_opened');
    focusTrap.activate();
  },
  onClose(track('pricing_modal_closed');
    focusTrap.deactivate();
  },
});
// JSX 变得简洁
<button onClick={onOpen}>查看定价</button>

回調在狀態更新*之後*觸發。回調 props 內部通過 useLatest 包裝——你可以傳入內聯箭頭函數而不會導致返回的 onOpen / onClose 獲得新的引用。

受控模式：由父組件掌控狀態

有時打開狀態屬於父組件或狀態管理器。傳入 isOpen prop，Hook 就會切換到受控模式：

function ControlledDrawer({ isOpen, onToggle }: Props) {
  const disclosure = useDisclosure({
    isOpen,
    onOpen: onToggle,
    onClose: onToggle,
  });
  // disclosure.isControlled === true
  // disclosure.isOpen 反映 prop 的值
  // disclosure.onOpen / onClose 触发父组件的 onToggle
  return (
    <aside className={disclosure.isOpen ? 'open' : ''}>
      <button onClick={disclosure.onClose}>×</button>
      {/* 抽屉内容 */}
    </aside>
  );
}

受控模式下，onOpen 和 onClose *不会*更新内部状态——Hook 尊重 prop 作为数据源。两种模式的边界很清晰：isOpen 是 undefined → 非受控。isOpen 是布尔值 → 受控。

onOpenChange：切换简写

useDisclosure 返回的 onOpenChange 函数就是一个切换器：disclosure 关闭时调用 onOpen，打开时调用 onClose。直接映射到暴露单一回调的组件：

const { isOpen, onOpenChange } = useDisclosure();
// 适配 Radix 风格的 API
<Dialog.Root open={isOpen} onOpenChange={onOpenChange}>
  <Dialog.Trigger>打开</Dialog.Trigger>
  <Dialog.Content>...</Dialog.Content>
</Dialog.Root>

內部實現

完整實現很簡短，三個構建模塊：

- `useControlled`- `useState`和外部 prop 之间切换的 Hook。

- `useLatest`

- **受控守卫**—- `if (!isControlled) setIsOpen(...)`确保 Hook 不会与父组件的状态冲突。

沒有 effect，沒有訂閱，沒有瀏覽器 API。Hook 天然 SSR 安全——純 React 狀態。

useDisclosure vs useBoolean vs useToggle

@reactuses/core 有三个管理布尔值的 Hook：

如果不需要回调或受控模式，useBoolean 或 useToggle 更轻量。

實際模式

確認對話框

function DeleteButton({ onConfirm }: { onConfirm: () => void }) {
  const { isOpen, onOpen, onClose } = useDisclosure();
  return (
    <>
      <button onClick={onOpen}>删除</button>
      {isOpen && (
        <div className="overlay" onClick={onClose}>
          <div className="dialog" onClick={e => e.stopPropagation()}>
            <p>确定要删除吗？</p>
            <button onClick={() => { onConfirm(); onClose(); }}>
              是的，删除
            </button>
            <button onClick={onClose}>取消</button>
          </div>
        </div>
      )}
    </>
  );
}

多个 Disclosure 互斥

function SettingsPanel(const general = useDisclosure({ defaultOpen: true });
  const security = useDisclosure();
  const notifications = useDisclosure();
  const closeAll = (onClose();
    security.onClose();
    notifications.onClose();
  };
  const openExclusive = (target) => {
    closeAll();
    target.onOpen();
  };
  return (
    <div>
      <button onClick={() => openExclusive(general)}>常规</button>
      <button onClick={() => openExclusive(security)}>安全</button>
      <button onClick={() => openExclusive(notifications)}>通知</button>
      {general.isOpen && <GeneralSettings />}
      {security.isOpen && <SecuritySettings />}
      {notifications.isOpen && <NotificationSettings />}
    </div>
  );
}

每個區段有自己的 useDisclosure。openExclusive 輔助函數先關閉所有，再打開一個——不需要手風琴庫就能實現手風琴行爲。

从 Chakra UI 迁移

API 幾乎一樣。主要區別：

- 没有 `getButtonProps`/`getDisclosureProps`— 管理状态，不管理 DOM 属性。

- `onOpenChange`而非- `onToggle`— 行为相同，与 Radix/Headless UI 命名一致。

- 暴露 `onChange`回調用於同步到外部 store。

- 不依賴 UI 框架。

遷移就是一次重命名。

要點總結

- `useDisclosure`替代了- `useState(false)`+ 三個內聯處理函數的模式

- **生命週期回調集中管理副作用**——埋點、焦點管理、動畫觸發。

- **受控模式可選**：傳入- `isOpen`，Hook 聽從你的狀態；不傳，Hook 自己管理。

- **處理函數引用穩定**——安全傳給 memo 化的子組件。

- `onOpenChange`是切换函数

- **天然 SSR 安全**——纯 React 状态。
