OpenRouter 推出美國區域路由，與去年上線的 EU 路由配套保障數據駐留

內容機器翻譯自第三方媒體（OpenRouter：Announcements（RSS）），僅供參考，以原文為準。

今天，我們在去年十月推出的歐盟區域路由基礎上，正式上線美國區域路由，讓您對 AI 工作負載的處理位置擁有確定性控制。發送至 us.openrouter.ai 的請求會在美國境內解密，並且僅路由至美國境內的服務商端點，因此您的提示詞和生成結果在請求的整個生命週期內都始終留在該區域內。eu.openrouter.ai 對歐盟區域也提供同樣的保障。

企業需要更強的數據駐留與處理保障。OpenRouter 的區域路由讓您輕鬆為美國或歐盟區域完成配置。

工作原理

通過區域專屬的 base URL（而非 openrouter.ai）發送 API 請求：

https://us.openrouter.ai/api/v1
https://eu.openrouter.ai/api/v1

您的 API 密鑰、請求體和模型 ID 均保持不變，服務商偏好、回退設置和隱私設置也會從您的賬户自動沿用。您可以將某個服務指向 us.openrouter.ai，而其餘流量繼續使用 openrouter.ai。

發送至 us.openrouter.ai 或 eu.openrouter.ai 的請求會在該區域內完成解密和處理，並且只有運行在該區域內的服務商才能為其提供服務。如果區域內沒有服務商提供該模型，請求將返回 404（No endpoints found supporting your data region.），而不會被路由到區域之外。

區域端點以相同的模型 ID 提供全球目錄中的一部分模型。如果至少有一個提供商能在該區域內提供某個模型，則該模型會列入該區域。要查看實時列表，請通過區域域名調用 /api/v1/models，或在模型頁面按“區域內路由”篩選（US 或 EU）。我們將繼續向兩個區域添加模型和提供商。在 Discord 的 #feedback 中告訴我們你希望接下來哪些模型支持區域內服務。

你還可以通過 Guardrails 為特定工作區、團隊或 API key 強制啓用區域內路由。將 Guardrail 的允許數據區域設置為一個區域後，OpenRouter 會拒絕任何在其他主機名上到達的、受該規則覆蓋的請求。你可以在設置中的 Guardrails 下進行配置，或通過 Management API 進行配置。

區域內路由適用於 Business 和 Enterprise 套餐。

US/EU 區域內提供的模型

如果不使用區域內路由（In-Region Routing），使用總部位於美國或歐盟的實驗室所開發的模型，並不能保證請求一定由該區域內的數據中心處理。在全球端點上，來自 OpenAI、Anthropic、Google、xAI、Meta、NVIDIA、Thinking Machines 或 Mistral 的模型，可以在提供請求服務的供應商所運營的任何地方運行。數據駐留審查會詢問你的請求在哪裏被解密、推理在哪裏執行，因此一個美國團隊在全球端點上使用 GPT-5.6、Claude Opus 5 或 Gemini 3.6 Flash，仍可能無法通過合規審查。OpenRouter 的區域內路由可確保請求始終停留在你指定的區域內：美國或歐盟。

區域內可用的中國開源權重模型

開源權重模型正在快速進步，將流量轉向它們可以顯著降低成本。在 OpenRouter 上，無論是來自美國還是歐盟的請求，流向開源權重模型的 token 佔比都在穩步上升：

來自美國實驗室的模型，如 NVIDIA 的 Nemotron 3 Ultra 和 Thinking Machines 的 Inkling，是這一增長的一部分。但來自中國實驗室的模型仍佔據大部分流量，而這些模型的採購審批可能比較困難。

區域路由（In-Region Routing）讓有數據駐留要求的團隊也能獲得中國開源權重模型帶來的價格與性能優勢。當美國或歐盟的提供商託管模型時，請求會發往該提供商，模型實驗室本身不參與其中。DeepSeek V4 Pro、Kimi K3 和 GLM 5.2 均可用於美國區域路由，因為 Baseten、Fireworks 和 Azure 在美國數據中心提供這些模型的服務。通過 us.openrouter.ai 向其中任何一個發送提示詞，請求都會在美國境內解密並運行。GLM 5.2 也可在 eu.openrouter.ai 上使用，由 Mistral 的歐盟數據中心提供服務。

確保端到端的區域路由

當網關提供區域路由時，它可能意味着兩種不同的情況。區別在於你的提示詞是否會以明文形式存在於該區域之外。

  • 僅推理層面的區域路由。 網關將提供商的推理服務固定在你的區域內。但請求本身會在被轉發給提供商之前，先在網關運行的地方完成解密和處理。在這段路徑中，你的提示詞會以明文形式存在於你的區域之外。服務器工具在區域化方面常常被忽視，這可能導致你的提示詞數據離開管轄範圍。例如，網絡搜索有時會在區域推理端點上使用全局實例。
  • 端到端區域路由。 這就是 OpenRouter 的區域內部路由（In-Region Routing）的工作方式。它確保你的數據在整個路徑中都留在區域內。發往 us.openrouter.ai 或 eu.openrouter.ai 的請求會在區域內解密，並在每一步都在區域內處理。只有運行在該區域的提供商才會收到這些請求。如果沒有區域內提供商能夠提供該模型，請求將以 404 失敗（No endpoints found supporting your data region.）。數據永遠不會離開該區域。在特定司法管轄區提供服務器工具之前，我們會全面評估這些工具及其運行所在的數據司法管轄區。會將數據發送到區域之外的工具會被禁用，而不會回退到全球基礎設施。

在評估任何網關的數據駐留聲明時，要問兩個問題：請求在哪裏被解密和處理？它的工具在哪裏運行？

區域內部路由在我們的 Business 和 Enterprise 套餐中可用。你可以從 套餐設置 升級到 Business，或 聯繫企業團隊。

然後從 US 或 EU 列表中選擇一個模型，並將請求發送到 https://us.openrouter.ai/api/v1 或 https://eu.openrouter.ai/api/v1。
