Antigravity SDK 支持本地模型，可完全離線運行智能體

內容機器翻譯自第三方媒體（Google Developers Blog），僅供參考，以原文為準。

AI 導讀

Google 宣佈 Antigravity SDK 支持本地模型工作流，首發通過 Google AI Edge 的 LiteRT 支持 Gemma 4 26B A4B，可完全離線運行智能體，建議機器配備 >24GB VRAM 或統一內存。

推薦理由

官方發佈了本地模型支持與混合編排示例，給出代碼、硬件要求和具體 token 數據，開發者可評估離線智能體工作流的可行性。

正文

今天，我們宣佈Antigravity SDK支持跨多種本地模型和執行選項的本地工作流，並初步支持Gemma 4 26B A4B使用Google AI Edge的LiteRT.

Antigravity SDK 讓開發者能夠利用驅動 Google Antigravity 的同一套智能體能力進行構建。藉助這項新支持，你可以完全離線地通過本地模型啓用智能體輔助。我們已針對 LiteRT 和 Gemma 4 26B 優化了這一工作流，高效利用本地 GPU 和 RAM，從而進一步放大你本地機器所能提供的性能！

為什麼要本地運行智能體？

本地模型執行能為智能體體驗帶來多項優勢：

  • 成本效益：無需 API 費用或速率限制即可執行本地智能體工作流。
  • 隱私性：將你的代碼和請求完全保留在本地機器上，非常適合需要應對嚴格數據隱私要求或受合規限制的企業環境的開發者。
  • 離線韌性：即使在沒有穩定或持續互聯網連接的環境中，也能無縫執行你的智能體工作流。
  • 混合工作流：將 token 高效的本地流程與雲端流程相結合，在需要時仍可訪問更大、更強大的模型，從而最大化效率。

以下是如何開始：（我們建議使用顯存或統一內存大於 24GB 的機器）。

創建虛擬環境：

python3 -m venv .venv
source .venv/bin/activate

安裝 Antigravity SDK 和 LiteRT-LM，並下載 Gemma 4 26B A4B：

pip install google-antigravity litert-lm

litert-lm import \
  --from-huggingface-repo=litert-community/gemma-4-26B-A4B-it-litert-lm \
  gemma-4-26B-A4B-it-gpu.litertlm \
  gemma4-26b

在你的目錄中，創建一個文件，命名為 agy_sample.py。將以下內容粘貼進去。

import asyncio
import os
from google.antigravity import Agent, LiteRTAgentConfig
from google.antigravity.hooks import policy

# UPDATE: Point to the locally downloaded model from the previous step (litert-lm import ...)
MODEL_PATH = os.path.expanduser("~/.litert-lm/models/gemma4-26b/model.litertlm")

async def main():
   print(f"Using local LiteRT model: {MODEL_PATH}. Please wait for local inference to complete. This could take several minutes.")

   config = LiteRTAgentConfig(model_path=MODEL_PATH).lightweight()
   async with Agent(config) as agent:
      response = await agent.chat("What files are in the current directory?")
      async for token in response:
         print(token, end="", flush=True)

if __name__ == "__main__":
   asyncio.run(main())

混合編排：雲端架構師遇上端側工作大軍

在許多情況下，我們發現架構師-構建者模式是將雲端模型規模與本地模型優勢相結合的絕佳方式。在下方使用更新版 Antigravity SDK 構建的混合演示視頻中，一位雲端架構師（Gemini 3.8 Flash）擔任規劃者和指揮者，而由 Gemma 4 26B 實例組成的本地集群則完全在端側承擔繁重的工作。

當任務是對三個存在漏洞的模塊（auth.py、billing.py 和 database.py）進行審計和修補時，該工作流保持了嚴格的數據隱私，並讓我們能夠最大限度地利用 token：

  • 未上傳任何代碼： Gemini 3.8 Flash 僅根據文件名和任務描述來規劃策略並拆解工作——僅消耗 95 個雲端 token，且任何源代碼都從未離開本機。
  • 自主本地挑戰流程： 本地 Gemma 4 26B 模型接管本地 GPU，執行對抗性審計循環：復現安全漏洞、編寫候選修復、評審補丁，並針對迴歸測試套件進行驗證。
  • 成本與隱私的巨大收益： 在本次記錄的運行中，97.2% 的 token（3,322 個 token）在本地離線運行，未調用任何雲端 API，在交付完全驗證通過的綠色補丁的同時，將專有代碼完全安全地保留在設備本地。

查看此處的示例項目，運行內置的 3 文件挑戰流程，或將其指向你自己的 Python 模塊和測試套件。

零 token 本地實用工具：CLI 資源監控器

搭載 Gemma 4 26B A4B 的 Antigravity SDK 在構建實用系統工具方面表現出色。在這個示例中，該智能體構建了一個在終端中運行的實時更新資源監視器。只需一條提示詞，智能體就會自主編寫一個使用 psutil 和 rich 庫來跟蹤 CPU 和內存使用情況的 Python 腳本，生成所需的 requirements.txt 文件，甚至還會測試生成的代碼以確保其正常工作——這一切都完全在你的本地機器上運行，並使用 Gemma 4 26B。

一個使用 Gemma 4 26B 在設備端生成的基於 Python 的 CLI 資源監視器工具

## cli_resource_monitor.py

import asyncio
import os
from google.antigravity import Agent, LiteRTAgentConfig
from google.antigravity.hooks import policy

# UPDATE: Your prompt
PROMPT = "Build a command-line interface tool using the psutil and rich libraries that displays a live-updating terminal dashboard. It should show CPU usage, memory consumption, and a sorted table of the top 5 most memory-intensive processes. Save the script as 'monitor.py' and create a 'requirements.txt' file. Test that it works."

# UPDATE: Point to the locally imported LiteRT-LM model path
MODEL_PATH = os.path.expanduser("~/.litert-lm/models/gemma4-26b/model.litertlm")

# UPDATE: Give AGY-SDK a workspace to write files
WORKING_DIR = os.path.expanduser("~/agy-test")

os.makedirs(WORKING_DIR, exist_ok=True)
os.chdir(WORKING_DIR)

async def main():
  print(f"Using local LiteRT model: {MODEL_PATH}. Please wait for local inference to complete. This could take several minutes.")

  config = LiteRTAgentConfig(
     model_path=MODEL_PATH,
     workspaces=[WORKING_DIR],
     policies=[policy.allow_all()],
  ).lightweight()

  async with Agent(config) as agent:
     response = await agent.chat(PROMPT)
     async for token in response:
        print(token, end="", flush=True)

if __name__ == "__main__":
  asyncio.run(main())

Antigravity SDK 還通過 LocalOpenAIAgentConfig 為任何兼容 OpenAI 的服務器（如 Ollama、LM Studio 或 vLLM）提供無縫的即插即用支持。這讓你能夠靈活地試驗不同的本地推理後端，同時保持你的智能體編排、工具和工作流完全不變。

查看 Antigravity Python SDK README 中的説明即可開始使用本地 AI，並通過 LiteRT 瞭解更多關於如何在邊緣高效運行模型的信息。請在 Antigravity Python SDK GitHub Issue Tracker. 上分享你的反饋和功能請求。我們期待看到你構建的作品！
