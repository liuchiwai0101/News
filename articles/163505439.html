在 Vue 應用中，狀態管理從“多組件共享數據”到“複雜業務邏輯協調”，常常是項目架構中最具挑戰性的一環。隨着 Vue3 的普及，Pinia已取代 Vuex 成爲官方推薦的狀態管理庫。

本文將從前端狀態管理的核心問題出發，通過完整的實戰案例，對比 Vuex 與 Pinia 的差異，並深入講解模塊化設計與數據持久化的最佳實踐。

**語法極簡**：在 Vuex 中定義一個計數器需要編寫 state、mutations、actions 等多個部分；而 Pinia 只需一個 `defineStore`，在 actions 中直接修改 `this.count` 即可。

**TypeScript 一等公民**：Pinia 在設計之初就充分考慮了對 TypeScript 的支持，幾乎所有 API 都能自動推導類型，大幅減少手動類型聲明的工作量。

**輕量且性能優秀**：在同樣執行 1000 次同步 action 的場景下，Pinia 的延遲約爲 5-8ms，而 Vuex 爲 8-12ms，提升約 30%。高頻觸發場景（1000次/秒）下，Pinia 的吞吐量更是優於 Vuex 約 40-50%。

- 項目爲 Vue2 且已深度使用 Vuex，遷移成本過高

- 依賴較複雜的 Vuex 中間件生態，如 `vuex-persistedstate`的特殊用法

- 對 Vuex 的嚴格單向數據流規範有強依賴

對於新項目，尤其是 Vue3 項目，Pinia 無疑是更優的選擇。

pnpm add pinia

在 main.ts 中注册 Pinia：

import { createApp } from 'vue'
import { createPinia } from 'pinia'
import App from './App.vue'
const pinia = createPinia()
const app = createApp(App)
app.use(pinia)
app.mount('#app')
// stores/counter.ts
import { defineStore } from 'pinia'
export const useCounterStore = defineStore('counter', {
  state: () => ({
    count: 0,
    name: '计数器'
  }),
  getters: {
    // 自动推导返回类型
    doubleCount: (state) => state.count * 2,
    // 使用 this 访问其他 getter
    formattedCount(): string {
      return `${this.name}: ${this.count}`
    }
  },
  actions: {
    increment() {
      this.count++
    },
    incrementBy(amount: number) {
      this.count += amount
    },
    // 异步 action 直接返回 Promise
    async fetchInitialCount() {
      const res = await api.get('/count')
      this.count = res.data
    }
  }
})
<script setup lang="ts">
import { storeToRefs } from 'pinia'
import { useCounterStore } from '@/stores/counter'
const counterStore = useCounterStore()
// ✅ 使用 storeToRefs 解构 state 和 getters，保持响应性
const { count, doubleCount, formattedCount } = storeToRefs(counterStore)
// ❌ 直接解构会丢失响应性
// const { count, doubleCount } = counterStore
// ✅ actions 可以直接解构
const { increment, incrementBy } = counterStore
</script>
<template>
  <div>
    <p>Count: {{ count }}</p>
    <p>Double: {{ doubleCount }}</p>
    <p>{{ formattedCount }}</p>
    <button @click="increment()">+1</button>
    <button @click="incrementBy(5)">+5</button>
  </div>
</template>

Pinia 同時支持 Composition API 風格的 Store，更靈活且與 Vue3 生態融合更好：

// stores/user.ts
import { ref, computed } from 'vue'
import { defineStore } from 'pinia'
export const useUserStore = defineStore('user', () => {
  // state
  const userInfo = ref<UserInfo | null>(null)
  const token = ref('')
  // getters
  const isLoggedIn = computed(() => !!token.value)
  const userName = computed(() => userInfo.value?.username || '游客')
  // actions
  function setToken(newToken: string) {
    token.value = newToken
  }
  async function login(credentials: LoginParams) {
    const res = await api.login(credentials)
    token.value = res.token
    userInfo.value = res.user
  }
  function logout() {
    token.value = ''
    userInfo.value = null
  }
  return { userInfo, token, isLoggedIn, userName, setToken, login, logout }
})

隨着應用規模增長，將狀態按業務領域拆分是保持代碼可維護性的關鍵。Pinia 天然支持模塊化——每個 defineStore 定義的就是一個獨立的模塊。

stores/
├── index.ts              # Pinia 实例导出
├── modules/
│   ├── user.ts           # 用户模块
│   ├── cart.ts           # 购物车模块
│   ├── app.ts            # 应用全局配置
│   └── permission.ts     # 权限模块
└── types/
    └── index.ts          # 类型定义

不同 Store 之間可以相互引用，只需在 action 中調用其他 Store 的實例：

// stores/modules/cart.ts
import { defineStore } from 'pinia'
import { useUserStore } from './user'
export const useCartStore = defineStore('cart', {
  state: () => ({
    items: [] as CartItem[]
  }),
  actions: {
    async checkout() {
      const userStore = useUserStore()
      if (!userStore.isLoggedIn) {
        throw new Error('请先登录')
      }
      // 执行下单逻辑...
    }
  }
})

在 stores/index.ts 中统一导出所有模块：

// stores/index.ts
import { createPinia } from 'pinia'
const pinia = createPinia()
export default pinia
export * from './modules/user'
export * from './modules/cart'
export * from './modules/app'

頁面刷新後狀態重置是單頁應用最常見的問題之一。Pinia 本身不提供持久化能力，但可通過插件輕鬆實現。最成熟方案是 pinia-plugin-persistedstate，它受到 vuex-persistedstate 啓發，API 簡潔且功能完備。

pnpm add pinia-plugin-persistedstate

在 main.ts 中注册：

import { createPinia } from 'pinia'
import piniaPluginPersistedstate from 'pinia-plugin-persistedstate'
const pinia = createPinia()
pinia.use(piniaPluginPersistedstate)

在需要持久化的 Store 中添加 persist 選項：

// stores/user.ts
export const useUserStore = defineStore('user', {
  state: () => ({
    token: '',
    userInfo: null
  }),
  actions: { /* ... */ },
  persist: {
    key: 'user-storage',      // 存储 key，默认使用 store id
    storage: localStorage,    // 默认 localStorage
    pick: ['token', 'userInfo'] // 仅持久化指定字段
  }
})
// 使用 sessionStorage，且排除敏感字段
persist: {
  storage: sessionStorage,
  omit: ['tempData'],   // 排除不需要持久化的字段
}
// 在 Setup Store 中使用
export const useCounterStore = defineStore(
  'counter',
  () => {
    const count = ref(0)
    return { count }
  },
  {
    persist: true   // 简单启用全部持久化
  }
)

- `pinia-plugin-persist-uni`：专为 uni-app 设计的持久化方案，采用 uniAppStorage 存储

- Pinia 基於 Vue3 的 Proxy 響應式系統，在深度嵌套對象和大規模狀態變更場景下，性能顯著優於 Vuex（約 20-50%）

- 單個 Store 的 state 不宜過大，否則會影響依賴追蹤效率

- 高頻觸發場景下，Pinia 的吞吐量比 Vuex 高約 40-50%
