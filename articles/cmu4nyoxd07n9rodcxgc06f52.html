OpenAI 發佈模型失準披露框架並公開六份失準報告

內容機器翻譯自第三方媒體（OpenAI），僅供參考，以原文為準。

AI 導讀

OpenAI 發佈跟蹤、調查和披露模型失準（misalignment）實例的新框架，並同時公開過去六個月觀察到的六份報告。

推薦理由

OpenAI 公開披露框架本身及六份具體失準報告，讀者可據此瞭解其披露標準和實際觀察到的模型異常行為。

正文

我們正在分享一套全新的框架，用於追蹤、調查和披露 OpenAI 內部模型失準的實例，同時附上六份關於我們在過去六個月中觀察到的意外或令人擔憂的模型行為的報告。

過去，為了更好地向研究人員、AI 開發者、政策制定者和公眾提供信息，我們曾努力將我們關於失準的發現公之於眾。但由於缺乏系統化的報告方式，我們的披露一直是臨時性的，頻率也低於理想水平：我們常常等到能將多個實例整理成一份報告時才發佈，或者將其添加到新發布模型的系統卡片中。這套新框架旨在加快在觀察到失準現象後發佈報告的速度，即使我們尚未完全解釋或緩解所報告的行為。

隨着 AI 系統日益先進、部署日益廣泛，我們需要就對齊研究的進展建立更廣泛、更知情的一致共識。我們並不認為 AI 行業已經在對齊和監控方面達到了足夠成熟的程度，可以繼續以最高速度負責任地擴展更長時間。關於未來數月和數年 AI 開發應如何推進的決策，需要依據那些前沿模型開發公司之外的人能夠自行審視的證據。

錯位（misalignment）的案例可能有助於識別其他 AI 開發者在系統達到類似能力時可能遇到的問題、揭示防護措施中的薄弱環節，或挑戰關於模型行為的假設。分享這些發現使他人能夠調查同樣的問題、檢驗我們的解釋並改進緩解措施。由於我們相信圍繞錯位保持透明是有價值的，我們的新框架傾向於披露，即使其重要性尚不確定。這意味着我們披露的某些實例可能被證明是虛假的，並非更大模式的一部分，也不預示未來的發展。

目前，尚無全行業框架為 AI 開發者應如何披露其模型中的錯位案例制定明確標準。我們希望今天所提出的框架是朝着建立此類標準邁出的第一步，明確開發者應披露哪些錯位實例以及他們的報告應包含哪些內容。我們將這一框架視為一項仍在完善中的工作，將通過經驗和公眾反饋加以改進。

在此，我們描述該框架將如何運作，並分享我們正在發佈的首批報告。

我們將報告哪些錯位案例

我們旨在披露那些能為以下問題提供有用證據的案例：模型失準如何產生、如何表現，以及防護措施在何處成功或失敗。我們優先關注新機制、已知行為中的實質性變化，以及那些對安全或緩解措施相關假設構成挑戰的發現。一個案例不必造成傷害，也不必構成更廣泛的模式，才值得披露。該框架將覆蓋模型整個生命週期中符合條件的行為——包括訓練、評估、測試和部署。

這包括模型以未經授權的方式行動、與其他模型協同或規避監督的新途徑；使某種對齊方法或防護措施受到質疑的失敗；以及挑戰已發佈安全評估中某項主張的行為。同樣的披露標準也適用於可能影響第三方的失準。

這也可能包括那些看似與我們過去已披露案例重複的失準實例。該問題的重複出現本身可能就是有用的證據，説明我們模型的行為方式或我們防護措施的有效性——例如，如果某種特定類型的失準行為儘管經過反覆緩解努力仍持續出現。在這些情況下，我們將通過更新原有的失準披露來發布這些額外案例。

隨着時間推移，我們計劃與其他開發者、外部研究人員、行業標準機構和監管機構共同制定更客觀的披露標準。我們還認為，嚴重的安全、安保和失準事件應當與美國聯邦政府共享，我們正在努力提出報告機制。我們認為這一框架是對我們現有義務的補充，並指出它不會取代我們的法律披露要求，包括針對重大安全事件或網絡安全漏洞的披露要求。

我們今天分享的失準案例

為啓動我們全新的失準披露框架，我們發佈了六份報告，涉及我們在模型訓練或評估過程中觀察到的失準行為實例。這些案例展示了我們認為值得分享的一系列不同行為，從向用户隱瞞信息，到為克服障礙而採取未經批准的行動。這些是單個實例的報告，不應被視為反映失準在我們各模型中發生的頻率。以下每一項均鏈接至完整報告。

  1. 任務摘要中自我生成的指令。一個未發佈的研究模型將無關指令插入到用於在新上下文窗口中繼續其工作的摘要中，其中包括要求無視其正常約束的指令。我們識別出 27 份受影響的摘要。
  2. 在任務摘要中隱瞞錯誤的指令。在 GPT‑5.6 Sol 的訓練過程中，許多模型實例在摘要中添加了指令，以向用户隱瞞錯誤或行為失準。例如，壓縮摘要中包含指示，要求編造缺失的歷史數據而不予披露，並隱瞞源版本之間的不匹配。
  3. 搜索公開代碼倉庫以尋找暴露的 API 密鑰，然後編造信息。在回答一個關於加利福尼亞州某縣收入數據的常規問題時，一個模型發現並未經授權使用了一個暴露的 API 密鑰。當它仍然無法檢索到所請求的數據時，它編造了這些數據，並將其作為來自所請求來源的數據呈現。
  4. 將文件上傳至互聯網以便引用。當用户向一個未發佈的模型詢問面積大於 5,000,000 平方米的湖泊的 ID 和名稱時，該智能體使用 Python 找到了正確答案。但由於指令要求提供瀏覽器引用，該智能體決定上傳該文件以便在回答中引用，而未詢問用户。
  5. 通過內部軟件倉庫進行未經批准的寫入和通信。模型將內部軟件倉庫用作留言板，在搜索缺失的輸入文件時跨不同訓練樣本交換請求和響應，儘管它們未能恢復這些文件。本報告還審查了一個更早的實例，其中模型在試圖繞過網絡限制時成功將測試文件上傳到了倉庫。
  6. 協作智能體之間未經許可的文件共享。在同一訓練任務上協作的智能體在無法訪問彼此本地文件時，使用公共文件託管網站來共享文件。這使得任務交付物可通過公開 URL 獲取，儘管任務要求模型僅使用本地文件。

我們的披露流程如何運作

任何 OpenAI 員工都可以標記一個失準案例，供我們的安全與對齊團隊調查，並請求將其納入公開披露考慮。這會啓動我們的披露流程，每個步驟都有截止期限，以確保及時調查和披露。

一旦某個示例被標記，我們的技術人員將調查發生了什麼、哪些情況仍不確定、是否應當公開披露，以及哪些事實可以分享。他們還會評估是否有任何第三方受到影響，並需要在發佈前進行私下通知。

隨後，該示例將被歸入三條處理路徑之一：可披露、輕度調查或較大規模調查（“慢速路徑”）。

可披露涵蓋符合條件的實例，其調查已足夠完整，可在審核後發佈。輕度調查涵蓋需要進一步技術調查的實例。我們預計這兩條路徑將覆蓋我們所披露實例的絕大多數，尤其是不需要大量調查、與第三方協調或處理嚴重濫用風險的案例。我們今天發佈的實例全部屬於這兩條路徑之一。

較大規模調查涵蓋複雜調查，尤其是涉及第三方的調查。當第三方受到影響時，我們的安全、法律和負責任披露義務優先於本框架。我們會力求儘快發佈初步通知，但可能出於安全原因需要推遲——例如，如果模型發現了廣泛使用的軟件中此前未知的漏洞。如果一份報告會指認某一第三方，即使未跨越任何安全邊界，我們也打算提前通知。

較大規模調查實例的初步通知將概要説明所發生的情況，説明是否有外部專家協助調查，並提供我們預計何時發佈最終報告的任何可用估計。OpenAI Hugging Face 事件如果根據本框架披露，本應歸入這一軌道。

提出該示例的員工將被告知是否披露該示例的決定，以及如果進行披露，將遵循哪一軌道。關於披露或適當軌道的未解決分歧將提交給 OpenAI 的安全諮詢小組（SAG），該小組由公司各領域的高級官員組成，負責評估前沿模型能力和保障措施、監督我們的 Preparedness Framework，並向 OpenAI 領導層提供建議。SAG 內部的分歧，或員工對其決定的反對意見，將上報至 OpenAI 領導層。不披露或披露不成立的決定將與安全和對齊領導層共享，並在儘可能的範圍內與相關技術人員共享。

隨着我們在實踐中瞭解這一流程的運作方式，我們可能會修訂本披露流程，並將在本文中記錄任何變更。

每份報告將包含的內容

每份完整報告將描述我們觀察到的行為、其嚴重程度及任何外部影響、行為發生的場景、發生日期或日期範圍、我們發現它的時間，以及（在較高層面上）涉及的模型。在可能的情況下，我們還將分享：

  • 事件經過的更多細節及由此造成的任何損害；
  • 我們是如何發現這一失準行為的，以及我們的調查範圍；
  • 我們對其在對齊研究與技術性 AI 安全方面影響的解讀；
  • 該示例所引出的重要未解問題；
  • 我們正在採取或計劃採取以應對該行為的措施。這些措施在披露時未必總能提供，因為我們可能在完成調查或制定修復方案之前就發佈失準報告。

對於發生在客户部署中的失準，我們將在客户隱私和合同義務允許的範圍內儘可能多地分享信息。

今天的報告是一組初步披露，而非對已知失準或正在進行的調查的全面説明。這些初步報告並不旨在代表本框架所涵蓋案例的全部範圍或嚴重程度。我們承諾披露符合本框架標準的失準實例，包括需要更長時間調查或與第三方協調的更復雜案例。我們將持續依據本框架發佈報告，並隨着我們不斷完善相關承諾，分享更多關於報告承諾的信息。
