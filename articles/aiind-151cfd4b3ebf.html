模型剛接進業務，CEO又要換新：紅帽如何接住企業AI落地難題？

內容機器翻譯自第三方媒體（InfoQ），僅供參考，以原文為準。

正文

“剛選定模型、完成平台搭建，業務流程也已經接入。但沒過幾天，市場上又出現一個表現更好的模型，CEO 轉頭就問 CIO：能不能也試試？”紅帽全球副總裁兼大中華區總裁曹衡康（Victor Tsao）提到了企業落地 AI 時經常遇到的一個困境。

對企業來説，換模型並不像個人更換一個聊天工具那麼簡單。模型背後還連接着 GPU 適配、推理服務、數據接口和業務流程，前一套系統剛剛跑順，新模型就來了，企業既不想錯過技術進步，也不願意為此重新搭建整套環境。

Agent 的出現又帶來了另一層壓力。當智能體開始接入企業內部系統，能夠訪問什麼數據、執行哪些操作，就成了必須明確的問題。如果缺乏有效的權限約束，Agent 為了完成任務，甚至可能直接刪除生產數據庫。

模型迭代越來越快，企業需要保持技術選擇的靈活性；Agent 能力越來越強，企業又必須確保其行為可控。這些變化正在推動企業 AI 基礎設施從模型部署和算力供給，進一步走向推理效率、資源管理和運行治理。

紅帽近幾個月的產品佈局也圍繞這些問題展開：從 GPU 調度和 Token 生產，到 Agent 權限管理，再到軟件漏洞發現與修復，試圖解決 AI 從試點走向生產環境時遇到的實際困難。

模型廠商之間的競爭，正在讓企業 IT 部門面臨新的選擇難題。

企業如果把業務流程深度綁定在某個模型和運行環境上，就很難及時享受到新技術帶來的收益。模型換代還會牽動底層硬件、推理框架和應用接口，之前的投入也未必能夠直接複用。

曹衡康認為，企業 CIO 真正關心的不只是哪個模型最好，而是當前選擇的平台能否適應持續變化的技術環境。過去，紅帽將這一思路概括為“四個 Any”：任意加速器、任意雲、任意模型和任意智能體。

紅帽希望延續 Linux 和 OpenShift 的路徑，將開源技術轉化為企業可以長期使用的商業化平台。底層硬件和模型可以變化，但企業不必每次都重新建設整個運行環境。據紅帽介紹，目前其平台支持 20 多個開源模型、合計 700 多個版本。在加速器方面，除了 NVIDIA、Intel 和 AMD，也已經支持國產 GPU 廠商沐曦，並繼續推進其他國產算力產品的適配。

隨着企業對算力的管理需求增加，這種開放性也開始從硬件層向推理服務延伸。

紅帽大中華區方案架構部總經理王慧慧（Aella Wang）提到，紅帽早期將相關場景稱為 GPU as a Service，即通過統一平台管理不同品牌的 GPU，讓企業按需使用。隨着推理需求增長，客户開始更多地談 Token 工廠：將 GPU 資源集中起來，通過模型和推理引擎生產 Token，再將其作為服務提供給不同業務部門。再往上一層，則是 Model as a Service，由企業 IT 部門統一提供模型服務，業務部門根據自身需求選擇模型，而不必分別搭建運行環境。

曹衡康指出，過去一年，單位 Token 價格雖然持續下降，但企業的總賬單不一定減少。隨着思考模型和 Agent 普及，一項任務可能需要多輪推理、工具調用和結果驗證，Token 消耗量也隨之增加。單價下降，並不意味着總支出同步下降。

這也是紅帽提出企業不能只做 Token 消費者，還應該考慮成為 Token 生產者的原因。對於已經投入大量 GPU 資源的企業，可以通過自建推理平台提高算力利用率，減少對外部 API 的長期依賴。

不過，自建 Token 工廠並非天然更便宜。它需要相對穩定的業務負載、合理的 GPU 利用率、專業的運維團隊，以及持續的模型優化能力。如果算力長期閒置，折舊、電力和維護成本反而可能高於直接調用商業 API。企業真正需要比較的，不是單個 Token 的價格，而是完成一項有效任務的綜合成本。

紅帽在推理基礎設施上的佈局，正是圍繞這一問題展開。其深度參與的 vLLM 已經成為開源模型推理領域的重要項目。與此同時，紅帽還推動分佈式推理項目 llm-d，希望進一步解決大規模 GPU 集群中的資源調度和推理效率問題。

10 月 20 日，llm-d 發佈 1.0 版本。相比此前主要關注推理性能和集群調度，這次更新進一步補齊了生產環境所需要的多租户資源管理、請求優先級調度、高可用和滾動升級能力，並增加了面向 Agent 工作流的會話感知路由，讓多輪請求儘可能複用已有上下文緩存，減少重複計算。

IBM Research 的一項基準測試展示了其規模化能力：通過 llm-d 部署約 7530 億參數的模型，在並行 Agent 工作負載下，最多支持 3000 個併發編碼 Agent，峯值輸出吞吐超過每分鐘 660 萬 Token。按照測試採用的雲資源租賃價格估算，單位 Token 成本比同等商業 API 低 5 至 10 倍。

這類優化的價值不僅在於提高吞吐量，也在於讓 GPU 資源能夠承載更多併發任務，降低高負載下的推理成本。

在中國市場，紅帽還與趨境科技共建推理 AI 創新實驗室 AI 推理技術聯合創新實驗室。雙方的分工是，紅帽提供 vLLM 推理框架和標準化平台，趨境科技負責不同模型、加速卡和平台環境下的具體優化，包括 KV Cache 處理等技術實現。雙方希望將成熟成果進一步回饋開源社區。

推理效率解決的是 AI 能否以合理成本運行，Agent 進入企業工作流後，另一個問題隨之出現：企業敢不敢讓它真正執行操作？

王慧慧認為，當前智能體開發本身已經不是很高的門檻，開發人員經過幾個小時培訓，就可能搭建一個能夠完成特定任務的 Agent。真正複雜的是權限管理和治理。

當 Agent 開始承擔 IT 運維工作，它可能修改服務器配置、關閉機器、執行腳本，甚至刪除數據庫。一旦操作超出預期，影響的就不再是一段錯誤回答，而可能是企業真實運行的業務系統。紅帽將這一方向稱為 Agent AIOps，即通過智能體承擔企業內部的 IT 運維工作。

類似的風險也出現在 AI 輔助軟件開發中。AI 生成代碼之後，可以進入自動化開發流程，但並不意味着可以跳過審核。無論代碼由人還是 AI 生成，都需要經過相應檢查，尤其是 AI 生成的代碼，仍需要必要的審核環節，才能進入最終合併流程。

這意味着，企業需要管理的不只是模型本身，還包括 Agent 的實際執行行為：它能調用哪些工具、訪問哪些數據，哪些操作可以自主完成，哪些必須經過人工確認。
