Grok Build 推出記憶功能，可跨會話保留項目約定與決策

內容機器翻譯自第三方媒體（xAI），僅供參考，以原文為準。

AI 導讀

xAI 宣佈 Grok Build 上線記憶功能，會在每輪對話結束後於後台記錄項目約定、決策及事實，供後續會話讀取。記憶按項目區分並另有全局偏好集，/memory 可只讀瀏覽記憶文件，/dream 會將筆記整理為主題文件；當前對話中的指令優先於筆記內容。

推薦理由

原文説明瞭記憶的記錄、整理和優先級機制，讀者可以據此評估它對長期項目編碼工作流的影響。

正文

Grok Build 現在有了記憶。在你工作的過程中，它會記錄出現的約定、決策和項目事實，之後的會話在接觸相關代碼之前會先讀取這些筆記。Grok Build 用得越多，就越好用。

~/dev/orbit

運行測試套件

運行

cargo test

error: connection refused (postgres at localhost:5432)

test result: FAILED. 143 passed; 5 failed; 0 ignored

用 just test，不要用 cargo test。它會先啓動測試數據庫。

運行

just test

正在 :5433 上啓動 postgres ... 就緒

test result: ok. 148 passed; 0 failed; 0 ignored

用 just test 後全部 148 個測試通過。

在該輪對話之後捕獲

一輪對話完成後，Grok 會在後台對其進行回顧，並記錄下任何具有持久價值的內容：約定、決策以及項目事實。捕獲會在每一輪完成的對話上運行，且不會中斷會話。

它記住了什麼

記憶會保存那些在後續會話中最可能重要的細節：團隊如何編寫和審查代碼、決策及其背後的推理，以及關於項目的持久事實，從某個子系統位於何處到哪條命令運行測試套件。任務狀態、暫定結論、機密信息，以及倉庫或其文檔已經涵蓋的任何內容都會被排除在外。

筆記按項目分別保存，另有一套全局筆記用於存放適用於所有地方的偏好設置。

在後台寫入

捕獲會在一輪對話完成後運行，且從不阻塞會話。Grok 會回顧已完成的這一輪對話，將任何值得保留的內容寫成 markdown 筆記，然後繼續。隨着時間推移，/dream 會將這些筆記歸併到主題文件中，每個主題一個文件，因此每個項目最終都會得到一小組有條理的參考資料。

當你回到某個項目時，Grok 會讀取涵蓋它即將着手處理領域的那些主題。當前對話中的指令優先於筆記中的任何內容。

瀏覽記憶

/memory 會打開一個只讀瀏覽器，展示每個記憶文件，按作用域分組，並帶有選中文件的預覽。這是查看某次會話產出了什麼、以及在某條筆記有誤時找到要編輯的文件的最快方式。

新命令

  • /memory 會在上方打開瀏覽器。
  • /dream 會把近期的筆記整理成主題文件，例如 topics/testing.md。Dream 也會在後台定期自行運行。

可用性

Memory 現已在 Grok Build 中可用。它適用於新會話：運行 /new 或啓動一個新的 grok，筆記會在首個完整回合之後開始記錄。
