ArrowJS 1.0 發佈，定位為「代理時代」的輕量響應式 UI 庫

本文為原文轉錄（繁體中文，簡體已自動轉繁），版權歸原媒體所有；內容機器翻譯自第三方媒體，僅供參考，以原文為準。

由 FormKit 和 AutoAnimate 創始人 Justin Schroeder 創建的輕量級響應式 UI 庫 ArrowJS 已經發布 1.0 版本，並被重新定位爲“代理時代”的首個 UI 框架。在作爲公開實驗項目運行約三年後，ArrowJS 1.0 穩定版開源，其代碼庫已經遷移至 GitHub 上的 standardagents 組織下，最新補丁版本於 2026 年 4 月更新至 v1.0.6。

該框架完全基於開發者和大型語言模型都已經熟知的平臺基礎組件構建，即 JavaScript 模塊、帶標籤的模板字面量和 DOM。它不使用 JSX，沒有編譯器，也不需要構建步驟，核心運行時文件大小不到 5KB。其團隊聲稱，該框架的性能基準測試結果與 Vue 3 相當。整個框架僅基於三個函數：reactive、html 和 component。其維護者指出，該框架的全部文檔內容僅佔 20 萬 Token 上下文窗口的不到 5%，這正是其宣稱對智能體友好的核心賣點。

1.0 版本的主要新增功能是一個可選的 WASM 沙箱。@arrow-js/sandbox 包在 QuickJS WebAssembly realm 內運行組件邏輯，同時仍然渲染真實的內聯 DOM，從而允許應用程序在不使用 iframe 或 eval 的情況下執行不可信的、由代理生成的代碼。按照有篇分析文章的說法，這解決了以前無法解決的難題，即如何安全地運行 AI 生成的不可信的界面。圍繞核心功能，本次發佈還在不同的層上通過 @arrow-js/framework、@arrow-js/ssr 和 @arrow-js/hydrate 提供了用於異步組件、服務器端渲染和客戶端水合的包。

在 Hacker News 上，有位評論者認爲， Arrow 實際上是在鼓吹只使用原生 JavaScript，卻通過僞裝成框架來誤導用戶；也有人詢問它與 RxJS 究竟有何不同。一位 r/webdev 用戶稱讚了其極簡主義，指出它僅包含三個輔助函數，卻能用它們構建完整的 Web 應用。而長期用戶則更坦率地指出了其不足之處。

在 GitHub 的一場討論中，一位已經發布過完整應用的開發者報告了以下問題：在監聽器內部修改狀態時會出現錯誤；除非每個項目都帶有唯一鍵，否則映射數據會引發重渲染故障；響應式對象嵌套在其他響應式對象內部時存在一個陷阱。同時，他還提出了對生命週期鉤子、事件修飾符和 DOM 引用（DOM refs）的需求。Schroeder 表示同意，他也認爲值得添加 DOM 引用和一個基本的 mounted 鉤子。

與 React 和 Vue 相比，ArrowJS 以犧牲深厚的組件生態系統和慣用規範爲代價，換取了原始的簡潔性和與平臺的緊密結合，LogRocket 在對這三者的對比分析中探討了這一權衡。

該團隊還提供了一個代理技能，可通過 npx @arrow-js/skill 安裝。該技能可以指導編程代理將 Arrow 添加到當前已有的項目中。完整的文檔和 API 參考涵蓋了詳細的遷移信息以及完整的 API。

ArrowJS 是一個由 FormKit 和 AutoAnimate 的開發者 Justin Schroeder 創建的、體積小巧且無需任何依賴的響應式 UI 庫。它完全基於 JavaScript 模塊、帶標籤的模板字面量和 DOM 等 Web 平臺基礎組件構建，包體大小不足 5KB，無需 JSX、編譯器或任何構建步驟，僅提供三個核心函數：reactive、html 和 component。隨着 1.0 版本的發佈，它現在已經被定位爲專爲“代理時代”設計的框架。目前，該項目在 GitHub 上擁有 3.5k 個星標。
