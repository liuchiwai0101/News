今天我們正式開源了新一代通用視頻模型 MiniMax H3。

**模型概覽**

MiniMax H3 是一個通用型全模態生成系統。它能夠統一理解由文本、圖像、視頻和音頻構成的多模態上下文，並可生成最高 2K 分辨率、最長 15 秒、帶有原生立體聲音頻的視頻。得益於以任務泛化爲導向的系統設計，H3 在預訓練階段便已具備廣泛的多模態上下文理解與生成能力，因此能夠出色地遵循複雜的多模態指令。

H3 支持以下輸入與輸出規格：

- **輸出時長：4–15 秒**

- **輸出寬高比：支持多種寬高比，包括但不限於 21:9、16:9、4:3、1:1、3:4 和 9:16**

- **輸出分辨率：支持多種分辨率尺寸，默認將較短邊設置爲 768 像素。使用 H3-Regenerate-2K 可實現 2K 分辨率生成**

- **输出帧率：24 FPS**

- **輸出音頻：32 kHz 立體聲**

- **支持的對話語言：穩定支持 11 種語言：阿拉伯語、中文、英語、法語、德語、意大利語、日語、韓語、葡萄牙語、俄語和西班牙語。對於其他語言，也提供不同程度的支持。**

模型版本與輸入規格：

**① H3-Base-FL2VA**

**首尾幀模式：**支持輸入 0 張、1 張或 2 張圖像：

- 不輸入圖像時，爲文生視頻模式；

- 輸入首幀圖像時，爲首幀生視頻模式；

- 輸入尾幀圖像時，爲尾幀生視頻模式；

- 同時輸入首幀和尾幀圖像時，爲首尾幀生視頻模式

**② H3-Base-Ref2VA**

**全模態參考模式：**

- **圖像：**最多 9 張；

- **視頻：**最多 3 段；每段時長鬚爲 2–15 秒，總時長不超過 15 秒；

- **音頻：**最多 3 段。音頻必須與圖像或視頻一同輸入，不能作爲唯一輸入；每段時長鬚爲 2–15 秒，總時長不超過 15 秒；

- **混合輸入：**所有類型輸入文件合計最多 12 個

完整的 H3 系統由以下三個模塊組成：

- **H3-Context-IR：**隨着輸入日益複雜，我們構建了一套專門的系統，用於深入理解和提煉輸入的多模態指令，並將其轉換爲 H3 更易於理解、可直接用於生成的形式，即 Context Intermediate Representation（上下文中間表示）。- **H3-Context-IR 對最終輸出質量非常重要。因此我們強烈建議將 H3-Context-IR API 接入生成流程。或者，可參考提示詞指南搭建自己的上下文處理系統。**

- **H3-Base：**根據 H3-Context-IR 的輸出生成音頻和視頻，並輸出 768p 分辨率的結果。

- **H3-Regenerate-2K：**將 768p 的生成結果連同原始上下文一併送回 H3，以 2K 分辨率重新生成輸出。這既發揮了 H3 強大的生成能力，又充分利用了原始上下文中蘊含的豐富信息，從而生成細節更準確、視覺保真度更高的高分辨率結果。

**模型架構**

**H3-Context-IR**

**H3-Context-IR**

H3-Context-IR 是一套託管式預處理與編排系統，專爲自由形式的多模態輸入而設計。

它能夠理解文本、圖像、音頻和參考視頻之間的關係，以及這些素材與預期生成結果之間的關係。其內部工作流包括指令解析、跨模態關聯、時序理解和複雜邏輯推理。

H3-Context-IR 會將其對上下文的理解序列化爲一種 H3-Base 可接收的結構化表示。在不偏離用戶原始意圖的前提下，它也可能在適當情況下補充缺失或描述不充分的語義細節。

由於 H3-Context-IR 依賴多階段工作流，以及多個託管模型與服務，因此不包含在本次開源發佈中。我們提供了 API，幫助用戶復現官方工作流的行爲。同時，我們也提供了詳細教程，開發者可以參考**提示詞指南（鏈接見下方）**，構建自己的預處理系統。

在安全防護機制上，用戶提交的文本、圖像和視頻，以及經過增強的 Prompt，均會接受自動化內容審覈。涉嫌違法、色情或侵犯第三方權利的內容可能會被攔截。我們採用行業標準的過濾措施，但無法完全避免誤判或漏判。上述安全防護機制不影響被許可方在MiniMax H3 Community License下應承擔的義務，尤其是與合法使用和使用限制相關的義務。

**H3-Base**

**H3-Base**

**架構概覽：**

H3-Base 使用不同模態各自對應的編碼器或 VAE 進行編碼，並將編碼後的表示組織成統一的 packed multimodal sequence。隨後，通過 RoPE 表達 token 之間必要的空間和時間關係，再將整個序列輸入 H3-Omni-Transformer。

具體而言，文本由 H3-Encoder 編碼；視覺輸入同時由 H3-Encoder 和 H3-VisualVAE 編碼；音頻則僅由 H3-AudioVAE 編碼。

H3-Omni-Transformer 聯合預測視頻 latent 和音頻 latent，隨後分別將其解碼爲視頻和立體聲音頻。

爲降低長多模態序列的計算開銷，H3 原生支持稀疏注意力訓練與推理。首個開源版本僅提供全注意力推理。我們的稀疏注意力實現將在後續更新中發佈。

**H3-Encoder：**

H3-Encoder 使用 Qwen3-VL-32B 的完整预训练权重，并将其第 50 层的 hidden states 提供给 H3-Omni-Transformer。

我們在 tokenizer 配置中增加了若干 special tokens，例如 。使用 H3 時，需要採用 H3 倉庫中提供的 tokenizer 及相關配置文件。

**H3-VAE：**

H3 分別使用獨立的視覺 latent 和音頻 latent 來表示對應模態。

**① H3-VisualVAE**

H3-VisualVAE 是一個採用時間因果結構的視頻自編碼器，空間壓縮倍率爲 16 倍，時間壓縮倍率爲 4 倍，latent channel 數量爲 24，記作 f16t4d24。我們採用了多種 latent space 優化技術，以同時提升重建質量和 latent 的可學習性。

- 在輸入 H3-Omni-Transformer 之前，視覺 latent 會按照時間、高度和寬度三個維度，以 `1 × 2 × 2`的 patch size 進一步進行 patchify。因此，進入 Transformer 的視覺 token 具有等效 32 倍的空間下采樣倍率，而時間下采樣倍率仍保持爲 4 倍。

- H3-VisualVAE 的 latent space 同時針對重建質量和生成模型的易學性進行了優化。在完成 encoder 訓練後，我們還進一步訓練了一個基於 ViT 的 decoder，以降低解碼成本，並進一步提升重建質量。

**② H3-AudioVAE**

- H3-AudioVAE 使用同一套編碼器和解碼器分別獨立處理左、右音頻聲道，再將解碼後的兩個聲道重新組合，從而支持立體聲音頻的輸入與輸出。

- 對於每個聲道，H3-AudioVAE 會將 32 kHz 音頻壓縮爲時間頻率爲 40 Hz 的 latent token 序列。

- 受 VA-VAE 啓發，我們對 latent space 進行優化，在保持音頻重建質量的同時，使生成模型更容易學習。

**H3-Omni-Transformer：**

爲了實現可擴展性和泛化性，我們採用了相對簡潔的 Transformer block 設計。H3-Omni-Transformer 是一個擁有 33B 參數的 dense、single-stream Transformer，其中約 13B 參數位於與 AdaLN 相關的分支中。由於 AdaLN 的調製輸出可以預先計算並緩存，因此在僅用於推理的部署中，無需加載這部分參數。我們發佈了完整模型權重，以支持包括微調在內的進一步開發。

attention 層和 FFN 層均不包含 modality-specific 結構。與模態相關的參數僅存在於 input/output layer 和 AdaLN 分支中。特別是，modality-specific AdaLN 能夠以相對較低的額外訓練和推理成本提升生成質量。

模型使用三維 Multimodal Rotary Position Embeddings（MM-RoPE），表達時間維度和兩個空間維度，即 (t, h, w) 上的位置關係。

在訓練的最後階段，我們引入了原生稀疏注意力，以降低長序列的計算開銷。稀疏注意力實現未包含在首個開源版本中，將在後續更新中單獨發佈。

**H3-Regenerate-2K**

**H3-Regenerate-2K**

對於 H3 的 2K 分辨率輸出，我們沒有采用傳統的專用超分辨率模塊，而是通過 in-context 的方式，使用 H3 基礎模型對其自身生成的低分辨率結果進行重新生成。

這一方法具有兩方面優勢：

- 再生成過程能夠最大限度地複用 H3 基礎模型已有的生成能力；

- In-context 的形式能夠在生成高分辨率輸出時再次利用原始多模態上下文，從而還原傳統超分辨率方法只能依靠“猜測”來補充的信息，例如小文字和精細細節。

In-context regeneration 也是任務泛化的一個例子。

**由於系統較爲複雜，該模塊目前尚未開源。目前我們正在抓緊完成開源這個模塊所需的大量工作，一旦就緒，會第一時間開放給大家。我們同時提供了一個 API，可用於復現並驗證官方的完整生成結果，具體請參閱下方的完整 2K 工作流。**

**推薦工作流**

爲了幫助社區正確部署 MiniMax H3，我們提供了兩種驗證方法。

完整的 H3 系統由 H3-Context-IR、H3-Base 和 H3-Regenerate-2K 三個模塊組成。因此，“完整 2K 工作流”結合開放平臺 API 與本地部署的 H3-Base，提供了一套用於驗證 2K 輸出的端到端流程。“H3-Base 本地部署”部分則介紹瞭如何僅使用本地部署的 H3-Base，對 768p 輸出進行驗證。

此外，我們也提供了提示詞指南，供開發者進一步參考。

**H3-Base 本地部署**

**H3-Base 本地部署**

MiniMax H3 以两个 task-specific checkpoints 的形式发布。每个 checkpoint 均包含针对相应任务训练的 Omni Transformer Model，以及推理所需的 processor、tokenizer、text encoder、Visual VAE 和独立 Audio VAE。

发布的 checkpoint 均采用针对具体任务进行 CFG Distillation 的 Omni Transformer 权重。每个 checkpoint 均以 self-contained 的 Hugging Face 模型仓库发布，包含以下组件：processor、tokenizer、text encoder、Omni Transformer、Visual VAE、Audio VAE

開發者可以直接從 Hugging Face 下載模型。H3-Base 目前支持通過 **SGLang、vLLM、diffusers 和 ComfyUI** 等推理框架和工作流進行部署。

以 SGLang 爲例，我們分別提供了 FL2VA 和 Ref2VA 兩個 checkpoint 的服務啓動配置。其中，FL2VA checkpoint 支持 T2VA 和 FL2VA 任務；Ref2VA checkpoint 支持基於參考圖像、視頻和音頻的 Ref2VA 任務。開發者可根據具體任務選擇相應的 model variant，並通過多 GPU 並行完成本地推理。

爲幫助社區驗證部署結果，我們同時提供了 T2VA、FL2VA 和 Ref2VA 三類可復現的 768p 音視頻生成案例：

- **T2VA**：輸入完整的 H3-Context-IR Prompt，直接生成包含畫面、環境音、音效與配樂的音視頻內容；

- **FL2VA**：以首幀、尾幀或首尾幀作爲 keyframe，根據 H3-Context-IR Prompt 生成後續音視頻內容。

- **Ref2VA**：聯合使用參考圖像、視頻和音頻，實現人物與場景保留、動作與嘴型編輯、音色參考、原始音頻複用等複合任務。

在 Ref2VA 示例中，模型保留原視頻中的人物身份、服裝、鏡頭構圖、光線和場景，並部分複用原視頻的背景音樂；同時參考另一段男性語音的 voice timbre，爲人物生成新的對白及相應嘴型動作。

三類案例均通過本地 API 提交生成任務，並提供任務狀態查詢和結果下載方法。完整請求參數、H3-Context-IR Prompt 和復現代碼可在 Hugging Face Model Card 中查看。

**完整 2K 工作流**

**完整 2K 工作流**

爲了幫助開發者驗證完整的 H3 生成流程，我們提供了一套 Full 2K Workflow，將本地部署的 H3-Base 與官方 H3-Context-IR、H3-Regenerate-2K API 組合使用，以復現通過 MiniMax API 直接生成的 2K 視頻質量。

整個流程分爲三個階段：

首先，H3-Context-IR 對用戶輸入的文本、圖像、視頻和音頻等多模態信息進行理解與擴展，生成供 H3-Base 和後續再生成階段使用的完整 Prompt。

隨後，本地部署的 H3-Base 根據擴展後的 Prompt 與輸入條件，生成短邊爲 768 像素的音視頻結果。

最後，H3-Regenerate-2K 將 H3-Base 生成的 768p 視頻作爲 base_video，並結合擴展後的 Prompt 與原始輸入上下文，再生成 2K 視頻。

我們同樣提供了三類完整復現案例：

- **T2VA**：输入文本 Prompt，依次完成 H3-Context-IR 扩展、H3-Base 768p 生成与 H3-Regenerate-2K 再生成；

- **I2VA**：輸入文本與首幀圖像，由 H3-Context-IR 生成擴展 Prompt，再通過 H3-Base 和 H3-Regenerate-2K 完成首幀圖生視頻；

- **Ref2VA**：輸入文本、參考視頻與參考音頻，完成多模態參考視頻生成，並在 2K 再生成階段繼續使用原始參考素材與 H3-Base 輸出。

對於每個案例，我們還提供了通過開放平臺 API 直接生成的 2K 和 768p 參考結果，方便開發者對本地部署與完整工作流的輸出進行驗證。

在示例代碼中，本地 H3-Base 輸出會被編碼爲 Base64 Data URL 並傳入 H3-Regenerate-2K；在生產環境中，我們建議將視頻上傳至可公開訪問的 URL，並將該 URL 作爲 base_video 傳入。
