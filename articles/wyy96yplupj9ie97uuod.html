Waku：最小的 React 框架发布 Alpha 版本，专为 RSC 而生

本文為原文轉錄（繁體中文，簡體已自動轉繁），版權歸原媒體所有；內容機器翻譯自第三方媒體，僅供參考，以原文為準。

Waku，一個最小的 React 框架，已經發布了 1.0 alpha 版本，這標誌着它的公共 API 領域已經非常穩定，項目將重點轉移到缺陷修復和兼容性改進上。

Waku 1.0 alpha 對於這個輕量級框架來說是一個重要的里程碑，它已經開發了將近三年。這個版本的發佈穩定了框架的公共 API，並標誌着從功能開發轉向完善和穩定性。團隊承諾在每個版本中提供發佈說明，並在需要時提供遷移指南，因爲他們朝着 1.0 beta 和發佈候選階段努力。

這個版本強調的一個關鍵優勢是 Waku 在大多數具有動態路由的靜態站點中找到了自己的最佳點，包括營銷站點、博客、文檔站點和輕量級電子商務應用。該框架簡單的每個路由配置使得它可以直接在完全靜態或完全動態渲染之間進行選擇，甚至可以將這兩種方法混合在一起，佈局、切片和頁面都有自己的渲染配置。

與早期版本相比，1.0 alpha 版本的發佈引入了一個破壞性變更，這影響了實現基於配置的路由或部署適配器的用戶。入口文件已經從 server-entry.ts 和 client-entry.ts 重命名爲 waku.server.ts 和 waku.client.ts 。從早期版本升級的開發者需要相應地重命名這些文件。這個版本沒有遷移指南，但是有一個早期社區創建的遷移指南提供了從版本 0.25 升級到 0.27 的詳細升級說明。

Waku 將自己定位爲像Next.js這樣的更重框架的替代品，特別是對於那些想要直接使用React Server Components而不需要企業級特性複雜性的小型項目開發者。該框架建立在Vite和Hono之上，優先考慮了開發者體驗，同時支持所有最新的 React 19 特性，包括服務器組件和服務器操作。LogRocket上的一篇比較文章指出，雖然 Next.js 爲複雜應用提供了廣泛的功能，但 Waku 的極簡主義方法使其成爲不需要全面框架化重量級項目的理想選擇。

這個發佈在 React 社區引起了興趣。在Reddit上，一些用戶注意到了公告的簡潔性，Waku 的創造者Daishi Kato在一位用戶詢問框架的目的是什麼後，反饋到：

沒有解釋它是什麼，或者爲什麼我們應該好奇？

Waku 創造者回應：

好主意。它甚至沒有提到它是一個 React 框架...

希望https://waku.gg/#introduction有所幫助，但我不確定是否足以讓人們好奇。如果我要加一些話讓它變得有趣，那就是：

* 它是一個從一開始就爲 React Server Components 開發的 React 框架。

* 它是基於 Vite 和 Hono 的。

* 它的 API 很小，易於學習。

* 開發服務器和構建過程非常快，這主要歸功於 Vite。

這個公告也被Bytes newsletter和Netlify 2025網絡框架回顧所報道，後者指出 Waku 向 alpha 的轉變是 React Server Components 在整個生態系統中成熟的一部分。

開發者應該注意到一些架構考慮。Waku 在這個階段明確設計爲非生產項目，團隊通過他們的GitHub討論積極尋求反饋。框架目前缺乏一些開發者可能期望從成熟框架中獲得的功能，例如內置緩存層，儘管它支持部署到多個平臺，包括 Cloudflare 和 AWS Lambda。

Waku 是一個主要由 Daishi Kato 開發的開源項目，他以創建流行的 React 狀態管理庫Zustand、Jotai和Valtio而聞名。框架的名字，在日語中意味着“激發”，反映了它的目標是在保持輕量級和專注於 React Server Components 基礎的同時，提供一種令人興奮和愉快的開發者體驗。
