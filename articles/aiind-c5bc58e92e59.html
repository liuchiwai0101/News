從三天Demo到一個月全員可用：小紅書企業級AI助理Seal的規模化實踐

內容機器翻譯自第三方媒體（InfoQ），僅供參考，以原文為準。

正文

在 AICon 全球人工智能開發與應用大會上，小紅書架構師孟洪進分享了企業級 AI 個人助理 Seal 的建設實踐。春節前，小紅書團隊基於 OpenClaw 啓動內測，只用三天推出第一個版本；在驗證產品價值後，又迅速完成架構升級和規模化推廣，最終在一個月內實現全員覆蓋。

從 Demo 走向萬級用户，難點並不只是把 Agent 部署起來。企業還必須解決安全、成本、記憶、能力複用和產品生態等一系列問題。本文將結合 Seal 的完整建設過程，介紹小紅書如何應對這些挑戰，以及團隊對下一代智能體的思考。

一個月，從 Demo 到全員覆蓋 春節前，OpenClaw 在全球迅速走紅，小紅書上甚至出現了“500 元上門安裝”的服務。公司內部也有不少員工詢問能否使用。出於安全考慮，安全團隊不建議員工直接在個人電腦上安裝。但此前已經積累了一些 Agent 研發經驗，我們呢判斷 OpenClaw 很有潛力成長為企業通用 AI 助理。

當時，我們決定先投入三個人，用三天時間做出一個內測版本。

項目啓動時，第一個關鍵決策是：基於開源社區做二次開發，還是完全自研？

從技術團隊的角度看，自研往往更有吸引力。不過，在做決策時，主要考慮了四個方面。

第一是產品成熟度。OpenClaw 當時已經在全球範圍內得到大規模試用，產品形態和核心能力都經過了一定程度的驗證。

第二是產品生長規律。一個新產品首先需要驗證需求和價值，而不是一開始就投入大量研發資源。更合理的方式是快速做出原型，通過內測驗證產品是否成立，再決定是否擴大投入。

第三是架構擴展性。我們需要判斷開源項目的架構能否支持企業後續的深度定製。OpenClaw 的插件機制能夠承載計劃建設的很多能力，為後續演進留下了空間。

第四是社區生態。全球開發者不斷貢獻新的 Skill 和代碼。如果完全自研，就很難及時獲得這部分技術紅利。基於社區版本開發，可以持續跟進外部生態的進展。

綜合產品成熟度、驗證成本、架構擴展性和社區生態四個因素，最終決定基於 OpenClaw 二次開發，而不是從零自研。

第一批內測只開放了 200 個名額，但用户熱情遠超預期，很快覆蓋了銷售、運營、算法、HR、財務等不同職能。例如，一位銷售和行業運營同學用 Seal 快速生成了一份火鍋投流方案；算法同學直接讓它輔助取數和分析日常關注的數據；HR 將簡歷篩選設置成定時任務，讓 Agent 每天按照人才畫像完成簡歷初篩。

一位財務同學的案例給我留下了很深印象。以往，財務部門需要向平台團隊提交需求，但很多需求未必能夠及時排期。這位同學直接用 Seal 構建了一個財務平台，用來管理公司內部與 GPU 相關的預算提報和預算使用情況。

這些案例驗證了最初的判斷：通用型 AI 助理可以跨出 Coding 場景，覆蓋公司內不同職能的辦公需求，並帶來明顯的效率提升。

春節前，用三個人、三天時間推出內測版本。春節後，團隊又用一週完成架構升級，使系統具備水平擴展能力，並開放了 2000 個公測名額。發佈後僅五分鐘，所有名額就被搶完，系統甚至一度被大量請求壓垮。

那一刻，我覺得我們迎來了內部產品的“iPhone 時刻”：不再是研發團隊希望推廣產品，而是用户主動要求開放使用。接下來，又用兩週完成規模化提升，並於 3 月中旬實現全員覆蓋。從最初的 Demo 到公司級產品，整個過程非常快。

Seal 的建設過程迫使我們嘗試了一套 AI Native 的項目機制。回頭看，這套機制不僅適用於 Seal，對今後的項目管理和組織設計同樣具有參考價值。我們將產品發展過程分為三個階段：

與之對應，團隊也逐漸形成了三類角色：一小部分人專門研究前沿場景和新模式；一部分人具備很強的動手能力，能夠快速做出原型；還有一部分人擅長架構和穩定性建設，負責把已經驗證成功的產品迅速規模化。

在我的團隊內部，我們已經不再完全按照傳統方式配置專職產品和前端角色，產品同學也開始藉助 AI 直接參與構建。AI Native 不只是用 AI 提升研發效率，更意味着產品驗證方式、項目流程和組織結構都需要隨之改變。

當一個產品從少量用户使用的 Demo 變成萬級規模的企業應用，最直接的挑戰集中在兩個方面：安全和成本。

很多團隊在嘗試企業級 AI 助理時，遇到的第一個問題就是能否把它安裝在員工電腦上。安全團隊通常不會允許一個擁有較強操作能力的 Agent 直接運行在個人終端上。

因此，我們從一開始就選擇了純雲端方案。雲端模式不僅更容易進行統一的安全控制，還可以讓 Agent 24 小時運行，不受員工本地電腦狀態的限制。

另一個問題是成本。AI 助理確實能夠帶來效率提升，但企業仍然需要衡量投入產出比。隨着用户和調用量持續增長，如果不進行系統性的成本治理，模型費用會迅速擴大。

Seal 的安全體系主要包含三個層面：集群安全、運行時安全和數據安全。
